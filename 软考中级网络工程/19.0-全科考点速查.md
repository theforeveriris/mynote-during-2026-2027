## 1.数据通信基础

> 详见 `2.0-通信原理基础.md`、`2.1-信道特性.md`、`2.2-编码与调制.md`、`2.3-差错控制.md`。

### 1.1 交换方式与数据报／虚电路

| 交换方式 | 典型应用 | 交换单位 | 时延特征 | 关键结论 |
| -------- | -------- | -------- | -------- | -------- |
| 电路交换 | PSTN 电话、DDN 专线 | 时隙／信道 | 建立时延大，传播时延小 | 独占资源，连续性好，利用率低 |
| 报文交换 | 电报 | 整份报文 | 存储转发，时延大 | 不独占链路，对大报文缓冲要求高 |
| 分组交换 | IP、X.25、帧中继、ATM | 分组／信元 | 存储转发，时延小 | 统计复用，可逐段纠错重传，吞吐量高 |

[注] 原文把 ADSL 列为电路交换典型，[错误]。ADSL 是用户线频分复用接入技术，其上承载多为 ATM 信元或以太网帧，不属于电路交换。

| 对比项 | 数据报 | 虚电路 |
| ------ | ------ | ------ |
| 连接建立 | 不需要 | 需要 |
| 选路 | 每个分组独立选路 | 建立时确定，所有分组走同一条 |
| 到达顺序 | 可能乱序 | 一般按序 |
| 节点故障 | 后续分组可绕行 | 虚电路中断，需重建 |
| 开销 | 每个分组都带完整目的地址 | 每个分组只带虚电路号 |
| 典型协议 | IP | X.25、帧中继、ATM |

### 1.2 多路复用

| 复用方式 | 分割维度 | 典型应用 | 必记点 |
| -------- | -------- | -------- | ------ |
| 频分 FDM | 频率 | 无线电广播、ADSL、FDD-LTE | 各路占用不同频带，同时发送 |
| 时分 TDM | 时间 | T1／E1、SONET／SDH、WiFi、TDD-LTE | 各路轮流占用同一频带 |
| 波分 WDM | 波长 | 光纤骨干 | 本质是光的频分复用，`c = λf` |
| 码分 CDM | 码型 | 3G、卫星 | 各路用正交码区分，抗干扰强 |
| 统计时分 | 时间（按需） | 分组交换 | 有数据才占时隙，利用率高 |
| OFDM | 正交子载波 | WiFi、4G／5G、ADSL | 子载波正交，频谱效率高 |

### 1.3 核心公式

| 名称 | 公式 | 单位 | 用法 |
| ---- | ---- | ---- | ---- |
| 模拟带宽 | `W = f₂ − f₁` | Hz | 只表示频率范围宽度 |
| 码元速率 | `B = 1/T` | Baud | T 为一个码元持续时间 |
| 每码元比特数 | `n = log₂N` | bit | N 为码元种类数（信号状态数） |
| 数据速率 | `R = B · n = B · log₂N` | bit/s | 码元速率换算比特率 |
| 奈氏码元速率 | `B = 2W` | Baud | 理想低通信道上限，与 N 无关 |
| 奈氏数据速率 | `R = 2W · log₂N` | bit/s | 无噪声信道求 N |
| 香农公式 | `C = W · log₂(1 + S/N)` | bit/s | 有噪声信道求容量，S/N 为线性值 |
| 分贝换算 | `dB = 10·lg(S/N)`，`S/N = 10^(dB/10)` | 无 | 30 dB 对应 1000 |
| 频带利用率 | `ηb = R/W`；`ηs = B/W` | bit/(s·Hz)；Baud/Hz | 同样速率占带宽越小越高 |
| 采样定理 | `f_s ≥ 2·f_max` | Hz | PCM 采样频率下限 |
| PCM 速率 | `R = f_s · n` | bit/s | n 为每个样本量化编码位数 |
| 量化级数 | `M = 2^n` | 个 | n 位编码可表示 M 个量化值 |
| 海明不等式 | `2^k − 1 ≥ m + k` | 位 | m 信息位，k 校验位，可纠 1 位错 |
| 异步有效速率 | `R有效 = 数据位数 × 字符数/秒` | bit/s | 起始、校验、停止位不计 |
| 误信率关系 | `Pb ≈ Pe / log₂M` | 无 | 多进制时误码率大于误信率 |

| 结论 | 表达式 |
| ---- | ------ |
| 两条上限同时存在 | `R ≤ min(2W·log₂N, W·log₂(1+S/N))` |
| 无噪声且只问状态数 | 用奈氏，`N = 2^(R/(2W))` |
| 给出 dB | 先换成线性 S/N，再用香农 |
| 奈氏频带上限 | 2 Baud/Hz |
| 香农频带上限 | `log₂(1+S/N)` bit/(s·Hz) |

[注] dB 速记：10 dB→10，20 dB→100，30 dB→1000，40 dB→10000；`log₂1000 ≈ 10`。

### 1.4 编码

| 编码 | 规则 | 效率 | 典型应用 |
| ---- | ---- | ---- | -------- |
| 单极性 NRZ | 高电平 1、零电平 0，无自同步能力 | 100% | 短距离板内信号 |
| 曼彻斯特 | 每个比特中间必跳变；高→低为 0，低→高为 1 | 50% | 10BASE-T、经典以太网 |
| 差分曼彻斯特 | 每比特中间必跳变；起始处有跳变为 0，无跳变为 1 | 50% | 令牌环网 |
| 4B/5B | 4 位数据映射为 5 位码，保证跳变 | 80% | 100BASE-FX／TX |
| 8B/10B | 8 位数据映射为 10 位码，兼顾直流平衡 | 80% | 1000BASE-X |
| 64B/66B | 64 位数据加 2 位同步头 | 约 97% | 10G／40G／100G 以太网 |
| AMI | 1 交替取正负电平，0 取零电平 | — | E1／T1 线路码基础 |
| HDB3 | AMI 改进，连续 4 个 0 用取代节 | — | E1 接口线路码 |

判断要点：

| 说法 | 判定 |
| ---- | ---- |
| 曼彻斯特编码效率 50%，数据速率是码元速率的一半 | [正确] |
| 差分曼彻斯特比较的是波形形状 | [错误] 比较的是每个比特起始处有无跳变，即上一比特终止电平与本比特起始电平 |
| 4B/5B 用于千兆以太网 | [错误] 4B/5B 用于百兆，千兆用 8B/10B |
| 64B/66B 效率高于 8B/10B | [正确] 约 97% 对 80% |

### 1.5 调制与 PCM

| 调制 | 改变参量 | 直观特征 | 每码元比特数 |
| ---- | -------- | -------- | ------------ |
| ASK | 幅度 | 高低不同 | 1（二进制） |
| FSK | 频率 | 快慢不同 | 1（二进制） |
| PSK | 相位 | 相位不同 | BPSK 1、QPSK 2、8PSK 3 |
| QAM | 幅度＋相位 | 星座点组合 | 16QAM 4、64QAM 6、256QAM 8 |

| 调制方式 | 码元种类数 N | 每码元比特数 |
| -------- | ------------ | ------------ |
| BPSK／DPSK | 2 | 1 |
| QPSK | 4 | 2 |
| 8PSK | 8 | 3 |
| 16QAM | 16 | 4 |
| 64QAM | 64 | 6 |

PCM 三步：

| 步骤 | 动作 | 关键结论 |
| ---- | ---- | -------- |
| 采样 | 按时间间隔取模拟信号瞬时值 | 必须满足 `f_s ≥ 2f_max` |
| 量化 | 连续幅值→离散幅值 | 量化级数越多，量化误差越小 |
| 编码 | 量化值→二进制码 | n 位编码对应 `2^n` 个量化级 |

[注] PCM 编码后直接上线传输，属基带传输；4 幅度 8 相位可组合 `4×8=32` 种码元。

### 1.6 差错控制

| 方法 | 能力 | 开销 | 关键结论 |
| ---- | ---- | ---- | -------- |
| 奇偶校验 | 只能检出奇数个比特错 | 1 位 | 检错不纠错，实现最简单 |
| CRC | 检错，漏检率极低 | 16／32 位 | 只能检错，不能纠错 |
| 海明码 | 可纠正 1 位错、检出 2 位错 | k 位 | 满足 `2^k−1 ≥ m+k`，校验位放在 2 的幂位 |
| 卷积码 | 纠错，用于无线与卫星 | 较大 | 常配合 Viterbi 译码 |

| ARQ 方式 | 发送窗口 | 接收窗口 | 重传范围 | 效率 |
| -------- | -------- | -------- | -------- | ---- |
| 停等 ARQ | 1 | 1 | 当前帧 | 最低，信道利用率差 |
| 后退 N 帧 | ≤2^n−1 | 1 | 从出错帧起全部重传 | 中 |
| 选择重传 | ≤2^(n−1) | ≤2^(n−1) | 只重传出错帧 | 最高，缓冲开销大 |

### 2.1 介质访问控制与 CSMA/CD

| 监听算法 | 信道空闲时 | 信道忙时 | 冲突概率 | 利用率 |
| -------- | ---------- | -------- | -------- | ------ |
| 非坚持 | 立即发送 | 退避随机时间后再听 | 低 | 低，信道有空闲 |
| 1-坚持 | 立即发送 | 持续监听，一空闲就发 | 高 | 高，易冲突 |
| P-坚持 | 以概率 P 发送 | 延迟一个时间单位再听 | 可调 | 折中 |

| 参数 | 10 Mbit/s | 100 Mbit/s | 1000 Mbit/s |
| ---- | --------- | ---------- | ----------- |
| 比特时间 | 100 ns | 10 ns | 1 ns |
| 争用期（10M/100M 为 512 比特时间） | 51.2 μs | 5.12 μs | 4.096 μs（半双工载波扩展，4096 比特时间） |
| 最小帧发送时间 | 51.2 μs | 5.12 μs | 0.512 μs |
| 帧间间隔 | 9.6 μs | 0.96 μs | 0.096 μs |

| 规则 | 内容 |
| ---- | ---- |
| 退避算法 | 第 k 次重传，`k = min(重传次数, 10)`，等待 `T × Random[0, 2^k−1]` |
| 放弃条件 | 连续 16 次冲突后认为网络拥塞或故障，不再发送 |
| 最小帧长 | `Lmin = 2R·d/v`，R 为速率、d 为最远距离、v 为传播速度 |
| 不冲突条件 | 发送时间 ≥ 往返传播时间，即 `L/R ≥ 2d/v` |
| 以太网取值 | `Lmin = 64 字节`（10 Mbit/s 争用期 51.2 μs 含中继器延时；纯 2×2500 m×5 μs/km 仅约 25 μs） |

判断要点：

| 说法 | 判定 |
| ---- | ---- |
| 载波监听可以完全避免冲突 | [错误] 只能减小冲突概率，冲突检测用于发现并中止冲突 |
| 后一次退避时间一定比前一次长 | [错误] 每次都是随机数，窗口变大但取值可更小 |
| 冲突后立即停止发送并发出 Jamming 信号 | [正确] |
| 最小帧长与网络速率、最大距离成正比 | [正确] `Lmin = 2R·d/v` |

| 存储转发 | 收完整帧并校验后转发 | 可差错校验、支持非对称速率 | 延迟大 |
| 直通 | 读到目的 MAC 即转发 | 延迟小、速度快 | 不校验，可能转发坏帧 |
| 碎片过滤 | 收满 64 字节后转发 | 过滤冲突碎片，折中 | 仍不校验 FCS |

| 域 | 定义 | 隔离设备 |
| -- | ---- | -------- |
| 冲突域 | 同一时刻只能有一个站点发送的范围 | 交换机每个端口、路由器每个接口 |
| 广播域 | 一个广播帧能到达的范围 | 路由器、VLAN、三层接口 |

判断要点：

| 说法 | 判定 |
| ---- | ---- |
| 集线器所有端口属于同一个冲突域 | [正确] |
| 交换机所有端口属于同一个广播域（未划分 VLAN） | [正确] |
| 划分 VLAN 可以减小冲突域 | [错误] VLAN 划分的是广播域，冲突域由交换机端口决定 |
| 交换机收到未知目的 MAC 的帧会泛洪 | [正确] 从除入接口外的所有同 VLAN 端口发出 |

### 2.4 VLAN

| 划分方式 | 依据 | 特点 |
| -------- | ---- | ---- |
| 静态（基于端口） | 交换机端口 | 配置简单、最常用，用户换端口即换 VLAN |
| 动态—MAC | 源 MAC 地址 | 用户可移动，需维护 MAC 表 |
| 动态—策略 | 组合条件 | 灵活，配置复杂 |
| 动态—网络层协议 | IP／IPX 等 | 按协议划分 |
| 动态—IP 子网 | 源 IP 地址 | 与子网对应，需三层信息 |

| 端口类型 | 收发规则 | 典型用途 |
| -------- | -------- | -------- |
| Access | 只属于 1 个 VLAN，收发均不带标签 | 接 PC、打印机、服务器 |
| Trunk | 可承载多个 VLAN，默认 PVID 帧不带标签，其余带标签 | 交换机互联、接路由器单臂 |
| Hybrid | 可任意指定哪些 VLAN 带标签／不带标签 | 灵活组网，接 AP 与终端混合 |
| QinQ | 内外两层 802.1Q 标签 | 运营商城域网，用户 VLAN 嵌套 |

802.1Q 标签 4 字节：

| 字段 | 长度 | 取值与作用 |
| ---- | ---- | ---------- |
| TPID | 2 字节 | 固定 0x8100，标识 802.1Q 帧 |
| PRI | 3 位 | 优先级 0～7，7 最高 |
| CFI／DEI | 1 位 | 经典格式为规范格式指示，802.1ad 后为丢弃 eligible |
| VID | 12 位 | 0～4095；0 表示只带优先级，4095 保留，可配 1～4094 |

| 结论 | 内容 |
| ---- | ---- |
| VLAN 数量 | 最多 4094 个可用 |
| 默认 VLAN | VLAN 1，不能删除 |
| 跨 VLAN 通信 | 必须经过三层设备：路由器、三层交换机、防火墙 |
| 单臂路由 | 路由器一个物理口划多个子接口，子接口封装 802.1Q |
| VLANIF | 三层交换机上给 VLAN 配 IP，作为该 VLAN 网关 |
| QinQ 标准 | IEEE 802.1ad（Provider Bridging） |
| PBB | IEEE 802.1ah，MAC-in-MAC |

### 2.5 STP／RSTP／MSTP

| 项目 | 内容 |
| ---- | ---- |
| 桥 ID | 8 字节＝2 字节优先级＋6 字节背板 MAC |
| 默认桥优先级 | 32768，步长 4096 |
| 路径开销 | 与端口带宽成反比，华为默认 802.1t 标准 |
| 根桥 | 优先级最小，其次 MAC 最小 |
| 根端口 | 非根桥上到根桥根路径开销最小的端口 |
| 指定端口 | 每条链路上负责转发 BPDU 的端口，根桥上全部为指定端口 |
| 阻塞端口 | 既非根端口又非指定端口，逻辑阻塞防环 |

| 比较项 | STP 802.1D | RSTP 802.1w | MSTP 802.1s |
| ------ | ---------- | ----------- | ----------- |
| 收敛速度 | 30～50 s | 亚秒级至数秒 | 同 RSTP |
| 端口角色 | 根、指定、阻塞 | 根、指定、替代、备份 | 增加多实例 |
| 端口状态 | 阻塞、监听、学习、转发、禁用 | 丢弃、学习、转发 | 同 RSTP |
| VLAN 负载分担 | 不支持 | 不支持 | 支持，多实例 |
| 兼容性 | 基准 | 兼容 STP | 兼容 STP／RSTP |

| 计时器 | 默认值 | 作用 |
| ------ | ------ | ---- |
| Hello Time | 2 s | 根桥发配置 BPDU 间隔 |
| Max Age | 20 s | BPDU 最长保留时间 |
| Forward Delay | 15 s | 监听、学习各停留 15 s |
| 拓扑变化收敛 | 30～50 s | STP 最坏收敛时间 |

| BPDU | 内容 |
| ---- | ---- |
| 配置 BPDU | 根桥 ID、根路径开销、发送桥 ID、端口 ID，用于选举 |
| TCN BPDU | 拓扑变化通知，向上游逐级传递 |
| 比较顺序 | 根桥 ID → 根路径开销 → 发送桥 ID → 端口 ID |

[注] RSTP“6 s 内收敛”为课程口径，实际典型值为亚秒级至数秒，考试按教材记“远快于 STP”即可。

### 2.6 链路与设备冗余

| 层次 | 技术 | 关键点 |
| ---- | ---- | ------ |
| 链路冗余 | 链路聚合（Eth-Trunk） | 多条物理链路捆绑，带宽叠加、互为备份 |
| 链路冗余 | STP／RSTP／MSTP | 阻塞冗余端口破环 |
| 链路冗余 | SmartLink | 双上行，主备切换，不依赖 STP |
| 链路冗余 | ERPS／RRPP／SEP | 环网保护，毫秒级切换 |
| 设备冗余 | 堆叠／集群 | 多台虚拟成一台，跨设备链路聚合 |
| 设备冗余 | 双电源、双引擎、双风扇 | 单台设备部件冗余 |
| 网关冗余 | VRRP | 虚拟 IP＋虚拟 MAC，Master 转发 |
| 网关冗余 | 堆叠＋Eth-Trunk | 跨设备网关冗余 |

| 扩展方式 | 目的 | 关键点 |
| -------- | ---- | ------ |
| 级联 | 增加端口数量、延长接入距离 | 用普通口或上行口互联，仍受 STP 与上行带宽限制 |
| 堆叠 | 提高上行带宽、设备冗余、统一管理 | 专用堆叠线缆或光口，多台虚拟成一台，可跨设备链路聚合 |

| 堆叠优点 | 堆叠缺点 |
| -------- | -------- |
| 多台虚拟成一台，简化运维 | 多为厂商私有，不能跨厂商 |
| 单台故障不影响转发与控制 | 需专用堆叠线缆或光口 |
| 跨设备链路聚合，物理无环，可不部署 STP | 高端设备双引擎堆叠后仅一套工作，资源浪费 |
| 聚合链路全部可用，利用率 100% | 升级或重启通常有 20～60 s 业务中断 |
| — | 控制平面统一，控制面故障影响整机 |

| VRRP 项目 | 内容 |
| --------- | ---- |
| 虚拟路由器 | VRID 取值 1～255，同一网段内唯一 |
| 虚拟 MAC | `00-00-5E-00-01-{VRID}` |
| 优先级 | 0～255，默认 100，大者当选 Master |
| 抢占 | 默认抢占，可配延迟，避免频繁切换 |
| Master | 响应虚拟 IP 的 ARP，周期发通告，承担转发 |
| Backup | 监听通告，Master 超时后接替 |
| 上行跟踪 | `track interface ... reduced`，接口故障自动降优先级 |
| 认证 | VRRPv2 支持明文与 MD5，VRRPv3 不支持认证（可借助 IPSec 保护） |

### 2.7 网络互联设备与三层架构

| 设备 | 工作层次 | 隔离冲突域 | 隔离广播域 | 关键结论 |

| 层次 | 典型设备 | 设计要点 |
| ---- | -------- | -------- |

| 汇聚层 | 三层交换机 | 路由汇总、VLAN 终结、策略与安全 |

| 字段 | 长度 | 关键结论 |
| ---- | ---- | -------- |
| 版本 | 4 位 | IPv4 为 4 |
| 首部长度 IHL | 4 位 | 单位 4 字节，最小 5（20 字节），最大 15（60 字节） |

### 3.3 ARP 与 ICMP

| 协议 | 作用 | 报文 | 关键结论 |
| ---- | ---- | ---- | -------- |
| ARP | 已知 IP 求 MAC | Request 广播、Reply 单播 | 结果存 ARP 缓存，Windows 用 `arp -a` 查看 |
| RARP | 已知 MAC 求 IP | 广播请求 | 已被 DHCP 取代 |
| 免费 ARP | 主动通告或检测 | 源 IP＝目的 IP 的 ARP Request | 可检测 IP 冲突、刷新交换机 MAC 表 |
| 代理 ARP | 路由器代答 | 路由器用自己的 MAC 回应 | 实现跨网段透明通信，现代网络少用 |

| ICMP 类型 | 含义 | 典型场景 |
| --------- | ---- | -------- |
| 0／8 | Echo Reply／Echo Request | ping |
| 3 | 目的不可达 | 端口不可达、需分片但 DF 置位 |
| 5 | 重定向 | 路由器告知更优下一跳 |
| 11 | 超时 | TTL 减为 0，tracert 依赖 |
| 13／14 | 时间戳请求／应答 | 时间同步探测 |

| 命令 | 协议与原理 | 结论 |
| ---- | ---------- | ---- |
| ping | ICMP Echo | 测试连通性与往返时延 |
| tracert（Windows） | ICMP TTL 递增 | 显示路径；Linux `traceroute` 默认 UDP 高端口 |
| arp -a | 查看 ARP 缓存 | 可发现 IP 冲突与 ARP 欺骗 |
| ipconfig /flushdns | 清 DNS 缓存 | 域名变更后立即生效 |

### 3.4 IPv6

| 字段 | 长度 | 说明 |
| ---- | ---- | ---- |
| 版本 | 4 位 | 6 |
| 流量类别 | 8 位 | 相当于 IPv4 TOS |
| 流标签 | 20 位 | 标识需特殊处理的数据流 |
| 负载长度 | 16 位 | 固定头 40 字节之外的负载，含扩展头 |
| 下一头部 | 8 位 | 扩展头或上层协议类型 |
| 跳数限制 | 8 位 | 相当于 TTL |
| 源／目的地址 | 各 128 位 | — |

| 地址类型 | 前缀 | 说明 |
| -------- | ---- | ---- |
| 全球单播 | 2000::/3（001） | 相当于公网地址 |
| 链路本地 | FE80::/10 | 同一链路通信，由 MAC 经 EUI-64 生成 |
| 站点本地 | FEC0::/10 | 相当于私网，已废弃 |
| 组播 | FF00::/8 | IPv6 无广播，广播功能由组播承担 |
| 任意播 | 从单播空间分配 | 只作目的地址，只配给路由器 |
| 环回 | ::1 | 相当于 127.0.0.1 |
| 未指定 | :: | 相当于 0.0.0.0 |

| 规则 | 内容 |
| ---- | ---- |
| 书写 | 8 组 16 位十六进制，冒号分隔 |
| 前导零 | 每组可省略前导零，不能省略末尾零 |
| 双冒号 | 连续全零组可用 `::` 代替，全地址只能出现一次 |
| 前缀 | `/64` 为常见子网前缀，接口 ID 64 位 |
| EUI-64 | MAC 中间插入 FFFE，并将第 7 位取反 |
| 分片 | 只由源节点分片，中间路由器不分片 |
| 过渡 | 双栈、隧道（6over4、ISATAP）、翻译（NAT-PT） |
| 路由协议 | RIPng、OSPFv3、BGP4+ |
| 地址配置 | DHCPv6 有状态给全参数；无状态只给前缀，接口 ID 由 EUI-64 生成 |
| 邻居发现 | ICMPv6 ND 代替 ARP |

### 3.7 OSPF

| 项目 | 内容 |
| ---- | ---- |
| 类型 | 内部网关、链路状态，IP 协议号 89 |
| 算法 | SPF（Dijkstra） |
| 度量 | Cost＝参考带宽÷接口带宽，默认参考 100 Mbit/s |
| 区域 | 骨干 Area 0，非骨干必须直连 Area 0（可用虚连接） |
| 更新 | 触发式，周期 Hello 维持邻居 |
| 组播 | 224.0.0.5 所有 OSPF 路由器，224.0.0.6 DR／BDR |
| 认证 | 区域或接口，明文／MD5／HMAC-SHA |

| 报文类型 | 编号 | 作用 |
| -------- | ---- | ---- |
| Hello | 1 | 发现与维持邻居、选 DR／BDR |
| DD | 2 | 交换 LSDB 摘要 |
| LSR | 3 | 请求缺失的 LSA |
| LSU | 4 | 发送完整 LSA |
| LSAck | 5 | 确认收到 LSA |

| LSA 类型 | 名称 | 产生者 | 范围 |
| -------- | ---- | ------ | ---- |
| 1 | Router LSA | 每台路由器 | 本区域 |
| 2 | Network LSA | DR | 本区域 |
| 3 | Summary LSA | ABR | 区域间 |
| 4 | ASBR Summary | ABR | 到 ASBR |
| 5 | AS External | ASBR | 全 AS |
| 7 | NSSA External | ASBR | NSSA 内 |

| 邻居状态 | 含义 |
| -------- | ---- |
| Down | 未收到 Hello |
| Init | 收到 Hello，但未看到自己的 Router ID |
| 2-Way | 双向通信，DRother 之间停留在此 |
| ExStart | 协商主从与 DD 序号 |
| Exchange | 交换 DD 摘要 |
| Loading | 发送 LSR 请求缺失 LSA |
| Full | LSDB 同步完成 |

| 网络类型 | Hello | Dead | 说明 |
| -------- | ----- | ---- | ---- |
| 广播 | 10 s | 40 s | 以太网，选 DR／BDR |
| 点对点 | 10 s | 40 s | PPP／HDLC，不选 DR |
| NBMA | 30 s | 120 s | 帧中继，需手工指定邻居 |
| 点对多点 | 30 s | 120 s | 按需电路 |

| DR 选举 | 规则 |
| ------- | ---- |
| 比较顺序 | 接口优先级（0～255，默认 1）→ Router ID（大者优） |
| 优先级 0 | 不参与选举，只能是 DRother |
| 抢占 | 非抢占，DR 稳定后新路由器不夺权 |
| BDR | 监视 DR，DR 故障后接替 |
| Router ID | 手工＞全局 router-id＞Loopback 最大 IP＞物理口最大 IP |

### 4.1 TCP 与 UDP

| ------ | --- | --- |
| 连接 | 面向连接 | 无连接 |

### 4.2 TCP 首部与连接管理

| 字段 | 长度 | 关键结论 |
| ---- | ---- | -------- |
| 源／目的端口 | 各 16 位 | 端口号 0～65535 |
| 序号 seq | 32 位 | 本报文第一个字节的编号 |
| 确认号 ack | 32 位 | 期望收到的下一个字节编号 |
| 数据偏移 | 4 位 | 首部长度，单位 4 字节，最小 5 |
| 标志 | 9 位 | URG、ACK、PSH、RST、SYN、FIN、ECE、CWR、NS |
| 窗口 | 16 位 | 接收窗口，单位字节，最大 65535（可用窗口缩放扩大） |
| 校验和 | 16 位 | 覆盖伪首部＋TCP 首部＋数据 |
| 紧急指针 | 16 位 | 仅 URG＝1 时有效 |
| 选项 | 0～40 字节 | MSS、窗口缩放、SACK、时间戳 |

| 伪首部字段 | 长度 | 说明 |
| ---------- | ---- | ---- |
| 源 IP | 4 字节 | — |
| 目的 IP | 4 字节 | — |
| 保留 | 1 字节 | 全 0 |
| 协议号 | 1 字节 | TCP 为 6 |
| TCP 长度 | 2 字节 | 首部＋数据长度，原文误写为“TCP 报头” |

| 阶段 | 报文 | 状态变化 |
| ---- | ---- | -------- |
| 三次握手 | SYN → SYN＋ACK → ACK | 客户 SYN-SENT→ESTABLISHED；服务器 LISTEN→SYN-RCVD→ESTABLISHED |
| 四次挥手 | FIN → ACK → FIN → ACK | 主动方 FIN-WAIT-1→FIN-WAIT-2→TIME-WAIT→CLOSED |
| 同时关闭 | 双方同时发 FIN | FIN-WAIT-1→CLOSING→TIME-WAIT |
| 被动关闭 | 收到 FIN | ESTABLISHED→CLOSE-WAIT→LAST-ACK→CLOSED |

| 机制 | 关键点 |
| ---- | ------ |
| 可靠传输 | 序号＋确认＋超时重传＋校验和 |
| 快速重传 | 收到 3 个重复 ACK 立即重传，不等 RTO |
| 选择确认 SACK | 只重传缺失段，提高效率 |
| 流量控制 | 接收方通告窗口，发送方不超过 `min(cwnd, rwnd)` |
| 零窗口 | 接收方窗口为 0，发送方启动持续计时器探测 |
| 拥塞控制 | 慢启动指数增长→达到 ssthresh 后线性增长→丢包时减半 |
| 快恢复 | 快重传后 ssthresh 减半，cwnd 从 ssthresh 开始，跳过慢启动 |
| MSS | 以太网下通常 1460 字节＝1500−20−20 |
| TIME-WAIT | 等待 2MSL，确保最后 ACK 到达并清除旧报文 |

| 计时器 | 作用 |
| ------ | ---- |
| 重传 RTO | 超时未确认即重传，RTO 按 RTT 自适应 |
| 持续 Persist | 窗口为 0 时周期性探测 |
| 保活 Keepalive | 长时间空闲探测对端存活 |
| TIME-WAIT | 2MSL 后释放连接 |

| Inform | Client→Server | 只请求配置参数，不要地址 |

| 项目 | 内容 |
| ---- | ---- |

| 租期到期 | 100% 放弃地址，重新 Discover |

| 中继 | 跨广播域，靠 giaddr 字段选地址池 |
| Option 43 | 通告 AC 的 IP，供 AP 上线 |
| Option 82 | 中继代理信息选项，防私接与定位用户 |

## 5.网络安全

> 详见 `9.0-网络安全基础与加密技术.md`、`9.1-网络安全防护系统.md`、`9.2-其他安全技术应用与章节总结.md`。

### 5.1 威胁与攻击类型

| 分类 | 代表 | 是否改变数据 | 检测难度 | 主要防御 |
| ---- | ---- | ------------ | -------- | -------- |
| 被动攻击 | 嗅探、监听、流量分析 | 不改变 | 最难检测 | 加密，重点在预防 |
| 主动攻击 | 假冒、重放、篡改、拒绝服务 | 改变或中断 | 可检测 | 防火墙、IDS／IPS、认证 |
| 物理临近 | 进入机房、接触设备 | — | — | 门禁、监控 |
| 内部人员 | 越权、泄露 | — | 难 | 最小权限、审计 |
| 分发攻击 | 软件发布前被植入 | — | 难 | 供应链校验、签名 |

| 攻击 | 原理 | 防御 |
| ---- | ---- | ---- |
| SYN Flood | 大量半开连接占满队列 | SYN Cookie、限速、源校验 |
| UDP／ICMP Flood | 洪泛消耗带宽 | 流量清洗、限速 |
| Smurf | 伪造源地址向广播地址发 ICMP | 关闭定向广播、入口过滤 |
| ARP 欺骗 | 伪造 ARP 应答劫持流量 | 静态绑定、DAI、ARP 检测 |
| DNS 欺骗／缓存投毒 | 伪造解析结果 | DNSSEC、可信 DNS |
| 中间人 | 截获并转发双方通信 | 证书校验、加密 |
| 重放 | 重复发送截获报文 | 时间戳、随机数、序列号 |
| SQL 注入 | 构造 SQL 语句窃取或篡改数据库 | 参数化查询、输入校验、WAF、数据库审计 |
| XSS | 页面植入恶意脚本 | 输出编码、CSP、WAF、输入过滤 |
| CSRF | 借用已登录 Cookie 发起请求 | Token、Referer 校验、SameSite |
| 暴力破解 | 枚举口令 | 复杂度策略、锁定、验证码、双因素 |
| APT | 长期潜伏、定向渗透 | 沙箱、态势感知、联动阻断、管理制度 |
| 社会工程／钓鱼 | 欺骗人员获取凭据 | 培训、邮件网关、多因素认证 |

| 恶意代码 | 特征 |
| -------- | ---- |
| 病毒 | 依附宿主程序，需用户触发，可自我复制 |
| 蠕虫 | 独立传播，利用漏洞自动扩散，消耗网络 |
| 木马 | 伪装合法程序，提供后门，不自我复制 |
| 勒索软件 | 加密文件索要赎金 |
| 僵尸网络 | 大量被控主机组成，发起 DDoS |
| 陷门／后门 | 绕过正常认证的隐藏入口 |

| 病毒阶段 | 说明 |
| -------- | ---- |
| 潜伏 | 静默等待触发条件，如震网 |
| 繁殖 | 自我复制扩散，如勒索软件 |
| 触发 | 条件满足启动破坏 |
| 执行 | 实施破坏或加密 |

### 5.2 密码算法

| 类型 | 算法 | 密钥／分组 | 结论 |
| ---- | ---- | ---------- | ---- |
| 对称 | DES | 56 位密钥，64 位分组，16 轮 | 已不安全 |
| 对称 | 3DES | 112／168 位密钥 | 兼容老系统，效率低 |
| 对称 | AES | 128／192／256 位密钥，128 位分组 | 主流，软硬件实现快 |
| 对称 | IDEA | 128 位密钥，64 位分组 | PGP 早期使用 |
| 对称 | RC4 | 可变密钥，流密码 | WEP／WPA 使用，已不安全 |
| 对称 | SM1／SM4 | 128 位分组 | 国产商用，硬件／软件实现 |
| 非对称 | RSA | 512～2048 位 | 加密、签名，计算量大 |
| 非对称 | ECC | 160～256 位 | 同等安全强度密钥更短，移动端常用 |
| 非对称 | DH | 大素数 | 只用于密钥交换，不用于加密数据 |
| 非对称 | ElGamal | 大素数 | 加密与签名 |
| 非对称 | DSA | 1024／2048 位 | 只用于数字签名 |
| 非对称 | SM2 | 256 位 | 国产椭圆曲线，加密与签名 |
| 摘要 | MD5 | 512 位分组，128 位输出 | 已可碰撞，不再用于安全场景 |
| 摘要 | SHA-1 | 512 位分组，160 位输出 | 已不推荐 |
| 摘要 | SHA-256 | 512 位分组，256 位输出 | 主流 |
| 摘要 | SM3 | 512 位分组，256 位输出 | 国产杂凑标准 |

| 对比项 | 对称加密 | 非对称加密 |
| ------ | -------- | ---------- |
| 密钥 | 加解密同一把 | 公钥加密、私钥解密，或私钥签名、公钥验证 |
| 速度 | 快，适合大数据量 | 慢，适合小数据量或密钥 |
| 密钥管理 | 分发困难，n 人需 n(n−1)/2 把 | 公钥公开，管理简单 |
| 功能 | 保密性 | 保密性、身份认证、不可否认 |
| 典型 | AES、SM4 | RSA、ECC、SM2 |

| 混合加密步骤 | 内容 |
| ------------ | ---- |
| 1 | 发送方生成一次性对称密钥，加密正文 |
| 2 | 用接收方公钥加密该对称密钥 |
| 3 | 密文与加密后的密钥一起发送 |
| 4 | 接收方用私钥解出对称密钥，再解正文 |

### 5.3 哈希、数字签名与证书

| 项目 | 内容 |
| ---- | ---- |
| 哈希特性 | 单向不可逆、输出定长、抗碰撞、雪崩效应 |
| 完整性 | 对比摘要是否一致 |
| 口令存储 | 存加盐哈希，不存明文 |
| 数字签名流程 | 发送方对消息求摘要→用自己私钥签名→附在消息后 |
| 验签流程 | 接收方用发送方公钥解签名→对消息求摘要→两者比对 |
| 签名提供 | 完整性、身份认证、不可否认；不提供保密性 |
| 签名算法 | RSA、DSA、ECDSA、SM2 |
| 证书内容 | 所有者信息、公钥、有效期、CA 签名、序列号 |
| 证书标准 | X.509 v3 |
| 证书链 | 根 CA→中间 CA→终端证书，逐级验证签名 |

| PKI 组件 | 职责 |
| -------- | ---- |
| 终端实体 | 申请并使用证书的用户、设备或服务 |
| RA 注册机构 | 受理申请、审核身份，不签发证书 |
| CA 认证中心 | 签发、管理、撤销证书，签发 CRL |
| CRL | 证书吊销列表，存放未到期但已失效的证书 |
| 证书发布系统 | 通过目录服务或网站分发证书 |
| 时间戳服务 | 证明签名发生的时间 |

### 5.4 认证与密钥管理

| 方式 | 过程 | 安全性 |
| ---- | ---- | ------ |
| PAP | 两次握手，口令明文 | 低，易被窃听 |
| CHAP | 三次握手，传 MD5 摘要，带随机挑战 | 较高，不传口令 |
| RADIUS | AAA，UDP 1812 认证、1813 计费 | 企业常用 |
| 802.1X | 端口级接入认证，EAP over LAN | 配合 RADIUS，控制入网 |
| Kerberos | KDC 下设 AS 与 TGS，票据授权 | 适合域内单点登录 |
| 数字证书认证 | 用 CA 证书验证对方公钥 | 高，需 PKI |

| Kerberos 步骤 | 内容 |
| ------------- | ---- |
| 1 | 用户向 AS 申请初始票据 TGT |
| 2 | AS 验证身份，返回 TGT 与会话密钥 |
| 3 | 用户持 TGT 向 TGS 申请服务票据 |
| 4 | TGS 返回服务票据，用户访问应用服务器 |

| 密钥分配 | 内容 |
| -------- | ---- |
| 方式 | 设立 KDC，通信双方信任 KDC |
| 会话密钥 | 由 KDC 临时分配，一次一密 |
| 典型协议 | Kerberos |
| 公钥分发 | 证书目录、PKI，防伪造 |

### 5.5 IPSec 与 VPN

| 协议 | 协议号／端口 | 功能 |
| ---- | ------------ | ---- |
| AH | IP 协议号 51 | 完整性、数据源认证，不加密 |
| ESP | IP 协议号 50 | 加密、完整性、认证 |
| IKE | UDP 500；NAT-T 用 4500 | 协商 SA、交换密钥 |
| GRE | IP 协议号 47 | 通用隧道，可承载组播与路由协议 |
| PPTP | TCP 1723＋GRE | 二层隧道，基于 PPP，只支持 IP |
| L2TP | UDP 1701 | 二层隧道，基于 PPP，可跑在 IP／X.25／FR／ATM |
| SSL VPN | TCP 443 | 远程接入，浏览器即可用 |

| 模式 | 封装方式 | 适用 |
| ---- | -------- | ---- |
| 传输模式 | 原 IP 头与 TCP 头之间插入 AH／ESP | 主机到主机 |
| 隧道模式 | 原 IP 头前加 AH／ESP，再套新 IP 头 | 网关到网关、站点互联 |

| 场景 | 推荐 |
| ---- | ---- |
| 出差人员拨号访问内网 | SSL VPN |
| 总部与分支机构互联 | IPSec VPN |
| 需要承载组播／动态路由 | GRE over IPSec |
| 纯二层链路延伸 | L2TP／PPTP |

| IPSec 配置顺序 | 内容 |
| -------------- | ---- |
| 1 | 创建 ACL，匹配感兴趣流 |
| 2 | 创建 IPSec 提议，配置加密与认证算法 |
| 3 | 创建 IKE 提议，配置密钥协商参数 |
| 4 | 创建 IKE 对等体，指定远端地址与预共享密钥 |
| 5 | 创建 IPSec 安全策略，关联 ACL、提议、对等体 |
| 6 | 在出接口应用安全策略 |

### 5.6 安全设备与部署

| 设备 | 部署方式 | 作用 |
| ---- | -------- | ---- |
| 防火墙 | 串行于网络出口 | 区域隔离、访问控制、NAT、VPN |
| IDS | 旁路，端口镜像 | 检测、告警、记录，不阻断 |
| IPS | 串行 | 检测并主动阻断 |
| WAF | Web 服务器前串行 | 防 SQL 注入、XSS 等应用层攻击 |
| 堡垒机 | 旁路 | 运维审计、操作录像、权限管控 |
| 上网行为管理 | 串行于出口 | 应用识别、流量控制、行为审计 |

| 防火墙区域 | 默认优先级 | 说明 |
| ---------- | ---------- | ---- |
| Local | 100 | 防火墙自身 |
| Trust | 85 | 内部可信网络 |
| DMZ | 50 | 对外服务器区，缓冲带 |
| Untrust | 5 | 外部互联网 |

| 方向 | 定义 | 示例 |
| ---- | ---- | ---- |
| Inbound | 低优先级区域→高优先级区域 | Untrust→Trust |
| Outbound | 高优先级区域→低优先级区域 | Trust→Untrust |
| 同区域 | 同优先级互访 | Trust→Trust，默认允许（不受缺省安全策略控制） |

判断要点：

| 说法 | 判定 |
| ---- | ---- |
| IDS 可以主动阻断攻击 | [错误] IDS 旁路部署，只检测告警；IPS 才能阻断 |
| IPS 是 IDS 与防火墙的简单组合 | [错误] IPS 是主动、深层次的防御体系 |
| DMZ 放在 Trust 与 Untrust 之间 | [正确] 常放对外 Web、邮件、DNS 服务器 |
| WAF 主要防网络层攻击 | [错误] WAF 防护应用层 HTTP／HTTPS 攻击 |

### 6.1 网络管理五大功能与协议

| 功能 | 内容 | 记忆 |
| ---- | ---- | ---- |
| 故障管理 | 发现、定位、排除故障 | 障 |
| 配置管理 | 采集、下发、维护配置 | 配 |
| 计费管理 | 流量与费用统计 | 计 |
| 性能管理 | 吞吐、时延、丢包、利用率 | 能 |
| 安全管理 | 认证、授权、审计、加密 | 安 |

| 协议／标准 | 制定者 | 特点 |
| ---------- | ------ | ---- |
| CMIS／CMIP | ISO | 公共管理信息服务与协议，体系完整但复杂 |
| SNMP | IETF | 基于 TCP／IP，简单、实用、事实标准 |
| RMON | IETF | 远程网络监视，减少管理站与被管设备通信量 |
| CMOL | IEEE | 基于 LLC 的 CMIP，用于 LAN／MAN |
| TMN | ITU-T | 电信网管理标准 |
| NETCONF／YANG | IETF | 基于 XML，可编程配置，SDN 常用 |

| SNMP 版本 | 关键机制 | 安全 |
| --------- | -------- | ---- |
| v1 | 团体名 community，Get／Set／Trap | 明文，弱 |
| v2c | 增加 GetBulk、Inform | 仍为明文团体名 |
| v3 | USM 认证加密、VACM 视图、时间序列防重放 | 支持 SHA／MD5 认证、DES／AES 加密 |

[注] SNMPv3 仍未防护的两类威胁：拒绝服务与流量分析。

| SNMP 操作 | 作用 |
| --------- | ---- |
| Get | 读取一个 OID |
| GetNext | 读取下一个 OID，遍历表 |
| GetBulk | 一次读取大块数据（v2 起） |
| Set | 修改被管对象 |
| Response | 代理响应 |
| Trap | 代理主动告警，不需确认 |
| Inform | 管理站间告警，需确认（v2 起） |

| 项目 | 内容 |
| ---- | ---- |
| 承载 | UDP |
| 端口 | Agent 161 收 Get／Set，NMS 162 收 Trap |
| 管理模型 | NMS＋Agent＋MIB |
| MIB | 管理信息库，树形结构 |
| OID | 对象标识符，如 `1.3.6.1.4.1` |
| MIB-II | TCP／IP 管理信息库，含 system、interfaces、ip、tcp、udp 等组 |
| RMON1 | 10 组：统计、历史、告警、主机、主机 TopN、矩阵、过滤、抓包、事件、日志 |
| RMON2 | 扩展到网络层与应用层，9 组 |

### 6.4 RAID

| 级别 | 技术 | 利用率 | 允许坏盘 | 最少盘数 | 结论 |
| ---- | ---- | ------ | -------- | -------- | ---- |
| RAID 0 | 条带化，无冗余 | 100% | 0 | 2 | 性能最好，可靠性最差 |
| RAID 1 | 镜像 | 50% | 每组 1 | 2 | 读性能好，成本高 |
| RAID 3 | 字节条带＋专用校验盘 | (n−1)/n | 1 | 3 | 大文件连续读写好，校验盘瓶颈 |
| RAID 4 | 块条带＋专用校验盘 | (n−1)/n | 1 | 3 | 写校验盘瓶颈明显 |
| RAID 5 | 块条带＋分布式校验 | (n−1)/n | 1 | 3 | 性能、容量、可靠性均衡，最常用 |
| RAID 6 | 双校验 P＋Q | (n−2)/n | 2 | 4 | 允许任意两块盘故障 |
| RAID 10 | 先镜像再条带 | 50% | 每个镜像对 1 | 4 | 可靠性高，数据库常用 |
| RAID 50 | RAID 5 组再条带 | (n−组数)/n | 每组 1 | 6 | 兼顾容量与性能 |

| 概念 | 内容 |
| ---- | ---- |
| 分块 | 分区被切分的相邻等长块，是条带元素 |
| 条带 | 多块磁盘上相同位置的分块集合 |
| 条带深度 | 单个磁盘上连续分块的大小，常见 64～256 KB |
| 条带宽度 | 一个条带跨越的数据盘数量 |
| 热备 | 故障盘自动顶替，分全局热备与专用热备 |
| 重构 | 依据校验或镜像恢复数据，期间性能下降 |
| RAID 2.0 | 磁盘虚拟化，快速重构、负载均衡、利用率高 |

判断要点：

| 说法 | 判定 |
| ---- | ---- |
| 有几块校验盘就最多允许坏几块盘 | [正确] RAID 5 一块、RAID 6 两块 |
| RAID 5 任意坏两块盘仍可恢复 | [错误] 只能坏一块 |
| RAID 10 比 RAID 01 可靠 | [正确] RAID 10 允许不同镜像对各坏一块，RAID 01 可能整体失效 |
| RAID 0 利用率 100% 且具备容错 | [错误] 无冗余，无容错 |

### 6.5 存储架构

| 架构 | 访问级别 | 连接 | 速率 | 典型场景 |
| ---- | -------- | ---- | ---- | -------- |
| DAS | 块级，直连 | SCSI／SAS／FC | 20～320 MB/s | 单机数据库、早期系统 |
| NAS | 文件级 | 以太网，CIFS／NFS | 1／10 Gbit/s | 文件共享、并发读写同一目录 |
| FC SAN | 块级 | FC 交换机，专用网络 | 2／4／8／16／32 Gbit/s | 核心数据库、高 IOPS |
| IP SAN | 块级 | 以太网，iSCSI | 1／10／40／100 Gbit/s | 音视频、大容量、成本敏感 |
| 分布式存储 | 块／文件／对象 | 以太网 | 随节点线性增长 | 云平台、海量并发 |

| 对比项 | FC SAN | IP SAN |
| ------ | ------ | ------ |
| 成本 | 高 | 低 |
| 带宽 | 2～32 Gbit/s | 1～100 Gbit/s |
| 时延 | 低且稳定 | 受 IP 网络影响 |
| 运维 | 专用技能 | 复用 IP 网络与工具 |
| 适用 | 核心数据库小块随机读写 | 音视频、备份、大块顺序读写 |

| 概念 | 内容 |
| ---- | ---- |
| LUN | 逻辑单元号，存储空间划分给前端服务器，一个 LUN 通常只属于一台服务器 |
| 精简配置 | 按需分配物理空间，提高利用率，需监控容量并及时回收 |
| 分层存储 | 按数据热度分 SSD／SAS／SATA，降低成本 |
| 分布式三部分 | 客户端、元数据节点、数据存储节点 |
| 冗余方式 | 多副本、纠删码 |
| 对象存储 | 扁平命名空间，HTTP／S3 接口，适合海量非结构化数据 |

### 6.6 备份与容灾

| 备份类型 | 每次备份内容 | 恢复步骤 | 空间 |
| -------- | ------------ | -------- | ---- |
| 全量 | 全部数据 | 直接恢复 | 最大 |
| 增量 | 上次备份后的变化 | 全量＋依次增量 | 最小 |
| 差异 | 上次全量后的变化 | 全量＋最后一次差异 | 中 |
| 快照 | 某一时刻数据视图 | 回滚快照 | 依实现 |
| CDP | 持续捕获变化 | 任意时间点恢复 | 较大 |

| 指标 | 含义 |
| ---- | ---- |
| RTO | 恢复时间目标，业务中断可容忍时长 |
| RPO | 恢复点目标，允许丢失的数据时长 |
| 双活 | 两个中心同时承载业务，RTO≈0 |
| 主备 | 主中心故障切换备中心 |
| 同城容灾 | 距离数十公里，低时延 |
| 异地容灾 | 距离数百公里以上，防区域性灾难 |
| 3-2-1 原则 | 3 份副本、2 种介质、1 份异地 |

### 7.7 ACL

```text
[R1] acl 2000
[R1-acl-basic-2000] rule 10 permit source 192.168.1.0 0.0.0.255
[R1-acl-basic-2000] rule 20 deny source any
[R1] acl 3000
[R1-acl-adv-3000] rule 10 permit tcp source 192.168.1.0 0.0.0.255 destination 192.168.3.100 0.0.0.0 destination-port eq 80
[R1-acl-adv-3000] rule 20 deny ip
[R1] interface GigabitEthernet0/0/2
[R1-GigabitEthernet0/0/2] traffic-filter inbound acl 3000
```

| 要点 | 内容 |
| ---- | ---- |
| 通配符 | 0 表示严格匹配，255 表示任意；`192.168.1.0 0.0.0.255` 匹配整个 /24 |
| 规则顺序 | 从上到下，命中即停；步长默认 5 |
| 默认动作 | 未命中任何规则时，华为默认 permit |
| 方向 | `inbound` 先查 ACL 再查路由，`outbound` 先查路由再查 ACL |
| 基本／高级 | 2000～2999 基本，3000～3999 高级 |

```text
[R1] interface GigabitEthernet0/0/1
[R1-GigabitEthernet0/0/1] nat static enable
[R1-GigabitEthernet0/0/1] nat static global 12.1.1.2 inside 192.168.1.1
[R1-GigabitEthernet0/0/1] quit
```

```text
[R1] nat address-group 1
[R1-address-group-1] section 0 12.1.1.2 12.1.1.4
[R1] acl 2000
[R1-acl-basic-2000] rule 10 permit source 192.168.1.0 0.0.0.255
```

```text
[R1-GigabitEthernet0/0/1] nat outbound 2000 address-group 1
[R1-GigabitEthernet0/0/1] nat outbound 2000
[R1-GigabitEthernet0/0/1] nat server protocol tcp global 12.1.1.2 80 inside 192.168.1.10 80
```

| 类型 | 命令特征 | 转换对象 |
| ---- | -------- | -------- |
| 静态 NAT | `nat static global ... inside ...` | 一对一固定 IP |
| 动态 NAT | `nat outbound ... address-group ... no-pat` | 多对多，只换 IP |
| NAPT | `nat outbound ... address-group ...` | 多对一，IP＋端口 |
| Easy IP | `nat outbound 2000` | 直接用出接口地址 |
| NAT Server | `nat server protocol ... global ... inside ...` | 公网访问内网服务器 |

## 8.项目管理与法律法规

> 本节无对应视频章节，条文以教材与现行法律为准；真题见 `真题\` 目录。

### 8.1 软件生命周期模型

| 模型 | 核心特征 | 适用 | 缺点 |
| ---- | -------- | ---- | ---- |
| 瀑布 | 阶段线性，文档驱动 | 需求明确稳定 | 后期才见成果，难适应变更 |
| 螺旋 | 迭代＋风险分析，四步循环 | 大型、高风险项目 | 成本高，需风险分析能力 |
| 迭代 | 多次迭代，逐步完善 | 需求渐进明确 | 需良好架构与计划 |
| 增量 | 按功能分批交付 | 可拆分功能 | 需整体架构，集成复杂 |
| V 模型 | 左侧开发、右侧测试一一对应 | 需求明确、变更少 | 灵活度低 |
| 原型 | 快速原型确认需求 | 需求不明确 | 易被原型束缚，管理要求高 |
| 敏捷 | 小增量、快速迭代、拥抱变化 | 中小团队、需求多变 | 文档少，依赖团队自律 |

| 螺旋四步 | 制定计划→风险分析→实施工程→客户评估 |
| -------- | ------------------------------------ |
| RUP 四阶段 | 初始→细化→构建→交付 |
| V 模型对应 | 需求↔验收、概要设计↔系统测试、详细设计↔集成测试、编码↔单元测试 |
| 敏捷迭代 | 常见 2～4 周，Scrum 角色为产品负责人、Scrum Master、开发团队 |

### 8.2 开发方法与语言

| 方法 | 核心 | 特点 |
| ---- | ---- | ---- |
| 结构化 | SA→SD→SP，自顶向下、逐步求精、模块化 | 目标清晰、阶段化、文档规范；周期长、难适应变化 |
| 面向对象 | 封装、继承、多态，类与对象 | 复用性好、易沟通、缩短周期 |
| 原型法 | 快速构建原型，用户参与 | 适合需求不明确；环境与管理要求高 |
| 面向服务 SOA | 服务封装业务流程，粗粒度、松耦合、标准化接口 | 跨系统复用、业务驱动 |

| 语言 | 代表 | 执行方式 |
| ---- | ---- | -------- |
| 标记语言 | HTML、XML | 描述结构与数据，不执行逻辑 |
| 脚本语言 | Python、JavaScript、PHP、VBScript | 调用时解释，跨平台好 |
| 编译型 | C、C++ | 先编译为目标代码，执行快，移植难 |
| 混合型 | Java、C# | 编译为字节码，再由虚拟机解释或 JIT |

[注] 原文把 Java 直接归入编译型，[错误]。Java 先编译为字节码，运行期由 JVM 解释执行或 JIT 编译，属编译＋解释混合模型。

### 8.3 软件测试

| 分类 | 方法 | 是否运行程序 | 适用 |
| ---- | ---- | ------------ | ---- |
| 静态 | 文档检查、代码走查、代码审查 | 否 | 早期发现缺陷 |
| 动态—白盒 | 语句、判定、条件、路径覆盖 | 是 | 单元测试，关注内部结构 |
| 动态—黑盒 | 等价类、边界值、判定表、因果图、正交、错误推测 | 是 | 集成、确认、系统测试，关注功能 |

| 测试阶段 | 依据 | 目的 |
| -------- | ---- | ---- |
| 单元测试 | 详细设计 | 模块内部逻辑 |
| 集成测试 | 详细设计／架构 | 模块接口与协作 |
| 系统测试 | 需求规格 | 整体功能、性能、安全 |
| 验收测试 | 用户需求 | 确认可交付，α／β 测试 |
| 回归测试 | 变更影响 | 确认修改未引入新缺陷 |
| 冒烟测试 | 基本功能 | 版本是否可测 |

[注] 原文“白盒测试不运行测试功能”表述不准确，[错误]。白盒分静态与动态，动态白盒必须运行程序；黑盒主要用于集成、确认、系统测试，不是“概要设计阶段完成”。

### 8.4 项目管理要点

| 概念 | 公式／内容 |
| ---- | ---------- |
| WBS | 工作分解结构，面向可交付成果逐层分解 |
| 关键路径 | 网络图中最长路径，总浮动为 0，决定工期 |
| 总时差 | `TF = LS − ES = LF − EF` |
| 自由时差 | `FF = 紧后工作最早开始 − 本工作最早完成` |
| PERT 期望 | `TE = (O + 4M + P) / 6` |
| PERT 标准差 | `σ = (P − O) / 6` |
| 挣值 PV／EV／AC | 计划值／挣值／实际成本 |
| 成本偏差 | `CV = EV − AC`，大于 0 节约 |
| 进度偏差 | `SV = EV − PV`，大于 0 提前 |
| 成本绩效 | `CPI = EV / AC`，大于 1 节约 |
| 进度绩效 | `SPI = EV / PV`，大于 1 提前 |
| 完工估算 | `EAC = BAC / CPI` |
| 完工尚需 | `ETC = EAC − AC` |

| 风险应对 | 内容 |
| -------- | ---- |
| 规避 | 改变计划消除风险 |
| 转移 | 保险、外包、合同 |
| 减轻 | 降低概率或影响 |
| 接受 | 预留应急储备 |

三条纪律：

1. 公式只背适用条件，不背推导：看到 dB 用香农，问状态数用奈氏。
2. 命令只背视图与关键字顺序，参数按题干替换，不背具体 IP。
3. 判断题遇到“必须、一定、完全、只能”先怀疑，回到表里的边界条件。

### 10.2 最容易混淆的 10 组概念

| 组 | 概念 A | 概念 B | 一句话区分 |
| -- | ------ | ------ | ---------- |
| 1 | 奈奎斯特定理 | 香农公式 | 无噪声、求码元种类数用奈氏；有噪声、给 dB 求容量用香农 |
| 2 | 冲突域 | 广播域 | 冲突域看交换机端口，广播域看 VLAN／路由器 |
| 3 | VLAN | IP 子网 | VLAN 是二层隔离，子网是三层划分；二者常一一对应但不等价 |
| 4 | 根端口 | 指定端口 | 根端口在非根桥上、朝向根桥最近；指定端口在每条链路上负责转发，根桥所有端口都是指定端口 |
| 5 | 流量控制 | 拥塞控制 | 流量控制看接收方缓冲（rwnd），拥塞控制看全网承载（cwnd），发送窗口取二者较小值 |
| 6 | 路由策略 | 策略路由 | 路由策略管“哪些路由进路由表”（控制面），策略路由管“报文往哪走”（数据面） |
| 7 | IDS | IPS | IDS 旁路监听只告警，IPS 串行部署可阻断 |
| 8 | 增量备份 | 差异备份 | 增量备份每次只备“上次备份后”的变化，恢复要全量＋全部增量；差异备份每次都备“上次全量后”的变化，恢复只要全量＋最后一次差异 |
| 9 | 对称加密 | 非对称加密 | 对称一把钥匙、速度快、不签名；非对称公私钥分离、速度慢、可签名与密钥分发 |
| 10 | RAID 5 | RAID 6 | RAID 5 一份校验、坏 1 块；RAID 6 两份校验、坏 2 块；利用率分别为 (n−1)/n 与 (n−2)/n |

### 10.3 原文勘误清单

| 序 | 原文表述 | 纠正 |
| -- | -------- | ---- |
| 1 | ADSL 属于电路交换 | ADSL 是用户线频分复用接入技术，承载于 ATM／以太网，不是电路交换 |
| 2 | 单模波长 810／1300 nm，多模 1310／1550 nm | 写反了：单模 1310／1550 nm，多模 850／1300 nm |
| 3 | 单模纤芯 5～10 μm | 单模纤芯约 9～10 μm，G.652 模场直径约 9.2 μm |
| 4 | 多模光纤最长 550 m | 仅千兆 OM2 为 550 m；万兆多模约 300～400 m，随规格变化 |
| 5 | ATM 典型速率 150 M | 155.52 Mbit/s（STM-1／OC-3） |
| 6 | 400G 以太网标准 802.3bS | 802.3bs |
| 7 | VLAN 有助于“减小冲突域” | VLAN 划分广播域，冲突域由交换机端口决定，不因 VLAN 改变 |
| 8 | TCP 伪首部包含“TCP 报头” | 应为 TCP 长度（2 字节）；伪首部共 12 字节 |
| 9 | SNMP 客户端 161、服务器端 162 | Agent 用 161 收 Get／Set，NMS 用 162 收 Trap |
| 10 | RMON 定义 RMON MIB-II 与 SNMP MIB | RMON 有独立 RMON MIB；MIB-II 是 TCP／IP 标准管理信息库 |
| 11 | 企业标准发布后 30 日内备案 | 2018 年《标准化法》修订后改为自我声明公开，不再备案 |
| 12 | 白盒测试“不运行测试功能” | 白盒含静态与动态，动态白盒需运行程序；黑盒用于集成、确认、系统测试 |
| 13 | Java 属于编译型语言 | Java 编译为字节码后由 JVM 解释或 JIT 执行，属编译＋解释混合 |
| 14 | 级联用于“组成堆叠系统扩展端口”，堆叠用于“增大上行带宽” | 表述错位：级联扩展端口与距离，堆叠才用于带宽叠加、统一管理与冗余 |
| 15 | “IFS（分布式协调 IFS）” | 应为 DIFS，长度顺序 SIFS＜PIFS＜DIFS |
| 16 | 224.0.0.5 指“所有路由器” | 224.0.0.5 指所有 OSPF 路由器；所有路由器是 224.0.0.2 |

以上 16 条为原文与标准或厂商文档不一致之处；其余口误、重复、水印与图片占位已直接剔除，不再逐条列出。全表数值以华为 VRP 默认值与 IEEE／IETF 标准为准，课程口径不同处已在表中标注。
