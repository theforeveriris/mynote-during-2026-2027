## 1.案例分析

### 1.1 案例1 交换机初始配置与远程管理

> 考点：Console 登录参数、系统视图与时钟配置、管理 VLAN、Telnet + AAA 本地用户、用户级别

**【说明】**（15 分）

某公司新购一批交换机对网络进行升级改造，网络工程师计划对交换机进行配置，配置内容如下：

1. 配置交换机的基本信息，包括日期、时间、时区及名称，以方便管理。
2. 配置 Console 用户界面的认证方式为 AAA，实现通过 Console 口登录交换机时需要本地认证的功能。
3. 配置 VLAN10 作为管理 VLAN，管理地址为 172.16.100.1，接口 GigabitEthernet0/0/24 为管理接口。
4. 开启交换机 Telnet 功能，认证方式为 AAA，便于对交换机进行远程维护。
5. 创建管理员用户 adminxyz，设置用户登录口令：`xyz@789##`。

**问题1**（15 分）

对交换机进行初始配置时，需使用 PC 机的（1）接口连接交换机的（2）接口，使用终端仿真软件，设置其（3）、流控方式、停止位、数据位等参数登录到交换机。设置日期、时间、时区及名称时，应在（4）视图下，使用（5）命令配置日期，使用 clock timezone 命令配置其时区和时间。

请根据配置内容，补齐以下配置片段：

```text
[Switch] vlan 10
[Switch-vlan10]（6）                 //配置管理VLAN
[Switch-vlan10] quit
[Switch] interface vlanif 10
[Switch-Vlanif10] ip address（7）24
[Switch-Vlanif10] quit
[Switch] interface GigabitEthernet 0/0/24
[Switch-GigabitEthernet0/0/24] port link-type（8）
[Switch-GigabitEthernet0/0/24] port default（9）
[Switch-GigabitEthernet0/0/24] quit
[Switch] telnet server（10）
[Switch] telnet server source -i GigabitEthernet 0/0/24
[Switch] user-interface（11）0 4
[Switch-ui-vty0-4] protocol inbound telnet
[Switch-ui-vty0-4] user privilege level 15
[Switch-ui-vty0-4] authentication-mode（12）
[Switch-ui-vty0-4] quit
[Switch] aaa
[Switch-aaa] local-user（13）password irreversible-cipher xyz@789##
[Switch-aaa] local-user adminxyz privilege level 15   //（14）
Warning: This operation may affect online users, are you sure to change the user
privilege level ?[Y/N]y
[Switch-aaa] local-user adminxyz service-type（15）
[Switch-aaa] quit
```

**参考答案**

| 空号 | 答案 | 说明 |
| ---- | ---- | ---- |
| （1） | 串口（RS-232，或 USB 转串口） | PC 侧异步串行接口 |
| （2） | Console（控制台） | 交换机 Console 口，RJ-45 或 USB |
| （3） | 波特率（速率，9600bit/s） | 其余：8 位数据位、1 位停止位、无校验、无流控 |
| （4） | 系统（`system-view`，即 `[Switch]`） | `clock` 命令是系统视图命令 |
| （5） | `clock datetime` | 如 `clock datetime 14:30:00 2025-05-24` |
| （6） | `management-vlan`（部分版本为 `description management`） | 把 VLAN10 指定为管理 VLAN |
| （7） | `172.16.100.1` | `ip address 172.16.100.1 24` |
| （8） | `access` | 管理接口作为接入口划入管理 VLAN |
| （9） | `vlan 10` | `port default vlan 10` |
| （10） | `enable` | `telnet server enable`，开启 Telnet 服务 |
| （11） | `vty` | `user-interface vty 0 4` |
| （12） | `aaa` | 认证交给 AAA（本地用户库） |
| （13） | `adminxyz` | 用户名，与下一行 `local-user adminxyz` 一致 |
| （14） | 将该用户的权限级别设置为 15（最高管理级） | 题中注释要写出的功能 |
| （15） | `telnet` | 允许该用户使用 Telnet 服务 |

相关命令补齐（便于理解）：

```text
<Switch> system-view
[Switch] sysname SW-Core
[Switch] clock timezone BJ add 08:00:00
[Switch] clock datetime 14:30:00 2025-05-24
[Switch] interface vlanif 10
[Switch-Vlanif10] ip address 172.16.100.1 255.255.255.0
```

**解析**

本题是「设备初始化」的模板题，15 个空基本覆盖了交换机上线配置的全流程：**物理连接 → 终端参数 → 系统视图/时钟 → 管理 VLAN → 管理地址 → Telnet + AAA**。

高频失分点：

1. **Console 参数**只背「9600」，忘了波特率这个名称；标准参数是 9600-8-N-1、无流控；
2. **视图判断**：`clock`、`sysname`、`vlan` 都在系统视图 `[Switch]` 下，用户视图是 `<Switch>`；
3. **管理 VLAN 的命令**在不同 VRP 版本有差异（`management-vlan`），考场上写「将 VLAN10 指定为管理 VLAN」并给出命令即可拿分；
4. **`service-type`** 漏写或写成 `ssh` 与题干「Telnet」不符；
5. `ip address 172.16.100.1 24` 中掩码可用位数简写，但不能漏。

安全提示（题干未问，答题可加分）：Telnet 明文传输口令，生产环境应改为 SSH（`stelnet server enable` + `user-interface vty` 下 `protocol inbound ssh`），并配置 ACL 限制管理源地址。

### 1.2 案例2 网络安全事件分析与服务器 RAID 规划

> 考点：钓鱼邮件识别与防护、DNS 劫持/欺骗、运维不规范行为、RAID 级别选择与可用容量计算

**【说明】**

某单位企业网络中部署有 WEB 网站、邮件系统，配有防火墙、Web 应用防火墙和上网行为管理系统。信息中心网络工程师小李在个人电脑上安装了远程控制软件，以便从外部随时采用 telnet 登录管理所有网络设备，并设置 Admin123 为各设备登录口令。近期，该企业发生了两起网络安全事件：

事件一：企业员工小王收到一封系统升级通知邮件，要求员工点击链接修改密码，小王点击链接之后，按提示输入旧的密码后，心有疑惑，没有继续设置新的密码，联系网络工程师小李，得知邮件系统并未升级也未发送任何通知。

事件二：多名员工反馈在知名网站登录页面输入用户名密码后，点击登录无反应，更换终端 PC 的 DNS 后登录正常，直接输入 IP 地址也能正常登录。

**问题1**（5 分）

请简要分析事件一，该企业可能受到了什么类型的攻击？并提出防护措施。（至少回答 3 点）对于此类攻击，可以进行以下措施来防护：

**参考答案**

攻击类型：**网络钓鱼（Phishing）**，具体为**仿冒邮件/钓鱼网站骗取账号口令**（邮件伪装成系统升级通知，链接指向伪造的修改密码页面）。可同时答「社会工程学攻击」。

防护措施（答出 3 点即可）：

- **邮件网关防护**：部署反垃圾/反钓鱼邮件网关，做 SPF、DKIM、DMARC 校验与发件人仿冒检测，对可疑链接与附件沙箱检测；
- **URL 与域名防护**：上网行为管理/威胁检测设备拦截已知钓鱼域名，邮件中链接先重写再检测；
- **安全意识培训与演练**：定期钓鱼演练，明确「任何索要口令的邮件都不可信」，口令修改只从官网/内网入口进入；
- **强制多因素认证（MFA）**：即使口令泄露也无法直接登录；
- **账号与口令策略**：口令复杂度、定期更换、禁止多系统复用，关键系统登录做异常检测；
- **终端防护与隔离**：终端 EDR/防病毒，浏览器防护插件，限制未知站点访问；
- **应急响应**：发现后立即封禁钓鱼域名、重置相关账号口令、排查是否已失陷。

**解析**

事件一的特征非常典型：**「系统升级通知 + 点击链接 + 修改密码」**，是钓鱼邮件三件套。答「病毒/木马」不给分——本题没有恶意代码迹象，核心是**骗取凭据**。

采分逻辑：类型 1～2 分（必须出现「钓鱼」），措施 3 分（技术 + 管理 + 意识三类各一点最稳）。只答「不要点陌生链接」属于用户侧单点措施，最多给 1 分。

注意题干的「至少回答 3 点」是硬要求，少答直接扣分。

**问题2**（5 分）

请简要分析事件二，该企业可能受到了什么类型的攻击？并提出防护措施。（至少回答 3 点）。

**参考答案**

攻击类型：**DNS 劫持 / DNS 欺骗（DNS 缓存投毒）**，即用户被引导到伪造的登录页面（域名解析指向攻击者服务器），所以「换 DNS 后正常、直接输 IP 也正常」。

判断依据：

- 同一网站在**换 DNS 后恢复正常**，说明域名解析结果被篡改，而非网站本身故障；
- **直接用 IP 访问正常**，绕过了 DNS 解析环节，进一步印证解析被劫持；
- 「输入用户名密码后点击登录无反应」，说明页面是伪造的（表单提交到攻击者服务器）。

防护措施（答出 3 点即可）：

- **使用可信 DNS**：内部部署递归 DNS 并开启 DNSSEC 验证，或使用可信公共 DNS，禁止终端随意配置外部 DNS；
- **DNS 流量管控**：防火墙/上网行为管理只允许终端访问指定 DNS 服务器（禁止 53 端口外联任意地址），阻断 DNS 隧道与劫持；
- **DNSSEC / HTTPS 强制**：启用 DNSSEC 校验；浏览器与业务系统强制 HTTPS + HSTS + 证书校验，伪造站点无有效证书即告警；
- **网关与终端防护**：网关侧检测异常 DNS 响应与域名黑名单，终端安装防护软件，检测 hosts 文件被篡改；
- **路由器/交换机加固**：修改默认口令、关闭 WAN 侧管理、升级固件，防止家用/边界路由器被入侵后篡改 DNS；
- **监测与应急**：监控 DNS 解析结果异常变化，出事后清理 DNS 缓存、封禁恶意域名。

**解析**

本题的关键是**两个「对照实验」**：换 DNS 恢复正常、直接输 IP 正常。这两个现象把故障范围精确锁定在「域名解析」这一层，因此必须答 DNS 劫持/欺骗，答「ARP 欺骗」只能给部分分（ARP 欺骗通常表现为网关不通或断网，不会是「登录无反应」）。

答题要把**判断依据写出来**，这是本题区别于纯背诵题的地方。措施按「解析链路（可信 DNS/DNSSEC）—传输链路（HTTPS/证书）—终端（hosts 检查）—边界（路由器加固）」四层写，覆盖度最好。

**问题3**（4 分）

根据题干描述，请简要分析网络工程师小李在运维工作中存在的不规范行为和安全隐患，并提出整改措施。（至少回答 2 点）

**参考答案**

不规范行为与隐患（答出 2～3 点）：

| 隐患 | 风险 |
| ---- | ---- |
| 在**个人电脑**上安装远程控制软件管理网络设备 | 个人终端防护等级低，易被控端反向控制，成为进入网络设备的跳板 |
| 使用 **Telnet** 远程登录设备 | 用户名口令**明文**传输，可被嗅探；会话可被劫持 |
| 所有设备统一使用 **Admin123** 弱口令 | 一处泄露全网失陷；无差异化、无定期更换 |
| 从**外部直接**登录管理所有设备 | 管理面暴露在互联网，易被暴力破解/扫描 |
| 无堡垒机、无操作审计 | 操作无法追溯，误操作与内鬼行为难以发现 |
| 缺多因素认证、无登录源限制 | 单因素口令即可获得最高权限 |

整改措施（对应作答）：

- 部署**堡垒机（运维审计系统）**，所有设备运维统一经堡垒机跳转，做账号集中管理、命令审计与录像；
- 用 **SSH/HTTPS** 替代 Telnet，关闭明文管理协议；
- **一机一口令**、强口令策略（长度、复杂度、定期更换），关键设备启用 **MFA**；
- 管理面**不暴露公网**：通过 VPN 接入后再运维，或用 ACL 限制管理源地址、配置 `ssh server acl`；
- 个人终端纳入**终端准入与 EDR 管理**，禁止用个人 PC 直连管理网；
- 划分独立**管理 VLAN/带外管理网**，与业务隔离；建立变更与操作审批流程。

**解析**

这题是「找茬题」，答案必须**从题干逐句提取**，不能泛泛而谈安全。题干给了四个抓手：个人电脑、远程控制软件、telnet、Admin123，每一条都对应一个明确隐患。

阅卷时「隐患 + 措施」要成对出现，只写措施不写隐患会丢一半分。加分点是能提到**堡垒机 + 管理 VLAN + 审计**这套体系化方案，而不是零散地写「改密码、用 SSH」。

**问题4**（6 分）

该单位新增一台文件服务器、一台数据库服务器，新增服务器均配置 2 块系统盘，每块容量 480GB、10 块数据盘，每块容量 2TB，计划使用 RAID 实现数据冗余。小李配置服务器时，为实现服务器系统高容错能力，单盘故障不影响系统，服务器系统盘应采用的 RAID 级别为（1），可用容量为（2）；文件服务器数据盘要求支持最多任意双盘故障不影响数据，且容量最大化，应采用 RAID 级别为（3），可用容量为（4）；数据库服务器要求写入效率高、数据安全可靠，应采用 RAID 级别为（5），可用容量为（6）。

**参考答案**

| 空号 | 答案 | 计算依据 |
| ---- | ---- | -------- |
| （1） | RAID1（镜像） | 2 块盘做镜像，允许单盘故障 |
| （2） | 480GB | 容量 = 单盘容量 ×（n/2）= 480GB × 1 |
| （3） | RAID6（双校验） | 允许任意 2 块盘同时故障，容量损失最小（仅 2 块校验盘） |
| （4） | 16TB | （10 − 2）× 2TB = 16TB |
| （5） | RAID10（镜像 + 条带） | 写入性能好、可靠性高，适合数据库 |
| （6） | 10TB | 10 × 2TB ÷ 2 = 10TB |

判定说明：

- 系统盘只有 2 块，要求「单盘故障不影响系统」，只能是 **RAID1**（RAID5 至少 3 块）；
- 「任意双盘故障 + 容量最大化」→ **RAID6**：RAID1/RAID10 只能容忍特定盘故障（RAID10 坏两块同组即失效），RAID5 只容 1 块，RAID6 容 2 块且开销固定为 2 块盘；
- 「写入效率高 + 数据安全」→ **RAID10**：无校验计算，写性能接近单盘叠加，同时具备镜像保护；RAID5/6 写操作有「读-改-写」惩罚，写入效率低。

**解析**

本题三组选择其实是三个判据的对应：

| 判据 | 结论 |
| ---- | ---- |
| 单盘故障（2 块盘） | RAID1 |
| 任意双盘故障 + 容量最大 | RAID6 |
| 写性能 + 可靠（数据库） | RAID10 |

容量计算是必考项，记住公式：

```text
RAID0 :  n × C
RAID1 :  C（n/2 组镜像，容量为一半）
RAID5 :  (n − 1) × C
RAID6 :  (n − 2) × C
RAID10:  (n / 2) × C
```

单位换算注意：本题 2TB × 8 = 16TB，直接写 16TB，折算成 GB 时按 1TB=1024GB 写 16384GB 也可，但**不要把 TB 与 TiB 混算**。

常见失分：① 文件服务器选 RAID5（只容 1 块）；② 数据库选 RAID5（写惩罚大）；③ 系统盘选 RAID0（无冗余）；④ 容量按「全部盘之和」算，忘记扣除校验/镜像开销。

> 考点：网络生命周期六阶段、需求分析内容、综合布线子系统与介质/以太网标准、OSPF 与 BGP 选型

**【说明】**（20 分）

某企业计划新建生产研发中心，包括办公、研发、数据中心、生产车间等区域。网络拓扑如图 1 所示，采用三层网络结构，数据中心机房安装 2 台核心交换机和路由器，办公大楼、研发中心、生产车间分别安装 2 台汇聚交换机，每个建筑的楼层分别安装 2 台接入交换机，按照业务类型划分不同 VLAN，将网络划分为不同子网。网络系统要求骨干万兆、配置简单、路由收敛快、管理便捷。

`[原文为图/表，需对照原卷]`（图 1 拓扑未收录）

**问题1**（4 分）

该企业计划按照六阶段周期完成园区网络系统建设，则建设过程应包括：需求分析、（1）（2）、（3）、（4）和监测及性能优化阶段。

**参考答案**

（1）**通信规范分析（流量/业务分析）**
（2）**逻辑网络设计**
（3）**物理网络设计**
（4）**实施与部署（安装实施、测试验收）**

即完整六阶段：

```text
需求分析 → 通信规范分析 → 逻辑网络设计 → 物理网络设计 → 实施部署 → 监测及性能优化
```

（不同教材表述略有差异，如「实施与测试」「运行维护」，考场按「分析—逻辑—物理—实施」的顺序作答即可，关键词对上即给分。）

**解析**

网络生命周期是固定考点，核心是理解「**先摸需求、再算流量、再画逻辑、再定物理、再施工、再优化**」的递进关系：

- **需求分析**：业务目标、用户数、应用类型、可用性要求；
- **通信规范分析**：现有网络基线、流量模型、峰值带宽、时延要求；
- **逻辑设计**：拓扑、编址与命名、路由协议、安全策略、VLAN 规划；
- **物理设计**：设备选型、布线、机房、供电、机柜与端口分配；
- **实施部署**：安装调试、割接、测试验收、文档交付；
- **监测与优化**：性能监控、故障管理、容量与优化迭代。

失分点：把「逻辑设计」与「物理设计」顺序颠倒，或只写「设计」一个阶段。

**问题2**（6 分）

在网络建设中，需求分析非常重要，有助于设计者更好地理解网络系统的功能和性能要求，请简要说明在本项目需求分析阶段，网络带宽和无线网络接入分别应收集和分析哪些内容。（每个部分至少回答 3 点）

**参考答案**

（1）网络带宽需求应收集和分析：

- **业务类型与流量特征**：办公/OA、研发代码与仿真数据、生产车间 MES/AGV 控制、视频监控与视频会议，各自的并发量、单流带宽、上下行比例；
- **用户与终端规模**：各区域人数、终端数、服务器数量，峰值并发与忙时模型；
- **关键应用的带宽与时延要求**：如研发大文件传输、数据中心东西向流量、视频类业务的时延/抖动/丢包指标；
- **现有网络基线与增长率**：历史流量峰值、年增长率，用于容量预测（通常预留 30%～50% 余量）；
- **链路与出口需求**：互联网出口带宽、跨区域互联带宽、是否需要专线/MPLS/VPN；
- **可靠性要求**：链路冗余与带宽收敛比（超配比）。

（2）无线网络接入需求应收集和分析：

- **覆盖范围与场景**：办公区、研发区、车间的面积、隔断材质（车间金属结构对信号影响大）、层高与遮挡；
- **终端类型与数量**：笔记本、手机、PDA/扫码枪、AGV 车载终端，各频段能力（是否支持 5GHz）；
- **并发与带宽**：单 AP 接入数、人均带宽、是否存在高密度区域（会议室、车间工位）；
- **业务与漫游要求**：AGV/移动终端需要**无缝漫游**与低时延切换，语音/视频对抖动敏感；
- **安全与接入控制**：员工/访客/生产设备的分权接入、802.1X 或 Portal、IoT 设备准入；
- **管理与运维**：AC 集中管理、AP 供电（PoE）条件、信道与功率规划、干扰源排查。

**解析**

6 分题分两块，每块 3 分，「至少 3 点」是底线，写 4 点更稳。答题时务必**结合本项目**（研发大文件、生产车间 AGV、数据中心），而不是抄通用清单，否则即使条数够也只得一半分。

带宽部分的关键词是「**业务流量特征 + 规模 + 峰值 + 增长 + 冗余**」；无线部分的关键词是「**覆盖 + 终端 + 并发 + 漫游 + 安全**」。特别提示：车间场景要提到**金属遮挡与干扰、AGV 漫游**，这是本题的差异化采分点。

按照结构化布线系统相关要求，楼层弱电间到办公室之间的综合布线系统称为（5）子系统，线缆长度应不超过（6）米。办公大楼、研发中心、数据中心、生产车间之间的综合布线系统为（7）子系统，应采用（8）传输介质，可采用（9）以太网标准。

**问题4**（5 分）

在对本项目网络系统设计时，技术人员提供 OSPF 和 BGP 两种动态路由协议方案，结合本项目实际需求，你认为哪种方案较为合理，请说明理由。

**参考答案**

选 **OSPF**。

理由：

- **属于同一自治系统内的园区网**：办公、研发、数据中心、生产车间由同一企业管辖，属 IGP 场景，OSPF 正是为域内路由设计；BGP 用于 AS 之间（EGP），在此属于「杀鸡用牛刀」；
- **收敛快**：题干要求「路由收敛快」，OSPF 支持触发更新、SPF 快速计算，配合 BFD 可达毫秒/亚秒级收敛；BGP 默认收敛慢（扫描/保持定时器），不适合园区内部快速切换；
- **配置简单、管理便捷**：OSPF 只需宣告网段，支持区域划分与路由汇总；BGP 需要规划 AS 号、邻居、路由策略（filter-policy/route-policy），配置与排错复杂度高，与题干「配置简单、管理便捷」矛盾；
- **支持等价多路径与层次化设计**：OSPF 天然支持 ECMP 负载分担与 Area 分层，适合三层架构的多汇聚、多核心组网；
- **无策略依赖**：BGP 的价值在于大规模路由策略控制与跨域选路，本项目无跨 AS 需求，用 BGP 反而增加故障面。

补充（加分）：

- 若企业后续需要与运营商或多个外部网络交换大量路由，可在**边界**使用 BGP，内部仍用 OSPF，即「IGP 管内、BGP 管外」；
- OSPF 区域规划：核心/数据中心放 Area 0，各楼栋汇聚放 Area 1/2/3，ABR 做汇总。

**解析**

选型题得分靠「**结论 + 逐条对应题干需求**」。题干给了四个约束：骨干万兆、配置简单、路由收敛快、管理便捷，答案要逐条回应，而不是泛泛比较协议特性。

常见失分：① 只写「OSPF 收敛快」一句，不对比 BGP；② 认为「BGP 更高级所以选 BGP」；③ 忽略「同一 AS」这一根本前提。若答「BGP」但理由能自洽（如多出口选路），一般只得 1～2 分。

### 1.4 案例4 OSPF 与 BGP 配置补全及策略路由

> 考点：OSPF 进程/Router-ID/区域/网段宣告、BGP 邻居与 network 宣告、BGP 引入 OSPF、自动汇总、基于 TCP/UDP 的策略路由

**【说明】**（20 分）

下图为某公司网络拓扑片段，所有网段网络地址信息如图所示，各路由器上已经完成各个接口 IP 等基本信息配置。

`[原文为图/表，需对照原卷]`（拓扑图未收录，各路由器接口地址、AS 号、ISP1/ISP2 出口地址需对照原卷）

**问题1**（4 分）

公司总部路由器 R2 和 R3 之间运行 OSPF 路由协议，请补全如下 OSPF 的配置命令：

```text
#R2 的 OSPF配置，Router-ID为 2.2.2.2
[R2]（1）
[R2-ospf-1] area 0
[R2-ospf-1-area-0.0.0.0]（2）      //接口地址宣告
[R2-ospf-1-area-0.0.0.0] quit
[R2-ospf-1] quit
```

**参考答案**

| 空号 | 答案 | 说明 |
| ---- | ---- | ---- |
| （1） | `ospf 1 router-id 2.2.2.2` | 创建 OSPF 进程 1 并指定 Router-ID，进入 `[R2-ospf-1]` |
| （2） | `network 网段地址 反掩码`（按图填写，如 `network 12.1.1.0 0.0.0.255`） | 宣告 R2 与 R3 互联接口所在网段，华为用**反掩码** |

说明：

- 也可先 `ospf 1` 进入进程，再 `router-id 2.2.2.2`，两条命令等价，但题干只给一个空，`ospf 1 router-id 2.2.2.2` 最稳；
- `network` 后可跟「网段 + 反掩码」或「接口 IP + 0.0.0.0」两种写法；
- 图未收录，具体网段须按原卷填写，格式与反掩码写法是主要得分点。

**解析**

OSPF 配置三步走：**建进程（带 Router-ID）→ 进区域 → 宣告网段**。

失分点：

1. Router-ID 与进程号写混（`ospf 2.2.2.2` 错，进程号是本地有效整数）；
2. **反掩码**写成子网掩码（`255.255.255.0` 错，应为 `0.0.0.255`），这是最高频错误；
3. 宣告了错误的网段（如宣告了 Loopback 而非互联口），导致邻居起不来；
4. 忘记 `area 0`，接口被宣告进错误区域。

**问题2**（10 分）

公司总部与分部通过 BGP 传递路由，补全下列 R1 的 BGP 功能配置命令：

```text
#配置EBGP连接和BGP路由引入
[R1] bgp 65008
[R1-bgp] router-id 1.1.1.1
[R1-bgp] peer（3）as-number（4）      #公司分部网络宣告
[R1-bgp] ipv4-family unicast
[R1-bgp-af-ipv4] network（5）255.255.255.0
```

补全下列命令配置 R2 的 BGP 引入 OSPF 路由：

```text
[R2-bgp] ipv4-family unicast
[R2-bgp-af-ipv4]（6）ospf 1
[R2-bgp-af-ipv4] quit
[R2-bgp] quit
```

以下配置的功能是（7）：

```text
[R2] bgp 65009
[R2-bgp] ipv4-family unicast
[R2-bgp-af-ipv4] summary automatic
```

**参考答案**

| 空号 | 答案 | 说明 |
| ---- | ---- | ---- |
| （3） | 对端（分部）BGP 邻居的 IP 地址（按图） | `peer x.x.x.x as-number ...` |
| （4） | 分部所在 AS 号（按图，如 `65009`） | EBGP 邻居的 AS 号，与本地 65008 不同 |
| （5） | 公司分部网络的网段地址（按图，如 `10.10.10.0`） | `network 10.10.10.0 255.255.255.0`，注意 BGP 用**正掩码** |
| （6） | `import-route` | `import-route ospf 1`，把 OSPF 路由引入 BGP |
| （7） | 开启 BGP **自动汇总**：对引入（import-route）的路由按有类网络边界自动聚合，减少路由条目 | 只对引入路由生效，对 `network` 宣告的路由不生效 |

补充说明：

- `peer` 后也可先写地址再单独 `peer x.x.x.x as-number 65009`；
- BGP 中 `network` 必须**精确匹配路由表中存在的路由**，否则不会宣告；
- `summary automatic` 是「自动汇总」，与 `aggregate`（手工聚合，可控制明细抑制）不同。

**解析**

BGP 配置的采分点是「**邻居 + AS + 宣告**」三件套，以及两个易混点：

1. **掩码写法**：OSPF 用反掩码（`0.0.0.255`），BGP 的 `network` 用正掩码（`255.255.255.0`），一题之内同时考，很容易写串；
2. **引入方向**：`import-route ospf 1` 是「把 OSPF 路由灌进 BGP」，方向写反（在 OSPF 里 import BGP）就变成另一个题意；
3. **自动汇总的边界**：`summary automatic` 只汇总通过 `import-route` 引入的路由，且按**有类**边界汇总（如 10.1.1.0/24 汇总为 10.0.0.0/8），在 CIDR 环境下可能造成路由不精确，生产上更常用手工聚合。

EBGP 还需注意：默认无多跳，直连即可；若非直连要 `peer ... ebgp-max-hop`。

**问题3**（6 分）

公司分部 PC 连接总部网络后，在文件传输业务（由 TCP 传输）时路由到 ISP1 出口，在开展视频业务（由 UDP 传输）时路由到 ISP2 出口，请简要说明配置思路。要求写出：

1. 配置策略路由的具体思路；
2. 配置的设备、接口和方向。

**参考答案**

（1）配置策略路由的具体思路：

1. **定义流量分类**：用高级 ACL（如 `acl 3000`）匹配「协议号 TCP」的报文，用 `acl 3001` 匹配「协议号 UDP」的报文（可按需叠加源/目的地址、端口）；
2. **定义策略路由**：创建 `policy-based-route` 两个节点（如 `pbr-tcp`、`pbr-udp`），分别 `if-match acl 3000/3001`；
3. **指定下一跳**：`apply ip-address next-hop <ISP1 网关>` / `<ISP2 网关>`（也可用 `apply output-interface`）；
4. **在接口上应用**：在**内网侧入方向**接口调用 `ip policy-based-route pbr-tcp`，使流量在进入路由器时即被引流；
5. **兜底**：未命中的流量按路由表（默认路由/等价路由）正常转发；同时保证两条出口的 NAT 与回程路由正确（否则去得去、回不来）；
6. **验证**：`display policy-based-route` 查看命中计数，tracert 验证路径。

配置示例：

```text
[R1] acl 3000
[R1-acl-adv-3000] rule 5 permit tcp
[R1] acl 3001
[R1-acl-adv-3001] rule 5 permit udp

[R1] policy-based-route pbr-tcp permit node 10
[R1-policy-based-route-pbr-tcp-10] if-match acl 3000
[R1-policy-based-route-pbr-tcp-10] apply ip-address next-hop <ISP1网关>
[R1] policy-based-route pbr-udp permit node 10
[R1-policy-based-route-pbr-udp-10] if-match acl 3001
[R1-policy-based-route-pbr-udp-10] apply ip-address next-hop <ISP2网关>

[R1] interface GigabitEthernet 0/0/1          // 内网侧接口
[R1-GigabitEthernet0/0/1] ip policy-based-route pbr-tcp
[R1-GigabitEthernet0/0/1] ip policy-based-route pbr-udp
```

（2）配置的设备、接口和方向：

| 项 | 结论 |
| -- | ---- |
| 设备 | 连接分部与总部、且拥有两个出口的**出口路由器**（R1） |
| 接口 | **内网侧（下行，接分部/内网）接口**，即流量进入 R1 的那个接口 |
| 方向 | **入方向（inbound）**——在报文进入路由器时用 PBR 改写下一跳 |

**解析**

策略路由（PBR）的黄金三问就是题干的三问：**在哪台设备、哪个接口、哪个方向**。答案固定为「**靠近源、入方向**」：越早引流越好，放到出方向时路由表已经选过路，容易出现「PBR 生效但回程不对」。

本题的两个坑：

1. **用协议号区分**：ACL 中 `rule permit tcp` / `rule permit udp`，不是用端口号（视频业务端口不固定），这是题干「由 TCP/UDP 传输」的暗示；
2. **只引去程不够**：两个出口都要做 NAT，且回程路由要能回到内网，否则业务仍然不通——答出这一点是加分项。

另外注意：PBR 的优先级高于路由表，但对**本机产生的流量**默认不生效（需要在全局或本地策略中处理），这也是常见失分点。

```text
现象 → 类型（钓鱼/DNS 劫持/勒索/ARP 欺骗）→ 判断依据（题干的对照现象）
→ 技术措施（边界/解析/终端/审计）→ 管理措施（制度/培训/演练）
每条措施写清「做什么 + 防住什么」，条数满足题干下限
```

**模板三：RAID 选择**

```text
读题抓三个关键词：容错几块盘、容量还是性能、写多还是读多
系统盘（2 块）→ RAID1；容双盘 → RAID6；写性能 → RAID10；纯性能 → RAID0
容量按公式算，记得单位
```

**模板四：协议选型 / PBR**

```text
选型：同一 AS 内 → OSPF/IS-IS；跨 AS、多出口选路 → BGP
逐条回应题干约束（收敛、配置量、规模、管理），再给结论
PBR：哪台设备（靠源）、哪个接口（内网侧）、哪个方向（入）、匹配什么（ACL）、下一跳给谁
```
