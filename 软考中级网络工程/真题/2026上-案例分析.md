### 1.1 案例1 集团总部与展示中心互联（DHCP 与接入安全）

企业网络拓扑如图所示，由集团总部与展示中心两部分组成，展示中心距离集团 20km，通过运营商提供的 200Mbps 链路实现互联。

> 说明：原页导航列出「问题1～问题4」，但题库正文仅收录了**问题1**的原文，问题2～问题4 的题干未被收录，本笔记不作补写。

**问题1**（4 分）

（1）展示中心投入运行后，该中心日均接待访客 300 余人，同时接待人数不超过 150 人。访客无线业务经常出现无法获取 IP 地址的现象，经排查发现 DHCP 地址池可用地址不足。在排除网络攻击的情况下，请简要分析产生该故障的原因并提出处置措施。

（2）办公区反映部分终端能够获取到 IP 地址，但无法访问互联网。经查网络中非法接入了启用 DHCP 服务的路由器。为有效解决该行为对网络的影响，应在交换机 SW03 上采取哪些安全配置？

**参考答案**

（1）原因（答出 2～3 点即可）：

- **地址池容量按「人数」而非「终端数」规划**：访客普遍一人多终端（手机＋笔记本），同时 150 人实际并发地址需求可达 250～300 个，池子本身偏小。
- **租期过长**：访客即来即走，租期设为数小时以上时，终端离场不发 Release，地址在租期内被长期占用，形成「地址被占但人已离开」的泄漏。
- **可用地址被无效占用**：`excluded-ip-address` 排除范围过大（整段预留），或未给 AP、打印机、服务器做静态绑定，动态池可用数进一步缩水。
- **未启用地址探测/回收**：异常下线终端的租约只能等自然到期。
- **单 VLAN 单网段规划过小**：如只有一个 /25，扣除网关与保留地址后余量不足。

处置措施（答出 3 点即可）：

- **缩短租期**（如 1～2 小时），加速地址回收；
- **扩容地址池**：按「同时在线终端数 × 1.5～2」重新规划，放大掩码（/25→/24 或 /23），或按区域新增访客 VLAN/SSID，各自建池分流；
- **精确配置** `excluded-ip-address`，只排除网关与确实保留的少量地址；
- 固定设备（AP、打印机、服务器）**静态绑定**，不占动态池；
- 开启 **DHCP 探测/回收**（ping 探测、ARP 探测），及时释放无效租约；
- 部署 **DHCP Snooping + 地址利用率监控告警**，接近阈值提前扩容。

（2）在 SW03 上部署 **DHCP Snooping**，只信任「合法 DHCP 服务器方向」的端口，用户端口一律不信任，丢弃用户侧伪造的 DHCP Offer/ACK：

```text
[SW03] dhcp enable
[SW03] dhcp snooping enable
[SW03] interface GigabitEthernet 0/0/1          // 上联合法DHCP服务器/Core方向的端口
[SW03-GigabitEthernet0/0/1] dhcp snooping trusted
[SW03-GigabitEthernet0/0/1] quit
[SW03] interface GigabitEthernet 0/0/2          // 办公区用户接入口
[SW03-GigabitEthernet0/0/2] dhcp snooping enable
[SW03-GigabitEthernet0/0/2] quit
```

配套加固（任答 2 点）：

- 用户端口**端口安全**：`port-security enable`、`port-security max-mac-num 1`，私接设备即触发违规动作；
- 用户端口**端口隔离**，抑制私接设备扩散 DHCP 报文；
- 基于 Snooping 绑定表启用 **IP Source Guard / IPSG**，阻断仿冒网关地址；
- 关闭空闲端口，用户端口做**风暴抑制**。

**解析**

第（1）问考的是把业务特征翻译成 DHCP 参数：日均 300 人、同时 150 人、访客流动性强，对应「终端数倍率、短租期、地址回收」三个动作。题干已排除网络攻击，因此原因必须落在容量、租期、回收三类可操作项上。

第（2）问的题眼是「**能获取 IP 但上不了网**」——这是私接 DHCP 下发了错误网关/DNS，而不是地址池不足。得分点是「全局使能 + 上联口 trusted + 用户口不信任」三件套；只写「开启 DHCP Snooping」通常给一半分，把用户口设为 trusted 则不得分。只答「绑定 IP-MAC」属于治标，可给部分分。

### 1.2 案例2 交换机 VLAN 与 DHCP 配置补全

> 考点：基于接口地址池的 DHCP、VLAN 批量创建、Trunk/Access 端口、Telnet + AAA 本地认证

**【说明】**（20 分）

某公司网络拓扑如图所示，交换机 SW1 及其所连终端电脑为新接入网络的设备，交换机 Core 为 VLAN10 和 VLAN20 终端电脑的网关，并提供 DHCP 服务。

`[原文为图/表，需对照原卷]`（拓扑图未收录，SW1 各接入口所属 VLAN 需按图中终端归属确定）

**问题1**（6 分）

在交换机 Core 上完成 Vlanif10 接口 IP 地址配置；配置基于接口地址池的 DHCP 服务，排除 172.16.10.1 至 172.16.10.99 的地址。请补全以下配置：

```text
[Core]（1）
[Core-vlanif10]（2）
[Core-vlanif10] dhcp select（3）
[Core-vlanif10] dhcp server excluded-ip-address（4）
……//Vlanif 20配置略去
```

**参考答案**

| 空号 | 答案 | 说明 |
| ---- | ---- | ---- |
| （1） | `dhcp enable` | 全局使能 DHCP，否则地址池不生效 |
| （2） | `ip address 172.16.10.254 255.255.255.0` | Vlanif10 网关地址；末位按原图网关规划，通常为 .254 |
| （3） | `interface` | 基于接口地址池（`dhcp select interface`） |
| （4） | `172.16.10.1 172.16.10.99` | 排除段起止地址，中间用空格，不加 `to` |

配置补充说明：

- `dhcp select interface` 表示该接口采用**接口地址池**，池的网段＝接口所在网段，网关自动为接口地址，无需再写 `network`、`gateway-list`；
- 排除段必须覆盖网关本身（.254 不在 1～99 内，安全）；若网关取 .1，则排除段会把网关排除掉，需另行注意；
- Vlanif20 同理：`ip address 172.16.20.254 24` + `dhcp select interface` + 排除 172.16.20.1～172.16.20.99。

**解析**

本题是华为 DHCP 的标准填空。失分点集中在两处：一是忘记 `[Core] dhcp enable`（全局开关不打开，接口下配了也不分配地址）；二是把 `excluded-ip-address` 写成 `172.16.10.1 to 172.16.10.99` 或只写起始地址——华为命令是「起始地址 结束地址」，以空格分隔。

「基于接口地址池」与「基于全局地址池」的区别要能一眼分辨：题干出现 `dhcp select interface`、且池参数直接挂在 Vlanif 下，就是接口池；出现 `ip pool xxx`、`dhcp select global`，就是全局池。

**问题2**（5 分）

在交换机 SW1 批量创建 vlan10、vlan20，并完成相关接口配置，其中 GigabitEthernet0/0/5 仅放行 vlan10 和 vlan20。请补全以下配置：

```text
[SW1]vlan batch（1）
[SW1]interface GigabitEthernet 0/0/5
[SW1-GigabitEthernet0/0/5]port link-type（2）
[SW1-GigabitEthernet0/0/5]port trunk allow-pass（3）
[SW1-GigabitEthernet0/0/5]quit
[SW1]port-group 1
[SW1-port-group-1]group-member GigabitEthernet 0/0/1 to GigabitEthernet 0/0/2
[SW1-port-group-1]port link-type（4）
[SW1-port-group-1]port default（5）
……//其他接口配置略去
```

**参考答案**

| 空号 | 答案 | 说明 |
| ---- | ---- | ---- |
| （1） | `10 20` | 批量创建，空格分隔，`vlan batch 10 20` |
| （2） | `trunk` | 上联 Core 的口，需透传多 VLAN |
| （3） | `vlan 10 20` | 仅放行这两个 VLAN（不放行 VLAN1 则需 `undo port trunk allow-pass vlan 1`） |
| （4） | `access` | 端口组内为终端接入口 |
| （5） | `vlan 10` | 端口组内终端所属 VLAN，按原图确定（图示缺失；若 0/0/1 属 VLAN10、0/0/2 属 VLAN20，则不能用一个端口组，需分开配置） |

**解析**

`port-group` 的价值在于「一次配置、批量下发」，因此组内成员必须**属性相同**。若两台终端的 VLAN 不同，就不能放进同一个端口组用一条 `port default` 覆盖——这是本题最容易踩的坑，答题时应点明「同组端口需同 VLAN，否则应分组配置」。

Trunk 的 `allow-pass` 是白名单机制：不写就不放行；反之若题干要求「仅放行」，还要记得把默认放行的 VLAN1 去掉。Access 口加入 VLAN 的命令是 `port default vlan X`（华为），不要写成 Cisco 的 `switchport access vlan X`。

**问题3**（4 分）

开启 Telnet 服务，认证模式为 AAA，创建本地用户 sysadmin，口令为 `Aaa!@#$%523`。

```text
[SW1] telnet server enable
[SW1] user-interface vty 0 4
[SW1-ui-vty0-4] authentication-mode（1）
[SW1-ui-vty0-4] quit
[SW1] aaa
[SW1-aaa] local-user（2）password cipher（3）
[SW1-aaa] local-user sysadmin service-type（4）
……其他配置略去
```

**参考答案**

| 空号 | 答案 | 说明 |
| ---- | ---- | ---- |
| （1） | `aaa` | VTY 采用 AAA 认证，配合本地用户库 |
| （2） | `sysadmin` | 用户名 |
| （3） | `Aaa!@#$%523` | 密文口令，与题干完全一致（注意大小写与特殊字符） |
| （4） | `telnet` | 服务类型，允许该用户通过 Telnet 登录 |

配套建议（题干「其他配置略去」的部分，理解即可）：

```text
[SW1-ui-vty0-4] protocol inbound telnet
[SW1-ui-vty0-4] idle-timeout 10
[SW1-aaa] local-user sysadmin privilege level 15
```

**解析**

AAA 认证模式下，`authentication-mode aaa` 只是「把认证交给 AAA 处理」，真正的账号在 `aaa` 视图里用 `local-user` 创建，两处必须配套，缺一处就登录失败。`service-type` 决定该账号能做什么：`telnet`（或 `ssh`）、`http`、`ppp` 等，漏写则无法登录。

安全角度可以补一句：生产环境应用 SSH 替代 Telnet，并把 `privilege level` 控制在满足运维的最低级别，避免默认 15 级。题干把口令写死，抄写时特殊字符 `@#$%` 不能丢。

**【说明】**（20 分）

某集团公司新建一座办公楼，其中一层为市场部（100 个工位）、二层为客服部（63 个工位）、三层为技术部（58 个工位）和数据机房（7 台服务器）、四层为行政部（29 个工位）、五层为会议室（16 个工位），网络拓扑如图所示。

`[原文为图/表，需对照原卷]`（拓扑图未收录）

**问题1**（4 分）

集团公司信息中心为该大楼分配的 IP 地址段为 192.168.0.0/24、192.168.1.0/24，按照既满足业务需要，又能节约 IP 地址的原则，完成下列 IP 地址规划表。

`[原文为图/表，需对照原卷]`（规划表的行、列与待填空格均未收录，无法逐格给出答案）

**参考答案**

原表未收录，以下给出**填表所需的判定依据与可给分要点**，具体每格的网段/掩码/可用地址范围须对照原卷表格填写：

1. **按主机数定掩码**：可用主机数 = 2^h − 2 ≥ 工位数（预留 20%～30% 余量更稳妥）。

   | 区域 | 主机数 | 最小可用掩码 | 地址块大小 |
   | ---- | ------ | ------------ | ---------- |
   | 市场部 | 100 | /25（126 可用） | 128 |
   | 客服部 | 63 | /26（62 可用，不足）→ /25 | 128 |
   | 技术部 | 58 | /26（62 可用） | 64 |
   | 数据机房 | 7 | /28（14 可用） | 16 |
   | 行政部 | 29 | /27（30 可用） | 32 |
   | 会议室 | 16 | /27（30 可用） | 32 |

   注：客服部 63 台用 /26 只有 62 个可用地址，**差 1 个**，这是本题的经典陷阱，必须提到 /25 或说明预留策略。

2. **按块连续分配、不重叠**：两个 /24 共 512 个地址，上述需求合计约 273 个，余量充足；建议一个 /24 放办公区（市场部、客服部、技术部），另一个 /24 放机房、行政部、会议室，便于按部门做 ACL 与路由汇总。
3. **每段留出网关地址**（通常取首个或末个可用地址），并在表中标注「可用地址范围」时把网关、广播地址排除。
4. **预留管理网段**：AP、交换机管理地址单独规划一个小网段或 VLAN，不占业务地址。

**解析**

地址规划题阅卷看三件事：**掩码算得对不对、网段有没有重叠、网关是否落在网段内**。常见失分：① 客服部 63 台直接给 /26（62 可用）而不作说明；② 市场部 100 台给 /26（不够）或给 /24（浪费，违反「节约」原则）；③ 各段起点不是块边界（如 192.168.0.100/26），导致地址块重叠。

题目既然强调「既满足需要又节约」，就要在答案里体现「按 2 的幂取块、连续分配、保留增长余量」的思路，而不是简单按部门顺序切 /24。

**问题2**（4 分）

按照结构化综合布线规范，楼层配线间至办公室信息面板之间的布线称为（1）；如果采用双绞线，则线缆总长度不应超过（2）米；该新建办公楼与集团信息中心机房（位于其他楼栋）之间的布线称为（3）布线子系统，应铺设（4）介质，确保骨干网络的远距离高速传输。

**参考答案**

| 空号 | 答案 | 说明 |
| ---- | ---- | ---- |
| （1） | 水平子系统（水平布线子系统） | 楼层配线间（IDF）→ 信息插座 |
| （2） | 90 | 水平电缆永久链路 ≤90m，加两端跳线信道总长 ≤100m |
| （3） | 建筑群子系统（园区子系统） | 楼栋之间 |
| （4） | 光缆（单模光纤，如 G.652） | 跨楼栋距离远、需抗干扰与高带宽 |

**解析**

六个子系统的对应关系必须背成条件反射：**工作区**（面板到终端跳线）—**水平**（楼层配线间到面板）—**管理**（配线架、跳线管理）—**垂直/干线**（楼层配线间到楼栋主配线间）—**设备间**（主配线间、核心设备）—**建筑群**（楼到楼）。

90m 与 100m 的区别是高频失分点：90m 是**永久链路**（水平缆线），100m 是**信道**（含两端各 5m 跳线）。跨楼栋、距离可能超过 2km 且要求万兆骨干，只能选**单模光缆**；多模光纤一般用于楼内主干（数百米内）。

**问题3**（4 分）

（1）请简要概述采取什么措施可以实现各部门、数据机房、会议室之间的广播域隔离？

（2）集团信息中心与新建大楼之间可以配置静态路由或动态路由实现网络互通，请简要说明使用动态路由协议的优点。

**参考答案**

（1）广播域隔离措施：

- 在接入/汇聚交换机上**按部门与功能区划分 VLAN**（市场部、客服部、技术部、机房、行政部、会议室各一个或多个 VLAN），一个 VLAN 即一个广播域；
- 交换机之间用 **Trunk** 承载多 VLAN，接入端口用 **Access** 划入对应 VLAN；
- 每个 VLAN 配置一个 **Vlanif 三层接口**作为网关，VLAN 间通信经三层转发并可用 **ACL** 控制；
- 无线侧为不同业务/部门**绑定不同 VLAN 的 SSID**；会议室可单独 SSID + 单独 VLAN；
- 需要更细的隔离时，可叠加**端口隔离**（同 VLAN 内）或 **MUX VLAN / Super-VLAN**。

（2）动态路由协议的优点：

- **自动适应拓扑变化**：链路/设备故障后自动重新计算并收敛，无需人工改配置；
- **收敛快、可靠性高**：配合 BFD 可实现毫秒级故障感知与切换；
- **减轻运维负担**：新增网段只需宣告，不必逐台设备写静态路由，避免遗漏与环路；
- **支持负载分担与备份**：等开销多路径可同时转发，不等开销路径自动作为备份；
- **易扩展**：网络规模增大时按区域（OSPF Area）分层设计，路由可通过汇总减少表项。

**解析**

（1）的核心是「**一个 VLAN = 一个广播域**」，答「划分 VLAN」只是起点，还要答出「Trunk 承载、三层网关、ACL 控制」才算完整；只写「用路由器隔离」在本题语境下不给分，因为部门众多、需要交换式组网。

（2）要围绕「**自动**」二字展开：自动发现、自动收敛、自动备份。答「动态路由配置简单」这种笼统说法得分低；能写出 OSPF 区域划分与路由汇总属于加分点。

**问题4**（8 分）

请从设备、部署位置、安全规划三个方面简要说明大楼无线网络规划要点，实现无缝漫游和安全接入。

**参考答案**

（1）设备选型与组网（约 3 分）：

- 采用 **AC + Fit AP** 架构（或云管理 AP），AC 旁挂/直挂核心，统一管理 AP 的配置、射频、漫游与认证；
- 接入交换机按 AP 数量与功率预算配置 **PoE 供电**（802.3af/at），预留功率与端口余量；
- 认证与策略集中在 **AC 或认证服务器（Radius/Portal）**，DHCP 由核心/AC 统一分配；
- AP 支持双频/双流以上，5GHz 优先承载业务，2.4GHz 仅作补充。

（2）部署位置与覆盖（约 3 分）：

- AP **吸顶安装**在走廊/房间中央，避开金属吊顶、承重墙、强弱电井；办公室按隔断密度**每 1～2 间一个 AP**，会议室按**高密度场景**单独加密布放；
- 做**现场勘测与仿真**，控制覆盖电平（如 −65dBm 以上）与**同频干扰**，相邻 AP 采用 1/6/11（2.4G）非重叠信道，5G 做信道与功率自动调优；
- 控制单 AP 接入数（如 ≤30～40 终端）与带宽，避免「缩小间隔、无限加 AP」造成同频干扰与漫游频繁；
- 楼层间 AP 覆盖交叠 15%～20%，保证**无缝漫游**（同一 AC/同一 mobility group 内，SSID 与安全策略一致，启用快速漫游 802.11r/k/v）。

（3）安全规划（约 2 分）：

- 认证：员工用 **WPA2/WPA3-Enterprise + 802.1X**（账号或证书），访客用 **Portal 短信/微信认证**，与内网 VLAN 隔离；
- 加密：强制 **AES-CCMP/GCMP**，禁用 WEP/TKIP 与 WPS；
- 边界：Guest 流量经独立 VLAN 直出互联网，ACL 禁止访问内网与设备管理网段；
- 管理面：AP 管理 VLAN 独立、关闭不必要的管理协议，启用**非法 AP/钓鱼 AP 检测与反制**、无线 IPS、DHCP Snooping 与 ARP 防欺骗；
- 审计：上网行为日志留存，SSID 隐藏不作为安全手段（仅减少暴露）。

**解析**

8 分题要「三个方面各自成段、每段 2～3 条」，按「设备—位置—安全」三块给分，写成一段大杂烩容易被判漏点。

本题的隐藏采分点是「**无缝漫游**」与「**安全接入**」这两个题干要求，答案必须显式出现：漫游要在同一 AC/同一漫游组、SSID 与密钥一致、覆盖交叠、启用 802.11r/k/v；安全要区分员工与访客两套认证与 VLAN。只答「多装 AP、设密码」得分很低。

### 1.4 案例4 BGP 路由引入 OSPF 与路由过滤

> 考点：单臂路由/三层交换机默认路由的下一跳、静态路由、OSPF 进程与网段宣告、BGP 引入 OSPF、ip-prefix 与 filter-policy

**【说明】**（20 分）

图所示为某公司网络简化拓扑。总部运行 OSPF 协议的网络中，路由器 R1 从 R0 通过 BGP 接收到路由，包括：10.1.32.0/24、10.1.33.0/24 以及 10.1.34.0/24。要求 R1 向 OSPF 网络仅发布 10.1.33.0/24 和 10.1.34.0/24 两个网段。总部与分部租用光纤直连。分部网络中由交换机 S1 提供汇聚连接。各设备接口及地址信息如图 1 所示，且各设备已完成基本参数配置。

`[原文为图/表，需对照原卷]`（图 1 未收录，R1～R4 各接口地址、S1 的 VLAN 接口地址、PC1/PC2/PC3 所在网段均需对照原卷）

**问题1**（4 分）

交换机 S1 的 VLAN 接口参数信息如图 1 所示，经测试发现 PC1 和 PC2 相互可以 Ping 通，但均无法访问总部网络。查看交换机 S1 的配置发现如下条目：

```text
ip route-static 0.0.0.0 0.0.0.0 10.14.14.1
```

则 PC1 和 PC2 无法访问总部网络的原因是：（1），解决方法是（2）。

**参考答案**

（1）原因：**S1 上默认路由的下一跳 10.14.14.1 不是 R4 与 S1 互联接口的地址（或该地址与 S1 的 VLAN 接口不在同一网段、不存在）**，默认路由的下一跳不可达，报文无法送出分部网络。

判断依据：

- PC1、PC2 能互 ping，说明**二层与 S1 的 VLAN 接口正常**，故障在三层出口；
- S1 是分部汇聚（三层）交换机，去总部只能靠这条默认路由；下一跳写错/不可达时，报文在 S1 上被丢弃或 ARP 无响应。

（2）解决方法：

- 把默认路由的下一跳改为 **R4 与 S1 互联的接口地址**（按图 1 填写）：

```text
[S1] undo ip route-static 0.0.0.0 0.0.0.0 10.14.14.1
[S1] ip route-static 0.0.0.0 0.0.0.0 <R4互联接口地址>
```

- 同时确认 S1 的 **Vlanif 接口地址与 R4 接口在同一网段**、两者互联的 VLAN 在 Trunk 上已放行、接口 UP；
- 若 R4 侧还有回程路由（192.168.0.0/16 → S1），需一并核对（见问题2）。

**解析**

本题的题眼是「**PC 之间能通、出不去**」：这说明同一交换机内的二层转发、VLAN 接口都正常，问题只可能出在「网关/默认路由/上行链路」。

`ip route-static 0.0.0.0 0.0.0.0 10.14.14.1` 的下一跳必须是**直连可达**的地址；如果图中 R4 的接口是 10.14.14.2 或其它网段，这条路由就是「悬空路由」——路由表里有，但 ARP 解析不到，报文直接丢弃。

失分点：只写「默认路由配置错误」而不指出「下一跳不可达」；解决方法写成「加一条明细路由」（治标，未修根因）。

**问题2**（4 分）

配置路由器 R4，补全下列命令：

```text
[R4] ip route-static 0.0.0.0 0.0.0.0（1）
[R4] ip route-static 192.168.0.0 255.255.0.0（2）
```

**参考答案**

| 空号 | 答案 | 说明 |
| ---- | ---- | ---- |
| （1） | 总部方向（R4 上行）直连邻居的接口地址（按图 1） | 默认路由指向总部，下一跳为与 R4 直连的路由器接口 |
| （2） | S1 的 Vlanif 接口地址（按图 1） | 192.168.0.0/16 是分部内网，下一跳指向分部汇聚交换机 S1 |

配置含义：

- 第一条：R4 把所有未知目的地（含互联网/总部其它网段）送往总部；
- 第二条：R4 把发往分部 192.168.0.0/16 的流量交回 S1（S1 是分部的三层网关/汇聚）；
- 两条构成「**去程 + 回程**」的完整路径，缺一条就会单向不通。

**解析**

静态路由题永远检查两件事：**目的网段对不对、下一跳是不是直连邻居**。

（1）的下一跳不能写「总部某台远端路由器的地址」，必须是与 R4 直连的上行接口；（2）的下一跳不能写 PC 的地址，必须写 S1 的 Vlanif（三层接口）地址——因为 R4 要把帧交给 S1，再由 S1 转发给各 VLAN 内的 PC。

补充：如果 R4 与 S1 之间跑 OSPF，则可省掉第二条（由 OSPF 学习），但题干明确是静态路由场景。

**问题3**（4 分）

完成 R1、R2 和 R3 的 OSPF 配置：

```text
#以R1为例
[R1] ospf
[R1-ospf-1]（1）
[R1-ospf-1-area-0.0.0.0]（2）    #发布10.12.12.0/24
```

**参考答案**

| 空号 | 答案 | 说明 |
| ---- | ---- | ---- |
| （1） | `router-id 1.1.1.1`（或 `area 0`） | 若下一行已显式进入区域，则此空填 Router-ID，如 `router-id 1.1.1.1` |
| （2） | `network 10.12.12.0 0.0.0.255` | 华为用**反掩码**宣告 10.12.12.0/24 |

说明：

- 题干下一行提示符已是 `[R1-ospf-1-area-0.0.0.0]`，说明区域已进入，因此（1）最合理的是配置 Router-ID；
- 若考场版本要求（1）为 `area 0`，则 Router-ID 已在别处配置，两种写法都对应「进区域 + 宣告」这两步；
- `network` 必须写**接口所在网段 + 反掩码**，也可写成 `network 10.12.12.1 0.0.0.0`（接口地址 + 全 0 反掩码）。

**解析**

OSPF 配置的固定三步：**建进程 → 定 Router-ID → 进区域宣告网段**。

本题最容易错的是「反掩码」：`0.0.0.255` 对应 /24，写成 `255.255.255.0` 接口就不会被使能 OSPF，邻居也起不来。这是网络工程师考试中重复率最高的失分点之一。

另外注意 Router-ID 的选取规则：手工配置 > 最大 Loopback 地址 > 最大物理接口地址；同一区域内 Router-ID 不能重复。

**问题4**（8 分）

在 R1 上将 BGP 路由引入到 OSPF 协议中：

```text
[R1] ospf
[R1-ospf-1]（1）
[R1-ospf-1] quit
#下列命令的功能是:（2）
[R1] ip ip-prefix 1to2 index 33 permit 10.1.33.0 24
[R1] ip ip-prefix 1to2 index 34 permit 10.1.34.0 24
#补全下列命令。
[R1] ospf
[R1-ospf-1] filter-policy ip-prefix（3）export bgp
```

要求 PC3 只能访问 10.1.34.0/24 路由，在 R3 上配置路由策略，只接收 10.1.34.0/24 路由的配置思路是：（4）。

**参考答案**

| 空号 | 答案 | 说明 |
| ---- | ---- | ---- |
| （1） | `import-route bgp` | 把 BGP 路由引入 OSPF，使 R1 成为 ASBR |
| （2） | 定义名为 `1to2` 的**地址前缀列表**，用 index 33、34 分别**精确匹配并允许** 10.1.33.0/24 与 10.1.34.0/24 两条路由；未匹配的其他前缀被隐含拒绝（用于后续过滤，只放行这两个网段） | ip-prefix 是过滤工具，本身不做引入 |
| （3） | `1to2` | `filter-policy ip-prefix 1to2 export bgp`，在向 OSPF 发布 BGP 路由时按前缀列表过滤 |
| （4） | 见下 | R3 上只接收 10.1.34.0/24 的思路 |

（4）R3 上的配置思路：

1. **定义匹配工具**：用 `ip ip-prefix`（或 ACL）**精确匹配 10.1.34.0/24**（`ip ip-prefix only34 permit 10.1.34.0 24`），其余不匹配即被拒绝；
2. **在 R3 的 OSPF 进程的接收方向调用过滤**：`filter-policy ip-prefix only34 import`，使 R3 只把 10.1.34.0/24 装入路由表，10.1.33.0/24 及 10.1.32.0/24 被过滤；
3. **验证**：`display ip routing-table` 确认只剩 10.1.34.0/24，`display ospf routing` 查看 OSPF 路由；
4. 若要更精细（改开销、打 tag），可用 `route-policy` + `apply cost`，在 `import` 方向调用；
5. 注意过滤方向是 **import（接收）**，因为需求是「R3 只接收」，不是「R1 只发送」。

配置示例：

```text
[R3] ip ip-prefix only34 index 10 permit 10.1.34.0 24
[R3] ospf 1
[R3-ospf-1] filter-policy ip-prefix only34 import
```

**解析**

本题四个空构成一条完整的「**引入 → 过滤 → 定向**」链路：

```text
R1: import-route bgp（把三条都引入）
R1: ip-prefix 1to2（只匹配 33、34）
R1: filter-policy ... export bgp（发布时只放行 33、34）
R3: ip-prefix only34 → filter-policy import（接收时只留 34）
```

关键概念区分：

| 工具 | 作用 |
| ---- | ---- |
| `import-route` | 把其他协议的路由**引入**本协议（产生 Type 5 LSA） |
| `ip-prefix` | 定义前缀匹配列表（可精确匹配掩码长度），本身不过滤 |
| `filter-policy` | 在**引入/发布/接收**方向调用过滤工具，真正生效 |
| `route-policy` | 可匹配 + 修改属性（cost、tag、community） |

高频失分：

1. （1）写成 `import-route ospf`（方向反了）或 `import-route direct`（引入对象错）；
2. （3）写成 `1to2` 以外的名字，或漏写 `export bgp`；
3. （4）把过滤方向写成 `export`——R3 是接收方，必须 `import`；
4. 只写「用 ACL 过滤」而不说「在 OSPF 的 import 方向调用」，缺少落地动作。

补充：`filter-policy` 只影响**路由表安装/发布**，不影响 LSA 泛洪（OSPF 中需用 `filter-lsa-out` 才能抑制 LSA），这是概念题常考的细节。

| 场景 | 结论 |
| ---- | ---- |
| DHCP 地址不够 | 缩租期 + 扩池（加掩码位/加 VLAN）+ 精确排除 + 静态绑定 + 探测回收 |
| 能拿地址不能上网 | 私接 DHCP → 全局 `dhcp enable` + `dhcp snooping enable` + 上联口 `trusted` |
| 接口地址池 | `dhcp select interface`，网关自动取接口地址，排除段写「起始 结束」 |
| 批量建 VLAN | `vlan batch 10 20`（空格分隔，无逗号） |
| 仅放行指定 VLAN | `port trunk allow-pass vlan 10 20` + 必要时 `undo ... vlan 1` |
| 水平布线 | 永久链路 ≤90m，信道 ≤100m |
| 跨楼栋 | 建筑群子系统 + 单模光缆 |
| 63 台主机 | /26 只有 62 可用 → 必须 /25（差 1 台的经典陷阱） |
| 无线无缝漫游 | 同 AC/同漫游组、SSID 与密钥一致、覆盖交叠、802.11r/k/v |

### 2.3 答题模板

**模板一：故障原因 + 处置（DHCP/DNS/路由类）**

```text
原因：① 资源侧（池容量/租期/排除范围）② 配置侧（网关、掩码、下一跳）
      ③ 行为侧（私接设备、终端异常下线、攻击——题干排除的不要写）
处置：① 立即恢复（扩池/改配置/切换链路）
      ② 根因治理（重新规划、缩短租期、静态绑定）
      ③ 长效防护（Snooping/端口安全/监控告警/冗余）
```

**模板二：配置补全**

```text
1. 先判视图：[R] 系统视图 / [R-接口] / [R-协议] / [R-aaa]
2. 再判方向：全局开关（enable）→ 接口参数（ip address/port link-type）→ 协议参数
3. 最后抄格式：地址+掩码、排除段「起 止」、allow-pass 后接 VLAN 列表
```

**模板三：规划类（地址/布线/无线）**

```text
地址：需求主机数 → 2^h-2 ≥ 需求 → 定掩码 → 按块连续分配 → 网关与保留地址
布线：工作区/水平/管理/垂直/设备间/建筑群 六子系统 + 90m/100m + 单模多模选择
无线：设备（AC+FIT+PoE）→ 位置（勘测、信道、功率、密度）→ 安全（认证、加密、隔离、审计）
```

**模板四：路由控制（引入/过滤）**

```text
引入：ospf → import-route bgp/static/direct
过滤：ip ip-prefix 名 index N permit 网络 掩码长度
      ospf → filter-policy ip-prefix 名 export/import
只收某条：ACL/prefix 精确匹配该网段，其余 deny，再 import 过滤
```
