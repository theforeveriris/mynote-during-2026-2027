### 1.1 案例1 企业办公网 IPv4 地址规划（第1题，20分）

> 考点：VLSM 子网划分、可用地址数计算、地址块对齐、部门地址规划

**【说明】**（20分）

某企业办公楼网络拓扑如图1-1所示。该网络中交换机Switch1-Switch4均是二层设备，分布在办公楼的各层，上联采用千兆光纤。核心交换机、防火墙、服务器部署在数据机房，其中核心交换机实现冗余配置。

> `[原文为图1-1，需对照原卷]` 拓扑细节（各交换机端口、链路带宽、VLAN 划分）未随原文收录。

**问题1**：该企业办公网络采用172.16.1.0/25地址段，部门终端数量如表1-1所示，请将网络地址规划补充完整。（4分）

> `[原文为表1-1，需对照原卷]` 表中「部门名称 / 终端数量 / 待填空」三列数据未随原文收录，因此本题的**确定答案无法给出**，下面给出必须掌握的计算方法与填表格式。

**参考答案**

- 计算前提：172.16.1.0/25 的掩码为 255.255.255.128，地址范围 172.16.1.0 ~ 172.16.1.127，可用主机地址 126 个（172.16.1.1 ~ 172.16.1.126），172.16.1.127 为广播地址。
- 规划步骤（VLSM，从大到小切分）：
  1. 把各部门终端数按从大到小排序；
  2. 对每个部门取满足 `2^n − 2 ≥ 终端数` 的最小 n，子网掩码为 `/（32−n）`；
  3. 按块大小顺序分配，**起始地址必须能被块大小整除**；
  4. 每块扣除网络地址与广播地址，网关一般占用该块第一个可用地址。
- 块大小速查：

| 掩码 | 块大小 | 可用主机数 | 适用终端数 |
| --- | --- | --- | --- |
| /25 | 128 | 126 | 127 以下 |
| /26 | 64 | 62 | 63 以下 |
| /27 | 32 | 30 | 31 以下 |
| /28 | 16 | 14 | 15 以下 |
| /29 | 8 | 6 | 7 以下 |
| /30 | 4 | 2 | 2（点对点链路） |

- 填表格式（下列部门名称与数量为**示例，非原表数据**，仅演示写法）：

| 部门 | 终端数（示例） | 子网地址/掩码 | 可用地址范围 | 广播地址 |
| --- | --- | --- | --- | --- |
| 部门A | 50 | 172.16.1.0/26 | 172.16.1.1 ~ 62 | 172.16.1.63 |
| 部门B | 25 | 172.16.1.64/27 | 172.16.1.65 ~ 94 | 172.16.1.95 |
| 部门C | 10 | 172.16.1.96/28 | 172.16.1.97 ~ 110 | 172.16.1.111 |

- 若原表某部门终端数大于 126，则该部门无法被 /25 内的任何一个子网容纳，必须另申请地址段（这是本题最常见的陷阱，答题时要明确指出）。

**解析**

- 为什么是 /25：题干已限定「172.16.1.0/25」，说明只给了半个 C 类地址空间（128 个地址、126 个可用），**不是 /24**。很多考生按 /24 计算，答案整体偏移，直接失分。
- VLSM 的核心是「**按需借位 + 块对齐**」：/26 只能在 .0、.64、.128、.192 处起始；/27 只能在 32 的倍数处起始；/28 只能在 16 的倍数处起始。起始地址未对齐的写法一律判错。
- 可用主机数必须减 2（网络地址 + 广播地址）。若部门数量刚好等于块大小（例如 62 台终端分 /26），仍然只能放 62 台，因为可用地址只有 62 个。
- 网关地址要从可用地址中预留，若部门终端数已经用满 2^n−2，则必须升级到更大掩码。

### 1.2 案例2 双 ISP 出口的负载分担与 NAT 发布（第2题，20分）

> 考点：多出口链路负载策略、防火墙安全策略（源/目的区域、服务、动作）、多出口非对称路由、域内 NAT（hairpin）

**【说明】**（20分）

某企业网络拓扑如图2-1所示，该企业通过两个不同的运营商(ISP1和ISP2)接入Internet，内网用户通过NAT访问Internet。公网用户可通过不同的ISP访问企业内部的应用。

> `[原文为图2-1，需对照原卷]` 各接口地址、Server 私网地址、两个 ISP 的公网地址段未随原文收录。

**问题1**：为充分利用两个运营商的带宽，请提供至少4种多出口链路负载策略。（6分）

**参考答案**

| 序号 | 策略 | 做法与适用场景 |
| --- | --- | --- |
| 1 | 基于源地址的策略路由 | 把内网按部门/网段分组，不同网段固定从不同 ISP 出口，实现按用户分流 |
| 2 | 基于目的地址（运营商地址库）的策略路由 | 访问 ISP1 的地址走 ISP1、访问 ISP2 的地址走 ISP2，解决跨运营商访问慢的问题 |
| 3 | 基于应用/协议端口的策略路由 | 语音、视频等实时业务走质量好的链路，普通上网、下载走另一条链路 |
| 4 | 等价多路径（ECMP）负载分担 | 配置两条同一优先级的默认路由，设备按逐流（源/目的 IP、端口哈希）分担到两条链路 |
| 5 | 按链路带宽加权分担 | 两条链路带宽不同时，按带宽比例分配会话数或流量，避免小带宽链路被打满 |
| 6 | 链路质量智能选路 | 用 NQA/健康探测实时检测两条链路的时延、丢包、带宽利用率，动态选择较优链路，故障时自动切换 |
| 7 | 主备（浮动静态路由） | 一条为主用、一条为备份，主链路故障时自动切换；严格说是可靠性方案，常与上面几种组合使用 |

**解析**

- 题目问的是「负载策略」，答题时要区分三个层次：**按什么分流**（源、目的、应用、带宽比例）、**怎么分流**（策略路由、ECMP、加权）、**怎么保证质量**（探测与切换）。三层各写一两条即可拿满 6 分。
- 华为设备上对应的落地手段：`traffic classifier` + `traffic behavior redirect ip-nexthop` + `traffic policy` 做策略路由；`ip route-static 0.0.0.0 0 网关1` 与 `... 网关2` 同优先级做 ECMP；`nqa test-instance` 与静态路由 `track` 联动做智能选路。
- 失分点：只写「两条默认路由」而不说分流粒度；把「链路聚合」当成多出口策略（链路聚合只能聚合到同一对端，不能跨运营商）。

**问题2**：内网服务器Server需对外发布提供服务，互联网用户可通过ISP1、ISP2来访问，Server的服务端口为TCP 9980。请根据以上需求配置安全策略，允许来自互联网的用户访问Server提供的服务。（6分）

配置片段：

```text
[USG]security-policy
[USG-policy-security]rule name http
[USG-policy-security-rule-http]source-zone ISP1
[USG-policy-security-rule-http]source-zone ISP2
[USG-policy-security-rule-http]destination-zone trust
[USG-policy-security-rule-http]destination-address   (1)
[USG-policy-security-rule-http]service protocol    (2)  destination-port   (3)
[USG-policy-security-rule-http]action (4)
[USG-policy-security-rule-http]quit
```

**参考答案**

| 空号 | 答案 | 说明 |
| --- | --- | --- |
| （1） | **Server 的私网地址**（如 `10.x.x.x 32`，或该地址所在地址组） | 安全策略匹配的是 NAT Server 转换后的目的地址，目的区域为 trust，故填服务器私网地址 |
| （2） | **tcp** | 题干明确服务端口为 TCP 9980 |
| （3） | **9980** | 与 NAT Server 中 `inside ... 9980` 的服务端口一致 |
| （4） | **permit** | 允许互联网用户访问该服务 |

**解析**

- 华为 USG 的匹配顺序是：**目的 NAT（NAT Server）先做地址转换，安全策略再匹配转换后的报文**。因此目的地址写服务器私网地址，而不是公网地址；若写公网地址，报文已被转换成私网地址，策略匹配不上，表现为「NAT 配了但不通」。
- 源区域要同时包含 ISP1、ISP2 两个 untrust 侧区域（本题把两个出口分别划为 ISP1、ISP2 区域），只写一个会出现「一个运营商能访问、另一个不能」。
- 服务匹配推荐写成 `service protocol tcp destination-port 9980`，比只写 `service tcp` 更精确；若设备用 `service` 引用预定义服务，则需先自定义 9980 端口的服务。
- 同时别忘了对应的 NAT Server 配置（目的 NAT）：`nat server policy _web protocol tcp global <公网地址> 9980 inside <Server私网地址> 9980`，两个 ISP 各配一条或在同一策略中引用两个公网地址。

**问题3**：经过一段时间运行，经常有互联网用户反映访问Server的服务比较慢。经过抓包分析发现部分应用请求报文和服务器的回应报文经过的不是同一个ISP接口。请分析原因并提供解决方法。（4分）

**参考答案**

- 原因：多出口做了**逐流/逐包的负载分担**（ECMP 或按会话哈希），去程与回程的哈希结果不一致；或者去程被策略路由固定到 ISP1，而回程按目的地址（公网地址属于另一个 ISP 的地址段）走了 ISP2，形成**非对称路由**。非对称路径会导致：两个方向时延/带宽不同、路径 MTU 不同引起分片、运营商侧 uRPF 源地址校验丢弃、防火墙会话状态不匹配而丢包，最终表现为访问慢、重传多。
- 解决方法（答出 2~3 条即可）：
  1. **会话保持**：负载分担改为基于源 IP（或五元组）的哈希，保证同一会话的去程与回程走同一出口；
  2. **NAT 与出口绑定**：按出接口使用对应运营商的地址池（ISP1 池 / ISP2 池），使源地址与出口同运营商，回程自然回到同一 ISP；
  3. **双向策略路由**：去程与回程都按运营商地址库分流，避免跨运营商回程；
  4. 关闭或调整运营商侧的 uRPF 严格校验；启用链路质量探测，把劣化链路从负载分担中剔除；
  5. 服务器对外发布可只绑定一个 ISP 入口（另一 ISP 仅作备份），从根上避免非对称。

**解析**

- 「请求和回应走不同 ISP」是典型的非对称路由，答题要点是**先说机制（哈希/等价路由导致两个方向选路不一致），再说后果（时延差、uRPF 丢包、状态防火墙会话不匹配），最后说手段（会话保持、NAT 与出口绑定、双向分流）**。
- 只写「配置策略路由」不够，必须说明「保证同一会话同进同出」，否则仍会被判不完整。

**问题4**：企业网络在运行了一段时间后，网络管理员发现了一个现象：互联网用户通过公网地址可以正常访问Server，内网用户也可以通过内网地址正常访问Server，但内网用户无法通过公网地址访问Server，经过排查，安全策略配置都正确。请分析造成该现象的原因并提供解决方案。（4分）

**参考答案**

- 原因：内网用户访问公网地址时，流量从 trust 区域进入、又从 trust 区域出去（**域内流量 trust→trust**），存在两个问题：
  1. 防火墙的 NAT Server 只在报文从 untrust 侧进入时做目的地址转换，内网发起的访问没有做「公网地址 → 私网地址」的转换，报文被送到出口后因目的地址是本机/公网地址而无法回到内网服务器；
  2. 现有安全策略只放行了 untrust→trust，没有放行 trust→trust 的这条访问。
- 解决方案（任选其一，推荐前两条）：
  1. **开启域内 NAT（hairpin / 双向 NAT）**：对 trust→trust 的流量也做目的 NAT，把公网地址转换为 Server 私网地址，并放行对应安全策略；
  2. **内网 DNS 分离解析**：内网 DNS 把服务器域名解析为私网地址，内网用户直接访问私网地址，不经过公网地址回环；
  3. 在核心交换机或内网侧设备上做目的地址重定向（策略路由/NAT），把访问公网地址的流量直接引到服务器私网地址。

**解析**

- 这是 NAT 环境下的经典「回流」问题，关键词是 **hairpin / 域内 NAT / NAT 回流**。判断特征：外网能访问、内网用私网地址能访问、内网用公网地址不能访问，且策略「看起来是对的」。
- 答题时要说明「NAT Server 默认只对从一个区域进入另一个区域的流量生效」，所以同区域访问不会被转换，这是与「安全策略配置正确」并不矛盾的原因。

### 1.3 案例3 BGP 与 OSPF 互引的路由环路（第3题，20分）

> 考点：双点双向路由引入的环路成因、iBGP 配置、OSPF 认证方式、路由策略（ACL + route-policy）、BGP 环路检测

**【说明】**（20分）

图3-1为某公司网络骨干路由拓扑片段(分部网络略),公司总部与分部之间运行BGP获得路由，路由器RA、RB、RC以及RD之间配置iBGP建立邻居关系，RC和RD之间配置OSPF进程。所有路由器接口地址信息如图所示，假设各路由器已经完成各个接口IP等基本信息配置。

> `[原文为图3-1，需对照原卷]` 拓扑中的接口地址、AS 号、财务专网网段等细节需对照原图；下文空（1）~（11）的地址类答案依据题干中出现的信息与被引用的地址推断，已逐条注明依据。

**问题1**：按图3-1所示配置完成BGP和OSPF路由相互引入后，可能会出现路由环路，请分析产生路由环路的原因。（2分）

**参考答案**

- 根本原因是**同一批路由在两个路由协议之间被双向重复引入**：RC、RD 上既把 OSPF 路由 `import-route` 进 BGP，又把 BGP 路由 `import-route` 进 OSPF。
- 一条 OSPF 路由被引入 BGP 后，以 BGP 路由形式传到另一台路由器，又被该路由器引入回 OSPF；此时它已变成 OSPF 的 AS-External 路由，**BGP 的 AS_PATH 防环机制在 OSPF 域内不起作用**，OSPF 无法识别这条路由「回过家」，于是继续泛洪，再次被引入 BGP，形成环路或次优路径。
- 叠加因素：iBGP 邻居是全互联的，任意一台路由器引入的路由都会传给其他 iBGP 对等体，使回灌路径更多；引入时未用 route-policy / filter-policy 做过滤，未给引入路由打 tag 做防环。

**解析**

- 一句话总结：**双向引入 + 缺乏过滤标记 = 环路**。标准解法有三种：单向引入（只在一个方向引入）、用 route-policy 只引入必要网段、用 tag 标记并在另一端过滤（OSPF 引入时打 tag，BGP 引入 OSPF 时用 route-policy 拒绝带该 tag 的路由）。
- 本题只有 2 分，答出「双向引入、协议间回灌、AS_PATH 防环失效」即可，不必展开配置。

**问题2**：要求：配置BGP和OSPF基本功能(以RA和RB为例),并启用RC和RD之间的认证，以提升安全性。补全下列命令完成RA和RB之间的BGP配置：（10分）

（5）OSPF认证方式有哪些?上述命令中配置RC的为哪种?
（6）如果将命令`authentication-mode simple ruankao`替换为`authentication-mode simple plain ruankao`,则两者之间有何差异?

**参考答案**

| 空号 | 答案 | 依据 |
| --- | --- | --- |
| （1） | **100** | 题干说明 RA、RB、RC、RD 之间是 iBGP，同一 AS；RB 的 `bgp 100` 已给出 |
| （2） | **10.12.0.2** | `peer x enable` 中的 x 必须是已用 `peer ... as-number` 声明的对等体地址，即 RB 的接口地址 |
| （3） | **10.12.0.1** | RB 侧配置与 RA 的对等关系，填 RA 的接口地址（与 RA 上 `peer 10.12.0.2` 对称） |
| （4） | **10.10.10.0 0.0.0.255** | 题干要求「发布财务专网给RD」，而问题3的 ACL 注释写明「禁止10.10.10.0/24通过」，故财务专网为 10.10.10.0/24 |
| （5） | 认证方式：按范围分**区域认证**（`area` 视图下 `authentication-mode`）和**接口认证**（接口视图下 `ospf authentication-mode`）；按算法分明文认证（simple）和密文认证（MD5 / HMAC-SHA256）。上述命令是在 area 0 视图下配置，属于**区域内的 simple 明文认证** | 题干命令位于 `[RC-ospf-1-area-0.0.0.0]` 视图 |
| （6） | 两者的**认证过程与效果相同**，差别只在配置文件中口令的保存方式：`simple ruankao` 把口令以**密文**形式保存在配置中；`simple plain ruankao` 表示后面跟的是**明文**口令，配置回显时也以明文显示，便于核对，但安全性较低 | `plain` 关键字表示「按明文输入/显示」 |

**解析**

- iBGP 的三个必答点：`bgp <本AS号>`、`peer <对端地址> as-number <同一AS号>`、`ipv4-family unicast` 下 `peer <对端地址> enable`。少写 `ipv4-family` 是本题最常见的失分点——华为设备 BGP 的对等体能力必须在地址族视图下使能。
- `router-id` 必须唯一，通常用 Loopback 地址；RA 为 10.11.0.1、RB 为 10.22.0.2、RC 为 10.33.0.3，规律可推 RD 为 10.44.0.4。
- `network` 命令的通配符写法：`network 10.10.10.0 0.0.0.255`，必须是**精确匹配**的网段（掩码反写），不能写成 `10.10.10.0 0.0.0.0`（那是 /32 主机路由）。
- OSPF 认证的记忆口诀：**两种范围（区域/接口）× 两种算法（simple 明文 / md5 密文）**；本题命令在 area 视图，所以是区域认证。

**问题3**：要求：配置BGP和OSPF之间的相互路由引入并满足相应的策略，配置路由环路检测功能。（8分）

配置片段：

```text
[RC-ospf-1]import-route bgp permit-ibgp    #该命令的作用是(7)
……
#配置RD的BGP引入OSPF路由，并配置路由策略禁止发布财务专网的路由给BGP。
[RD]acl number 2000       #配置编号为2000的ACL,禁止10.10.10.0/24通过
[RD-acl-basic-2000]rule deny source (8) 0.0.0.255
[RD-acl-basic-2000]quit
[RD]route-policy rp   #配置名为rp的路由策略
[RD-route-policy]if-match acl(9)
[RD-route-policy]quit
[RD]bgp 100
[RD-bgp]ipv4-family unicast
[RD-bgp-af-ipv4]import-route ospf 1(10)
[RD-bgp]quit
#以RA为例，启用BGP环路检测功能。
[RA]route (11) bgp enable
```

**参考答案**

| 空号 | 答案 | 说明 |
| --- | --- | --- |
| （7） | 在 OSPF 中引入 BGP 路由，并**允许引入 iBGP 路由**（默认只引入 eBGP 路由，iBGP 路由不引入） | `permit-ibgp` 是关键参数 |
| （8） | **10.10.10.0** | 与 ACL 注释「禁止10.10.10.0/24通过」一致，通配符 0.0.0.255 由题干给出 |
| （9） | **2000** | `if-match acl` 引用上面定义的 ACL 编号 |
| （10） | **route-policy rp** | 引入 OSPF 路由时调用路由策略，过滤财务专网 |
| （11） | **loop-detect** | 完整命令 `route loop-detect bgp enable`，启用 BGP 路由环路检测 |

**解析**

- `import-route bgp permit-ibgp` 是华为 OSPF 的特有参数：不加 `permit-ibgp` 时，OSPF 只引入 eBGP 路由，本案例中 RC 从 iBGP 邻居学到的路由就引不进来，会出现「配置了引入但路由表没有」的现象。
- route-policy 的两段式写法要背熟：`route-policy rp permit node 10` → `if-match acl 2000`（拒绝的流量不进入该节点）→ `quit`；被 ACL `deny` 的路由不匹配任何节点，因而被丢弃，实现「不发布财务专网」。
- `route loop-detect bgp enable` 用于在设备上开启 BGP 路由环路检测，配合前面的双向引入使用；注意命令层级是系统视图。
- 失分点：把（7）写成「引入 BGP 路由」而漏掉 `permit-ibgp` 的含义；把（10）写成 `route-policy rp import` 之类的错误语法。

某公司网络拓扑如图4-1所示。

**问题1**：公司计划在R1、R2、R3上运行RIP,保证网络层相互可达。接口IP地址配置如表4-1所示。请将下面的配置代码补充完整。（10分）

```text
[HUAWEI](1)
[HUAWEI]sysname(2)
[R1] interface GigabitEthernet 0/0/0
[R1-GigabitEthernet 0/0/0]ip address 10.0.1.254 255.255.255.252
[R1-GigabitEthernet 0/0/0]interface GigabitEthernet0/0/1
```

**参考答案**

| 空号 | 答案 | 依据 |
| --- | --- | --- |
| （1） | **system-view** | 从用户视图进入系统视图，提示符由 `<HUAWEI>` 变为 `[HUAWEI]` |
| （2） | **R1** | 将设备名改为 R1，后续提示符为 `[R1]` |
| （3） | GE0/0/1 接口的 IP 地址（与对端同网段、掩码 /30，例如 `10.0.2.1`） | 掩码已给出 255.255.255.252；**具体数值需对照表4-1**，原文未收录该表，无法唯一确定 |
| （4） | **version 2** | RIPv2 支持 VLSM 与组播更新，且后续有 `undo summary`（关闭自动汇总），说明用的是 v2 |
| （5） | **10.0.0.0** | `network` 用主类网络号；R1 的 10.0.1.254/30 属于 10.0.0.0/8，故写 `network 10.0.0.0`；下一行 `network 100.0.0.0` 对应 100.1.1.0/24 |

**解析**

- VRP 的视图层级：用户视图 `<HUAWEI>` → `system-view` → 系统视图 `[HUAWEI]` → `sysname R1` → `[R1]`。空（1）（2）几乎是送分题。
- 华为 RIP 的 `network` 参数是**主类网络号**（A/B/C 类），不是子网号，也不带掩码。写 `network 10.0.1.0` 是典型错误。
- `undo summary` 关闭 RIPv2 自动汇总，使明细子网（如 10.0.1.0/30、10.0.2.0/30）能被正确通告；不关闭时会被汇总成 10.0.0.0/8。
- 空（3）虽然原表缺失，但答题时要体现两点：与对端同网段、掩码 255.255.255.252（/30，仅 2 个可用地址，用于路由器互联）。

**问题2**：公司计划在R2和R3的链路上使用RIP与BFD联动技术，采用BFD echo报文方式实现当链路出现故障时，BFD能够快速感知并通告RIP协议。请将下面的配置代码补充完整。（3分）

配置片段：

```text
[R2]interface gigabitethernet(6)
[R2-GigabitEthernet0/0/1]undo  (7)    #关闭接口GE0/0/1的二层转发特性
[R2-GigabitEthernet0/0/1]rip bfd (8)   #使能接口GE0/0/1的静态BFD特性
```

**参考答案**

| 空号 | 答案 | 说明 |
| --- | --- | --- |
| （6） | **0/0/1** | 与下一行提示符 `[R2-GigabitEthernet0/0/1]` 一致 |
| （7） | **portswitch** | `undo portswitch` 把二层交换口切换为三层路由口（关闭二层转发特性） |
| （8） | **static** | `rip bfd static` 使能接口的静态 BFD 会话，用于 RIP 与 BFD 联动 |

**解析**

- `undo portswitch` 是华为盒式/框式交换机把交换口变路由口的命令；题目明确要求「关闭二层转发特性」，且提示符为 `GigabitEthernet0/0/1`，因此填 `portswitch`。
- BFD 联动有两种：`rip bfd enable`（动态 BFD，会话由协议触发建立）与 `rip bfd static`（静态 BFD，需手工 `bfd 1 bind peer-ip ...`）。题干说「静态BFD特性」，且注释就是「使能接口的静态BFD」，因此填 `static`。
- 若填 `enable` 会与「静态」矛盾，属于典型失分。

**问题3**：公司通过R1连接Internet,为公司提供互联网访问服务，在R1上配置了静态路由向互联网接口，为了使网络均能够访问互联网，需通过RIP将该静态路由进行重分布。将下面的配置代码补充完整。（2分）

配置片段：

```text
[R1-rip-2]default-route (9)
```

**参考答案**

| 空号 | 答案 | 说明 |
| --- | --- | --- |
| （9） | **originate** | `default-route originate` 在 RIP 中生成并发布缺省路由，使下游路由器学到 0.0.0.0/0 |

**解析**

- `default-route originate`：RIP 视图下主动向邻居发布一条缺省路由（0.0.0.0/0），让 R2、R3 把未知流量都交给 R1，从而访问 Internet。这是「边缘路由器向内部注入默认路由」的标准做法。
- 另一条路是 `import-route static`（把静态路由重分布进 RIP），但题干已给出 `default-route` 命令骨架，只能填 `originate`。
- 可加参数：`default-route originate cost 1` 指定度量值；`default-route originate match default` 仅当本地存在默认路由时才发布，常用于「有线上行才发默认路由」的场景。

### 2.2 答题模板

**模板一：配置填空类**

1. 先看视图提示符，确定命令层级（用户视图 / 系统视图 / 接口视图 / 协议视图 / 地址族视图）；
2. 再看注释，注释往往直接点明参数含义（如「关闭二层转发特性」→ `undo portswitch`、「静态BFD」→ `static`）；
3. 地址类空格用题干已给信息反推（对称性：RA 的 peer 是 RB 的地址，RB 的 peer 是 RA 的地址；子网内地址同网段）；
4. 写完整命令而不是只写关键字，检查是否漏了 `enable`、`permit`、`route-policy` 等后缀。

**模板二：故障分析类**

```text
现象（哪个方向不通 / 哪个区域不通）
→ 分层定位（物理层 → 二层 VLAN/STP → 三层路由 → NAT → 安全策略 → 会话状态）
→ 找「配置正确但不通」的环节（顺序问题、区域问题、非对称、回流）
→ 给出解决措施（改配置 / 加策略 / 换方案）
```

**模板三：规划计算类**

```text
需求终端数 → 2^n−2 ≥ 需求 → 掩码 /(32−n) → 块大小 → 起始地址对齐 → 可用范围 / 广播地址 / 网关
```

**模板四：路由协议对比类**

从「算法原理、适用范围、功能特性」三方面作答：距离矢量 vs 链路状态、跳数 vs 带宽/开销、自治域内 vs 域间、收敛速度、是否支持 VLSM、防环机制。
