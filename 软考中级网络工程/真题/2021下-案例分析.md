### 1.1 案例1 大楼有线无线一体化网络规划（第1、2、3题，20分）

> 考点：AC 部署方式（直连/旁路、核心层/接入层）、NAT 部署位置、Portal 认证

**【说明】**（20分）

某单位由于业务要求，在六层的大楼内同时部署有线和无线网络，楼外停车场部署无线网络。网络拓扑如图1-1 所示。

> `[原文为图1-1，需对照原卷]` 拓扑（AC、交换机、Router、AP 的连接关系与认证服务器位置）未随原文收录。

**问题1**：
1.该网络规划中，相较于以旁路方式部署，将AC直连部署存在的问题是(1)。相较于部署在核心层，将AC部署在接入层存在的问题是(2)。
2.在不增加网络设备的情况下，防止外网用户对本网络进行攻击，隐藏内部网NAT策略通常配置在(3) 。
(3)备选答案:
A.AC　B.Switch　C.Router
3.某用户通过手机连接该网络的WIFI信号，使用WEB页面进行认证后上网，则该无线网络使用的认证方式是(4) 认证。
(4)备选答案:
A. PPPoE　B. Portal　C. IEEE 802.1x

（8分）

**参考答案**

| 空号 | 答案 | 说明 |
| --- | --- | --- |
| （1） | **AC 成为业务转发的单点故障与性能瓶颈**。直连（串接）部署时，所有 AP 的管理流量与用户业务流量都要经过 AC，AC 的吞吐与会话数容易打满；AC 一旦故障，全部 AP 下线、无线业务全断；扩容也不灵活 | 与旁路部署对比：旁路时业务流量可由交换机直接转发，AC 只做管理 |
| （2） | **管理分散、跨 AC 漫游困难、占用接入层上行带宽**。部署在接入层只能就近管理少量 AP，六层大楼需多台 AC，管理分散、成本高；跨楼层/跨 AC 漫游体验差；AC 的 CAPWAP 流量还要挤占接入层上联 | 与核心层部署对比：核心层可统一管理全网 AP，性能与扩展性更好 |
| （3） | **C（Router）** | NAT 部署在内外网边界的出口路由器上，把内网私有地址转换为公网地址，从而隐藏内部网络结构；AC、Switch 是内网设备，对外部用户起不到隐藏作用 |
| （4） | **B（Portal）** | 用户先连上 WIFI，访问任意网页被重定向到认证页面，输入账号口令后放行，是典型的 Portal（Web）认证 |

**解析**

- AC 部署方式对比：

| 部署方式 | 数据路径 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 直连式（串接） | AP—AC—上层网络 | 组网简单，AC 可直接控制转发 | AC 单点故障、性能瓶颈、扩容困难 |
| 旁挂式 | AC 旁挂核心/汇聚，业务流量可由交换机直接转发 | 可靠性高、扩展性好 | 需规划管理 VLAN 与业务 VLAN |
| AC 放核心层 | 统一管理全网 AP | 管理集中、性能强、漫游范围大 | 核心层压力集中 |
| AC 放接入层 | 就近管理本接入层 AP | 管理报文路径短 | 管理分散、跨 AC 漫游难、设备数量多 |

- 三种认证方式的区分：**Portal＝先上网后认证，用 Web 页面；802.1X＝先认证后上网，用 EAPoL；PPPoE＝拨号**。题干「WEB 页面认证」直接指向 Portal。
- NAT 位置：内网→外网的源 NAT 必须做在**边界设备**（路由器/防火墙）上，这是「隐藏内部网」的唯一有效位置。

### 1.2 案例2 出口防火墙 NAT、安全策略与 NAT Server（第4、5题，20分）

> 考点：防火墙工作模式（透明/路由/混合）、DHCP 服务、NAT Server（目的 NAT）、安全区域、安全策略、源 NAT 与 PAT 地址池

**【说明】**（20分）

某企业内部局域网拓扑如图2-1所示，局域网内分为办公区和服务器区。
图2-1中，办公区域的业务网段为10.1.1.0/24，服务器区网段为10.2.1.0/24，服务网段的网关均在防火墙上，网关分别对应为10.1.1.254、10.2.1.254；防火墙作为DHCP服务器，为办公区终端自动下发IP地址，并通过NAT实现用户访问互联网。防火墙外网服务部IP地址为100.1.1.2/28，办公区用户出口IP地址池为100.1.1.10-100.1.1.15。

> `[原文为图2-1，需对照原卷]` 防火墙接口编号与连接关系未随原文收录；原文「外网服务部」应为「外网接口」。

**问题1**：防火墙常用工作模式有透明模式、路由模式、混合模式，图2-1 中的出口防火墙工作于(1)模式；防火墙为办公区用户动态分配IP地址，需在防火墙完成开启(2) 功能；Server2为WEB服务器，服务端口为tcp 443，外网用户通过`https://100.1.1.9:8443`访问，在防火墙上需要配置(3)。（6分）

(3)备选答案：
A.`nat server policy _web protocol tcp global 100.1.1.9 8443 inside 10.2.1.2 443 unr-route`
B.`nat server policy _web protocol tcp global 10.2.1.2 8443 inside 100.1.1.9 443 unr-route`
C.`nat server policy _web protocol tcp global 100.1.1.9 443 inside 10.2.1.2 8443 unr-route`
D.`nat server policy _web protocol tcp global 10.2.1.2 inside 10.2.1.2 8443 unr-route`

**参考答案**

| 空号 | 答案 | 说明 |
| --- | --- | --- |
| （1） | **路由模式** | 防火墙接口配置了 10.1.1.254、10.2.1.254、100.1.1.2 等 IP，作为各网段网关并做 NAT，属于三层路由模式（透明模式接口不配 IP、不做路由） |
| （2） | **DHCP（DHCP 服务）** | 防火墙作为 DHCP 服务器为办公区终端自动下发地址，需开启 DHCP 功能并配置地址池 |
| （3） | **A** | 外网用户访问 `100.1.1.9:8443`，映射到内网 `10.2.1.2:443`；`global` 写公网地址+公网端口，`inside` 写私网地址+私网端口 |

**解析**

- NAT Server 的书写规则：`nat server policy <名称> protocol <协议> global <公网IP> <公网端口> inside <私网IP> <私网端口> unr-route`。**global 在前、inside 在后**，端口必须一一对应题干给出的「外网 8443 → 内网 443」。
- B 把内外网写反；C 把端口写反；D 两边地址都写成私网地址——都是典型错项。
- 三种工作模式：**透明模式**（二层接入，不改变原有 IP 规划，接口不配 IP）、**路由模式**（三层转发，接口配 IP，可做 NAT/路由）、**混合模式**（部分接口二层、部分接口三层）。本题网关在防火墙上、还要做 NAT，只能是路由模式。
- `unr-route` 表示该 NAT Server 不参与路由发布（避免把公网地址发布到内网路由表）。

**问题2**：为了使局域网中10.1.1.0/24网段的用户可以正常访问internet，需要在防火墙上完成NAT、安全策略等配置，请根据需求完善以下配置。（14分）

```text
#将对应接口加入trust或者untrust区域。
[FW] firewall zone trust
[FW-zone-trust] add interface(4)
[FW-zone-trust] quit
[FW] firewall zone untrust
[FW-zone-untrust] add interface_(5)
[FW-zone-untrust]quit
#配置安全策略，允许局域网指定网段与Internet进行报文交互。
[FW] security-policy
[FW-policy-security]rule name policy1
#将局域网作为源信任区域，将互联网作为非信任区域
[FW-policy-security-rule-policy1]source-zone(6)
[FW-policy-security-rule-policy1]destination-zone untrust
#指定局域网办公区域的用户访问互联网
[FW-policy-security-rule-policy1]source-address(7)
#指定安全策略为允许
[FW-policy-security-rule-policy1] action(8)
[FW-policy-security-rule-policy1] quit
[FW-policy-security] quit
#配置NAT地址池，配置时开启允许端口地址转换，实现公网地址复用。
[FW] nat address-group address-group1
[FW-address-group-address-group1] mode pat
[FW-address-group-address-group1]section 0(9)
#配置源NAT策略，实现局域网指定网段访问Internet时自动进行源地址转换。
[FW] nat policy
[FW-policy-nat]rule name policy_nat1
#指定具体哪些区域为信任和非信任区域
[FW-policy-nat-rule-policy_nat1] source-zone trust
[FW-policy-nat-rule-policy_nat1] destination-zone untrust
#指定局域网源IP地址
[FW-policy-nat-rule-policy_nat1] source-address 10.1.1.0 24
[FW-policy-nat-rule-policy_nat1]action source-nat address-group (10)
[FW-policy-nat-rule-policy_nat1]quit
[FW-policy-nat] quit
```

**参考答案**

| 空号 | 答案 | 说明 |
| --- | --- | --- |
| （4） | **内网接口**（连接办公区的接口，如 `GigabitEthernet1/0/1`；若服务器区也在 trust，还需 add 服务器区接口） | trust 区域承载内网网段 10.1.1.0/24、10.2.1.0/24 |
| （5） | **外网接口**（连接 Internet 的接口，如 `GigabitEthernet1/0/3`，地址 100.1.1.2/28） | untrust 区域承载公网侧 |
| （6） | **trust** | 源区域为内网信任区域 |
| （7） | **10.1.1.0 24**（也可写 `10.1.1.0 mask 255.255.255.0`） | 办公区业务网段 |
| （8） | **permit** | 允许该网段访问互联网 |
| （9） | **100.1.1.10 100.1.1.15** | 题干给出的出口地址池范围 |
| （10） | **address-group1** | 引用上面创建的 NAT 地址池名称 |

**解析**

- 完整链路是「**区域划分 → 安全策略放行 → NAT 地址池 → 源 NAT 策略**」四步，缺一步就不通：
  - 接口没加入区域：报文找不到源/目的区域，策略无法匹配；
  - 安全策略没放行：默认拒绝，报文被丢；
  - 没有 NAT：私网地址无法在公网路由；
  - NAT 策略没引用地址池：不会做地址转换。
- `mode pat` 是端口地址转换（NAPT），多个内网地址复用少量公网地址，靠源端口区分会话；`section 0 100.1.1.10 100.1.1.15` 定义地址池范围（section 编号从 0 开始）。
- 源 NAT 策略里 `source-zone trust`、`destination-zone untrust` 必须与安全策略一致，否则会出现「策略放行了但 NAT 没生效」。
- 失分点：（7）写成 10.1.1.1/24（应为网络地址）；（9）写成单个地址或漏写 section 编号；（10）写成 `address-group 1`（名称必须与定义一致）。

### 1.3 案例3 静态路由/BFD/VRRP/ACL 综合（第6、7、8、9题，20分）

> 考点：浮动静态路由主备、BFD 会话、VRRP 虚拟网关与跟踪上行接口、基于时间的 ACL、ACL 部署位置

**【说明】**（20分）

某公司网络拓扑如图3-1所示，其中出口路由器R2连接Internet，PC所在网段为10.1.1.0/24，服务IP地址为10.2.2.22/24，R2连接的Internet出口网关地址为110.125.0.1/28。各路由端口及所对应的IP地址信息如表3-1所示。假设各个路由器和主机均完成了各个接口IP地址的配置。

> `[原文为图3-1、表3-1，需对照原卷]` 拓扑与接口地址表未随原文收录；下文地址类答案依据题干命令中已出现的 10.12.0.1、10.23.0.3、10.2.2.10、110.125.0.1 推断，已逐条注明。

**问题1**：通过静态路由配置使路由器R1经过路由器R2作为主链路连接internet，R1→R3→R2→Internet作为备份链路；路由器R3经过路由器R2作为主链路连接上internet，R3→R1→R2→Internet作为备份链路。请按要求补全命令或回答问题。（6分）

```text
R1上的配置片段
[R1]ip route-static 0.0.0.0 0.0.0.0 (1)
[R1]ip route-static 0.0.0.0 0.0.0.0 (2)preference 100
R2上的配置片段：
[R2]ip route-static (3) 110.125.0.1
以下两条命令的作用是(4)
[R2]ip route-static 10.2.2.0 0.255.255.255 10.12.0.1
[R2]ip route-static 10.2.2.0 0.255.255.255 10.23.0.3 preference 100
```

**参考答案**

| 空号 | 答案 | 依据 |
| --- | --- | --- |
| （1） | **10.12.0.2**（R2 与 R1 互联的接口地址） | R2 侧路由写的是 `... 10.12.0.1`，说明 10.12.0.1 是 R1 侧地址，对端 R2 为 10.12.0.2 |
| （2） | **10.13.0.2**（R3 与 R1 互联的接口地址） | 备份路径为 R1→R3，下一跳为 R3；按 10.12/10.13/10.23 的编号规律推断，**具体以表3-1 为准** |
| （3） | **0.0.0.0 0.0.0.0** | 默认路由指向 ISP 网关 110.125.0.1，命令为 `ip route-static 0.0.0.0 0.0.0.0 110.125.0.1` |
| （4） | 配置**去往服务器网段 10.2.2.0/24 的两条静态路由，形成主备**：第一条下一跳 10.12.0.1（经 R1）为**主用**；第二条下一跳 10.23.0.3（经 R3）且 `preference 100` 为**备份**。当主路径故障时，备份路由（优先级数值更大、优先级更低）自动生效，保证服务器网段访问不中断 | 两条命令目的网段相同、下一跳不同、优先级不同 |

**解析**

- 静态路由的 `preference` 默认 60，数值**越小越优先**。同目的网段写两条、备份那条把 preference 调大（如 100），即「浮动静态路由」，实现主备切换。
- 空（1）（2）的方向要理清：R1 的默认路由下一跳是「去往 Internet 的第一跳」，主路径经 R2、备份路径经 R3，所以分别填 R2、R3 与 R1 互联的地址；题干已给出 `10.12.0.1`（R1 侧）与 `10.23.0.3`（R3 侧），可据此对称推出。
- 失分点：把（3）写成 `ip route-static 0.0.0.0 0.0.0.0 110.125.0.1`（重复 0.0.0.0）；把主备优先级写反（备份的 preference 应更大）。

**问题2**：通过在R1、R2和R3上配置双向转发检测(Bidirectional Forwarding Detection，BFD)实现链路故障快速检测和静态路由的自动切换。以R3为例配置R3和R2之间的BFD会话，请补全下列命令。（3分）

```text
[R3](5)
[R3-bfd] quit
[R3]bfd 1 bind peer-ip(6)source-ip (7)auto
[R3-bfd-session-1]commit
[R3-bfd-session-1]quit
```

**参考答案**

| 空号 | 答案 | 依据 |
| --- | --- | --- |
| （5） | **bfd** | 进入 BFD 视图（提示符变为 `[R3-bfd]`） |
| （6） | **10.23.0.2** | BFD 会话对端为 R2，R3 侧地址为 10.23.0.3（见问题1 中 R2 的下一跳 10.23.0.3），故 peer-ip 为 R2 的 10.23.0.2 |
| （7） | **10.23.0.3** | 本端（R3）与 R2 互联的接口地址 |

**解析**

- BFD 会话建立三要素：**peer-ip（对端）＋ source-ip（本端）＋ 出接口/标识符**；`auto` 表示由协议自动协商标识符（discriminator）。
- 静态 BFD 需要 `commit` 提交才生效，这是常被忽略的一步。
- BFD 的价值：把故障检测时间从路由协议的秒级降到毫秒级（默认 3×100ms 左右），配合静态路由 `track bfd-session` 实现快速切换。
- 失分点：（6）（7）写反；漏写 `commit`；把 `bfd 1 bind` 写成 `bfd-session 1`。

**问题3**：通过配置虚拟路由冗余协议(VRRP)使交换机S1双归属到R1和R3，从而保证链路发生故障时服务面的业务不中断，R1为主路由，R3为备份路由，且虚拟浮动IP地址为10.2.2.10。（6分）

```text
根据上述配置要求，服务器的网关地址应配置为(8)。
在R1上配置与R3的VRRP虚拟组相互备份：
[R1]int g0/0/1
//创建VRRP虚拟组
[R1-GigabitEthernet0/0/1]vrrp vrid 1 virtual-ip (9)
//配置优先级为120
[R1-GigabitEthernet0/0/1]vrrp vrid 1 priority 120
下面这条命令的作用是 (10)
[R1-GigabitEthernet0/0/1]vrrp vrid 1 preempt-mode timer delay 2
//跟踪GE0/0/0端口，如果GE0/0/0端口down，优先级自动减30
[R1-GigabitEthernet0/0/1]vrrp vrid 1 track interface GE0/0/0 reduced 30
请问R1为什么要跟踪GE0/0/0端口? 答：(11)
```

**参考答案**

| 空号 | 答案 | 说明 |
| --- | --- | --- |
| （8） | **10.2.2.10** | 服务器网关必须指向 VRRP 虚拟 IP，才能在主备切换时保持网关不变 |
| （9） | **10.2.2.10** | 同一备份组的虚拟 IP，Master 与 Backup 必须一致 |
| （10） | **配置 VRRP 抢占延时为 2 秒**：Backup 在收到 Master 失效通告后，等待 2s 再抢占为 Master，避免链路抖动或设备重启导致的频繁主备切换（防震荡） | `preempt-mode timer delay 2` |
| （11） | 因为 **GE0/0/0 是 R1 连接 Internet（上行）的接口**。若只跟踪 VRRP 心跳，当 R1 自身正常、但上行链路断了时，R1 仍是 Master，会把主机流量吸引过来却无法转发，造成断网。跟踪 GE0/0/0 后，该口 down 时 R1 的优先级从 120 减 30 变为 90（低于 R3 的默认 100），R3 抢占成为 Master，业务改由 R3 转发，实现真正的不中断 | `track interface ... reduced 30` |

**解析**

- VRRP 优先级默认 100，数值越大越优先；本题 R1 设 120 为 Master，R3 默认 100 为 Backup。优先级降低 30 后为 90 < 100，触发切换，这是「120 减 30」这个数字的用意。
- 只配 VRRP 不配 track 是「假冗余」：网关活着但出口断了，主备不会切换。VRRP + 上行链路跟踪 + BFD 是完整方案。
- 抢占延时（preempt-mode timer delay）与切换延时的区别：抢占延时是「Backup 等多久再抢回」，不是「Master 故障后等多久切换」（后者由 Backup 检测到 Master 超时决定，默认 3×Advertisement_Interval）。
- 失分点：（8）（9）写成 R1 的接口地址 10.2.2.x（必须是虚拟 IP）；（11）只写「提高可靠性」而不解释「上行断但网关仍在」的具体场景。

**参考答案**

| 空号 | 答案 | 说明 |
| --- | --- | --- |
| （12） | **time-range worktime**（名称可自定，如 `time-range worktime`） | 先定义时间段，原文 `ftime` 为 `from` 的 OCR 误字，完整命令 `time-range worktime from 9:00 2021/11/6 to 17:00 2021/11/6` |

某公司办公网络拓扑结构如图4-1所示，其中，在交换机SwitchA上启用DHCP为客户端分配IP地址。公司内部网络采用基于子网的VLAN划分。

**问题1**：由于公司业务特点需要，大部分工作人员无固定工位。故公司内部网络采用基于子网划分VLAN并采用DHCP策略VLAN功能为客户端分配IP地址。请根据以上描述，填写下面的空白。（5分）

DHCP策略VLAN功能可实现新加入网络主机和DHCP服务器之间DHCP报文的互通，使新加入网络主机通过DHCP服务器获得合法IP地址及网络配置等参数。
在基于子网划分VLAN的网络中，如果设备收到的是Untagged帧，设备将根据报文中的(1)，确定用户主机添加的VLAN ID。新加入网络的主机在申请到合法的IP地址前采用源IP地址(2)进行临时通信，此时，该主机无法加入任何VLAN，设备会为该报文打上接口的缺省VLAN ID(3)。由于接口的缺省VLAN ID与DHCP服务器所在VLAN ID不同，因此主机不会收到IP地址及网络配置等参数配置信息。DHCP策略VLAN功能可使设备修改收到的DHCP报文的(4)VLAN Tag，将VLAN ID设置为(5)所在VLAN ID，从而实现新加入网络主机与DHCP服务器之间DHCP报文的互通，获得合法的IP地址及网络配置参数。该主机发送的报文可以通过基于子网划分VLAN的方式加入对应的VLAN。

(1)~(5)备选答案：
A.255.255.255.255　B.内层　C.外层　D.源IP地址　E.DHCP服务器　F.1　G.0.0.0.0　H.源MAC地址　I.1023

**参考答案**

| 空号 | 答案 | 说明 |
| --- | --- | --- |
| （1） | **D（源IP地址）** | 基于子网划分 VLAN 依据报文的源 IP 地址与已配置的子网关联表匹配，决定 VLAN ID |
| （2） | **G（0.0.0.0）** | 主机未获取地址前用 0.0.0.0 作源地址发 DHCP Discover |
| （3） | **F（1）** | 接口缺省 VLAN 为 VLAN 1，报文被打上 VLAN 1 的 Tag |
| （4） | **C（外层）** | 修改的是 DHCP 报文的外层 VLAN Tag（接入层打上的那一层） |
| （5） | **E（DHCP服务器）** | 把 VLAN ID 改为 DHCP 服务器所在 VLAN，使报文能到达服务器 |

**解析**

- 基于子网划分 VLAN：设备维护「子网地址 ↔ VLAN」映射，收到 Untagged 帧时按**源 IP** 查表打 VLAN Tag；因此前提是主机已有 IP——这与「主机还没有 IP 就要拿 IP」形成死循环，DHCP 策略 VLAN 就是为破这个死循环而设计的。
- 破环原理：主机用 0.0.0.0 发 Discover，接入设备打上缺省 VLAN 1 的 Tag，报文到不了 DHCP 服务器；开启 DHCP 策略 VLAN 后，设备把该 DHCP 报文的外层 Tag 改成服务器所在 VLAN，服务器回包后主机拿到地址，后续报文就能按源 IP 正常匹配 VLAN 了。
- 「外层 Tag」针对 QinQ 场景：内层是用户 VLAN，外层是运营商/骨干 VLAN，改外层不影响用户侧语义。
- 失分点：（1）写源 MAC（那是基于 MAC 划分 VLAN）；（3）写 0 或 1023。

### 2.2 答题模板

**模板一：防火墙配置类**

```text
接口加入区域（trust/untrust/dmz）→ 安全策略（源区域、目的区域、源/目的地址、服务、动作）
→ NAT（源 NAT 地址池 / NAT Server 目的 NAT）→ 会话与路由（unr-route、回程路由）
```

**模板二：网关冗余类**

```text
VRRP 组（VRID + 虚拟 IP）→ 优先级（Master 高）→ 抢占延时（防震荡）→ 上行跟踪（track + reduced）→ BFD 加速检测
```

**模板三：ACL 类**

```text
基本 ACL（2000-2999，源地址）/ 高级 ACL（3000-3999，协议+端口+地址）
→ 时间段先定义后引用 → 部署位置（扩展 ACL 靠近源）
```

**模板四：VLAN 划分类**

```text
划分依据：端口 / MAC / 子网 / 协议 → 打 Tag 规则（access、trunk、hybrid tagged/untagged）
→ 三层网关（VLANIF）→ DHCP（全局池 / 接口池 / 中继 / 策略 VLAN）
```
