## 1.案例分析

### 1.1 案例1：链路冗余（静态路由 + BFD）与双出口 NAT

**【说明】**（20 分）

某公司网络拓扑如图 1-1 所示，从 R1 到 R2 有两条转发路径，下一跳分别为 R2 和 R3。由于 R1 和 R2 之间的物理距离较远，通过一个二层交换机 S1 作为中继。假设所有设备均已完成接口 IP 地址配置。

**拓扑要点**（据原图整理）

| 链路 | 两端地址 | 说明 |
| ---- | -------- | ---- |
| PC1—R1 | PC1 10.10.10.2/24，R1 GE0/0/1 10.10.10.1 | 用户网段 |
| R1—S1—R2 | R1 GE2/0/1 10.12.12.1/28，R2 10.12.12.2/28 | 主路径，S1 做二层中继 |
| R1—R3 | R1 GE2/0/2 10.13.13.1/28，R3 10.13.13.3/28 | 备份路径，R3 再连 R2 |
| R2—运营商 | GE0/0/1 → ISP1 网关 221.137.0.1；GE0/0/2 → ISP2 网关 210.25.0.1 | 双链路接入 |

**问题1**（2 分）

从 PC1 发出的目的地址为 ISP1 的 IP 报文默认将发到 R2 的 GE2/0/1。PC1 构造帧时，是否需要获得该接口的 MAC 地址？请说明原因。

**参考答案**

不需要。

- PC1 与 R1 的接口 10.10.10.1 在同一网段，PC1 的默认网关是 R1，因此 PC1 只需通过 ARP 解析**网关 R1 的 MAC 地址**作为帧的目的 MAC。
- IP 报文跨网段转发时，源/目的 IP 地址全程不变，但源/目的 MAC 地址**逐跳重写**。R1 收到帧后重新封装，才去解析下一跳（R2 的 GE2/0/1）的 MAC；R2 再转发给 ISP1 时又会重新封装。
- 所以 PC1 既不知道、也不需要知道 R2 接口的 MAC。

**解析**

考查「IP 不变、MAC 逐跳变化」这一转发基本模型，以及 ARP 的作用范围（仅本网段）。

- 判断口诀：只看「目的 IP 与本机是否同网段」——同网段 ARP 目的主机，不同网段 ARP 网关。
- 易错点：认为「目的地址是 ISP1，所以要解析去 ISP1 的 MAC」。实际 PC1 的路由表中 ISP1 的下一跳是默认网关 R1，帧的目的 MAC 必然是 R1。
- 常见失分点：只答「不需要」不说明原因；或答「需要，因为要封装帧」——封装帧用的是网关 MAC，不是 R2 的。

**【考点】** 数据封装与解封装；ARP 的作用范围；IP 转发中 MAC 地址的逐跳变化。

**问题2**（10 分）

假设 R2 不支持 BFD，要求 R1 上使用静态路由与 BFD 联动技术，实现当 R1 到 R2 之间的链路故障时，R1 能快速感知，并将流量切换到 R3 的链路上。补全下列命令片段完成 R1 的相关配置：

```text
[R1] bfd                                    // 启动 BFD 功能
[R1] quit
[R1-bfd] bfd R1 to R2 bind peer-ip (1) interface GigabitEthernet2/0/1 one-arm-echo
                                            // 配置 R1 和 R2 之间的 BFD 会话
[R1-R1 to R2] discriminator local 1         // BFD 本地标识 1
[R1-R1 to R2] (2)                           // 提交配置
[R1] quit
[R1] ip route-static 0.0.0.0 0.0.0.0 GigabitEthernet2/0/1 (3) track (4) R1 to R2
[R1] ip route-static 0.0.0.0 0.0.0.0 GigabitEthernet2/0/2 10.13.13.3 preference 100
                                            // 该条命令的作用 (5)
```

**参考答案**

| 空 | 答案 | 说明 |
| -- | ---- | ---- |
| (1) | `10.12.12.2` | 对端（R2）接口地址；one-arm-echo 方式下只需本端有地址 |
| (2) | `commit` | 提交 BFD 会话配置，未提交不生效 |
| (3) | `10.12.12.2` | 主缺省路由的下一跳（R2 侧地址） |
| (4) | `bfd-session` | 关联 BFD 会话名，实现路由与 BFD 联动 |
| (5) | 配置一条优先级为 100 的备份缺省路由，下一跳为 R3（10.13.13.3）；主路由（默认优先级 60）有效时不生效，主链路故障、主路由被撤销后自动切换到此路径 | 关键字：备份/浮动静态路由、preference 100、主备切换 |

**解析**

考查静态路由与 BFD 联动，以及浮动静态路由的主备逻辑。

- BFD 会话建立三要素：对端地址（peer-ip）、本地标识（discriminator local）、远端标识（discriminator remote）；本题用 `one-arm-echo`（单臂回声），由本端发送并回收 echo 报文，因此 R2 不需要支持 BFD——这正是题干「R2 不支持 BFD」的用意。
- 静态路由联动：`track bfd-session <名称>` 把路由与该会话绑定，会话 Down 时路由立即失效，无需等待接口物理状态变化。
- 浮动静态路由：两条默认路由目的相同，靠 `preference` 区分优先级，数值越小越优。主路由 60、备份 100，只有在主路由消失时备份才进入路由表。
- 常见失分点：① (1) 填 R1 自己的地址；② 漏写 `commit`；③ (4) 写成 `bfd` 或 `nqa`；④ (5) 只答「配置备份路由」，不说 preference 与切换条件。

**【考点】** BFD 会话建立与 one-arm-echo；静态路由与 BFD 联动；浮动静态路由的主备切换。

**问题3**（8 分）

路由器 R2 为接入网关，为内网用户提供双链路接入，两条链路都通过静态 IP 接入运营商，要求在 R2 上行接口配置 NAT，使内网用户可以访问 Internet。补全下列命令片段完成 R2 的相关配置：

```text
[R2] acl number 3001                        // 允许内部所有网段通过 NAT 访问外网
[R2-acl-adv-3001] rule 5 permit ip source 10.0.0.0 (6)
[R2-acl-adv-3001] quit
[R2] interface GigabitEthernet0/0/1
[R2-GigabitEthernet0/0/1] nat (7) 3001      // 在 GE0/0/1 接口配置 NAT
[R2-GigabitEthernet0/0/1] quit
..........
[R2] ip route-static 0.0.0.0 0 221.137.0.1
[R2] ip route-static 0.0.0.0 0 210.25.0.1
[R2] ip load-balance hash src-ip
上述三条命令的功能是 (8)。
```

**参考答案**

| 空 | 答案 |
| -- | ---- |
| (6) | `0.255.255.255`（通配符掩码，匹配 10.0.0.0/8 全部内网地址） |
| (7) | `outbound`（`nat outbound 3001`，Easy IP：把源地址转换为接口地址） |
| (8) | 配置两条等价的默认路由，分别指向 ISP1、ISP2 的网关；再配置基于源 IP 的负载分担，使不同内网主机的流量按源地址散列到两条链路，实现双出口负载均衡（同时互为备份） |

补充：`ip load-balance hash src-ip` 表示按源 IP 做哈希选路，保证同一主机的流量固定走同一条链路，避免同一会话来回路径不一致。

**解析**

考查 NAT 的 ACL 匹配方式、Easy IP 与双出口负载分担。

- ACL 3001 是高级 ACL，但此处只匹配源地址；`source 10.0.0.0 0.255.255.255` 的通配符是「反掩码」，0 表示必须匹配、255 表示任意。
- `nat outbound 3001` 不带地址池即为 Easy IP，直接用出接口地址做转换，适合拨号或静态地址的双出口场景；若运营商给了地址池，则写 `nat outbound 3001 address-group 1`。
- 两条默认路由优先级相同（都是 60）才形成等价路由，此时才会做负载分担；若优先级不同则变成主备。
- 常见失分点：① (6) 写成子网掩码 `255.0.0.0`；② (7) 写成 `nat server`（那是发布内部服务器）；③ (8) 只说「配置两条默认路由」，漏掉负载分担及其方式。

**【考点】** 基本/高级 ACL 与通配符；Easy IP；双出口等价路由与基于源 IP 的负载分担。

### 1.2 案例2：生产网络 VRRP、静态路由与 AGV 无线可靠性

**【说明】**（20 分）

某企业生产网络拓扑如图 2-1 所示，该网络采用静态路由配置，交换机 A 和交换机 B 配置 VRRP，车间 1 和车间 2 部署了多台 AGV，通过无线 Wi-Fi 向 AGV 设备下发指令。

**拓扑要点**（据原图整理）

| 设备 | 接口/网段 | 地址 |
| ---- | --------- | ---- |
| 交换机 C（核心） | 到 A：VLAN30 / 11.0.0.0/30；到 B：VLAN30 / 22.0.0.0/30 | 11.0.0.1、22.0.0.1 |
| 交换机 A | VLAN30 11.0.0.2/30；VLAN20 192.168.20.97/27 | 下联车间 1 |
| 交换机 B | VLAN30 22.0.0.2/30；VLAN20 192.168.20.98/27 | 下联车间 3 |
| A—B | 直接互联 | 跑 VRRP |
| 车间 3 交换机 | VLAN20，VRRP 虚拟 IP 192.168.20.126/27 | PC1 网关 |
| PC1 | VLAN20 192.168.20.100/27 | 终端 |

**问题1**（6 分）

（1）写出 PC1 的网关地址。
（2）配置交换机 A 默认路由。
（3）配置交换机 C 到 PC1 网段的静态路由。

**参考答案**

（1）PC1 的网关是 VRRP 备份组的虚拟 IP：**192.168.20.126**（PC1 192.168.20.100/27 所在子网为 192.168.20.96/27，.126 为该子网内的虚拟网关地址）。

（2）交换机 A 的默认路由指向核心交换机 C：

```text
[SwitchA] ip route-static 0.0.0.0 0.0.0.0 11.0.0.1
```

（3）交换机 C 到 PC1 所在网段的静态路由，下一跳指向 A（或 B，二者等价）：

```text
[SwitchC] ip route-static 192.168.20.96 255.255.255.224 11.0.0.2
```

采分点：网关必须是虚拟 IP（不是 A 或 B 的实地址）；默认路由的目的/掩码为 `0.0.0.0 0.0.0.0`；静态路由的目的网段要写网络地址 `192.168.20.96` 且掩码为 `/27`（255.255.255.224），不能写主机地址。

**解析**

考查「网关冗余 + 静态路由」的组合：终端只看虚拟网关，路由器只看下一跳。

- 192.168.20.100/27 的子网边界是 96（27 位掩码，块大小 32），网络地址 192.168.20.96、广播地址 192.168.20.127，可用 97~126，虚拟网关取 .126 合理。
- 交换机 C 上有两条等价路径（经 A 或经 B）时，可写其中一条，也可写两条同优先级实现负载分担；若写两条要注意避免环路。
- 常见失分点：① 网关写 192.168.20.97 或 .98（实地址，主备切换后终端断网）；② 静态路由目的地址写成 192.168.20.100（主机地址）；③ 掩码写成 255.255.255.0。

**【考点】** VRRP 虚拟网关；默认路由与静态路由的写法；子网边界计算。

**问题2**（8 分）

（1）由于生产需要，车间 3 需要扩充网络接入端口，需要增加 1 台交换机。新增加的交换机与原交换机可采用哪些连接方式？简要说明这些连接方式的区别和优缺点。

（2）简要说明交换机 A、B 互联的配置要点。

**参考答案**

（1）三种方式，按可靠性从低到高：

| 方式 | 做法 | 优点 | 缺点 |
| ---- | ---- | ---- | ---- |
| 单链路级联 | 新交换机一个普通端口连原交换机 | 成本最低、配置最简单 | 无冗余，级联口是单点故障；多级级联时带宽收敛、时延增大 |
| 双链路级联 + 链路聚合 | 两台交换机之间用两条链路做 Eth-Trunk | 带宽叠加、链路冗余、毫秒级切换 | 需两端都支持并配置聚合（手工或 LACP），占用端口 |
| 堆叠（iStack/CSS） | 用堆叠线缆把两台交换机连成一台逻辑设备 | 统一管理、跨设备链路聚合、天然无环、可靠性高 | 受堆叠线缆长度限制（一般同一机房/机柜），堆叠分裂需双主检测，升级需整体重启 |
| 双上行到上游 | 新交换机同时上联到 A、B（或 C） | 利用已有冗余架构，接入层无环（靠 STP/堆叠） | 需要上游端口与 STP 配合，收敛依赖 STP |

采分点：答出任意两种并比较优缺点即可得满分；只列名称不比较，按半分计。

（2）A、B 互联配置要点：

1. 互联端口配置为 **Trunk**，允许 VLAN20、VLAN30 通过（VRRP 报文与业务 VLAN 都要放行）。
2. 若为双链路，配置 **Eth-Trunk**（LACP 模式），并在聚合口上再配 Trunk。
3. 配置 **VRRP**：同一 vrid、相同虚拟 IP、优先级区分 Master/Backup，配置抢占及延时；必要时配置上行链路跟踪。
4. 配置 **STP/RSTP/MSTP**（若存在冗余链路）防止二层环路，A、B 的桥优先级要合理设置。
5. 静态路由/默认路由与核心保持一致（A、B 到核心的下一跳分别为 11.0.0.1、22.0.0.1），避免主备切换后路由不可达。
6. 建议配置 VRRP 与上行接口联动，并在 A、B 之间保留心跳/管理连通性。

**解析**

考查接入层扩容的工程选型与「设备互联要配什么」的完整性。

- 选型逻辑：先看距离（能否堆叠）→ 再看带宽（是否需要聚合）→ 最后看冗余（是否需要双上行）。答题时把这三点讲清，比罗列名词得分高。
- A、B 互联不只是「连线」，还要让 VRRP、VLAN、STP、路由四件事同时成立，缺一项就可能在切换后断网。
- 常见失分点：① 只答「级联」一种；② 只说堆叠「好」，不说距离限制与分裂风险；③ 互联要点漏掉 Trunk 放行 VLAN 或 VRRP 参数。

**【考点】** 交换机级联、链路聚合、堆叠的对比；接入层扩容；VRRP 与 Trunk/STP 的配合。

**问题3**（6 分）

简要说明 AGV 可靠性受 Wi-Fi 信号影响，可能有哪些因素。

**参考答案**

按「覆盖、干扰、容量、移动性、设备、安全」六类作答，答出 5 点即可：

1. **覆盖不足**：车间金属货架、AGV 车体、墙体造成遮挡与多径，出现盲区或场强低于 -65dBm 的区域，AGV 在边缘区域掉线。
2. **同频/邻频干扰**：2.4G 只有 1/6/11 三个非重叠信道，AP 密集部署时信道复用度过高；车间内的电机、变频器、微波设备也工作在 2.4G，形成噪声。
3. **容量与并发不足**：单 AP 接入终端数、并发流量超限，AGV 的实时指令排队、时延抖动增大。
4. **漫游问题**：AGV 移动速度快，跨 AP 漫游时切换时延大、丢包，或未配置 802.11r/k/v、漫游阈值不合理，出现「粘滞」在弱信号 AP。
5. **设备与供电**：AP 单点故障、PoE 供电不足、AP 离线；未做 AC 双机/AP 冗余。
6. **安全与策略**：非法 AP/终端接入、认证时延过长、未对 AGV 业务做 QoS 优先级保障，视频/办公流量挤占指令流量。

**解析**

考查无线网络规划与工业场景的可靠性分析，属「开放型简答」，按维度给分。

- 组织答案的技巧：从「信号本身（覆盖/干扰）→ 网络能力（容量/漫游）→ 设备与运维（故障/供电）→ 策略（QoS/安全）」四层展开，既全面又不重复。
- 定量支撑更加分：2.4G 非重叠信道仅 1、6、11；漫游切换建议控制在 50ms 级；AGV 指令类业务时延要求通常 <100ms。
- 常见失分点：① 只答「信号不好」；② 把有线侧的问题（如交换机环路）混入；③ 不提漫游，而 AGV 场景漫游恰恰是最关键因素之一。

**【考点】** WLAN 覆盖与干扰；2.4G/5G 信道规划；漫游与 QoS；工业无线可靠性设计。

### 1.3 案例3：OSPF 故障、DHCP 异常、VLAN 隔离与分布式存储

**【说明】**（20 分）

图 3-1 为某企业网络拓扑结构，企业有生产部和研发部两个部门，全网 IP 地址由 DHCP 服务器统一分配。

**拓扑要点**：Core-Sw 为核心，Agg-Sw 为汇聚，二者之间运行 OSPF；下挂生产部、研发部接入交换机；另有 DHCP 服务器与存储设备。

**问题1**（2 分）

在 Agg-Sw 与 Core-Sw 之间采用 OSPF 协议，网络工程师小明负责方案实施，在配置完成后 Core-SW 和 Agg-SW 之间无法学习路由。以下为网络工程师的检查结果，请分析故障原因，简要说明在 Core-Sw 交换机上如何调整配置以解决该故障。

**参考答案**

故障原因（结合检查输出，按最可能项作答）：

- 两端 OSPF **区域 ID 不一致**（一端 area 0，另一端 area 0.0.0.1），或 `network` 宣告的网段/反掩码写错，导致接口未加入 OSPF、邻居无法进入 Full 状态；
- 也可能是两端接口 **MTU 不一致**，邻居停留在 ExStart/Exchange 状态，无法交换 DD 报文，因而学不到路由。

在 Core-Sw 上的调整：

```text
[Core-Sw] ospf 1
[Core-Sw-ospf-1] area 0
[Core-Sw-ospf-1-area-0.0.0.0] network 10.1.1.0 0.0.0.255   // 按实际互联网段宣告
[Core-Sw-ospf-1-area-0.0.0.0] quit
[Core-Sw-ospf-1] quit
```

若为 MTU 问题：

```text
[Core-Sw] interface GigabitEthernet0/0/1
[Core-Sw-GigabitEthernet0/0/1] mtu 1500        // 两端保持一致
```

并用 `display ospf peer` 确认状态为 Full、`display ospf lsdb` 确认有对端 LSA。

**解析**

考查 OSPF 邻居建立的条件与排障顺序，是「给检查结果、判原因」的典型题。

- 邻居起不来的六大条件：版本/区域 ID 一致、认证一致、Hello/Dead 定时器一致、MTU 一致（影响 DD 交换）、Router ID 不冲突、网络类型一致。
- 排障顺序：`display ospf peer`（看状态）→ `display ospf interface`（看 area、network、DR/BDR）→ `display ospf error`（看错因计数）→ 抓包看 Hello 参数。
- 常见失分点：① 只答「配置错误」不落到具体参数；② 把「学不到路由」一律归因于路由策略过滤；③ 只说原因不给命令。
- `[存疑]`：原题的两张检查截图（`display ospf peer` / `display ospf interface` 输出）在公开版本中不清晰，具体是区域不一致还是 MTU 不一致无法确定；考场应以图中状态字段为准——若状态为 `ExStart/Exchange` 多为 MTU，若为 `Down/Init` 多为区域或网络宣告问题。

**【考点】** OSPF 邻居建立条件；区域与 network 宣告；MTU 对 DD 交换的影响；OSPF 排障命令。

**问题2**（4 分）

网络运行中，经常出现网络终端获取到非规划的私有地址而导致无法上网和 IP 地址冲突的情况。请分析出现这两种现象的原因，并给出解决方案。

**参考答案**

原因：

- **获取到非规划私有地址**：接入网内存在**私接路由器/非法 DHCP 服务器**（家用路由器默认开启 DHCP），终端先收到它的 Offer，拿到 192.168.x.0/24 之类地址，网关指向私接设备，因而无法正常上网。也可能是合法 DHCP 地址池耗尽或中继配置错误。
- **IP 地址冲突**：非法 DHCP 分配了与本网段重叠的地址；或用户手工配置静态地址与 DHCP 动态分配地址重复；或私接设备跨越了 VLAN 导致地址池混用。

解决方案：

1. 接入交换机开启 **DHCP Snooping**，上联口设为信任端口，非信任端口收到的 DHCP Offer/ACK 直接丢弃：

```text
[SW] dhcp snooping enable
[SW] interface GigabitEthernet0/0/24
[SW-GigabitEthernet0/0/24] dhcp snooping trusted
```

2. 配合 **IP-MAC-端口绑定** 与 **ARP 检测（DAI）**，丢弃伪造报文；开启 `dhcp snooping check arp`。
3. 关闭闲置端口、启用端口安全（限制 MAC 数量），发现私接设备即隔离。
4. 规划上把用户 VLAN 与设备管理 VLAN 分离，禁止跨 VLAN 的二层互通。
5. 定期扫描（ARP 扫描/网管告警）发现非法 DHCP Server 与地址冲突。

**解析**

考查 DHCP 安全与地址冲突的根因分析，答题要「现象—原因—措施」一一对应。

- 两个现象常同源：私接路由器既是非法 DHCP 服务器，又可能分配与规划网段冲突的地址，因此可合并回答，但必须分别点出「无法上网」和「地址冲突」的机理。
- DHCP Snooping 的关键是**信任端口**：连接合法 DHCP 服务器/中继的端口才信任，接终端的端口一律不信任。只开功能不配信任端口，会导致合法 DHCP 也被丢弃。
- 常见失分点：① 只答「开启 DHCP Snooping」不配信任端口；② 把 DHCP Snooping 与 DHCP 中继混为一谈；③ 不解释「为什么拿到地址却不能上网」（网关指向了私接设备）。

**【考点】** DHCP Snooping 与信任端口；私接路由器的危害；IP 地址冲突的成因与防护；DAI/IP-MAC 绑定。

**问题3**（6 分）

该企业在网络中使用了 vlan 技术，vlan 是将一个物理的 LAN 在逻辑上划分成多个（1）的通信技术，实现网络隔离。当同一 VLAN 内也需要网络隔离时，我们可采用交换机的（2）功能，若在配置了二层隔离后，部分主机有互通的需求，则可在需求主机的网关上配置（3）功能。

**参考答案**

| 空 | 答案 |
| -- | ---- |
| (1) | 广播域（每个 VLAN 是一个独立的广播域） |
| (2) | 端口隔离（port-isolate；也可答 MUX VLAN / 私有 VLAN） |
| (3) | 代理 ARP（ARP Proxy，华为为 `arp-proxy enable` / `arp-proxy inter-subnet`） |

**解析**

考查 VLAN 的隔离粒度与「隔离后如何按需放通」。

- 三层隔离手段对照：VLAN 隔离广播域 → 端口隔离隔离同 VLAN 内的主机 → 代理 ARP 让被隔离主机经网关互通（网关代替目的主机回应 ARP，流量走三层）。
- 代理 ARP 的原理：主机 A 请求主机 B 的 MAC，网关以自己的 MAC 应答，A 把流量发给网关，网关再转发给 B，从而在二层隔离的前提下实现三层互通。
- 常见失分点：① (1) 答「冲突域」（VLAN 划分的是广播域，交换机端口才隔离冲突域）；② (2) 答「VLAN」——同 VLAN 内无法再用 VLAN 隔离；③ (3) 答「ACL」——ACL 是放行/拒绝，不是「按需互通」的机制。

**【考点】** VLAN 与广播域；端口隔离/MUX VLAN；代理 ARP 的作用。

**问题4**（8 分）

该企业计划将原存储系统升级为分布式存储，原存储设备依旧作为新建分布式存储的一个节点。为保证数据不丢失，采用 3 副本冗余，新建的分布式存储至少应规划（4）节点（含原存储设备）。将原存储设备磁盘的 RAID 模式修改为（5）模式，加入新建的分布式存储系统，该存储系统通过（6）技术实现数据冗余。

**参考答案**

| 空 | 答案 | 说明 |
| -- | ---- | ---- |
| (4) | 3 | 3 副本要求至少 3 个故障域（节点），每份数据存 3 份；考虑可靠性通常建议 ≥3 且分布在不同机柜 |
| (5) | JBOD（直通模式 / 单盘模式，即不做 RAID） | 分布式存储由软件层做副本，磁盘应交给系统直接管理，避免 RAID 与副本双重冗余浪费容量 |
| (6) | 副本（多副本机制，副本数 = 3） | 也可答「数据副本/多副本冗余」，写入时同时写 3 个节点 |

**解析**

考查分布式存储的冗余模型与传统 RAID 的区别，是「概念 + 容量规划」题。

- 3 副本的可靠性与容量：可用容量约为总容量的 1/3；至少 3 个节点才能保证任一节点故障后仍有 2 份数据，且能继续写入（多数派）。节点数少于 3 时副本无法分布，失去意义。
- 为什么改 JBOD：RAID 5/6 已经在磁盘级做冗余，上层再做 3 副本会造成「双重保护、双重开销」；分布式存储要求磁盘以直通方式交给软件定义存储管理，由副本或纠删码保证可靠性。
- 常见失分点：① (4) 答 2（只有 2 份，不满足 3 副本）；② (5) 答 RAID5/RAID10；③ (6) 答「RAID」或「快照」——快照是时点拷贝，不是持续冗余。

**【考点】** 分布式存储的副本机制与故障域；副本数与可用容量；JBOD 与 RAID 的取舍；与传统 RAID 的对比。

### 1.4 案例4：单臂路由、DHCP 地址池与全局地址池

**【说明】**（15 分）

某公司网络拓扑如图 4-1 所示，有 A 和 B 两个部门，分别使用 C 类地址 192.168.1.0/24 和 192.168.2.0/24 两个私用地址段，其中部门 A 为固定办公区域，部门 B 为移动办公区域。两个部门均有访问互联网的需求。

**拓扑要点**

| 项目 | 部门 A | 部门 B |
| ---- | ------ | ------ |
| 网段 | 192.168.1.0/24 | 192.168.2.0/24 |
| 网关 | 192.168.1.254（R1 子接口） | 192.168.2.254（R1 子接口） |
| DNS | 192.168.1.2 | 192.168.1.2 |
| 租期 | 30 天 | 2 天 |
| VLAN | VLAN10 | VLAN20 |

**问题1**（4 分）

请将下面配置代码补充完整。

```text
system-view
[R1] interface GigabitEthernet0/0/1.1        // (1)
[R1-GigabitEthernet0/0/1.1] ip address 192.168.1.254 255.255.255.0
[R1-GigabitEthernet0/0/1.1] dot1q termination vid 10   // (2)
[R1-GigabitEthernet0/0/1.1] arp broadcast enable       // (3)
.....略.....
```

为实现网络设计目标，工作人员需要在交换机 SwitchA 上完成创建 VLAN10、VLAN20，为对应 VLAN 添加接口，设置对应的接口模式；除此以外为确保网络连通，还需要在交换机 SwitchA 上完成（4）配置。

**参考答案**

| 空 | 答案 | 说明 |
| -- | ---- | ---- |
| (1) | 创建（进入）VLAN10 的网关子接口，用于单臂路由 | 子接口号与 VLAN 对应，便于维护 |
| (2) | 配置子接口的 802.1Q 封装，收到带 VLAN10 标签的帧时剥离标签 | `dot1q termination vid 10` |
| (3) | 使能子接口的 ARP 广播功能 | 子接口默认不处理广播，不开启则无法应答 ARP，终端学不到网关 MAC |
| (4) | 将与 R1 相连的接口配置为 **Trunk**，并允许 VLAN10、VLAN20 通过（`port trunk allow-pass vlan 10 20`） | 单臂路由的前提 |

完整配置参考：

```text
[R1] interface GigabitEthernet0/0/1.1
[R1-GigabitEthernet0/0/1.1] dot1q termination vid 10
[R1-GigabitEthernet0/0/1.1] ip address 192.168.1.254 255.255.255.0
[R1-GigabitEthernet0/0/1.1] arp broadcast enable

[SwitchA] interface GigabitEthernet0/0/1
[SwitchA-GigabitEthernet0/0/1] port link-type trunk
[SwitchA-GigabitEthernet0/0/1] port trunk allow-pass vlan 10 20
```

**解析**

考查单臂路由（Router-on-a-stick）的三个必备条件：子接口、dot1q 终结、ARP 广播。

- 为什么必须 `arp broadcast enable`：子接口是逻辑接口，默认不转发广播/组播报文，终端发 ARP 请求问网关 MAC 时收不到应答，表现为「能拿到 IP、ping 不通网关」。
- 一条物理链路承载多个 VLAN，靠 Trunk 打标签；路由器子接口用 `dot1q termination vid` 识别并剥离标签，再查路由表转发。
- 常见失分点：① 只配子接口 IP，漏 `dot1q termination`；② 漏 `arp broadcast enable`；③ SwitchA 侧配成 Access；④ 忘记在 Trunk 上放行两个 VLAN。

**【考点】** 单臂路由原理；802.1Q 子接口配置；ARP 广播使能；Trunk 放行 VLAN。

**问题2**（7 分）

公司计划使用 DHCP 服务器为两个部门的主机分配 IP 地址，其主要的配置信息如表 1 所示（部门 A：192.168.1.0/24，DNS 192.168.1.2，网关 192.168.1.254，租期 30 天；部门 B：192.168.2.0/24，DNS 192.168.1.2，网关 192.168.2.254，租期 2 天）。

可以使用（10）命令输出以上配置信息，上述配置信息是对部门（11）配置。

**参考答案**

| 空 | 答案 |
| -- | ---- |
| (5) | 配置该地址池分配给客户端的默认网关地址 |
| (6) | 配置地址池的可分配网段及掩码（192.168.1.0/24） |

**问题3**（4 分）

在路由器 R1 上启用全局 DHCP 服务，请将下面配置代码补充完整。

```text
[R1] dhcp (12)
[R1] interface GigabitEthernet0/0/1
[R1-GigabitEthernet0/0/1] dhcp (13) global    // 接口工作在全局地址池模式
[R1-GigabitEthernet0/0/1] quit
[R1] interface GigabitEthernet0/0/3
[R1-GigabitEthernet0/0/3] ip address 202.112.20.1 255.255.255.252
.....略.....
```

**参考答案**

| 空 | 答案 |
| -- | ---- |
| (12) | `enable`（`dhcp enable`，全局开启 DHCP 服务） |
| (13) | `select`（`dhcp select global`，接口使用全局地址池） |

**解析**

考查华为设备 DHCP 的两级开关：全局开关 + 接口选择方式。

- 两级缺一不可：不 `dhcp enable`，接口配了 `select` 也不生效；接口不 `select`，即使有地址池也不会响应 Discover。
- 三种接口模式要区分：`dhcp select global`（全局地址池）、`dhcp select interface`（接口地址池，网关即接口地址）、`dhcp select relay`（中继到外部服务器）。
- 常见失分点：① (12) 写 `server`；② (13) 写 `global`（关键字是 select，global 是参数）；③ 把子接口场景误配成 `dhcp select interface`。

**【考点】** DHCP 全局使能与接口地址池选择；global/interface/relay 三种模式的区别。

### 2.2 答题模板

**模板一：配置填空（命令补全）**

1. 看视图提示符定位当前模式，注意 `system-view`、`quit` 的层级关系。
2. 看行尾注释，把「功能」翻译成「关键字」：配置网关 → `gateway-list`，提交 → `commit`，使能 → `enable`。
3. 数值空用题干条件校验：IP 必须落在对应网段、标签必须上下游一致、优先级必须能区分主备。
4. 检查命令是否成对：子接口要 `dot1q termination` + `arp broadcast enable`；NAT 要 ACL + `nat outbound`；DHCP 要 `dhcp enable` + `dhcp select`。

**模板二：故障分析（给输出、判原因）**

1. 抓关键字段：邻居状态（Full/ExStart/Init）、会话表源地址、路由表下一跳、ARP 表 MAC 变化。
2. 按「物理 → 二层 → 三层 → 策略/服务」逐层排除，用一句话说明每层是否正常。
3. 给出根因 + 修复命令 + 验证命令三件套。
4. 若题目给的是「检查结果」而非「故障现象」，要先判断「配置是否生效」，再判断「是否被策略过滤」。

**模板三：方案比较（连接方式、冗余方式、存储方式）**

按「可靠性 / 带宽 / 成本 / 管理复杂度 / 距离限制」五维列表比较，最后给一句选型结论。只写名词不比较，最多得一半分。

**模板四：新技术概念填空（分布式存储、无线、VPN）**

先定位概念所属层次（存储冗余 / 二层隔离 / 无线转发），再填标准术语，不要用近义词替换（如「副本」不能写成「备份」，「JBOD」不能写成「RAID0」）。

**易错点清单**

- 网关写成设备实地址，忽略 VRRP 虚拟 IP。
- 静态路由目的地址写主机地址、掩码写错（/27 与 255.255.255.224 不对应）。
- BFD 会话忘记 `commit`；浮动路由忘记 `preference`。
- NAT 的 ACL 用子网掩码而非通配符；`nat outbound` 与 `nat server` 混用。
- 单臂路由漏 `arp broadcast enable`，症状是「能拿地址、ping 不通网关」。
- DHCP 只开全局或只配 select，缺一不可；租期单位（day/hour）看错。
- VLAN 划分的是广播域，不是冲突域；同 VLAN 内隔离要用端口隔离而非再划 VLAN。
- 分布式存储 3 副本至少 3 节点，磁盘改 JBOD 而不是继续做 RAID。
