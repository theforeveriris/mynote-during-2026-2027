## 1.案例分析

### 1.1 案例1：分支机构双网段与 VRRP

**【说明】**（20 分）

某分支机构网络拓扑图如图 1-1 所示，该网络通过 BGP 接收总部网络路由，设备 1 与设备 2 作为该网络的网关设备，且运行 VRRP（虚拟网络冗余协议），与出口设备运行 OSPF。该网络规划两个网段 10.11.229.0/24 和 10.11.230.0/24，其中 10.11.229.0 网段只能访问总部网络，10.11.230.0 网段只能访问互联网。

**拓扑要点**

| 对象 | 连接 | 说明 |
| ---- | ---- | ---- |
| 设备1、设备2 | 下联设备3、设备4；上联路由器与防火墙 | 网关设备，跑 VRRP |
| 路由器 | 上联总部网络 | link c：路由器→设备2；link d：防火墙→设备1 |
| 防火墙 | 上联 Internet | 与路由器交叉连接，形成冗余 |
| link e | 设备1—设备2 | VRRP 报文通道 |
| link a、link b | 设备1→设备3、设备4 | 下行链路 |
| 网段 | 10.11.229.0/24 → 总部；10.11.230.0/24 → Internet | 分流 |

**问题1**（4 分）

分支机构有营销部、市场部、生产部、人事部四个部门，每个部门需要访问互联网主机数量如表所示，现计划对网段 10.11.230.0/24 进行子网划分，为以上四个部门规划 IP 地址，请补充表中的空（1）—（4）。

| 部门 | 主机数量 | 网络号 | 子网掩码 |
| ---- | -------- | ------ | -------- |
| 营销部 | 110 | (1) | 255.255.255.128 |
| 市场部 | 50 | 10.11.230.128 | (2) |
| 生产部 | 25 | (3) | 255.255.255.224 |
| 人事部 | 10 | 10.11.230.208 `[存疑]` | (4) |

**参考答案**

| 部门 | 主机数量 | 网络号 | 子网掩码 |
| ---- | -------- | ------ | -------- |
| 营销部 | 110 | **10.11.230.0** | 255.255.255.128（/25） |
| 市场部 | 50 | 10.11.230.128 | **255.255.255.192**（/26） |
| 生产部 | 25 | **10.11.230.192** | 255.255.255.224（/27） |
| 人事部 | 10 | **10.11.230.224**（若原表为 .208，则掩码取 /28，见存疑） | **255.255.255.240**（/28） |

即（1）`10.11.230.0`；（2）`255.255.255.192`；（3）`10.11.230.192`；（4）`255.255.255.240`。

采分点：110 台 → /25（126 个可用）；50 台 → /26（62 个）；25 台 → /27（30 个）；10 台 → /28（14 个）。按块对齐后依次为 0/25、128/26、192/27、224/28，正好用满 10.11.230.0/24。

**解析**

考查 VLSM 的「由大到小、块对齐」分配法。

- 计算：2^7−2=126（/25）、2^6−2=62（/26）、2^5−2=30（/27）、2^4−2=14（/28）。110 台若用 /26 只有 62 个，不够；50 台用 /27 只有 30 个，不够。
- 题目已给出市场部 10.11.230.128/26（128~191）与生产部掩码 /27，可反推：营销部必须占 0~127，生产部接在 192~223，人事部接在 224~239。
- `[存疑]`：原表人事部网络号在扫描件中显示为 10.11.230.208，但 208~223 与生产部 192/27 重叠，逻辑上不成立；按「无缝填满 /24」应为 10.11.230.224/28。考场以试卷原表为准，若确为 .208，则生产部应改到其他 /27 块。
- 常见失分点：① 忘记减 2；② 掩码与位数不对应（/25=128、/26=192、/27=224、/28=240）；③ 网络号写成可用地址。

**【考点】** VLSM；可用主机数；子网块对齐；掩码与位数换算。

**问题2**（8 分）

在该网络中为避免环路，应该在交换机上配置（5），生成 BGP 路由有 network 与 import 两种方式，以下描述正确的是（6）（7）（8）。

空（6）—（8）备选答案：

- A. Network 方式逐条精确匹配路由
- B. Network 方式优先级高
- C. Import 方式按协议类型引入路由
- D. Import 方式逐条精确匹配路由
- E. Network 方式按协议类型引入路由
- F. Import 方式优先级高

**参考答案**

- （5）**STP（生成树协议）**，华为设备上可具体写 STP/RSTP/MSTP。
- （6）**A**：Network 方式逐条精确匹配路由（网段与掩码都要与路由表一致才宣告）。
- （7）**B**：Network 方式产生的路由优先级更高（Origin 属性为 IGP，优于 Import 的 Incomplete）。
- （8）**C**：Import 方式按协议类型批量引入路由（如 `import-route ospf`）。

**解析**

考查 BGP 两种路由来源方式的差异，以及「防环靠 STP」这一基础判断。

- `network` 与 `import-route` 的对比：

| 维度 | network | import-route |
| ---- | ------- | ------------ |
| 匹配方式 | 逐条、精确（掩码必须一致） | 按协议批量引入 |
| Origin 属性 | IGP | Incomplete |
| 选路优先级 | 高（Origin 更优） | 低 |
| 适用 | 少量关键网段 | 大量路由迁移 |

- BGP 选路中 Origin 的比较顺序为 IGP > EGP > Incomplete，因此同等条件下 network 引入的路由更优。
- 常见失分点：① (5) 答「VRRP」或「OSPF」（都不防二层环）；② 把 A 与 D、C 与 E 对调；③ 认为 import 优先级更高。

**【考点】** STP 防环；BGP 的 network 与 import-route；Origin 属性与选路。

**问题3**（4 分）

若设备 1 处于活动状态（Master），设备 2 的状态在哪条链路出现故障时会发生改变？请说明状态改变的原因。

**参考答案**

主答：**link e（设备 1 与设备 2 之间的 VRRP 报文通道）故障**。

原因：设备 2 作为 Backup，依靠周期性接收设备 1 发来的 VRRP 通告报文来维持 Backup 状态。link e 中断后，设备 2 在 **Master_Down_Interval（约 3×通告间隔 + 抢占延时）** 内收不到通告，判定 Master 失效，随即切换为 Master 并开始响应虚拟网关的 ARP 请求。

补充（若设备 1 配置了上行链路跟踪）：link c 或 link d（设备 1 的上行链路）故障时，设备 1 的 VRRP 优先级被降低（`track … reduced`），低于设备 2 后主动让位，设备 2 抢占成为 Master。若未配置跟踪，则上行故障不会引起 VRRP 状态变化。

**解析**

考查 VRRP 状态机的切换条件，核心是「Backup 靠收不到通告来判活」。

- 三种定时器：通告间隔（默认 1s）、Master_Down_Interval（默认 3s + 抢占延时）、抢占延时。切换时间由它们共同决定。
- 判断逻辑：VRRP 只看「虚拟网关这一层」是否可用；上行链路故障属于「能当网关但出不去」，必须靠 track 才能联动，这是本题的加分点。
- 常见失分点：① 答 link a/link b（只影响下挂终端，不影响 VRRP）；② 只说「link e 断了」不解释「收不到通告 → 超时 → 变 Master」；③ 认为设备 1 故障后设备 2 立即切换（忽略 Master_Down_Interval）。
- `[存疑]`：原题未说明是否配置 track，若试卷图中标注了跟踪接口，应以标注为准。

**【考点】** VRRP 状态机与定时器；Master_Down_Interval；上行链路跟踪（track）。

**问题4**（4 分）

如果路由器与总部网络的线路中断，在保证数据安全的前提下，分支机构可以在客户端采用什么方式访问总部网络？在防火墙上采用什么方式访问总部网络？

**参考答案**

- **客户端方式**：在终端安装 **SSL VPN 客户端**（或 L2TP over IPSec、IPSec 客户端）拨号接入总部。SSL VPN 基于 HTTPS（TCP 443），穿透性好、部署简单，且可用证书/双因素认证保证安全；要求数据加密时选 SSL VPN 或 L2TP/IPSec。
- **防火墙方式**：在分支机构防火墙与总部防火墙之间建立**站点到站点 IPSec VPN 隧道**（网关到网关），由防火墙自动加解密，终端无感知；也可用 **GRE over IPSec** 或 **DSVPN** 承载动态地址场景。

要点：两者都必须「加密 + 认证」，不能答 Telnet/明文 HTTP 等不安全方式；客户端方案适合少量移动用户，网关方案适合整网互通。

**解析**

考查 VPN 的两种形态与选型依据。

- 客户端（拨号）VPN：SSL VPN、L2TP/IPSec、SSTP；特点是「按用户接入」，适合出差/应急。
- 站点 VPN：IPSec 隧道、GRE over IPSec、DSVPN；特点是「按网络接入」，适合分支机构整体互通。
- 安全性判断：SSL VPN 用 TLS 加密 + 证书；IPSec 用 ESP 加密 + IKE 认证；两者都满足「保证数据安全」。
- 常见失分点：① 只答「VPN」不区分客户端与网关；② 答「专线/MPLS」——题干是「线路中断」后的应急；③ 忽略认证与加密，答成「远程桌面直接暴露公网」。

**【考点】** SSL VPN 与 IPSec VPN；拨号 VPN 与站点 VPN 的区别；远程接入的安全要素。

### 1.2 案例2：网站攻击、接入安全与存储

**【说明】**（20 分）

如图，为某公司的网络拓扑图。

**拓扑要点**：互联网接入区防火墙（记录日志）→ 核心 → 各楼层接入（10 层为办公区，规划网段 10.10.10.0/24）；内网有网站服务器、存储系统（数据库、ERP 使用企业级 SSD）。

**问题1**（6 分）

某日，网站管理员李工报告网站访问慢，他查看了互联网接入区防火墙的日志。日志如图。根据日志显示，初步判断该公司服务器遭到（1）攻击。该种攻击最常见的攻击方式为（2）、（3）等，李工立即开启防火墙相关防护功能，几分钟后，服务器恢复了正常使用。

空（1）—（3）备选答案：

- A. ARP
- B. 蜜罐
- C. DDoS
- D. SQL 注入
- E. IP 地址欺骗
- F. ICMP flood
- G. UDP flood

**参考答案**

| 空 | 答案 |
| -- | ---- |
| (1) | **C. DDoS**（分布式拒绝服务攻击） |
| (2) | **F. ICMP flood**（ICMP 泛洪） |
| (3) | **G. UDP flood**（UDP 泛洪） |

（(2)(3) 顺序可互换；若日志中体现 TCP SYN 突增，也可答 SYN Flood，但选项中对应的是 F、G。）

**解析**

考查从防火墙日志识别 DDoS 及其常见形式。

- 判断依据：短时间内大量源地址分散的报文涌向同一目的（网站），连接数/带宽被打满，服务器「响应慢但不宕机」，符合带宽型/流量型 DDoS。
- 常见 DDoS 形式：ICMP flood、UDP flood、SYN flood、DNS/NTP 反射放大、CC（应用层）。选项里能选的是 ICMP flood 与 UDP flood。
- 排除项：ARP 攻击在二层、SQL 注入是应用层漏洞利用（日志会体现异常 SQL 而非流量洪峰）、蜜罐是诱骗手段而非攻击、IP 欺骗是手段不是攻击类型。
- 常见失分点：① 选 SQL 注入（把「访问慢」误解为数据库被拖垮）；② 只选一个 F 或 G；③ 把 DDoS 与 DoS 混答（本题是分布式）。

**【考点】** DDoS 的类型与日志特征；防火墙 DDoS 防护；常见攻击的层次划分。

**问题2**（8 分）

某日，10 层区域用户反映，上网时断时续，网络管理员李工经过现场勘查，发现该用户通过 DHCP 获取到 192.168.1.0/24 网段的地址，而公司该楼层分配的地址段为 10.10.10.0/24，经判断该网络有用户私接路由器，于是李工在楼层的接入交换机上开启交换机（4）功能后，用户上网正常；同事开启（5）功能后，可防止公司内部电脑感染病毒，伪造 MAC 地址攻击网关。

空（4）—（5）备选答案：

- A. ARP detection
- B. DHCP
- C. DHCP Relay
- D. DHCP Snooping

为加强终端接入管理，李工对接入交换机配置限制每个端口只能学习 1 个终端设备的 MAC 地址，具体如下：

```text
interface GigabitEthernet 0/0/1
 port-security (6)
 port-security-mac-num mac-number (7)
```

**参考答案**

| 空 | 答案 |
| -- | -- |
| (4) | **D. DHCP Snooping** |
| (5) | **A. ARP detection**（DAI，动态 ARP 检测） |
| (6) | `enable`（`port-security enable`，开启端口安全） |
| (7) | `1`（每个端口允许学习的最大 MAC 数） |

**解析**

考查私接路由器的处置与端口安全配置。

- DHCP Snooping 的作用：监听 DHCP 报文，建立「IP—MAC—端口—VLAN」绑定表，丢弃非信任端口上的 DHCP Offer/ACK，私接路由器无法再给终端分配地址；同时为 DAI 提供绑定表。
- ARP detection（DAI）：依据绑定表校验 ARP 报文的 IP-MAC 是否匹配，防止伪造网关 MAC 的 ARP 欺骗（「感染病毒后伪造 MAC 攻击网关」正是此场景）。
- 端口安全：`port-security enable` 开启后，用 `port-security-mac-num 1` 限制学习 1 个 MAC，超出后按模式（restrict/protect/shutdown）处理。
- 常见失分点：① (4) 选 C（DHCP Relay 是跨网段中继，不解决私接）；② (5) 选 B/D（DHCP 相关功能不做 ARP 校验）；③ 命令写成 `port-security mac-number 1`（关键字是 `port-security-mac-num`）。

**【考点】** DHCP Snooping 与信任端口；DAI/ARP detection；端口安全与 MAC 数量限制。

**问题3**（4 分）

随着业务发展，公司需对存储系统升级，当前需要存储的数据主要为数据库、ERP、图片、视频、文档等。其中，数据库、ERP 采用企业级 SSD 硬盘存储，使用 RAID 5 冗余技术。该技术通过（8）方式来实现数据冗余保护，每个 RAID 组至少应配备（9）块硬盘。

**参考答案**

| 空 | 答案 |
| -- | ---- |
| (8) | **奇偶校验**（分布式奇偶校验，把校验信息分散存放在各成员盘上） |
| (9) | **3** |

**解析**

考查 RAID 5 的冗余原理与最小盘数。

- RAID 5 = 条带化 + 分布式奇偶校验：数据和校验块交替分布在各盘，任意一块盘故障可用其余盘的校验信息重建，容量利用率为 (n−1)/n。
- 最小盘数 3：2 块盘时校验只有 1 份且无分布式意义，无法容错；3 块盘可容忍 1 块故障。
- 与 RAID 6 的对比：RAID 6 双校验，最少 4 块，容忍 2 块故障；RAID 10 先镜像再条带，至少 4 块，性能好但利用率 50%。
- 常见失分点：① (8) 答「镜像」但不说「奇偶校验」；② (9) 答 2 或 4；③ 把 RAID 5 与 RAID 6 的最小盘数记混。

**【考点】** RAID 5 的校验机制；最小盘数与容错能力；RAID 级别对比。

**问题4**（2 分）

要求存储系统在不中断业务的基础上，快速获得一个 LUN 在某个时刻的完成数据拷贝进行业务分析，可以使用（10）功能实现。

空（10）备选答案：

- A. 快照
- B. 镜像
- C. 远程复制
- D. LUN 拷贝

**参考答案**

**A. 快照**。

**解析**

考查存储复制技术的适用场景，四个选项的差别是本题的核心。

| 功能 | 特点 | 适用 |
| ---- | ---- | ---- |
| 快照 | 记录某一时刻的数据视图，秒级完成，几乎不影响业务，占用空间小（写时复制） | 备份、测试、数据分析 |
| 镜像 | 实时同步写两份，容量翻倍 | 高可用 |
| 远程复制 | 跨阵列/跨站点同步或异步复制 | 容灾 |
| LUN 拷贝 | 整盘数据完整复制，耗时长、占空间 | 迁移、离线拷贝 |

题干关键词：「不中断业务」「快速」「某个时刻」——三点都指向快照。

- 常见失分点：① 选 LUN 拷贝（是全量复制，耗时长）；② 选镜像（是持续同步，不是时点拷贝）；③ 选远程复制（面向容灾，不是本地分析）。

**【考点】** 快照原理与写时复制；镜像/远程复制/LUN 拷贝的区别；存储备份与容灾。

### 1.3 案例3：策略路由分流与 NQA 联动

**【说明】**（20 分）

图为某公司的总部和分公司网络拓扑，分公司和总部数据中心通过 ISP1 的网络和 ISP2 的网络互连，并且连接 5G 出口作为应急链路，分公司和总部数据中心交互的业务有语音、视频、FTP 和 HTTP 四种。要求通过配置策略路由实现分公司访问业务分流。配置网络质量分析（NQA）与静态路由联动实现链路冗余。其中，语音和视频以 ISP1 为主链路、ISP2 为备份，FTP 和 HTTP 以 ISP2 为主链路，ISP1 为备份。

**拓扑要点**

| 链路 | 两端地址 | 说明 |
| ---- | -------- | ---- |
| 分公司 R1—ISP1 | 30.13.0.1 — 30.13.0.3 | L1，语音/视频主用 |
| 分公司 R1—ISP2 | 40.14.0.1 — 40.14.0.4 | L2，FTP/HTTP 主用 |
| 总部 R2—ISP1 | 30.23.0.2 — 30.23.0.3 | 回程 |
| 总部 R2—ISP2 | 40.24.0.2 — 40.24.0.4 | 回程 |

**问题1**（4 分）

通过在 R1 上配置策略路由，以实现分公司访问总部的流量可根据业务类型分组到 L1 和 L2 两条链路并形成主备关系，首先完成 ACL 相关配置。

```text
# 首先定义视频业务流 ACL 2000：
[R1] acl 2000
[R1-acl-basic-2000] rule 1 permit destination (1) 0.0.255.255
[R1-acl-basic-2000] quit

# 定义 Web 业务流 ACL 3000：
[R1] acl 3000
[R1-acl-adv-3000] rule 1 permit tcp destination any destination-port (2) 0.0.255.255
[R1-acl-adv-3000] quit
```

**参考答案**

| 空 | 答案 | 说明 |
| -- | ---- | ---- |
| (1) | `2.2.0.0` | 视频服务器 2.2.2.11 所在网段，通配符 0.0.255.255 表示匹配 2.2.0.0/16 |
| (2) | `eq 80` | HTTP 使用 TCP 80 端口（写 `www` 亦可，VRP 中等价） |

说明：ACL 3000 行尾的 `0.0.255.255` 属扫描串行，标准写法为：

```text
[R1-acl-adv-3000] rule 1 permit tcp destination any destination-port eq 80
```

**解析**

考查「用 ACL 抓业务流」的基本功：基本 ACL 只能匹配源，高级 ACL 可匹配协议、源/目的、端口。

- 视频流量的识别：题目未给端口，按目的网段抓（服务器 2.2.2.11 → 2.2.0.0/16）；若按端口，视频常用 RTP/UDP 动态端口，不适合。
- HTTP 的识别：TCP 80；HTTPS 是 443；FTP 是 TCP 20/21。题干虽提 FTP，但配置只示范 Web，故只填 80。
- ACL 通配符：`0.0.255.255` 对应 /16，与 2.2.2.11 吻合；若只针对单台服务器应写 `0.0.0.0`（host）。
- 常见失分点：① (1) 写 `2.2.2.11`（基本 ACL 匹配的是网段+反掩码）；② (2) 写 `80`（缺 `eq`）；③ 把目的端口写成源端口。

**【考点】** 基本/高级 ACL 的匹配字段；通配符掩码；业务流识别方法。

**问题2**（8 分）

完成 R1 策略路由剩余相关配置。

```text
1: 创建流分类，匹配相关 ACL 定义的流
[R1] traffic classifier video
[R1-classifier-video] if-match acl 2000
[R1-classifier-video] quit
[R1] traffic classifier web
[R1-classifier-web] if-match acl 3000
[R1-classifier-web] quit

2: 创建流行为并配置重定向
[R1] traffic behavior b1
[R1-behavior-b1] redirect ip-nexthop (3)
[R1-behavior-b1] quit
[R1] traffic behavior b2
[R1-behavior-b2] redirect ip-nexthop (4)
[R1-behavior-b2] quit

3: 创建流策略，并在接口上应用

[R1-trafficpolicy-p1] classifier video behavior b1
[R1-trafficpolicy-p1] classifier web behavior (5)
[R1-trafficpolicy-p1] quit
[R1] interface GigabitEthernet0/0/0

[R1-GigabitEthernet0/0/0] quit
```

**参考答案**

| 空 | 答案 | 说明 |
| -- | ---- | ---- |
| (3) | `30.13.0.3` | 视频走 ISP1，下一跳为 ISP1 侧地址 |
| (4) | `40.14.0.4` | Web/FTP 走 ISP2，下一跳为 ISP2 侧地址 |

| (6) | `inbound` | 在分公司上行接口的入方向应用流策略 |

**解析**

考查华为策略路由「流分类—流行为—流策略—接口应用」四段式（MQC 模型）。

- 匹配关系：classifier video → behavior b1（ISP1）；classifier web → behavior b2（ISP2）。空(5) 必须与(4) 对应，否则分流反了。
- 方向选择：在 R1 的 GE0/0/0（连接分公司内网的接口）入方向应用，才能在流量进入路由器时改下一跳；若应用在出方向，需注意设备是否支持 `redirect ip-nexthop` 在出方向生效。

- 常见失分点：① (3)(4) 写反；② (5) 写 `b1`；③ (6) 写 `outbound`（多数 VRP 版本策略路由需在入方向）；④ 忘记 `traffic policy` 与 `traffic-policy` 的拼写差异（创建用空格，应用用连字符）。

**【考点】** MQC 四段式；策略路由重定向；流策略的应用方向；策略路由与路由表的关系。

**问题3**（8 分）

在总部网络，通过配置静态路由与 NQA 联动，实现 R2 对主链路的 ICMP 监控，如果发现主链路断开，自动切换到备份链路。在 R2 上完成如下配置：

```text
1: 开启 NQA，配置 ICMP 类型的 NQA 测试例，检测 R2 到 ISP1 和 ISP2 网关的链路连通状态
# ISP1 链路探测:
[R2] nqa test-instance admin isp1     // 配置名为 admin isp1 的 NQA 测试例
……其他配置省略

# ISP2 链路探测:
[R2] nqa test-instance admin isp2
[R2-nqa-admin-isp2] test-type icmp
[R2-nqa-admin-isp2] destination-address ipv4 (7)    // 配置 NQA 测试目的地址
[R2-nqa-admin-isp2] frequency 10                     // 两次测试间隔 10 秒
[R2-nqa-admin-isp2] probe-count 2                    // 探针数目 2
[R2-nqa-admin-isp2] start now

2: 配置静态路由
[R2] ip route-static 30.0.0.0 255.0.0.0 (8) track nqa admin isp1
[R2] ip route-static 40.0.0.0 255.0.0.0 40.24.0.4 track nqa admin isp2
[R2] ip route-static 0.0.0.0 0.0.0.0 40.24.0.4 preference 100 track nqa admin isp2
[R2] ip route-static 0.0.0.0 0.0.0.0 (9) preference 110 track nqa admin isp1
[R2] ip route-static 0.0.0.0 0.0.0.0 (10) preference 120
```

**参考答案**

| 空 | 答案 | 说明 |
| -- | ---- | ---- |
| (7) | `40.24.0.4` | ISP2 侧网关地址（NQA 探测目的） |
| (8) | `30.23.0.3` | 去往 30.0.0.0/8 的下一跳（ISP1 侧） |
| (9) | `30.23.0.3` | ISP1 作为默认路由备份，优先级 110 |
| (10) | `50.15.0.5` | 5G 应急链路的下一跳，优先级 120（最低） |

优先级设计：ISP2 主（100）→ ISP1 备（110）→ 5G 应急（120）；数值越大越不优先，逐级兜底。

**解析**

考查 NQA 测试例与静态路由联动，以及多级备份的优先级编排。

- NQA 五要素：测试例名（admin isp2）、测试类型（icmp）、目的地址（对端网关）、频率（frequency）、探针数（probe-count）；`start now` 立即启动。
- `track nqa admin isp2` 把路由与该测试例绑定：探测失败 → 路由被置为无效 → 下一优先级路由生效，实现秒级切换。
- 为什么要探测「网关」而不是「对端业务地址」：网关可达性直接反映链路通断，且不依赖对端业务配置。
- 常见失分点：① (7) 填 ISP2 的对端业务地址；② (8) 填 ISP1 的本端地址 30.13.0.1；③ (9)(10) 优先级写反，导致 5G 抢占主用；④ 忘记 `track nqa`，只配路由不联动。

**【考点】** NQA 测试例配置；静态路由与 NQA 联动；浮动静态路由的多级备份；链路探测目的选择。

### 1.4 案例4：系统可靠性与接口备份

**【说明】**（15 分）

某公司两个机构之间的通信示意图如下图，为保证通信的可靠性，在正常情况下，R1 通过 GE1/0/1 接口与 RB 通信，GE1/0/2 和 GE1/0/3 接口作为备份接口，当接口故障或者带宽不足时，快速切换到备份接口，由备份接口来承担业务流量或者负载分担。

**问题1**（8 分）

评价系统可靠性通常采用 MTBF（Mean Time Between Failures，平均故障间隔时间）和 MTTR（Mean Time to Repair，平均修复时间）这两个技术指标。其中 MTBF 是指系统无故障运行的平均时间，通常以（1）为单位。MTBF 越（2），可靠性也就越高。在实际的网络中，故障难以避免，保证可靠性的技术从两个方面实现，故障检测技术和链路冗余，其中常见的关键链路冗余有接口备份、（3）、（4）和双机热备份技术。

**参考答案**

| 空 | 答案 |
| -- | ---- |
| (1) | **小时**（hour；也可答「天」，工程上常用小时） |
| (2) | **大**（越长越可靠） |
| (3) | **链路聚合**（Eth-Trunk，多链路捆绑） |
| (4) | **路由冗余**（浮动静态路由/动态路由多路径；或答 VRRP 网关冗余） |

补充公式：系统可用性 A = MTBF / (MTBF + MTTR)。MTBF 越大、MTTR 越小，可用性越高。

**解析**

考查可靠性的两个基本指标与冗余技术的分类。

- MTBF 是「两次故障之间的平均无故障时间」，单位是时间（小时）；MTTR 是「平均修复时间」，越短越好。二者共同决定可用性，单看 MTBF 不全面。
- 链路冗余的常见手段：接口备份、链路聚合、路由冗余（浮动静态/多路径）、设备冗余（双机热备/堆叠/VRRP）。本题空位在「接口备份」之后、「双机热备」之前，填链路聚合与路由冗余最贴切。
- 常见失分点：① (1) 答「次」或「个」；② (2) 答「小」（把 MTTR 的性质套到 MTBF 上）；③ (3)(4) 答「STP」「防火墙」（不是链路冗余手段）。

**【考点】** MTBF/MTTR 与可用性；可靠性技术的两大方向（故障检测、链路冗余）；冗余手段分类。

**问题2**（7 分）

路由器 RA 和 RB 的 GE1/0/1 接口为主接口，GE1/0/2 和 GE1/0/3 接口分别为备份接口，其优先级分别为 30 和 20，切换延时均为 10s。

1. 配置各接口 IP 地址及 Host A 和 Host B 之间的静态路由（RB 的配置略）。

```text
(5)
[Huawei] (6) RA
[RA] interface GigabitEthernet 1/0/1
[RA-GigabitEthernet1/0/1] (7) 10.1.1.1 255.255.255.0
[RA-GigabitEthernet1/0/1] quit
……
# 在 RA 上配置去往 Host B 所在网段的静态路由。
[RA] (8) 192.168.200.0 24 10.1.1.2 ……
```

2. 在 RA 上配置主备接口

```text
[RA] interface GigabitEthernet 1/0/1
[RA-GigabitEthernet1/0/1] (9) interface GigabitEthernet 1/0/2 (10)
[RA-GigabitEthernet1/0/1] standby interface GigabitEthernet 1/0/3 20
[RA-GigabitEthernet1/0/1] standby (11) 10 10
[RA-GigabitEthernet1/0/1] quit
```

空（5）—（11）备选答案：

- A. sysname/sysn
- B. timer delay
- C. standby
- D. 30
- E. ip address
- F. system-view/sys
- G. ip route-static

**参考答案**

| 空 | 答案 | 选项 |
| -- | ---- | ---- |
| (5) | `system-view` | F |
| (6) | `sysname` | A |
| (7) | `ip address` | E |
| (8) | `ip route-static` | G |
| (9) | `standby` | C |
| (10) | `30` | D |
| (11) | `timer delay` | B |

完整片段：

```text
<Huawei> system-view
[Huawei] sysname RA
[RA] interface GigabitEthernet 1/0/1
[RA-GigabitEthernet1/0/1] ip address 10.1.1.1 255.255.255.0
[RA-GigabitEthernet1/0/1] standby interface GigabitEthernet 1/0/2 30
[RA-GigabitEthernet1/0/1] standby interface GigabitEthernet 1/0/3 20
[RA-GigabitEthernet1/0/1] standby timer delay 10 10
[RA-GigabitEthernet1/0/1] quit
[RA] ip route-static 192.168.200.0 24 10.1.1.2
```

**解析**

考查接口备份（standby）的配置语法与优先级语义，属「选项对号入座」题，先看空位上下文再排除。

- 位置判断法：(5) 在 `<Huawei>` 之后、`[Huawei]` 之前 → 必是 `system-view`；(6) 在 `[Huawei]` 下改名前 → `sysname`；(7) 在接口视图配地址 → `ip address`；(8) 在系统视图配静态路由 → `ip route-static`；(9)(10) 一行配主备关系 → `standby … 30`；(11) 配切换延时 → `timer delay`。
- 接口备份的语义：主接口上 `standby interface <备份接口> <优先级>`，优先级越大越优先；主接口故障或带宽不足时按优先级启用备份。`standby timer delay <up> <down>` 中两个 10 分别表示主备切换的延时，避免抖动。
- 与 VRRP 的区别：接口备份是「同一台路由器的多个出接口互备」，VRRP 是「多台路由器的网关互备」，不要混。
- 常见失分点：① (9) 填 `vrrp`；② (10) 填 20（优先级 20 属于 GE1/0/3）；③ 把 `timer delay` 拆成两个词填错位置；④ 忘记 (5) 的视图切换。

**【考点】** 接口备份（standby）配置；优先级与切换延时；静态路由写法；VRP 视图层级。

### 2.2 答题模板

**模板一：选择题式填空（给备选项）**

1. 先数空位数与选项数，通常一一对应，可用排除法。
2. 看空位前后的命令关键字与视图，语法位置往往直接决定答案（如 `<Huawei>` 后必是 `system-view`）。
3. 剩下的空按「业务语义」匹配：主用/备份、优先级大小、方向 inbound/outbound。
4. 填完通读整段配置，确认没有同一选项重复使用（除题目允许）。

**模板二：策略路由（MQC）题**

固定四段：`traffic classifier`（抓流，if-match acl）→ `traffic behavior`（动作，redirect ip-nexthop）→ `traffic policy`（绑定 classifier 与 behavior）→ 接口下 `traffic-policy <名> <方向>`。答题时把「哪条流 → 哪个下一跳 → 在哪个接口哪个方向」三句话说清。

**模板三：可靠性/冗余题**

1. 理论指标：MTBF、MTTR、可用性公式。
2. 冗余层次：部件（电源/主控）→ 设备（双机/堆叠）→ 链路（聚合/接口备份）→ 网关（VRRP）→ 路由（浮动静态/多路径）。
3. 配置落地：主备接口的优先级、切换延时、track 对象。
4. 结论：说明「故障时如何切换、切换多久、切换后是否回切」。

**模板四：安全事件分析题**

按「现象（日志/告警）→ 攻击类型 → 判断依据 → 处置措施（近源/边界/主机/应用）→ 验证与加固」五步写，措施要分层，不要只写「封 IP」。

**易错点清单**

- VLSM 忘记减 2；掩码与位数不对应；网络号写成可用地址。
- 把 STP 与 VRRP 的作用混淆（前者防二层环，后者做网关冗余）。
- VRRP 切换只答「主挂了」，不解释 Master_Down_Interval 与收不到通告。
- DHCP Snooping 不配信任端口；把 DHCP Relay 当作防私接手段。
- RAID 5 最小盘数答 2；把快照与镜像/LUN 拷贝混淆。
- 策略路由在错误的接口/方向应用；ACL 目的端口漏写 `eq`。
- NQA 探测目的写成自己的接口地址；浮动路由优先级写反导致应急链路抢占。
- 接口备份与 VRRP 混为一谈；`standby timer delay` 的两个参数含义说不清。
