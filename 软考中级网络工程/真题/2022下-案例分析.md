### 1.2 案例2 校园无线网认证、攻击处置与堆叠（第2题，20分）

> 考点：802.1X 与 PSK 认证、无线转发模式（隧道/本地）、2.4GHz 信道规划、上行带宽扩容、DDoS 攻击处置、堆叠优缺点、广播风暴抑制

**【说明】**（20分）

图2-1为某大学校园网络拓扑图。

> `[原文为图2-1，需对照原卷]` 拓扑与设备型号未随原文收录。

**问题1**：根据网络安全的需要，无线校园网要求全网认证接入，其中台式电脑、笔记本、手机等智能终端，从兼容性角度考虑应优先选用(1)认证方式;打印机、门禁等非智能终端应该选用(2)认证方式。图2-1中，数据业务流量通过AC与AP建立的隧道进行转发时，该转发模式为(3)（原文空号误印为(1)）；不经过AC转发，由AP经接入交换机到核心交换机传输至上层网络时，该转发模式为(4)。学校的新一代无线网络采用Wifi6技术，要求兼容仍工作在2.4G的老旧终端，Wifi6 AP的部署密度较大，为减少无线AP在2.4G模式下信道之间的干扰，信道之间至少应间隔(5)个信道。无线网络实施后，校园网络在线用户数大幅增长。原楼宇汇聚为千兆上联，高峰时期上行链路负载已经100%，经常有丢包现象，在不更换设备的前提下，可以通过(6)解决。（6分）

**参考答案**

| 空号 | 答案 | 说明 |
| --- | --- | --- |
| （1） | **802.1X** | 主流操作系统（Windows/macOS/iOS/Android）均内置 802.1X 客户端（EAPoL），兼容性最好，且能实现一人一账号的准入认证 |
| （2） | **PSK（预共享密钥）**，也可答 **MAC 地址认证** | 打印机、门禁无 802.1X 客户端，无法输入账号；用统一 PSK 或把设备 MAC 加入白名单认证 |
| （3） | **隧道转发（集中转发）** | 业务流量封装在 CAPWAP 隧道中送到 AC，再由 AC 转发 |
| （4） | **本地转发（直接转发）** | 业务流量由 AP 直接送入接入交换机，不经 AC |
| （5） | **5 个** | 2.4GHz 可用互不重叠信道为 1、6、11，相邻信道中心频率相差 5 个信道号 |
| （6） | **增加上行链路并做链路聚合（Eth-Trunk）**，同时可把 AP 改为本地转发/开启负载均衡与限速 | 不换设备时，用空闲端口聚合扩容；本地转发可把业务流量从 AC 上联卸载 |

**解析**

- 认证方式三选一的口诀：**智能终端 → 802.1X（EAPoL）；访客/手机网页 → Portal；哑终端 → PSK 或 MAC 认证**。本题强调「兼容性」，802.1X 是操作系统原生支持最广的企业级方案。
- 转发模式对比：

| 模式 | 数据路径 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 隧道转发（集中） | AP—CAPWAP 隧道—AC—上层 | 集中管控、安全策略统一、漫游方便 | AC 成为带宽瓶颈与单点 |
| 本地转发（直接） | AP—接入交换机—核心—上层 | 转发效率高、AC 压力小 | 策略需下发到 AP/接入层，管理稍复杂 |

- 2.4GHz 只有 1/6/11 三个信道完全不重叠，相邻 AP 必须错开；5GHz 信道多，可做 20/40/80MHz 规划。
- 上行 100% 的解决思路按「不换设备」展开：链路聚合扩容 > 转发模式优化（本地转发卸载 AC 上联）> 无线侧负载均衡与限速 > 分层组网把流量就近卸载。写「换万兆设备」不得分。

**问题2**：网络管理员某天在防火墙上发现了大量图2-2所示的日志，由此可判断校园网站遭受到了什么攻击？请给出至少三种应对措施。（8分）

> `[原文为图2-2，需对照原卷]` 防火墙日志截图未随原文收录，**具体攻击类型无法据图确定**；下面按校园网出口最常见的攻击类型给出判断依据与通用处置。

**参考答案**

- 判断（按日志特征对号入座）：
  - 大量来自不同源 IP、目的为同一公网 IP/端口、包长很小且速率极高 → **DDoS 攻击**（SYN Flood、UDP Flood、ICMP Flood、DNS/NTP 反射放大）；
  - 大量针对 80/443 的畸形请求、含 `union select`、`../` 等特征 → **SQL 注入 / Web 攻击**；
  - 短时间大量登录失败 → **暴力破解**；
  - 大量不同端口连接尝试 → **端口扫描**。
- 应对措施（答出三条即可）：
  1. 在出口防火墙/抗 DDoS 设备上开启**流量清洗与限速**（SYN Cookie、连接数限制、异常包丢弃），并对单源 IP 做速率限制；
  2. **封禁攻击源 IP/网段**，或联动运营商在上游清洗；
  3. 开启/升级 **IPS、AV、WAF** 特征库，对 Web 站点做应用层防护；
  4. 关闭不必要的端口与服务，管理口不对外，采用强口令与双因素认证；
  5. 完善日志审计与告警（NetFlow/日志服务器），配置阈值告警，便于快速定位；
  6. 关键业务做 CDN/云清洗或流量分担，避免单点被打满。

**解析**

- 答题结构：**先定性（什么攻击）+ 再说判断依据（日志特征）+ 再给处置（检测、清洗、封禁、加固、审计）**。只写「装防火墙」不得分。
- DDoS 与 DoS 的区别、流量型与 CC 型（应用层）的区别要能说清；校园网出口的典型现象是「上行带宽被打满、防火墙会话表耗尽」。

**问题3**：
（1）校园网采用大二层组网结构，信息中心计划对核心交换机采用堆叠技术，请简述堆叠技术的优点和缺点。
（2）网络试运行一段时间后，在二层网络中发现了大量的广播报文，影响网络的性能。网络管理员在接入层交换机做了如下配置问题得以解决：

```text
[SW] interface gigabitethernet 0/0/3
[SW-GigabitEthernet0/0/3]broadcast-suppression 80
[SW-GigabitEthernet0/0/3]quit
```

请简述以上配置的功能。（6分）

**参考答案**

（1）堆叠技术的优缺点：

| 维度 | 优点 | 缺点 |
| --- | --- | --- |
| 可靠性 | 多台设备组成一台逻辑设备，成员故障时其余成员继续转发；支持跨设备链路聚合，链路冗余无需 STP 阻塞 | 堆叠线缆/堆叠口故障可能**分裂为双主**，需配置 MAD（多主检测）防止双主 |
| 带宽与端口 | 端口密度线性扩展，跨成员链路聚合提升带宽，链路利用率高 | 堆叠带宽受堆叠线缆限制，跨框流量可能成为瓶颈 |
| 管理 | 单一管理 IP、统一配置，运维简化 | 软件版本必须一致，升级通常需要整机重启，影响面大 |
| 组网 | 简化大二层结构，减少层级 | 故障域扩大（一台变砖可能影响整组）；堆叠线缆长度受限，成员必须同机房/近距离 |

（2）`broadcast-suppression 80` 的功能：
- 在 GE0/0/3 接口上启用**广播风暴抑制**，把该接口允许通过的广播报文速率限制为接口带宽的 **80%**（阈值），超过阈值的广播报文被丢弃，从而抑制广播风暴、保护链路带宽和交换机 CPU。
- 阈值可按百分比或 pps/kbps 配置；数值越小抑制越严格，配置过低会误丢正常广播（如 ARP）。

**解析**

- 堆叠（CSS/iStack）与集群、Eth-Trunk 的关系要分清：堆叠是「设备虚拟化」，链路聚合是「链路虚拟化」，STP 是「防环」。
- 大二层 + 堆叠的常见组合：核心堆叠 + 接入双上行跨框聚合，此时不再依赖 STP 阻塞，链路全活。
- 广播风暴抑制属于「端口流量控制」，与风暴控制（storm-control）、组播抑制、未知单播抑制是同一族命令；注意抑制只是止血，根因仍是环路或 ARP 攻击，需结合 STP、端口隔离、ARP 防攻击一起治理。

### 1.3 案例3 RIP 与 OSPF 互引与路由过滤（第3题，20分）

> 考点：RIP 与 OSPF 对比、ACL + route-policy 过滤直连路由、RIPv2 自动汇总、前缀列表 ip-prefix、filter-policy export、双向引入

**【说明】**（20分）

图3-1为某公司网络拓扑片段，公司总部路由器之间运行OSPF协议生成路由，分公司路由器运行RIP协议生成路由。分公司技术部门和外包部门通过路由器R1接入，分公司网络与公司总部网络通过路由器R2互联。公司总部通过路由器 R3 接入。所有网段网络地址信息如图所示，假设各路由器已经完成各个接口IP等基本信息配置。

> `[原文为图3-1，需对照原卷]` 各网段地址、接口编号未随原文收录，因此涉及**具体网段**的空（1）（6）无法唯一确定，下面给出判断依据与写法。

**问题1**：从算法原理、适用范围、功能特性三个方面简述RIP和OSPF的区别。（4分）

**参考答案**

| 对比维度 | RIP | OSPF |
| --- | --- | --- |
| 算法原理 | 距离矢量（Bellman-Ford），基于跳数，逐跳「传邻居的路由表」，周期泛洪整张路由表 | 链路状态（Dijkstra/SPF），每台路由器泛洪 LSA 构建全网 LSDB，各自算最短路径树 |
| 适用范围 | 小型网络（RIPv1 最大 15 跳，16 跳不可达），结构简单、配置容易 | 中大型企业/园区网，支持区域划分（骨干 area 0 + 普通区域），可分层扩展 |
| 功能特性 | 收敛慢（默认 30s 更新、180s 失效），易产生环路（水平分割、毒性逆转、触发更新辅助）；RIPv2 支持 VLSM、组播 224.0.0.9、明文/MD5 认证 | 收敛快（Hello 10s、Dead 40s，触发更新），天然无环（SPF 树），支持 VLSM、等开销多路径 ECMP、区域认证、路由分层与汇总 |

**解析**

- 题目明确要求「三个方面」，答题必须分点对应，不要写成散文。每方面一句话对比即可。
- 记忆锚点：**RIP 看跳数（距离矢量、慢、简单、小网）；OSPF 看带宽开销（链路状态、快、复杂、大网）**。
- 加分点：RIP 的 15 跳限制、30s 周期更新；OSPF 的 area 0、DR/BDR、LSA 类型。

**问题2**：要求：分公司路由器R1和R2之间运行RIP协议生成路由，路由器R1将直连路由导入RIP，通过配置直连路由引入策略，过滤外包部门网段，使外包部门网段不能访问公司总部。补全下列命令，填写空(1)～(3)处的内容，完成R1过滤外包部门所要求的相关配置。（10分）

**参考答案**

| 空号 | 答案 | 说明 |
| --- | --- | --- |
| （1） | **外包部门网段地址**（如 `192.168.20.0`，以图3-1为准） | ACL 里写网段地址，通配符部分为 `0.0.0.255`（原文 OCR 只剩 `0.`） |
| （2） | **if-match** | route-policy 节点内匹配 ACL：`if-match acl 2000` |
| （3） | **direct** | 把直连路由引入 RIP：`import-route direct route-policy rip-rp` |

| （5） | 执行 `undo summary` 后不再自动汇总，R2 收到的是**明细路由**，例如 `10.1.x.0/24`、`10.2.x.0/24`（技术部门、生产部门等网段，按图3-1的地址逐条列出），不再出现 `10.0.0.0/8` | 关闭汇总后按明细通告 |

**解析**

- **ACL 与 route-policy 的配合逻辑**：ACL 中 `rule deny` 命中外包部门网段 → 该路由不被任何 route-policy 节点匹配 → 引入时被丢弃，实现「不引入」。ACL 末尾的 `rule permit` 是华为默认放行其它所有（若不写，默认规则是 permit，但显式写出更清晰）。
- 基本 ACL（2000~2999）只能匹配**源地址**；本题匹配的是「被引入路由的网段」，因此用的是基本 ACL。若需匹配掩码/协议，则用高级 ACL（3000~3999）。
- **自动汇总**是本题的「隐藏考点」：RIPv2 默认 auto-summary，跨主类边界会汇总；`undo summary` 关闭后才能传明细。这也是「路由表里出现 10.0.0.0/8」的直接原因——不是有人配了汇总，而是默认行为。
- 失分点：（3）写成 `static` 或 `ospf`；（2）写成 `match acl`（正确关键字是 `if-match`）；（4）只说「汇总」不说「RIPv2 默认自动汇总」。

**问题3**：要求：通过配置R3的OSPF路由发布策略，仅发布生产网段和办公网段，不发布财务专网，以防止公司总部其它网段或分公司对财务专网的访问。（6分）

```text
[R3] ip ip-prefix 3to2 index 10 permit 10.1.0.0 24
[R3] ip ip-prefix 3to2 index 20 permit (6) 24
#配置发布策略，引用地址前缀列表 3to2 进行过滤
[R3]ospf
[R3-ospf-1] area 0
[R3-ospf-1-area-0.0.0.0]network 192.168.23.0 0.0.0.255
[R3-ospf-1] filter-policy ip-prefix (7) export
#将RIP路由导入公司总部
[R2]ospf
[R2-ospf-1]area 0
[R2-ospf-1-area-0.0.0.0] network 192.168.23.0 0.0.0.255
[R2-ospf-1] (8) rip
#将OSPF路由导入分公司
[R2]rip
[R2-rip-1]import-route ospf 1
```

**参考答案**

| 空号 | 答案 | 说明 |
| --- | --- | --- |
| （6） | **办公网段地址**（如 `10.2.0.0`，以图3-1为准） | index 10 已放行生产网段 10.1.0.0/24，index 20 放行办公网段 |
| （7） | **3to2** | 引用上面定义的前缀列表名（原文 `ip-prefix_` 为 OCR 分隔符，应连写为 `ip-prefix 3to2`） |
| （8） | **import-route** | 在 OSPF 中引入 RIP 路由：`import-route rip 1`（原文简写 `import-route rip`） |

**解析**

- `ip ip-prefix` 与 ACL 的区别：前缀列表按「地址 + 掩码长度」精确匹配，语义更清晰、性能更好，过滤路由（尤其是 OSPF/BGP）时优先使用；ACL 适合匹配报文五元组。
- `filter-policy ... export` 在 OSPF 视图下：控制**本机向外发布**的 LSA（只影响发布，不影响本地路由表）；若写 `import`，则是控制接收。
- 财务专网未出现在前缀列表里 → 不被匹配 → 不被发布，这就是「仅发布生产与办公」的实现方式（白名单思路）。
- 失分点：（8）写成 `import-route ospf`（方向反了）；（7）写成 `3 to 2`（名称中不能有空格）。

### 1.4 案例4 STP 与 VRRP 网关冗余（第4题，15分）

> 考点：STP 选举（BPDU、桥优先级、MAC、默认值）、RSTP 快速收敛、MSTP 多实例负载分担、VRRP 主备与抢占延时

**【说明】**（15分）

某公司网络的拓扑结构示意图如图4-1所示。

> `[原文为图4-1，需对照原卷]` 拓扑与接口连接未随原文收录。

**问题1**：STP (Spanning Tree Protocol)协议用来发现和消除网络中的环路。运行该协议的设备通过相互之间发送(1)报文，在交换网络中选举根桥，通过依次比较该报文中包含的各自的(2)、MAC 地址信息，来确定根桥，优先级值越(3)，优先级越高，MAC地址亦然，交换机默认的优先级值为(4)。RSTP (Rapid SpanningTree Protocol)在STP基础上进行了改进，实现了网络拓扑(5)。但他们均是通过阻塞某个端口来实现环路消除的，存在浪费带宽的缺点，MSTP在STP和RSTP的基础上进行了改进，既可以快速收敛，又提供了数据转发的多个冗余路径，在数据转发过程中实现VLAN数据的(6)。（6分）

**参考答案**

| 空号 | 答案 | 说明 |
| --- | --- | --- |
| （1） | **配置 BPDU**（Configuration BPDU） | STP 通过交换配置 BPDU 选举根桥、计算拓扑 |
| （2） | **桥优先级**（Bridge Priority） | 桥 ID = 桥优先级（2 字节）+ MAC 地址（6 字节），先比优先级 |
| （3） | **小** | 优先级数值越小，优先级越高 |
| （4） | **32768** | 默认桥优先级 32768（步长 4096） |
| （5） | **快速收敛** | RSTP 引入边缘端口、P/A 机制、替代/备份端口，收敛到秒级 |
| （6） | **负载分担** | MSTP 把一个或多个 VLAN 映射到一个实例（Instance），不同实例走不同生成树，实现 VLAN 数据的负载分担 |

**解析**

- 根桥选举顺序：**桥优先级（小优）→ MAC 地址（小优）**；根端口选举：根路径开销（小优）→ 对端桥 ID → 对端端口 ID。默认为 32768，实际配置常写 `stp priority 4096`（必须是 4096 的倍数）。
- STP/RSTP/MSTP 的演进主线：

| 协议 | 收敛 | 冗余带宽利用 | 备注 |
| --- | --- | --- | --- |
| STP（802.1D） | 30~50s | 阻塞冗余链路，浪费带宽 | 单一生成树 |
| RSTP（802.1w） | 秒级 | 仍然阻塞 | 增加端口角色与 P/A |
| MSTP（802.1s） | 秒级 | 按实例负载分担 | 多实例，兼容 STP/RSTP |

- 失分点：（3）写「大」；（4）写 4096 或 65535；（6）写「隔离」而不是「负载分担」。

**问题2**：管理员计划为交换机配置VRRP，以提高网络的可靠性。通过调整优先级使SwitchA作为 Master 设备承担流量转发，同时为了防止震荡，设置 20s 抢占延时；SwitchB为默认优先级，作为 Backup 设备，实现网关冗余备份。接口 IP 地址配置如表4-1所示。请将下面的配置代码补充完整。（9分）


**参考答案**

| 空号 | 答案 | 依据 |
| --- | --- | --- |
| （7） | **system-view** | 由用户视图进入系统视图 |
| （8） | **sysname** | 修改设备名：`sysname SwitchA` |
| （9） | **batch** | `vlan batch 100 200` 批量创建 VLAN |
| （10） | **hybrid** | 后续 `port hybrid ...` 说明接口为 Hybrid 类型 |

| （12） | vlanif200 的接口地址（如 `10.1.2.1`） | **需对照表4-1**；按 vlanif100 为 10.1.1.1/24 的规律，vlan200 通常为 10.1.2.1/24，原文未收录该表，无法唯一确定 |

### 2.2 答题模板

**模板一：协议对比类**

```text
算法原理（距离矢量/链路状态、度量）→ 适用范围（网络规模、分层）→ 功能特性（收敛、防环、VLSM、认证、ECMP）
```

**模板二：路由过滤类**

```text
定义匹配工具（ACL 2000-2999 基本 / 3000-3999 高级 / ip-prefix）
→ 定义策略（route-policy permit node N + if-match）
→ 在协议视图引用（import-route direct/static/ospf route-policy X）
→ 明确方向（import 影响本地路由表 / export 影响对外发布）
```

**模板三：无线网类**

```text
认证（802.1X/Portal/PSK/MAC）→ 转发（隧道/本地）→ 射频（信道、功率、频宽）→ 容量（链路聚合、负载均衡、限速）
```

**模板四：冗余网关类**

```text
VRRP 组（VRID + 虚拟 IP 一致）→ 优先级（Master 120 / Backup 100）→ 抢占与延时 → 上行跟踪（track）→ 与 STP/堆叠配合
```
