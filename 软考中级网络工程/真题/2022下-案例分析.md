## 1.案例分析

### 1.1 案例1：仓储企业监控网络

**【说明】**（20 分）

某仓储企业网络拓扑结构如图 1-1 所示，该企业占地 500 亩。有五层办公楼 1 栋，大型仓库 10 栋。每栋仓库内、外部配置视频监控 16 台，共计安装视频监控 160 台，SwitchA、服务器、防火墙、管理机、RouterA 等设备部署在企业办公楼一层的数据机房中，SwitchB 部署在办公楼一层配线间作为一层的接入设备，SwitchC 和 SwitchD 分别部署在仓库 1 和仓库 2，各仓库的交换机与 SwitchA 相连。

办公楼的其他楼层的交换机以及其他仓库的交换机的网络接入方式与图 1-1 中 SwitchB、SwitchC、SwitchD 接入方式相同，不再单独在图 1-1 上标示。

**拓扑要点**

| 位置 | 设备 | 说明 |
| ---- | ---- | ---- |
| 办公楼一层数据机房 | SwitchA（核心）、服务器、防火墙、管理机、RouterA | 核心与出口 |
| 办公楼一层配线间 | SwitchB | 一层接入 |
| 仓库 1、2 | SwitchC、SwitchD | 仓库接入，各接 16 台 IPC |
| 其余仓库 | 同类交换机 | 均上联 SwitchA |
| 出口 | RouterA → ISP；RouterB → 分支机构 | 位置 A 可新增 SwitchE |

**问题1**（4 分）

该企业办公网络采用 172.16.1.0/24 地址段，部门终端数量如表 1-1 所示，请将网络地址规划补充完整。

| 部门 | 终端数量 | IP 地址范围 | 子网掩码 |
| ---- | -------- | ----------- | -------- |
| 行政部 | 28 | 172.16.1.1~172.16.1.30 | (1) |
| 市场部 | 42 | (2) | 255.255.255.192 |
| 财务部 | 20 | (3) | 255.255.255.224 |
| 业务部 | 120 | 172.16.1.129~172.16.1.254 | (4) |

**参考答案**

| 部门 | 终端数量 | IP 地址范围 | 子网掩码 |
| ---- | -------- | ----------- | -------- |
| 行政部 | 28 | 172.16.1.1~172.16.1.30 | **255.255.255.224**（/27） |
| 市场部 | 42 | **172.16.1.65~172.16.1.126** | 255.255.255.192（/26） |
| 财务部 | 20 | **172.16.1.33~172.16.1.62** | 255.255.255.224（/27） |
| 业务部 | 120 | 172.16.1.129~172.16.1.254 | **255.255.255.128**（/25） |

即（1）`255.255.255.224`；（2）`172.16.1.65~172.16.1.126`；（3）`172.16.1.33~172.16.1.62`；（4）`255.255.255.128`。

采分点：28 台与 20 台都用 /27（30 个可用）；42 台用 /26（62 个可用）；120 台用 /25（126 个可用）。按块对齐后，四块依次为 0/27、32/27、64/26、128/25，正好填满 /24。

**解析**

考查 VLSM 与「块对齐、不重叠、不浪费」三项约束。

- 计算：2^5−2=30（/27 可用），2^6−2=62（/26），2^7−2=126（/25）。28 台用 /27 足够；42 台必须 /26；120 台必须 /25。
- 对齐验证：/27 块大小 32，故 0、32、64…；市场部 42 台若放在 32/27 只有 30 个可用，不够，只能放 64/26（64~127）；财务部回到 32/27（33~62）；业务部 128/25（129~254）。
- 常见失分点：① 只按「终端数 ≤ 2^h」计算，忘记减 2，导致 42 台误用 /27；② 市场部范围写成 172.16.1.64~172.16.1.127（含网络/广播地址）；③ 掩码与 /位数 不对应（/25=128、/26=192、/27=224）。

**【考点】** VLSM；可用主机数；地址块对齐与掩码换算。

**问题2**（6 分）

仓库到办公楼的布线系统属于什么子系统？应采用什么传输介质？该线缆与交换机连接需要用到哪些部件。

**参考答案**

- 子系统：**建筑群子系统**（园区子系统，Campus Subsystem）。仓库与办公楼是不同建筑物，跨楼宇的布线属于建筑群子系统；若只讨论办公楼内的垂直链路，才是干线子系统。
- 传输介质：**室外单模光缆**（长距离、抗电磁干扰、防雷）。距离较近（<500m）时也可用室外多模光缆；监控汇聚场景推荐单模，便于后期扩容到千兆/万兆。
- 连接部件：
  - 光配线架（ODF）、光纤终端盒/熔接盒；
  - 光模块（SFP/GBIC）、光纤跳线（尾纤）、耦合器/法兰盘；
  - 光缆接续盒、尾纤熔接；
  - 室外敷设还需管道/桥架、防雷接地与光缆标识；
  - 若为双绞线方案，则需要信息模块、配线架、跳线、理线架。

**解析**

考查综合布线子系统划分与传输介质选型，注意「跨建筑物」是判断建筑群子系统的关键词。

- 子系统边界：工作区—水平—管理—干线—设备间—建筑群—进线间。仓库到办公楼跨楼，属于建筑群；办公楼内一层到五层属于干线。
- 介质选型理由要写出来：单模光纤衰减小、带宽高、传输距离远（可达数公里），且不受电磁干扰、不导电（避免雷击与地电位差），适合 500 亩园区。
- 常见失分点：① 答「干线子系统」——未区分「楼内垂直」与「楼间」；② 只答「光纤」不区分单模/多模；③ 连接部件只写「光模块」，漏 ODF、跳线、终端盒。

**【考点】** 综合布线子系统；单模/多模光纤的选用；光纤链路连接部件。

**问题3**（4 分）

若接入的 IPC 采用 1080P 的图像传输质量传输数据，SwitchC、SwitchA 选用百兆交换机是否满足带宽要求，请说明理由。

**参考答案**

结论：**SwitchC 基本满足但余量不足，SwitchA 不满足**，整体方案不应选百兆。

计算与理由：

- 1080P（1920×1080）H.264 编码的单路码流一般按 **2~4Mbps** 估算，取 4Mbps。
- SwitchC 下挂仓库 1 的 **16 台** IPC：16 × 4Mbps = **64Mbps**，小于 100Mbps，理论上可跑，但监控是持续码流、存在突发，且还要与 SwitchA 上联共享带宽，余量仅 36%，实际易拥塞、丢包、花屏。
- SwitchA 汇聚 **10 栋仓库共 160 台** IPC：160 × 4Mbps = **640Mbps**，百兆上联（甚至单千兆）都远远不够，必须使用**千兆上行**，核心侧建议万兆或链路聚合。
- 若采用 H.265 或按 2Mbps 估算，SwitchC 为 32Mbps、SwitchA 为 320Mbps，结论不变：SwitchA 必须千兆以上。

**解析**

考查视频监控的带宽估算方法，关键是把「单路码流 × 路数」算清楚，并区分接入层与汇聚层。

- 估算口径要在答案中写明（例如「按 1080P H.264 每路 4Mbps」），否则数字无法复核；不同教材取 2/4/8Mbps，只要口径一致、结论合理即可得分。
- 分层判断：接入交换机只看本交换机下挂的摄像头数；核心/汇聚要看全量收敛比。监控流是「多路汇聚、持续上行」，收敛比接近 1:1，不能用办公网的 1:20 超配思路。
- 常见失分点：① 只算 SwitchC 不算 SwitchA，得出「满足」的片面结论；② 不写单路码流假设；③ 混淆上下行带宽（监控主要是上行）。

**【考点】** 视频监控带宽估算；接入层与汇聚层的收敛比；百兆/千兆选型依据。

**问题4**（6 分）

（1）在位置 A 增加一台交换机 SwitchE 做接入层到核心层的链路冗余，请以 SwitchC 为例简述接入层与核心层的配置变化。
（2）简要说明在 RouterA 与 RouterB 之间建立 IPSec VPN 隧道的配置要点。

**参考答案**

（1）以 SwitchC 为例：

- 接入层（SwitchC）：新增一条上联链路接到 SwitchE，两条上联都配置为 **Trunk** 并放行监控 VLAN；两条上联做**链路聚合（Eth-Trunk）**或保留双链路交由 **STP/MSTP** 阻塞一条；接摄像头端口设为 STP 边缘端口（`stp edged-port enable`），避免终端接入引起拓扑震荡。
- 核心层（SwitchA、SwitchE）：SwitchA 与 SwitchE 之间互联（或堆叠），对下联 SwitchC 的两个端口做**链路聚合**，并在两台核心上保持 VLAN、网关（VLANIF）一致；若采用 VRRP，则监控网关使用虚拟 IP。
- 效果：任一上联或任一核心故障，监控流量自动切换，接入层无环。

（2）IPSec VPN 配置要点（RouterA—RouterB，站点到站点）：

1. **定义感兴趣流**：ACL 匹配两端私网网段互访流量（源/目的网段互为镜像）。
2. **IKE 阶段 1**：配置 IKE 提议（加密算法 AES、认证算法 SHA2、DH 组）、IKE 对等体（对端公网地址、预共享密钥）、协商模式（主模式/野蛮模式）。
3. **IPSec 阶段 2**：配置 IPSec 提议（ESP、加密/认证算法、隧道模式）、IPSec 策略（引用 ACL 与提议）、绑定到接口。
4. **应用与路由**：在公网接口应用 IPSec 策略；配置到对端私网的路由（静态路由或动态路由）。
5. **NAT 穿越**：若出口同时做 NAT，需配置 NAT 豁免（ACL 拒绝感兴趣流做 NAT）或启用 NAT-T。
6. **可选**：DPD 保活检测、QoS、抗重放、密钥生命周期。

**解析**

考查接入层冗余的落地配置与 IPSec VPN 的五个配置块，属「配置要点」题，按模块写即可。

- 冗余的两种思路要分清：链路聚合是「两条当一条用」，不产生环路、带宽叠加；STP 是「留一条、堵一条」，有冗余但浪费带宽。二者可组合（聚合口再参与 STP）。
- IPSec 的记忆框架：**ACL（保护什么）→ IKE（怎么协商）→ IPSec 提议/策略（怎么加密）→ 应用到接口（在哪生效）→ 路由与 NAT 豁免（怎么走通）**。
- 常见失分点：① 只说「加一条线、配 STP」，不提 Trunk/聚合与网关一致性；② IPSec 只写「配预共享密钥」，漏 ACL 与提议；③ 忘记 NAT 豁免，导致 VPN 流量被 NAT 后协商失败。

**【考点】** 接入层双上行与链路聚合/STP；IPSec VPN 的 IKE/IPSec 两阶段；NAT 穿越。

### 1.2 案例2：校园无线网与安全运维

**【说明】**（20 分）

图 2-1 为某大学校园网络拓扑图。

**拓扑要点**：出口防火墙（含日志）→ 核心交换机（大二层组网，核心堆叠）→ 楼宇汇聚（千兆上联）→ 接入交换机 + AP；AC 旁挂或直连核心；校园网站服务器位于内网，对外发布。

**问题1**（6 分）

根据网络安全的需要，无线校园网要求全网认证接入，其中台式电脑、笔记本、手机等智能终端，从兼容性角度考虑应优先选用（1）认证方式；打印机、门禁等非智能终端应该选用（2）认证方式。

图 2-1 中，数据业务流量通过 AC 与 AP 建立的隧道进行转发时，该转发模式为（3）；不经过 AC 转发，由 AP 经接入交换机到核心交换机传输至上层网络时，该转发模式为（4）。

学校的新一代无线网络采用 WiFi6 技术，要求兼容仍工作在 2.4G 的老旧终端，WiFi6 AP 的部署密度较大，为减少无线 AP 在 2.4G 模式下信道之间的干扰，信道之间至少应间隔（5）个信道。

无线网络实施后，校园网络在线用户数大幅增长。原楼宇汇聚为千兆上联，高峰时期上行链路负载已经 100%，经常有丢包现象，在不更换设备的前提下，可以通过（6）解决。

**参考答案**

| 空 | 答案 | 说明 |
| -- | ---- | ---- |
| (1) | 802.1X 认证（可答 802.1X/EAP） | 智能终端有 supplicant，兼容性与安全性最好 |
| (2) | MAC 地址认证 | 打印机、门禁无客户端软件，只能基于 MAC 免认证 |
| (3) | 隧道转发（集中转发，CAPWAP 隧道） | 业务数据封装在 AC—AP 隧道中 |
| (4) | 直接转发（本地转发） | 数据从 AP 本地进入有线网，不经 AC |
| (5) | 5 | 2.4G 非重叠信道为 1、6、11，相邻使用需间隔 5 个信道 |
| (6) | 链路聚合（Eth-Trunk，多链路捆绑扩容） | 不换设备即可叠加带宽、提供冗余 |

**解析**

考查 WLAN 的认证方式、转发模式与 2.4G 信道规划，均为高频记忆点。

- 认证选型逻辑：有客户端能力 → 802.1X（最安全，支持双向认证与动态密钥）；无客户端能力 → MAC 认证（弱，需配合 ACL 与准入）；访客 → Portal。题目强调「兼容性」，故智能终端选 802.1X。
- 转发模式对比：隧道转发（集中）—管理方便、安全策略统一，但 AC 成为流量瓶颈；直接转发（本地）—转发效率高、AC 压力小，但策略需下沉到接入层。WiFi6 高带宽场景多采用本地转发。
- 信道：2.4G 信道相互重叠，只有 1/6/11 互不重叠；「间隔 5 个信道」是固定结论，不要答「间隔 1 个」或「间隔 3 个」。
- 千兆上联打满的解决办法：链路聚合（多千兆捆绑）、双上行、启用有线侧 QoS 限速、关闭低速率、负载分担到其他汇聚；「更换万兆」不符合「不更换设备」的前提。
- 常见失分点：① (1) 答 Portal（Portal 适合访客，非兼容性最优）；② (3)(4) 写「集中转发/分布转发」但不落到「是否经过 AC」；③ (6) 答「升级带宽」违反题设。

**【考点】** 802.1X 与 MAC 认证；CAPWAP 隧道转发与本地转发；2.4G 信道规划；链路聚合扩容。

**问题2**（8 分）

网络管理员某天在防火墙上发现了大量图 2-2 所示的日志，由此可判断校园网站遭受到了什么攻击？请给出至少三种应对措施。

**参考答案**

攻击类型：**DDoS 分布式拒绝服务攻击**（日志表现为大量源地址分散的请求在短时间内涌向网站，连接数/流量突增，服务器响应变慢）。

应对措施（答出三种即可）：

1. 在防火墙上启用 **DDoS 防护/流量清洗**，对 SYN Flood、UDP Flood、ICMP Flood 设置阈值与源限速。
2. 配置**连接数限制**与**新建连接速率限制**（每源 IP、每目的 IP），并启用 SYN Cookie 代理。
3. 配置**黑名单/异常源封禁**，对高频源地址临时阻断；结合运营商或云清洗服务做近源清洗。
4. 关闭服务器不必要的端口与服务，缩小攻击面；对 Web 应用前置 WAF，过滤恶意请求。
5. 优化服务器与链路：负载均衡、连接队列调优、带宽扩容。
6. 建立监控告警与应急预案（流量基线、阈值告警、切换备用线路）。

**解析**

考查 DDoS 的识别与分层处置，注意「大量日志」不一定等于 DDoS，也可能是扫描或 CC 攻击，答题时点明判断依据更稳。

- 判断依据：源地址分散、目标集中、请求速率异常、业务响应变慢——符合分布式拒绝服务特征；若源地址集中则为单点攻击，若请求内容异常（如大量登录失败）则偏向暴力破解/CC。
- 处置层次：近源清洗（运营商/云）→ 边界防护（防火墙阈值、限速、黑名单）→ 应用层（WAF、验证码）→ 系统层（连接数、超时）。
- 常见失分点：① 只答「DDoS」不给措施；② 措施只写「封 IP」（攻击源分散时无效）；③ 把 DDoS 与 ARP 欺骗、SQL 注入混为一谈。

**【考点】** DDoS 类型与特征（SYN/UDP/ICMP Flood）；防火墙 DDoS 防护；流量清洗与限速。

**问题3**（6 分）

（1）校园网采用大二层组网结构，信息中心计划对核心交换机采用堆叠技术，请简述堆叠技术的优点和缺点。

（2）网络试运行一段时间后，在二层网络中发现了大量的广播报文，影响网络的性能。网络管理员在接入层交换机做了如下配置问题得以解决：

```text
[SW] interface gigabitethernet 0/0/3
[SW-GigabitEthernet0/0/3] broadcast-suppression 80
[SW-GigabitEthernet0/0/3] quit
```

请简述以上配置的功能。

**参考答案**

（1）堆叠（iStack/CSS）的优点：

- 多台物理交换机虚拟成**一台逻辑设备**，管理、配置、升级统一，运维简单；
- 支持**跨设备链路聚合**，接入交换机可双归到堆叠组，带宽叠加且无环；
- 简化二层设计，**不再依赖 STP 收敛**，故障切换更快；
- 端口密度与背板带宽可平滑扩展，保护投资；
- 具备主备主控，单台故障时业务可由另一台接管。

缺点：

- 受**堆叠线缆长度**限制，一般只能同机房/同机柜部署，无法跨楼宇；
- 堆叠**分裂（双主）**风险，需配置双主检测（MAD），否则可能引发全网二层故障；
- 软件升级通常需要**整体重启**，影响面大；
- 故障定位与排障比单机复杂，堆叠口/堆叠线缆本身是新的故障点；
- 主备切换期间可能出现短暂丢包。

（2）`broadcast-suppression 80` 的功能：

- 在 GE0/0/3 接口上启用**广播风暴抑制**，把该接口的广播报文速率限制为端口的 **80%**（华为 VRP 中该值为百分比，也可用 `pps`/`kbps` 指定单位）。
- 超过阈值的广播报文被**丢弃**，从而抑制广播风暴、保护 CPU 与链路带宽；阈值内的正常广播（如 ARP）不受影响。

**解析**

考查堆叠的工程权衡与广播抑制命令的含义，属「技术评价 + 命令解释」题。

- 堆叠的价值在于「把冗余从 STP 的阻塞模式变成聚合模式」，这是与「双机 VRRP」最本质的区别：堆叠是设备虚拟化（二层合一），VRRP 是网关冗余（三层主备）。
- 广播抑制的取值要看清单位：`broadcast-suppression 80` 是百分比，`broadcast-suppression 80 pps` 是包速率。答「限制为 80pps」会失分。
- 常见失分点：① 只说优点不说缺点；② 缺点漏掉「距离限制」与「分裂风险」；③ 把广播抑制答成「关闭广播」或「划分 VLAN」。

**【考点】** 堆叠/虚拟化的优缺点；MAD 双主检测；广播风暴抑制命令与单位。

### 1.3 案例3：RIP 与 OSPF 混合组网

**【说明】**（20 分）

图 3-1 为某公司网络拓扑片段，公司总部路由器之间运行 OSPF 协议生成路由，分公司路由器运行 RIP 协议生成路由。分公司技术部门和外包部门通过路由器 R1 接入，分公司网络与公司总部网络通过路由器 R2 互联。公司总部通过路由器 R3 接入。所有网段网络地址信息如图所示，假设各路由器已经完成各个接口 IP 等基本信息配置。

**拓扑要点**

| 区域 | 网段 | 说明 |
| ---- | ---- | ---- |
| 分公司技术部门 | 10.2.0.0/29、10.2.0.8/29、10.2.0.16/29、10.2.0.32/29 | 挂 R1 |
| 分公司外包部门 | 10.3.0.0/24 | 挂 R1，需被过滤 |
| 分公司—总部 | 192.168.12.0/24（R1 .1、R2 .2） | 跑 RIP |
| 总部 Area 0 | 192.168.23.0/24（R2—R3） | 跑 OSPF |
| 总部网段 | 生产 10.5.0.0/24、办公 10.1.0.0/24、财务 10.9.0.0/24 | 挂 R3 |

**问题1**（4 分）

从算法原理、适用范围、功能特性三个方面简述 RIP 和 OSPF 的区别。

**参考答案**

| 维度 | RIP | OSPF |
| ---- | --- | ---- |
| 算法原理 | 距离矢量（Bellman-Ford），只与邻居交换整张路由表，靠「传闻」收敛 | 链路状态（Dijkstra/SPF），泛洪 LSA 建立全网拓扑数据库，各自算最短路径树 |
| 适用范围 | 小型网络（跳数 ≤15），结构简单、配置容易 | 中大型网络，支持区域划分（骨干 area 0 + 普通区域），可扩展到数千台路由器 |
| 度量 | 跳数（hop count），不看带宽 | 开销（cost = 参考带宽/接口带宽），可反映链路质量 |
| 收敛速度 | 慢（周期更新 30s，失效 180s，需水平分割/毒性逆转防环） | 快（触发更新、Hello 10s/Dead 40s，SPF 快速重算） |
| 环路防护 | 跳数上限、水平分割、毒性逆转、抑制计时器 | 区域划分 + SPF 树天然无环 |
| 其他特性 | RIPv2 支持 VLSM、组播 224.0.0.9、简单认证 | 支持 VLSM、组播 224.0.0.5/6、区域认证、LSA 分类型、DR/BDR 选举 |

**解析**

考查两种典型 IGP 的体系差异，按「原理—范围—特性」三段作答即可。

- 一句话对比：RIP 是「听邻居说」，OSPF 是「自己画地图」。前者简单但收敛慢、易环；后者复杂但收敛快、可分层。
- 度量差异是常考点：RIP 用跳数，导致「高速链路不如低跳数链路」的次优路径；OSPF 用 cost，可体现带宽。
- 常见失分点：① 只说「RIP 慢、OSPF 快」；② 把 OSPF 说成距离矢量；③ 漏掉「区域」这一 OSPF 的核心扩展手段。

**【考点】** 距离矢量与链路状态；RIP/OSPF 的度量、收敛与防环；区域划分。

**问题2**（10 分）

要求：分公司路由器 R1 和 R2 之间运行 RIP 协议生成路由，路由器 R1 将直连路由导入 RIP，通过配置直连路由引入策略，过滤外包部门网段，使外包部门网段不能访问公司总部。补全下列命令，填写空（1）~（3）处的内容。

```text
[R1] rip
[R1-rip-1] version 2
```

在 R2 上导入 R1 的直连路由条目后，RIP 路由条目如下所示，请简要说明 10.0.0.0/8 这条路由条目是如何产生的，将解答填入答题纸的空（4）处。

在 R2 执行 `undo summary` 命令后，请写出当前的 RIP 路由条目，将解答填入答题纸的空（5）处。

**参考答案**

| 空 | 答案 |
| -- | ---- |
| (1) | `10.3.0.0`（配合通配符 0.0.0.255，匹配外包部门网段；题干中的 `0` 为通配符简写） |

（5）执行 `undo summary` 后的路由条目（明细路由）：

```text

10.2.0.0/29             RIP     100   1      D       192.168.12.1    GigabitEthernet1/0/1
```

考查「引入 + 过滤 + 汇总」三件事，尤其是 auto-summary 对引入路由的影响。

要求：通过配置 R3 的 OSPF 路由发布策略，仅发布生产网段和办公网段，不发布财务专网，以防止公司总部其他网段或分公司对财务专网的访问。

考查 prefix-list 与 filter-policy 的配合，以及 OSPF 与 RIP 的双向引入。

### 1.4 案例4：STP 原理与 VRRP 配置

**【说明】**（15 分）

某公司网络的拓扑结构示意图如图 4-1 所示。

**拓扑要点**：SwitchA、SwitchB 为核心交换机，通过 VLANIF 提供网关；SwitchC、SwitchD 为接入交换机，双上行；VLAN100 为业务 VLAN（网关 10.1.1.0/24，虚拟 IP 10.1.1.111），VLAN200/300 为互联 VLAN。

**问题1**（6 分）

STP（Spanning Tree Protocol）协议用来发现和消除网络中的环路。运行该协议的设备通过相互之间发送（1）报文，在交换网络中选举根桥，通过依次比较该报文中包含的各自的（2）、MAC 地址信息，来确定根桥，优先级值越（3），优先级越高，MAC 地址亦然，交换机默认的优先级值为（4）。RSTP 在 STP 基础上进行了改进，实现了网络拓扑（5）。但他们均是通过阻塞某个端口来实现环路消除的，存在浪费带宽的缺点，MSTP 在 STP 和 RSTP 的基础上进行了改进，既可以快速收敛，又提供了数据转发的多个冗余路径，在数据转发过程中实现 VLAN 数据的（6）。

**参考答案**

| 空 | 答案 | 说明 |
| -- | ---- | ---- |
| (1) | BPDU（配置 BPDU / 网桥协议数据单元） | STP 通过 BPDU 交换桥 ID、路径开销等信息 |
| (2) | 桥 ID（Bridge ID，含优先级） | 先比优先级，再比 MAC |
| (3) | 小 | 优先级数值越小越优先 |
| (4) | 32768 | 默认优先级，取值 0~61440，步长 4096 |
| (5) | 快速收敛 | RSTP 引入边缘端口、P/A 机制，收敛到秒级 |
| (6) | 负载分担（负载均衡） | MSTP 多实例，不同 VLAN 走不同实例 |

**解析**

考查 STP/RSTP/MSTP 的演进主线，属于必背知识点。

- 根桥选举：先比桥优先级（小者优），相同再比 MAC（小者优）。桥 ID = 优先级（2 字节）+ MAC（6 字节）。
- 端口选举顺序：根路径开销 → 发送者桥 ID → 发送者端口 ID → 接收端口 ID。
- 三种协议的差异一句话：STP 慢（30~50s）、RSTP 快（P/A、边缘端口）、MSTP 既快又能按 VLAN 负载分担。
- 常见失分点：① (1) 写「Hello 报文」（那是 OSPF）；② (3) 写「大」；③ (5) 写「无环」；④ (6) 写「隔离」（MSTP 的作用是负载分担，不是隔离）。

**【考点】** STP 报文与根桥选举；优先级取值；RSTP 快速收敛机制；MSTP 多实例负载分担。

### 2.2 答题模板

**模板一：带宽估算题**

1. 写明单路码流假设（1080P H.264 取 2~4Mbps，H.265 减半）。
2. 接入层：路数 × 单路码流；汇聚/核心：全量路数 × 单路码流（监控收敛比接近 1:1）。
3. 与链路速率比较，给出「满足/不满足 + 余量」的结论，并给选型建议（千兆上行/链路聚合/万兆）。
4. 不要只给结论，计算式必须写出来。

**模板二：WLAN 方案题**

按「认证（802.1X/MAC/Portal）→ 转发（隧道/本地）→ 射频（信道、功率、频段）→ 容量（AP 数、并发、上行带宽）→ 漫游（802.11r/k/v、阈值）→ 安全（WIDS/WIPS、准入）」六段作答。

**模板三：路由过滤与引入题**

1. 先定方向：`import`（收进来）还是 `export`（发出去）。
2. 再定工具：ACL（反掩码）适合匹配地址段，prefix-list（地址+长度）适合精确匹配路由。
3. 最后定动作：route-policy 的 `if-match` 只选中，`apply` 才改属性；未匹配走下一节点，全部未匹配默认拒绝。
4. 涉及 RIP 必查 `version 2`、`undo summary`；涉及 OSPF 必查 `area`、`network`、`filter-policy`。

**模板四：协议原理对比题**

固定四维：算法（距离矢量/链路状态）、度量、收敛与防环、扩展性（区域/认证/VLSM）。每维一句话，配一张对比表最稳。

**易错点清单**

- VLSM 忘记减 2；地址范围含网络/广播地址；掩码与位数不对应。
- 跨建筑物答成干线子系统；光纤不区分单模/多模。
- 2.4G 非重叠信道只有 1/6/11，间隔 5 个信道。
- `broadcast-suppression 80` 是百分比，不是 80pps。
- RIP 引入直连写 `import-route static`；忘记 `undo summary` 导致明细变汇总。
- prefix-list 与 ACL 混用；`filter-policy` 的 import/export 方向写反。
- VRRP 主备虚拟 IP 不一致、vrid 不一致；抢占延时单位写成 `20s`。
- Hybrid 端口同一 VLAN 同时 tagged 与 untagged，属于配置错误。
