### 1.1 案例1 双校区 IPv6 地址规划（第1题，20分）

> 考点：IPv6 前缀长度与子网位数、/64 子网划分、双栈部署

**【说明】**

试题一（20分）
阅读以下说明，回答问题。
[说明]某高校网络拓扑如下图所示，两校区核心（CORE-1，CORE-2），出口防火墙（NGFW-1,NGFW-2）通过校区间光缆互联，配置OSPF实现全校路由收效，校区相距40km。两校区默认由本地出口进行互联网访问。

> `[原文为图，需对照原卷]` 双校区拓扑、OSPF 区域划分、链路带宽等细节未随原文收录。

**问题1**：新校区规划以双栈方式部署IPv6网络，分配的IPv6地址为:240C:DB8:1024::/49。请将IPv6网络地址规划表补充完整。（3分）

> `[原文为表，需对照原卷]` 待填的「部门/区域、子网前缀、可用地址范围」等行未随原文收录，因此本题的**逐行答案无法给出**，下面给出计算方法与填表格式。

**参考答案**

- 前缀分析：/49 表示前 49 位为网络前缀，其中前 48 位是全局路由前缀（240C:0DB8:1024），第 49 位是子网位的第一位。
- 子网位数：标准 IPv6 子网划分以 /64 为一个广播域（SLAAC、无状态自动配置要求 /64），因此可用的子网位 = 64 − 49 = **15 位**，可划分 2^15 = **32768 个 /64 子网**。
- 关键约束：由于 /49 已固定了第 4 个 16 位组（hextet）的最高位为 0，所以第 4 段的取值范围是 **0000 ~ 7FFF**；写成 `240C:0DB8:1024:8000::/64` 就越界了。
- 按 /64 逐段递增的填表方式（示例格式，具体部门分配以原表为准）：

| 区域（示例） | 子网前缀 | 可用地址范围 | 说明 |
| --- | --- | --- | --- |
| 核心/设备管理 | 240C:0DB8:1024:0000::/64 | ...:0000::1 ~ ...:0000::FFFF:FFFF:FFFF:FFFF | 第 1 个 /64 |
| 教学区 | 240C:0DB8:1024:0001::/64 | ...:0001::1 ~ ... | 逐段 +1 |
| 办公区 | 240C:0DB8:1024:0002::/64 | ...:0002::1 ~ ... | 逐段 +1 |
| 数据中心 | 240C:0DB8:1024:0003::/64 | ...:0003::1 ~ ... | 逐段 +1 |

- 若表中给出的是「每个部门需要的主机数」，则一律按 **/64 一段** 分配（IPv6 不做 VLSM 省地址），按需递增第 4 段即可。

**解析**

- IPv6 划分子网只看「**前缀到 /64 之间还剩几位**」：/48 → 16 位子网（65536 个 /64）；/49 → 15 位；/56 → 8 位（256 个 /64）；/64 → 1 个网段。
- 双栈部署的答题要点：同一物理接口同时配置 IPv4 与 IPv6 地址；IPv6 侧通常用 OSPFv3 或 IS-IS 建立路由；DHCPv6 或 SLAAC 分配地址；DNS 需同时提供 A 与 AAAA 记录；防火墙需放行 ICMPv6（ND、RA 依赖 ICMPv6，禁 ping 会直接导致 IPv6 不通）。
- 失分点：把 /49 当成 /48 算成 65536 个；把第 4 段写成 8000 以上；忽略 /64 是 SLAAC 的硬性要求。

> **原文缺失提示**：题干列出「问题1 ~ 问题5」五个标题，但原站只收录了问题1的题干。**问题2、问题3、问题4、问题5 的题干未随原文收录**，本笔记不臆造，请对照原卷补做（该题其余小问通常围绕 OSPF 跨校区路由、双出口选路、防火墙双机热备、40km 光缆的传输距离与光模块选型展开）。

### 1.2 案例2 核心堆叠、VRRP 网关冗余与终端隔离（第2题，20分）

> 考点：链路冗余与 STP、VRRP 主备网关、DHCP 部署、端口隔离/ACL、VLSM 地址规划

**【说明】**

试题二（20分）阅读以下说明,回答问题,将解答填入对应的解答栏内。某单位网络拓扑如下图所示。SW1、SW2为核心层交换机，PC网关配置在核心层，SW3-SW4为接入层交换机,行政部PC划为vlan10,销售部PC划为vlan20。

> `[原文为图，需对照原卷]` 拓扑与端口连接未随原文收录。原文「STISW2」为 OCR 误字，按上下文应为「SW1、SW2」。

**问题1**：要求实现骨干链路冗余，需要在哪些设备之间增加连线？增加连线后还需要配置什么避免形成二层环路?（4分）

**参考答案**

- 需要增加的连线：
  1. **SW1 与 SW2 之间**增加一条互联链路（核心层双机互联，形成核心冗余）；
  2. **SW3、SW4 分别与 SW1、SW2 交叉上联**（每台接入交换机双上行到两台核心），形成接入层到核心层的冗余；
  3. 如接入层之间也需要冗余，可在 **SW3 与 SW4 之间**增加一条链路（视原图是否已存在）。
- 增加连线后必须配置**生成树协议**（STP / RSTP / MSTP），通过选举根桥、阻塞冗余端口消除二层环路；推荐 MSTP，并做两项优化：
  - 把 SW1、SW2 配置为根桥（`stp root primary` / `stp root secondary`，或调低桥优先级），使流量走向可控；
  - 与 PC 相连的端口配置为边缘端口（`stp edged-port enable`）并开启 BPDU 保护，避免接入口参与生成树收敛。

**解析**

- 冗余链路带来环路，环路的后果是广播风暴、MAC 地址表震荡、多份帧复制。二层设备无法靠 TTL 防环，只能靠 STP 阻塞端口。
- 生成树会浪费被阻塞链路的带宽，若要求「链路冗余 + 带宽利用」，可进一步用 **Eth-Trunk 链路聚合 + 堆叠（CSS/iStack）** 把双上行变成一条逻辑链路，此时不需要 STP 阻塞。
- 失分点：只写「加一条线」不写 STP；或写「配置 VRRP」——VRRP 解决的是三层网关冗余，不能防二层环路。

**问题2**：要求vlan10的网关默认配置在SW1上，vlan20的网关默认配置在SW2上，当SW1或SW2任意一台设备故障后，不影响PC访问网关,请写出配置要点。（4分）

**参考答案**

- 在 SW1、SW2 上为 vlan10、vlan20 分别创建 **VRRP 备份组**，虚拟 IP 就是 PC 的网关地址：
  - vlan10：SW1 优先级调高（如 120），SW2 保持默认 100 → SW1 为 Master，承担 vlan10 网关转发；
  - vlan20：SW2 优先级调高（如 120），SW1 保持默认 100 → SW2 为 Master，承担 vlan20 网关转发；
  - 两台设备上同一 VRID 的**虚拟 IP 必须一致**，且 vlanif 接口的真实 IP 要在同一网段、互不相同。
- 配置抢占与抢占延时（`vrrp vrid N preempt-mode timer delay 20`），避免链路抖动导致主备频繁切换。
- 配置**上行链路跟踪**（`vrrp vrid N track interface uplink reduced 30`），当 Master 的上行/互联链路故障时自动降低优先级，让备份设备抢占，避免「网关还在、出口已断」。
- 两台核心之间需要有互通的二层链路（问题1增加的连线）和三层可达性，否则 VRRP 报文（组播 224.0.0.18）收不到，双主无法协商。

**解析**

- VRRP 的关键参数：VRID、虚拟 IP、优先级（默认 100，越大越优，0 与 255 保留）、抢占模式与延时、认证（可选）、跟踪对象。
- 「默认网关在 SW1、SW2 各承担一半」既实现了**网关冗余**，又实现了**流量负载分担**（不同 VLAN 的 Master 分散在两台设备）。
- 失分点：只写「配 VRRP」不写优先级关系；忘记虚拟 IP 要与 PC 网关一致；忘记配置抢占与跟踪。

**问题3**：要求配置PC能通过DHCP服务器正常获取IP地址，请写出配置要点。（4分）

**参考答案**

- 在作为 DHCP 服务器的设备（核心 SW1/SW2，或独立服务器）上：
  1. 全局开启 DHCP：`dhcp enable`；
  2. 创建地址池（全局地址池或 vlanif 接口地址池），配置 `network`、`gateway-list`、`dns-list`、`lease`，并用 `excluded-ip-address` 排除网关、服务器等固定地址；
  3. 在 vlanif 接口下指定地址池：`dhcp select global`（全局池）或 `dhcp select interface`（接口池）。
- 若 DHCP 服务器与 PC 不在同一网段（跨三层），需在网关设备上配置 **DHCP 中继**：`dhcp relay server-ip <服务器地址>` 或 `dhcp server group` + `dhcp select relay`。
- 二层侧：接入端口划分到对应 VLAN（access），上行 trunk 放行 vlan10/vlan20，保证 DHCP 广播能到达网关。
- 安全加固：接入交换机开启 **DHCP Snooping**，上联口设为信任口（`dhcp snooping trusted`），防止私接路由器/伪造 DHCP 服务器发放错误地址。

**解析**

- DHCP 四步：Discover（广播）→ Offer → Request → ACK。广播不能跨三层，所以跨网段必须中继（Relay 把广播变成单播发给服务器，并在请求中带 giaddr 指明网段）。
- 「PC 拿不到地址」的排查顺序：物理/端口 VLAN → 地址池是否有剩余 → 网关 vlanif 是否 up → 中继是否指向正确服务器 → 是否有私接 DHCP 服务器抢答（看 PC 拿到的网关是否异常）。
- 失分点：只写「开 DHCP」；忘记排除网关地址导致地址冲突；忘记中继。

**问题4**：为加强终端PC安全防护，要求各PC均不能互访，请写出配置要点。（4分）

**参考答案**

- 方案一（推荐，二层隔离）：在接入交换机连接 PC 的端口上配置**端口隔离**：
  ```text
  [SW3] interface GigabitEthernet 0/0/1
  [SW3-GigabitEthernet0/0/1] port-isolate enable group 1
  ```
  同一隔离组内的端口二层不能互通，但仍可经网关访问外部网络；上联口不加入隔离组。
- 方案二（三层控制）：在 vlanif 上配置**流策略/ACL**，拒绝同网段互访：
  ```text
  [SW1] acl 3000
  [SW1-acl-adv-3000] rule deny ip source 10.10.10.0 0.0.0.255 destination 10.10.10.0 0.0.0.255
  [SW1] interface Vlanif 10
  [SW1-Vlanif10] traffic-filter inbound acl 3000
  ```
- 方案三：把不同部门/终端划入不同 VLAN（三层隔离），并在 vlanif 上禁止 VLAN 间互通。
- 可叠加：端口安全（限制 MAC 数量、绑定 MAC/IP）、ARP 防攻击、802.1X 接入认证。

**解析**

- 端口隔离是「同一 VLAN 内不同端口二层隔离」的最轻量方案，隔离组（group）不同则互通；注意隔离只作用于二层，PC 仍能通过网关访问服务器与外网。
- 用 ACL 做同网段隔离时必须明确「源和目的都是本网段」，容易漏写；且 ACL 在三层设备上生效，二层直通的流量不一定经过网关，所以方案二的可靠性不如端口隔离。
- 失分点：写「划分 VLAN」却不说 VLAN 间是否放行；把「不能互访」理解成「不能上网」。

**问题5**：请按照IP地址最小范围规划要求完成下表。（4分）

> `[原文为表，需对照原卷]` 表中「部门/VLAN、终端数量、网络地址、掩码、可用地址范围」等列未随原文收录，**逐行答案无法给出**。下面给出「最小范围」规划方法与填写规范。

**参考答案**

- 「最小范围」= 为每个 VLAN/部门分配恰好能容纳其终端数的最小子网（VLSM），不留大块浪费。
- 计算规则：`2^n − 2 ≥ 终端数` 取最小 n；掩码 = /(32−n)；块大小 = 2^n；起始地址按块大小对齐。
- 常见块大小：/24（254）、/25（126）、/26（62）、/27（30）、/28（14）、/29（6）、/30（2）。
- 填写格式示例（数据为示例，非原表）：

| 部门/VLAN | 终端数 | 网络地址/掩码 | 可用地址范围 | 网关 |
| --- | --- | --- | --- | --- |
| vlan10 行政部 | 50 | 192.168.10.0/26 | .1 ~ .62 | .1 |
| vlan20 销售部 | 20 | 192.168.10.64/27 | .65 ~ .94 | .65 |

- 若各 VLAN 需要连续编址，按块大小从低地址向高地址依次切分，剩余的地址块留作扩展。

**解析**

- 本题与 2023 上第 1 题、2024 下同类题是同一考点，核心永远是「**需求 → 位数 → 掩码 → 对齐 → 范围**」五步。
- 常见失分：把「终端数」直接当「可用地址数」；忘记网关要占一个地址；起始地址没对齐导致网段重叠。

### 1.3 案例3 静态 MPLS 与静态 LSP（第3题，15分）

> 考点：MPLS 基本概念（LSR/LER/LSP/入节点/出节点）、静态 LSP 的 ingress/transit/egress 配置、in-label 与 out-label 的对应关系

**【说明】**（15分）

某公司计划在骨干网络上建立静态MPLS，以便部署L2VPN或者L3VPN业务。其网络拓扑结构如下所示。

> `[原文为图，需对照原卷]` LSR-1/LSR-2/LSR-3 的接口编号与地址需对照原图；下文命令中的 172.16.1.x、Vlanif100/200 等取自题干命令本身。

**问题1**：MPLS基于（1）进行转发，进行MPLS标签交换和报文转发的网络设备称为（2），构成MPLS域（MPLS Domain）。位于MPLS域边缘、连接其他网络的LSR称为（3）,区域内部的LSR称为核心LSR（Core LSR）。IP报文进入MPLS网络时，MPLS入口设备分析IP报文的内容并为其添加合适的标签，所有MPLS网络中的LSR根据标签转发数据，当该IP报文离开MPLS网络时，标签由出口LER弹出。IP报文在MPLS网络中经过的路径称为（4）,LSP是一个单向路径,与数据流的方向一致。LSP的入口LER称为（5）;位于LSP中间的LSR称为中间节点（Transit）;LSP的出口LER称为（6）。一条LSP可以有0个、1个或多个中间节点，但有且只有一个入节点和一个出节点。（6分）

（1）-（6）备选答案
A.标签交换路由器LSR（Label Switching Router）
B.标签交换路径LSP（Label Switched Path）
C.标签
D.入节点（Ingress）
E.边缘路由器LER（Label Edge Router）
F.出节点（Egress）

**参考答案**

| 空号 | 答案 | 说明 |
| --- | --- | --- |
| （1） | **C（标签）** | MPLS 用短的定长标签替代最长匹配查表，基于标签转发 |
| （2） | **A（LSR）** | 标签交换路由器，负责标签交换与报文转发 |
| （3） | **E（LER）** | 位于 MPLS 域边缘、连接其他网络的 LSR |
| （4） | **B（LSP）** | 报文在 MPLS 域中经过的路径，单向 |
| （5） | **D（入节点 Ingress）** | LSP 入口 LER，负责压入标签（Push） |
| （6） | **F（出节点 Egress）** | LSP 出口 LER，负责弹出标签（Pop） |

**解析**

- MPLS 的三个动作要能对号入座：**Push（入节点压标签）、Swap（中间节点换标签）、Pop（出节点弹标签）**。
- 术语关系：LSR 是设备统称；位于边缘的 LSR 叫 LER；LSP 是标签转发路径；入节点/中间节点/出节点是 LSR 在一条 LSP 上的角色。
- 记忆点：**MPLS 域 = 若干 LSR；边界 = LER；路径 = LSP；一条 LSP 只有一个入节点和一个出节点，中间节点可有可无**。

**问题2**：上图中，骨干网络中已完成路由协议配置，各个节点之间可以互通。下面是为该网络配置静态MPLS的代码，请将下面的配置代码补充完整。（9分）

配置片段：

```text
#使能LSR-1及各接口的MPLS功能
[LSR-1]mpls（1）1.1.1.9
[LSR-1]（2）
[LSR-1-mpls]quit
[LSR-1]interface（3）100
[LSR-1-Vlanif100]mpls
[LSR-1-Vlanif100]quit
#创建从LSR-1到LSR-3的静态LSP
[LSR-1]static-lsp ingress LSP1 destination 3.3.3.9 32 nexthop 172.16.1.2（4）20
[LSR-2]static-lsp transit LSP1 incoming-interface vlanif100 in-label（5）nexthop 172.16.1.2 out-label（6）
[LSR-3]static-lsp egress LSP1 incoming-interface vlanif200（7）40
#创建从LSR-3到LSR-1静态LSP
[LSR-3]static-lsp ingress LSP2 destination 1.1.1.9 32 nexthop 172.16.1.1 out-label 30
[LSR-2]static-lsp transit LSP2 incoming-interface vlanif200 in-label（8）nexthop 172.16.1.1 out-label（9）
[LSR-1]static-lsp egress LSP2 incoming-interface vlanif100 in-label 60
```

**参考答案**

| 空号 | 答案 | 依据 |
| --- | --- | --- |
| （1） | **lsr-id** | 完整命令 `mpls lsr-id 1.1.1.9`，配置本设备的 LSR ID（通常用 Loopback 地址） |
| （2） | **mpls** | 在系统视图执行 `mpls` 使能全局 MPLS，随后进入 `[LSR-1-mpls]` 视图 |
| （3） | **vlanif** | 接口视图为 `interface vlanif 100`，与提示符 `[LSR-1-Vlanif100]` 一致 |
| （4） | **out-label** | ingress 节点为报文压入的标签，即出标签 20 |
| （5） | **20** | transit 的入标签必须等于上游 ingress 的出标签 |
| （6） | **40** | transit 的出标签必须等于下游 egress 的入标签（空（7）已给出 40） |
| （7） | **in-label** | egress 节点接收报文的入标签，命令为 `in-label 40` |
| （8） | **30** | 反向 LSP2 中，LSR-3 的 ingress 出标签为 30，故 LSR-2 的入标签为 30 |
| （9） | **60** | LSR-2 的出标签必须等于下游 LSR-1（egress）的入标签 60 |

**解析**

- 静态 LSP 的核心规则只有一条：**上游的出标签 = 下游的入标签**。沿路径逐跳串起来即可：20 → 20/40 → 40；反向 30 → 30/60 → 60。
- 三个角色的命令差异：
  - ingress：`destination <目的地址> <掩码> nexthop <下一跳> out-label <标签>`；
  - transit：`incoming-interface <入接口> in-label <标签> nexthop <下一跳> out-label <标签>`；
  - egress：`incoming-interface <入接口> in-label <标签>`。
- 常见失分：把（5）写成 40（与下游混淆）；漏写 `lsr-id`（没有 LSR ID，MPLS 无法正常工作）；接口未使能 `mpls`（只有全局使能，报文不打标签）。
- 静态 LSP 是单向的，所以必须**双向各配一条**（LSP1 与 LSP2），否则业务只能单向通。

### 1.4 案例4 BGP 邻居、下一跳与路由反射（第4题，20分）

> 考点：BGP 建邻（AS 号、peer）、`next-hop-local`、network 宣告、路由可达性与回程、路由反射器三条规则、cluster-id

**【说明】**（20分）

某网络拓扑如下图所示，路由器R1、R2、R3通过OSPF实现网络互通，R1和R3建立iBGP邻居关系，R3和R5建立eBGP邻居关系，R1和R4建立eBGP邻居关系。

> `[原文为图，需对照原卷]` 各路由器 AS 号、接口地址、R2 的 router-id 未随原文收录。下文依据题干命令中出现的 10.14.14.4、3.3.3.3、210.23.3.4、bgp 200 等推断，已逐条注明。

**问题1**：各路由器IP地址等基本参数已正确配置,且R1、R2、R3之间OSPF邻居关系已建立且完成收敛，在R4配置本地回环Lo0模拟ISP地址210.23.3.4/32，根据要求完成以下配置。以R1为例配置BGP。（10分）

配置片段：

```text
[R1]bgp（1）
[R1-bgp]peer（2）as-number（3）//与R4建立BGP邻居关系
[R1-bgp]peer 10.14.14.4 enable
……
[R1-bgp]peer 3.3.3.3 next-hop-local//作用是:（4）
在R4将210.23.3.4/32引入BGP
[R4]bgp 200
[R4-bgp]（5）//将210.23.3.4/32引入BGP
```

**参考答案**

| 空号 | 答案 | 依据 |
| --- | --- | --- |
| （1） | **100** | R1 与 R3 是 iBGP（同 AS），R4 为 `bgp 200`（eBGP 对端），故 R1 的 AS 号为 100 |
| （2） | **10.14.14.4** | 与 R4 建邻，下一行 `peer 10.14.14.4 enable` 已给出对端地址 |
| （3） | **200** | R4 的 AS 号（`[R4]bgp 200`） |
| （4） | 把从 eBGP 邻居学到的路由发布给 iBGP 邻居时，**将下一跳改为自己的地址**（本机与 iBGP 邻居直连/可达的地址），避免 iBGP 邻居因下一跳是外部 AS 的地址而不可达、路由不优 | `next-hop-local` 的作用 |
| （5） | **network 210.23.3.4 32** | 将指定网段/主机路由宣告进 BGP；此处为 /32 主机路由 |

**解析**

- 建邻三要素：本端 AS（`bgp 100`）、对端地址（`peer x.x.x.x`）、对端 AS（`as-number 200`）；iBGP 的对端 AS 号必须与本端相同，eBGP 必须不同。本题 R1—R4 是 eBGP，所以（3）填 200。
- BGP 的 `network` 与 IGP 不同：它**不会自己产生路由**，路由必须已存在于本地路由表中（此处 210.23.3.4/32 来自 R4 的 Loopback 直连），`network` 只是把已有路由放进 BGP 表并宣告。
- `next-hop-local` 是 iBGP 场景的必配项：eBGP 学来的路由下一跳是外部地址，iBGP 邻居往往没有到该外部地址的路由，需要在边界路由器上改成自己的地址。
- 失分点：把（1）写成 200；把（3）写成 100；把（5）写成 `import-route direct`（也能通，但题干给了 `[R4-bgp]` 视图且强调「将 210.23.3.4/32 引入」，标准答案是 `network 210.23.3.4 32`）。

**问题2**：上述配置完成后，路由器R5上210.23.3.4/32的路由信息如下图所示，但是却无法ping通210.23.3.4，请分析原因。（3分）

> `[原文为图，需对照原卷]` R5 上 `display ip routing-table` / `display bgp routing-table` 的截图未随原文收录，**无法据图确认下一跳与 AS_PATH**，因此下面按两种最可能原因给出分析，答题时须以原图显示的下一跳为准。

**参考答案**

- 可能原因一（**下一跳不可达**）：R5 上该路由的下一跳指向 R1 与 R4 之间的互联地址（如 10.14.14.x）。R3 从 R1（iBGP）学到该路由时下一跳未改为自身地址（缺 `peer ... next-hop-local`），R5 又没有到该下一跳网段的路由，于是「路由表里有、转发时不可达」，表现为 ping 不通。
- 可能原因二（**回程路由缺失**）：去程能到 210.23.3.4，但 R4 侧没有到 R5 所在网段（或 R5 的 ping 源地址）的回程路由——R4 只把 Lo0 的 210.23.3.4/32 宣告进 BGP，未把 R5 的网段引入，也没有指向 R1 的默认路由，Echo Reply 无法返回。
- 排查与验证方法：在 R5 上 `tracert 210.23.3.4` 看在哪一跳断；在 R3 上 `display bgp routing-table 210.23.3.4` 看下一跳是否可达（`*>` 与 `*` 的区别）；在 R4 上 `display ip routing-table <R5网段>` 看是否有回程路由。
- 解决方向：在 R1/R3 上补齐 `peer ... next-hop-local`；在 R4 上补回程路由（静态路由或把 R5 网段引入 BGP）；必要时检查 R4 的 Loopback 是否被防火墙/ACL 过滤。

**解析**

- 「路由表里有路由但 ping 不通」在网络排错中只有三类原因：**下一跳不可达**（路由不优/无效）、**回程缺失**（单向通）、**策略丢弃**（ACL、uRPF、防火墙）。答题时按这三类逐一排除即可。
- BGP 路由前面的 `*>` 表示有效最优，`*` 表示有效但非最优，没有 `*` 表示下一跳不可达——这是用 BGP 表判断「下一跳是否可达」的直接依据。
- 本题只有 3 分，写出「下一跳不可达 / 缺少 next-hop-local」或「回程路由缺失」中的一条并说明理由即可得分。

**问题3**：管理员计划采用BGP路由反射功能解决上述问题。BGP路由反射功能需要遵循如下三条规则：从非客户机学到的路由，反射器发布给（1）；从客户机学到的路由,反射器发布给（2）；从eBGP邻居学到的路由，反射器发布给所有的非客户机和客户机。（7分）

配置片段：

```text
#BGP反射器配置片段，配置R1为反射器、R2为客户端
……略去R2和R1建立BGP邻居配置
[R1-bgp] reflector cluster-id 12   //该条命令的作用是（3）
[R1-bgp] peer （4） reflect-client
```

**参考答案**

| 空号 | 答案 | 说明 |
| --- | --- | --- |
| （1） | **所有客户机**（本集群内的 client） | 非客户机路由只反射给客户机，不再传给其他非客户机，避免环路 |
| （2） | **所有客户机和其他非客户机**（除该路由的来源客户机外） | 客户机路由要扩散到全网 iBGP |
| （3） | 配置路由反射器的**集群 ID（Cluster ID）**，用于标识反射器所属集群并在 AS 内防环；同一集群内的多台反射器应配置相同的 cluster-id（缺省为 router-id） | 防止路由在集群间循环 |
| （4） | R2 与 R1 建立 iBGP 邻居所用的地址（通常为 R2 的 Loopback 地址，如 `2.2.2.2`） | **题干省略了 R2 的建邻配置，具体地址需对照原图** |

**解析**

- 路由反射器解决的是 **iBGP 全互联（full mesh）扩展性问题**：iBGP 有水平分割（从 iBGP 学到的路由不再传给其他 iBGP 邻居），n 台路由器需要 n(n−1)/2 条邻居关系；引入 RR 后，客户端只需与 RR 建邻，由 RR 代为反射。
- 三条规则必背：
  1. 从**客户机**学到的 → 发给所有客户机 + 所有非客户机（除源）；
  2. 从**非客户机**学到的 → 只发给客户机；
  3. 从 **eBGP** 学到的 → 发给所有客户机和非客户机。
- 防环三件套：`cluster-id`（集群内防环）、`originator-id`（Originator ID，防路由回到发起者）、AS_PATH（AS 间防环）。
- 失分点：（1）（2）写反是最常见的错误——记法：**「非客户机的路由只给客户机，客户机的路由给所有人」**。
