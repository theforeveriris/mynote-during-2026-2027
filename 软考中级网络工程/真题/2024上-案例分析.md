## 1.案例分析

### 1.1 案例1：双校区出口、防火墙与 IPv6 地址规划

**【说明】**（20 分）

某高校网络拓扑如下图所示，两校区核心（CORE-1，CORE-2），出口防火墙（NGFW-1，NGFW-2）通过校区间光缆互联，配置 OSPF 实现全校路由收敛，校区相距 40km。两校区默认由本地出口进行互联网访问。

**拓扑要点**（据原图整理）

| 位置 | 设备 | 说明 |
| ---- | ---- | ---- |
| A 校区 | CORE-1、NGFW-1 | 本地出口访问 Internet |
| B 校区 | CORE-2、NGFW-2 | 本地出口访问 Internet |
| 互联 | CORE-1—CORE-2、NGFW-1—NGFW-2 | 校区之间 40km 光缆，跑 OSPF |
| 边界 | NGFW-1/NGFW-2 的 trust 域接内网，untrust 域接运营商 | 需放行 OSPF 才能建立邻居 |
| 终端 | 新校区终端网段 | 双栈部署，IPv6 前缀 240C:DB8:1024::/49 |

**问题1**（3 分）

新校区规划以双栈方式部署 IPv6 网络，分配的 IPv6 地址为 240C:DB8:1024::/49。请将 IPv6 网络地址规划表补充完整。

原表结构：业务 / 终端数量 / 可用地址范围 / 前缀长度 / 分配方式。已知「设备管理」300 台，范围 240C:DB8:1024::/64，前缀 64，静态分配；「有线网络终端」8000 台，范围 240C:DB8:1024:2000::/51，分配方式为动态。

**参考答案**

| 业务 | 终端数量 | 可用地址范围 | 前缀长度 | 分配方式 |
| ---- | -------- | ------------ | -------- | -------- |
| 设备管理 | 300 | 240C:DB8:1024::/64 ~ 240C:DB8:1024:0:FFFF:FFFF:FFFF:FFFF | 64 | 静态 |
| 有线网络终端 | 8000 | 240C:DB8:1024:2000::/51 ~ 240C:DB8:1024:3FFF:FFFF:FFFF:FFFF:FFFF | 51 | 动态 |
| 无线网络终端 | 15000 | **240C:DB8:1024:4000::/51** ~ **240C:DB8:1024:5FFF:FFFF:FFFF:FFFF:FFFF** | **51** | 动态 |

即空（1）填 `240C:DB8:1024:4000::/51`，空（2）填 `51`。

采分点：

- 前缀长度取 51：/49 只留出 15 位子网位，按 /51 切分正好得到 4 个业务地址块，第 4 组十六进制数依次为 `0000`、`2000`、`4000`、`6000`。
- 起始地址顺延：设备管理占第 1 块（0000），有线占第 2 块（2000），无线顺延取第 3 块（4000），不得与前两块重叠。
- 结束地址 = 起始地址 + 该前缀的地址空间减 1，`/51` 的第 4 组高 3 位固定，故结束于 `5FFF:FFFF:FFFF:FFFF:FFFF`。

**解析**

考查 IPv6 全局单播地址的结构（全局路由前缀 / 子网 ID / 接口 ID）与「按前缀长度切分地址块」的方法，属规划计算题。

- IPv6 没有 NAT 的需求，规划原则是「一个业务一个子网、子网按需取前缀」，终端数只用于校验地址块是否够用，不直接决定前缀：/51 可提供 2^77 个地址，远大于 15000，取 /51 是为了与已有两块保持同样的划分粒度（同一级子网）。
- 定位方法：把第 4 组十六进制数写成二进制，前缀 49 表示第 4 组第 1 位固定，前缀 51 表示第 4 组前 3 位固定。`0x2000 = 0010 0000 0000 0000`，说明第 2 块从第 4 组第 2 位开始变化；因此第 3 块是 `0100 …` 即 `0x4000`。
- 常见失分点：① 直接对「终端数量」做 2 的幂运算去选前缀，得出 /49 或 /64；② 结束地址漏写，或把 `FFFF:FFFF:FFFF:FFFF` 写成 4 组而非 5 组；③ 把「可用地址范围」写成「网络地址/前缀」形式，没有给出区间上下界。

**【考点】** IPv6 地址结构与子网划分；前缀长度与地址块边界的换算；地址规划表的填写规范。

**问题2**（4 分）

为实现 NGFW-2 与 NGFW-1、CORE-2 正常建立 OSPF 邻居关系，实现路由全收，网络工程师对 NGFW-2 进行相关配置，请补充完善下列由 trust 到 local 的配置。

```text
[NGFW-2] firewall zone trust
[NGFW-2-zone-trust] add interface GigabitEthernet0/0/1
[NGFW-2-zone-trust] add interface GigabitEthernet0/0/2
[NGFW-2] security-policy
[NGFW-2-policy-security] rule name policy1
[NGFW-2-policy-security-rule-policy1] source-zone trust
[NGFW-2-policy-security-rule-policy1] destination-zone (1)
[NGFW-2-policy-security-rule-policy1] source-address (2)
[NGFW-2-policy-security-rule-policy1] service protocol (3)
[NGFW-2-policy-security-rule-policy1] action (4)
```

**参考答案**

| 空 | 答案 | 说明 |
| -- | ---- | ---- |
| (1) | `local` | OSPF 报文的目的地址是防火墙自身接口，安全策略的目的域为 local |
| (2) | `10.0.0.0 0.255.255.255`（或 `any`） | 匹配对端 OSPF 邻居所在内网网段；写 `any` 亦可，但范围过宽 |
| (3) | `ospf` | OSPF 是 IP 协议号 89 的协议，也可写 `protocol 89` |
| (4) | `permit` | 放行，动作不能写 `allow`（华为 USG 用 permit/deny） |

```text
[NGFW-2-policy-security-rule-policy1] destination-zone local
[NGFW-2-policy-security-rule-policy1] source-address 10.0.0.0 0.255.255.255
[NGFW-2-policy-security-rule-policy1] service protocol ospf
[NGFW-2-policy-security-rule-policy1] action permit
```

**解析**

考查防火墙安全区域、域间安全策略与「防火墙自身也要作为 OSPF 邻居」这一常见场景。

- OSPF 用组播 224.0.0.5/224.0.0.6 发送 Hello，目的地址不是对端业务地址而是本机，因此被防火墙当作「发往自身」的流量，目的域必须写 `local`；写成 `trust` 是最典型错误。
- 华为 USG 的域间策略必须同时指定源域、目的域、源/目的地址、服务（或协议）、动作。OSPF 不是 TCP/UDP 应用，不能用 `service` 下的端口对象，要用 `service protocol`（协议号）。
- 常见失分点：① 目的域写 `trust`；② 服务写成 `ospf 89` 或 `tcp 89`；③ 忘记 `action permit`，默认动作是 deny；④ 只放行单向，未考虑 NGFW-2 主动发起与回应两个方向（回应报文由会话表放行，但邻居建立阶段的组播需双向可达）。

**【考点】** 防火墙安全区域与域间策略；OSPF 报文类型与协议号；防火墙参与动态路由时的放行配置。

**问题3**（4 分）

网络工程师收到故障报告，某终端用户可成功获取 IP 地址，正常访问校内业务，却无法访问 Internet。在该终端上路由跟踪测试，可正常至 NGFW-2，于是在终端上进行 `ping 114.114.114.114` 测试，结果显示「请求超时」，同时在 NGFW-2 查看到如下会话：

```text
[NGFW-2] display firewall session table verbose source inside 10.21.0.2 destination global
Current Total Sessions : 1
ICMP  VPN: public --> public
Zone: trust --> untrust   TTL: 00:00:20  Left: 00:00:20
Interface: GigabitEthernet0/0/4  NextHop: 61.2.7.1
<-- packets: 0  bytes: 0
10.21.0.2:5xxx --> 114.114.114.114:2048
```

请分析该故障的原因并提出解决措施。

**参考答案**

原因：会话表中源地址仍为私网地址 `10.21.0.2`，报文经 GE0/0/4 直接发往运营商下一跳 `61.2.7.1`，**没有做源 NAT 转换**。运营商侧收到源地址为私网的报文后直接丢弃，回程报文也无法回到私网，故表现为「能到防火墙、出不去、请求超时」。

解决措施（按顺序操作）：

1. 在 NGFW-2 上配置 NAT 策略（源 NAT / NAPT），将 trust 域访问 untrust 的流量转换为出接口地址：

```text
[NGFW-2] nat-policy
[NGFW-2-policy-nat] rule name nat1
[NGFW-2-policy-nat-rule-nat1] source-zone trust
[NGFW-2-policy-nat-rule-nat1] destination-zone untrust
[NGFW-2-policy-nat-rule-nat1] source-address 10.21.0.0 0.255.255.255
[NGFW-2-policy-nat-rule-nat1] action source-nat easy-ip
[NGFW-2-policy-nat-rule-nat1] quit
[NGFW-2] interface GigabitEthernet0/0/4
[NGFW-2-GigabitEthernet0/0/4] nat-policy nat1
```

2. 确认安全策略已放行 trust→untrust，且 NAT 策略的匹配顺序在拒绝策略之前（USG 的 NAT 策略与安全策略是两套策略，缺一不可）。
3. 验证：`display firewall session table` 中源地址应变为 GE0/0/4 的公网地址；`display nat-policy statistics` 查看命中计数。

**解析**

考查「能上内网、不能上外网」这一类出口故障的定位方法：先看会话表，再看 NAT，最后看安全策略与路由。

- 判据就在会话表里：`Zone: trust --> untrust` 说明策略已放行、会话已建立；`Interface/NextHop` 说明路由正确；但源地址没有被改写，说明 NAT 缺失或未命中。
- 若 NAT 已配置仍不生效，依次排查：NAT 策略是否被 `nat-policy` 应用到接口、源地址是否落在匹配范围、是否有更靠前的策略命中、是否有 `no-pat`/地址池耗尽。
- 常见失分点：① 只写「防火墙没放行」，与题干「能到 NGFW-2、会话已建立」矛盾；② 只答「配置 NAT」，不指出是源 NAT、在哪个接口、转换为什么地址；③ 混淆 NAT 策略与安全策略，认为放行即等于转换。

**【考点】** 源 NAT/NAPT 原理与配置；防火墙会话表判读；出口故障的分层定位（路由 → NAT → 策略）。

**问题4**（3 分）

网络工程师接到故障报告，某终端用户网络时通时断，无法正常上网。在用户终端上通过命令测试结果如下（两次 `arp -a` 输出中，网关 192.168.5.1 对应的 MAC 地址前后不一致，其余表项不变，说明网关的 IP-MAC 映射被篡改）：

```text
C:\> ipconfig
IPv4 地址 : 192.168.5.54
默认网关 : 192.168.5.1

C:\> arp -a
192.168.5.1     [MAC-A]     动态
...
C:\> arp -a
192.168.5.1     [MAC-B]     动态
```

通过上图可以判断网络遭受了（1）攻击，为解决该故障，网络工程师在用户电脑上配置了静态 ARP 绑定，同时在设备（2）上配置（3）功能。

**参考答案**

| 空 | 答案 |
| -- | ---- |
| (1) | ARP 欺骗（ARP spoofing，可答「中间人攻击 / ARP 毒化」） |
| (2) | 接入交换机（或网关设备） |
| (3) | ARP 防攻击 / 动态 ARP 检测（DAI，华为命令为 `arp anti-attack check user-bind enable`，配合 DHCP Snooping 绑定表） |

采分点：(1) 必须点出「ARP」而不是泛泛的「病毒攻击」；(2) 写「接入交换机」或「网关/核心交换机」均可，写「终端」不得分（终端上做的是静态绑定，已另述）；(3) 写「ARP detection / DAI / ARP 防欺骗 / IP-MAC 绑定」均可。

**解析**

考查 ARP 协议无认证的缺陷与二层安全防护。

- 判断依据：同一 IP 的 MAC 映射在短时间内改变，且变化的是网关地址，说明有主机持续发送伪造的免费 ARP/ARP 应答，把网关 IP 绑定到攻击者 MAC，终端流量被引到攻击者处再转发，表现为时通时断。
- 防护分三层：终端侧静态 ARP 绑定（治标）；接入交换机侧 DAI/ARP 防攻击（依赖 DHCP Snooping 生成的 IP-MAC-端口绑定表，对不符的 ARP 报文丢弃）；网关侧静态 ARP 或端口安全。
- 常见失分点：① 答「ARP 攻击」但不说清是伪造网关 MAC；② 把 DAI 配在防火墙上（防火墙不做二层 ARP 检测）；③ 忘记 DAI 依赖 DHCP Snooping 绑定表，导致「开了不生效」。

**【考点】** ARP 工作原理与 ARP 欺骗；DAI/ARP 检测与 DHCP Snooping 的配合；终端侧与网络侧防护手段的分工。

**问题5**（6 分）

网络工程师配置 NGFW-2 作为 SSL VPN 网关为网络管理员提供安全远程接入，可以随时随地对校园网内网络进行访问和管理。SSL VPN 充分利用 SSL 协议基于数字证书提供的安全机制，为应用层之间的通信建立安全连接。

（1）SSL 协议安全机制包括：（ ）、数据加密、（ ）。
（2）数据加解密算法主要分为对称密钥算法、非对称密钥算法，请简要描述 SSL 协议如何利用这两类算法实现数据传输的机密性。
（3）网络工程师在配置 SSL VPN 之前，需要向（ ）申请证书文件，并将其上传至 NGFW-2 的指定位置。

**参考答案**

（1）**身份认证（证书认证）**、**数据完整性校验**。补全后为：身份认证、数据加密、完整性校验（三项构成 SSL 的安全机制）。

（2）要点：

- 握手阶段：服务器把数字证书发给客户端，客户端用 CA 公钥验证证书，完成**服务器身份认证**；双方用**非对称算法**（RSA、DH 或 ECDHE 等）协商出本次会话的**对称密钥**，必要时用非对称算法对握手报文签名。
- 传输阶段：用协商出的**对称密钥**（AES、SM4 等）对应用数据做**加密**，对称算法速度快，适合大数据量；同时用 MAC/HMAC 做完整性校验。
- 结论：非对称算法负责「身份认证 + 密钥协商」，对称算法负责「数据加密」，两者结合兼顾安全性与效率。

（3）**CA（数字证书认证中心，Certificate Authority）**。自建环境可答「企业自建的 CA 服务器」。

**解析**

考查 SSL/TLS 的三大安全服务与混合密码体制，属于「安全技术 + 设备配置」的结合题。

- 记忆框架：SSL = 认证（我是谁）+ 加密（别人看不懂）+ 完整性（没被篡改）。三项缺一不可，答成「防火墙、加密、审计」即偏题。
- 混合体制是必答点：只说「用对称算法加密」会丢分，因为没有解决密钥如何安全分发；只说「用非对称算法加密」也不完整，因为非对称算法开销大，不用于业务数据。
- 常见失分点：① 把「数据加密」与「完整性校验」混为一谈；② 认为证书由设备自己签发（除非自建 CA）；③ 第（2）问只写结论不写两个阶段的分工。

**【考点】** SSL/TLS 协议的安全机制；对称与非对称算法的分工（混合加密）；数字证书与 CA；SSL VPN 的部署前提。

### 1.2 案例2：核心双机、VLAN 与地址规划

**【说明】**（20 分）

某单位网络拓扑如下图所示。SW1、SW2 为核心层交换机，PC 网关配置在核心层，SW3、SW4 为接入层交换机，行政部 PC 划为 vlan10，销售部 PC 划为 vlan20。

**拓扑要点**（据原图整理）

| 设备 | 角色 | 连接 |
| ---- | ---- | ---- |
| SW1、SW2 | 核心层，PC 网关（VLANIF10/20） | 分别下联 SW3、SW4 |
| SW3、SW4 | 接入层 | 接行政部（vlan10）、销售部（vlan20）终端 |
| 网关地址 | 网段 10.0.1.0/24 | 行政部网关 10.0.1.158，销售部网关同网段另一子网 |

**问题1**（4 分）

要求实现骨干链路冗余，需要在哪些设备之间增加连线？增加连线后还需要配置什么避免形成二层环路？

**参考答案**

- 增加连线：在 **SW1 与 SW2 之间**增加一条互联链路（核心层互联）；同时把 **SW3、SW4 分别双上行到 SW1 和 SW2**（每台接入交换机各有一条到两台核心的链路），形成「接入双归 + 核心互联」的冗余结构。
- 避免二层环路：配置**生成树协议**（STP/RSTP/MSTP），在冗余链路中选择一条阻塞；也可采用**堆叠/iStack**把 SW1、SW2 变成一台逻辑设备，或对双上行做**链路聚合（Eth-Trunk）**，从设计上消除环路。

采分点：设备对（SW1—SW2）+ 双上行（SW3/SW4 各到 SW1、SW2）；防环手段写「STP/RSTP/MSTP」即可得分，补充堆叠或链路聚合计加分。

**解析**

考查冗余设计与二层环路的关系：冗余必然产生环路，环路必须由 STP 或逻辑堆叠消除。

- 只加 SW1—SW2 一条线并不构成环路，必须同时存在「接入双归」才形成 SW1—SW3—SW2—SW1 的环；因此答案要同时写核心互联和接入双上行。
- 三种工程做法要能区分：STP 是「留一条、堵一条」，带宽浪费；链路聚合是「多条当一条」，需两端支持；堆叠是「多台当一台」，管理最简但受堆叠线缆距离限制。
- 常见失分点：① 只答「加一条线」不答防环；② 答「配置 VRRP 防环」——VRRP 是三层网关冗余，与二层环路无关；③ 答「配置 ACL 防环」。

**【考点】** 冗余组网与二层环路；STP/RSTP/MSTP 的作用；堆叠与链路聚合的适用场景。

**问题2**（4 分）

要求 vlan10 的网关默认配置在 SW1 上，vlan20 的网关默认配置在 SW2 上；当 SW1 或 SW2 任意一台设备故障后，不影响 PC 访问网关，请写出配置要点。

**参考答案**

采用 **VRRP 双活（负载分担）**，同一 VLAN 起一个备份组，两台核心互为主备：

1. 两台核心上都创建 VLANIF10、VLANIF20，配置各自的实地址（同一网段）。
2. VLANIF10 上配置 `vrrp vrid 10 virtual-ip 10.0.1.158`：SW1 优先级设为 120（高于默认 100，成为 Master），SW2 保持默认 100（Backup）。
3. VLANIF20 上配置 `vrrp vrid 20 virtual-ip <vlan20 网关>`：SW2 优先级 120（Master），SW1 默认 100（Backup）。
4. 两台设备都配置抢占及抢占延时，避免抖动：`vrrp vrid 10 preempt-mode timer delay 20`。
5. 配置上行链路跟踪（`vrrp vrid 10 track interface GigabitEthernet0/0/1 reduced 30`），使上行故障时能主动降优先级切换。
6. SW1—SW2 之间链路放行 VLAN10、VLAN20，保证 VRRP 报文互通；接入交换机双上行做 Trunk。

```text
[SW1] interface Vlanif 10
[SW1-Vlanif10] ip address 10.0.1.157 255.255.255.224
[SW1-Vlanif10] vrrp vrid 10 virtual-ip 10.0.1.158
[SW1-Vlanif10] vrrp vrid 10 priority 120
[SW1-Vlanif10] vrrp vrid 10 preempt-mode timer delay 20
[SW1-Vlanif10] quit
[SW1] interface Vlanif 20
[SW1-Vlanif20] vrrp vrid 20 virtual-ip 10.0.1.190
[SW1-Vlanif20] vrrp vrid 20 priority 100
```

**解析**

考查 VRRP 的报文、状态机与双活设计。核心是「虚拟 IP 做网关、优先级决定 Master、抢占与跟踪决定切换」。

- 双活的关键是「两个 VLAN 各自主备互换」：不要在同一个 VLAN 上把两台都设成 120，否则优先级相同会比较 IP 大小，退化成单活。
- VRRP 报文是组播 224.0.0.18（VRRPv2）/ff02::12（VRRPv3），封装在 IP 之上，协议号 112，因此 SW1—SW2 的二层链路必须放行对应 VLAN。
- 常见失分点：① 只写「配置 VRRP」不写 vrid、虚拟 IP、优先级；② 把虚拟 IP 配成某一台设备的实地址；③ 忘记抢占延时或跟踪，导致上行故障不切换、或频繁切换；④ 认为 VRRP 能解决接入层环路。

**【考点】** VRRP 备份组、优先级与抢占；网关双活（负载分担）；上行链路跟踪。

**问题3**（4 分）

要求配置 PC 能通过 DHCP 服务器正常获取 IP 地址，请写出配置要点。

**参考答案**

要点分「服务器侧、网关侧、链路侧」三部分：

1. 服务器侧：在 DHCP 服务器（或核心交换机作为 DHCP 服务器）上创建 VLAN10、VLAN20 两个地址池，配置 `network`、`gateway-list`（指向 VRRP 虚拟 IP）、`dns-list`、`excluded-ip-address`（排除网关、服务器等固定地址）、`lease`。
2. 网关侧：在 SW1、SW2 的 VLANIF 上启用 DHCP。若由外部服务器分配，则配置 DHCP 中继并指向服务器地址：

```text
[SW1] dhcp enable
[SW1] interface Vlanif 10
[SW1-Vlanif10] dhcp select relay
[SW1-Vlanif10] dhcp relay server-ip 10.0.1.10
```

3. 链路侧：SW1/SW2 与 SW3/SW4 之间为 Trunk 并允许 VLAN10、VLAN20 通过；接入交换机接终端的端口为 Access 并划入对应 VLAN。
4. 安全侧：接入交换机开启 **DHCP Snooping**，上联口设为信任端口，防止私接 DHCP 服务器；核心侧可配置 `dhcp snooping check` 与 Option82。

**解析**

考查 DHCP 的四种报文（Discover/Offer/Request/ACK）、单播/广播转换，以及中继与 Snooping 的分工。

- 网关在核心层时，DHCP 有两种落地方式：核心自己作服务器（`dhcp select global`）或作中继（`dhcp select relay`）。题干说「通过 DHCP 服务器」，故以中继为主，但要说明服务器侧地址池。
- `gateway-list` 必须填 VRRP 虚拟 IP，不能填某台核心的实地址，否则主备切换后终端网关失效——这是本题最易丢分的细节。
- 常见失分点：① 只写「开 DHCP」不区分服务器/中继；② 地址池网关填错；③ 漏掉 Trunk 放行 VLAN，导致 DHCP 广播到不了服务器；④ 把 DHCP Snooping 与 DHCP 中继混为一谈。

**【考点】** DHCP 报文交互与地址池参数；DHCP 中继；DHCP Snooping 的作用与信任端口。

**问题4**（4 分）

为加强终端 PC 安全防护，要求各 PC 均不能互访，请写出配置要点。

**参考答案**

按「同交换机」与「跨交换机」两种情况作答：

1. 同一接入交换机下的 PC：在接入端口上开启**端口隔离**，把端口加入同一隔离组：

```text
[SW3] port-group group-member GigabitEthernet0/0/1 to GigabitEthernet0/0/20
[SW3-port-group] port-isolate enable group 1
```

隔离后同组端口之间二层不通，但都能访问上行口（网关）。

2. 跨接入交换机的 PC：端口隔离只在单台设备内生效，需在网关（核心 VLANIF）上限制终端网段之间的互访，或在接入交换机上应用流策略丢弃「同网段互访」流量；也可用 **MUX VLAN**（主 VLAN 与隔离 VLAN）或 **VLAN 聚合**实现。
3. 在核心层用 ACL 拒绝同网段主机之间的访问（只放行到网关和服务器的流量），例如：

```text
[SW1] acl number 3000
[SW1-acl-adv-3000] rule deny ip source 10.0.1.0 0.0.0.255 destination 10.0.1.0 0.0.0.255
[SW1-acl-adv-3000] rule permit ip
```

**解析**

考查二层隔离手段的层次与生效范围，是「方案要落地」的典型题。

- 端口隔离（port-isolate）是交换机的二层特性，只在本机生效；题目若要求「各 PC 均不能互访」且网络有多台接入交换机，只答端口隔离不完整。
- 需要区分「隔离广播域」（VLAN）与「隔离同一广播域内的主机」（端口隔离/MUX VLAN/ACL）：同 VLAN 内隔离必须用后者。
- 常见失分点：① 答「划分 VLAN」——题目已按部门划分 VLAN，部门内 PC 仍可互访；② 只答端口隔离，忽略跨设备场景；③ ACL 写成拒绝整个网段（会把网关也拒绝），未放行网关与服务器。

**【考点】** 端口隔离与 MUX VLAN；同 VLAN 内二层隔离；ACL 在网关上的应用。

**问题5**（4 分）

请按照 IP 地址最小范围规划要求完成下表。

| 部门 | PC 数量 | 网关 | 可分配 IP 地址 | 子网掩码 |
| ---- | ------- | ---- | -------------- | -------- |
| 行政部 | 19 | 10.0.1.158 | (1) | 255.255.255.(3) |
| 销售部 | 36 | 10.0.1.126 `[存疑]` | (2) | (4) 位 |

**参考答案**

| 部门 | PC 数量 | 网关 | 可分配 IP 地址 | 子网掩码 |
| ---- | ------- | ---- | -------------- | -------- |
| 行政部 | 19 | 10.0.1.158 | 10.0.1.129 ~ 10.0.1.158（/27，其中 .158 被网关占用，主机可用 .129~.157） | 255.255.255.224（27 位） |
| 销售部 | 36 | 10.0.1.126 | 10.0.1.65 ~ 10.0.1.126（/26，其中 .126 被网关占用，主机可用 .65~.125） | 255.255.255.192（26 位） |

即（1）`10.0.1.129~10.0.1.158`；（2）`10.0.1.65~10.0.1.126`；（3）`224`；（4）`26`。

采分点：19 台 → 2^5-2=30，取 /27；36 台 → 2^6-2=62，取 /26；按「需求从大到小、地址块从低到高」排布，行政部落在 10.0.1.128/27，销售部落 10.0.1.64/26；掩码与位数必须对应。

**解析**

考查 VLSM（可变长子网掩码）与「最小范围」原则：每个子网的主机位数取满足需求的最小值。

- 计算口径：可用主机数 = 2^h - 2（去掉网络地址与广播地址）。19 台需要 h=5（30 个），36 台需要 h=6（62 个）。若忘记减 2，36 台会误算成 /27（30 个不够）。
- 排序技巧：先满足大网段（36 → 64 个地址的块），再放小网段；10.0.1.64/26 占 64~127，10.0.1.128/27 占 128~159，两块不重叠，且网关 .158、.126 恰好落在各自块的末尾。
- 常见失分点：① 两个部门用同一掩码（不做 VLSM）；② 「可分配 IP 地址」把网络地址或广播地址写进范围；③ 网关不在所划子网内；④ 子网掩码与「/位数」互换时写错（/26 → 192，/27 → 224）。
- `[存疑]`：原表两张截图中销售部网关亦显示为 10.0.1.158，与「两部门不同子网」矛盾；按行政部网关 .158 反推，其所在块必为 10.0.1.128/27，销售部取 10.0.1.64/26 时网关应为 .126，故按 .126 作答。考场上应以试卷原表为准。

**【考点】** VLSM 子网划分；可用主机数计算；网关与地址块的匹配。

### 1.3 案例3：静态 MPLS 与 LSP

**【说明】**（15 分）

某公司计划在骨干网络上建立静态 MPLS，以便部署 L2VPN 或者 L3VPN 业务。其网络拓扑结构如下所示。

**拓扑要点**（据原图整理）

| 设备 | 角色 | 接口与地址 | LoopBack |
| ---- | ---- | ---------- | -------- |
| LSR-1 | 入节点 LER | GE0/0/1 / VLANIF100：172.16.1.1/24 | 1.1.1.9/32 |
| LSR-2 | 中间节点 | VLANIF100：172.16.1.2/24；VLANIF200：172.16.2.1/24 | 2.2.2.9/32 |
| LSR-3 | 出节点 LER | VLANIF200：172.16.2.2/24 | 3.3.3.9/32 |

**问题1**（6 分）

MPLS 基于（1）进行转发，进行 MPLS 标签交换和报文转发的网络设备称为（2），构成 MPLS 域（MPLS Domain）。位于 MPLS 域边缘、连接其他网络的 LSR 称为（3），区域内部的 LSR 称为核心 LSR（Core LSR）。IP 报文进入 MPLS 网络时，MPLS 入口设备分析 IP 报文的内容并为其添加合适的标签，所有 MPLS 网络中的 LSR 根据标签转发数据，当该 IP 报文离开 MPLS 网络时，标签由出口 LER 弹出。IP 报文在 MPLS 网络中经过的路径称为（4），LSP 是一个单向路径，与数据流的方向一致。LSP 的入口 LER 称为（5）；位于 LSP 中间的 LSR 称为中间节点（Transit）；LSP 的出口 LER 称为（6）。一条 LSP 可以有 0 个、1 个或多个中间节点，但有且只有一个入节点和一个出节点。

（1）—（6）备选答案：

A. 标签交换路由器 LSR（Label Switching Router）
B. 标签交换路径 LSP（Label Switched Path）
C. 标签
D. 入节点（Ingress）
E. 边缘路由器 LER（Label Edge Router）
F. 出节点（Egress）

**参考答案**

| 空 | 答案 | 选项 |
| -- | ---- | ---- |
| (1) | 标签 | C |
| (2) | 标签交换路由器 LSR | A |
| (3) | 边缘路由器 LER | E |
| (4) | 标签交换路径 LSP | B |
| (5) | 入节点 Ingress | D |
| (6) | 出节点 Egress | F |

**解析**

考查 MPLS 的基本术语体系，属于「背了就能拿分」的题，但概念边界容易混。

- 记一条主线：**标签**是转发依据（替代目的 IP 查表）→ 做这件事的设备是 **LSR** → 域边缘的 LSR 叫 **LER** → 报文走过的单向路径叫 **LSP** → 路径两端叫 **Ingress/Egress**，中间叫 **Transit**。
- 易混点：LSR 是「设备」，LSP 是「路径」，LER 是「LSR 的一种角色」，三者不在同一维度；「核心 LSR」与「Transit」是同一台设备的两种叫法。
- 常见失分点：把 (1) 填成「IP 地址」或「FEC」；(3) 与 (5) 混淆（LER 是设备角色，Ingress 是 LSP 端点角色）。

**【考点】** MPLS 转发原理；LSR/LER/Transit 的角色；LSP 的单向性。

**问题2**（9 分）

上图中，骨干网络中已完成路由协议配置，各个节点之间可以互通。下面是为该网络配置静态 MPLS 的代码，请将下面的配置代码补充完整。

```text
# 使能 LSR-1 及各接口的 MPLS 功能
[LSR-1] mpls (1) 1.1.1.9
[LSR-1] (2)
[LSR-1-mpls] quit
[LSR-1] interface (3) 100
[LSR-1-Vlanif100] mpls
[LSR-1-Vlanif100] quit

# 创建从 LSR-1 到 LSR-3 的静态 LSP
[LSR-1] static-lsp ingress LSP1 destination 3.3.3.9 32 nexthop 172.16.1.2 (4) 20
[LSR-2] static-lsp transit LSP1 incoming-interface Vlanif100 in-label (5) nexthop 172.16.1.2 out-label (6)
[LSR-3] static-lsp egress LSP1 incoming-interface Vlanif200 (7) 40

# 创建从 LSR-3 到 LSR-1 的静态 LSP
[LSR-3] static-lsp ingress LSP2 destination 1.1.1.9 32 nexthop 172.16.1.1 out-label 30
[LSR-2] static-lsp transit LSP2 incoming-interface Vlanif200 in-label (8) nexthop 172.16.1.1 out-label (9)
[LSR-1] static-lsp egress LSP2 incoming-interface Vlanif100 in-label 60
```

**参考答案**

| 空 | 答案 | 含义 |
| -- | ---- | ---- |
| (1) | `lsr-id` | 配置本设备的 LSR ID（一般取 LoopBack0 地址） |
| (2) | `mpls` | 全局使能 MPLS 功能 |
| (3) | `Vlanif` | 进入 VLANIF100 接口视图（大小写不敏感） |
| (4) | `out-label` | 入节点为报文压入的出标签，值 20 |
| (5) | `20` | 中间节点的入标签，必须等于上游的出标签 |
| (6) | `40` | 中间节点的出标签，必须等于下游的入标签 |
| (7) | `in-label` | 出节点的入标签，值 40 |
| (8) | `30` | LSP2 中间节点的入标签，等于 LSR-3 的出标签 30 |
| (9) | `60` | LSP2 中间节点的出标签，等于 LSR-1 的入标签 60 |

**解析**

考查静态 LSP 的「逐跳标签一致性」：上游 out-label = 下游 in-label，标签在每一跳被交换。

- 配置顺序：先 `mpls lsr-id`（同时进入 MPLS 视图）→ 全局 `mpls` → 逐接口 `mpls`。三层接口（VLANIF）必须单独使能，漏掉这一步会出现「路由通、标签不通」。
- 静态 LSP 三个角色各一条命令：ingress 指定「目的网段 + 下一跳 + 出标签」，transit 指定「入接口 + 入标签 + 下一跳 + 出标签」，egress 指定「入接口 + 入标签」。
- 校验方法：沿路径把标签串起来（20 → 20/40 → 40；30 → 30/60 → 60），任意一处不相等，业务就不通。
- 常见失分点：① (1) 填 `router-id`（那是 OSPF/BGP 的命令）；② (4)(5)(6) 只填数值不填关键字或反之；③ 把 transit 的 `incoming-interface` 写成出接口；④ 忘记接口下的 `mpls`。

**【考点】** 静态 LSP 的建立；ingress/transit/egress 命令；标签分配与逐跳一致性；MPLS 与 IGP 的关系。

### 1.4 案例4：BGP 邻居、下一跳与路由反射

**【说明】**（20 分）

某网络拓扑如下图所示，路由器 R1、R2、R3 通过 OSPF 实现网络互通，R1 和 R3 建立 iBGP 邻居关系，R3 和 R5 建立 eBGP 邻居关系，R1 和 R4 建立 eBGP 邻居关系。

**拓扑要点**（据原图整理）

| 设备 | AS | 邻居关系 | 说明 |
| ---- | -- | -------- | ---- |
| R1 | 100 | 与 R3 iBGP；与 R4 eBGP | R1—R4 接口 10.14.14.1/.4 |
| R2 | 100 | 与 R1、R3 运行 OSPF | 纯 IGP 转发设备 |
| R3 | 100 | 与 R1 iBGP；与 R5 eBGP | R3—R5 接口 10.35.35.3/.5 |
| R4 | 200 | 与 R1 eBGP | LoopBack0 模拟 ISP 地址 210.23.3.4/32 |
| R5 | 300 | 与 R3 eBGP | 观察路由的一方 |

**问题1**（10 分）

各路由器 IP 地址等基本参数已正确配置，且 R1、R2、R3 之间 OSPF 邻居关系已建立且完成收敛，在 R4 配置本地回环 Lo0 模拟 ISP 地址 210.23.3.4/32，根据要求完成以下配置。

```text
# 以 R1 为例配置 BGP
[R1] bgp (1)
[R1-bgp] peer (2) as-number (3)     // 与 R4 建立 BGP 邻居关系
[R1-bgp] peer 10.14.14.4 enable
……
[R1-bgp] peer 3.3.3.3 next-hop-local    // 作用是：(4)

# 在 R4 将 210.23.3.4/32 引入 BGP
[R4] bgp 200
[R4-bgp] (5)                        // 将 210.23.3.4/32 引入 BGP
```

**参考答案**

| 空 | 答案 | 说明 |
| -- | ---- | ---- |
| (1) | `100` | R1 所在 AS 号；与 R3 是 iBGP，故与 R3 同 AS |
| (2) | `10.14.14.4` | R4 侧接口地址（对等体地址） |
| (3) | `200` | R4 的 AS 号，与本地不同即为 eBGP |
| (4) | 把从 eBGP 邻居学到的路由发给 iBGP 邻居时，将下一跳改为自己的接口地址，避免 iBGP 邻居因下一跳不可达而不选路 | 关键字：next-hop-local、下一跳改为自己、解决下一跳不可达 |
| (5) | `network 210.23.3.4 255.255.255.255`（或 `network 210.23.3.4 32`） | 用 network 精确宣告，掩码必须与路由表一致 |

**解析**

考查 BGP 的邻居类型判断与两条最常考的命令：`peer … as-number`、`next-hop-local`。

- iBGP 与 eBGP 的判别只看 AS 号是否相同：R1 与 R3 同为 AS 100 → iBGP；R1 与 R4 的 AS 不同 → eBGP。因此 `bgp` 后填本机 AS 100，`as-number` 后填对端 AS 200。
- 为什么需要 next-hop-local：BGP 从 eBGP 学到的路由，下一跳是外部对等体的地址；直接转给 iBGP 邻居时，iBGP 邻居可能没有到该外部地址的路由（该网段不在 IGP 中），路由虽在 BGP 表中却不可用（下一跳不可达）。改为 local 后下一跳变成自己，iBGP 邻居可经 IGP 到达。
- `network` 与 `import-route` 的区别：`network` 是逐条精确匹配（网段 + 掩码都要与路由表一致），`import-route` 是按协议批量引入（起源属性为 incomplete）。
- 常见失分点：① (1) 填 200；② (4) 只写「改变下一跳」不说「发给 iBGP 邻居时」；③ (5) 漏写掩码 32，导致路由不宣告。

**【考点】** iBGP 与 eBGP 的建立条件；BGP 下一跳行为与 next-hop-local；network 宣告方式。

**问题2**（3 分）

上述配置完成后，路由器 R5 上 210.23.3.4/32 的路由信息如下图所示，但是却无法 ping 通 210.23.3.4，请分析原因。

```text
<R5> display bgp routing-table
Total Number of Routes : 1
   Network            NextHop        MED   LocPrf   PreVal   Path/Ogn
*> 210.23.3.4/32      10.35.35.3                          100 200i
```

**参考答案**

BGP 表中有路由，只说明「控制平面学到了」，不代表「数据平面能转发」。原因从以下三点分析，答出任意两点并说清机理即可：

1. **AS 100 内 iBGP 未全互联 / 未配置路由反射**：R1 从 eBGP 邻居 R4 学到 210.23.3.4/32 后，受 iBGP 水平分割限制，从 iBGP 邻居学到的路由不会再传给其它 iBGP 邻居。若 R2 等设备没有该路由，报文在 AS 100 内部转发时会在缺少路由的设备上被丢弃，形成**路由黑洞**。
2. **下一跳不可达**：R5 看到的下一跳是 10.35.35.3（R3），若 R3 到 210.23.3.4 的下一跳（R1 与 R4 的互联地址 10.14.14.4）不在 OSPF 中宣告，R3 上该 BGP 路由不生效，报文到 R3 后无法继续转发。
3. **回程路由缺失**：R4 上没有回到 R5 源地址所在网段的路由（R5 侧网段未通过 BGP 通告给 R4），请求能到达、回应回不来，同样表现为 ping 不通。

**解析**

考查「BGP 路由存在 ≠ 业务可达」这一核心观念，以及 iBGP 水平分割、下一跳可达性、回程路由三大排查点。

- 排查顺序：R5 有路由 → 看下一跳能否 ping 通 → 在 R3 上看该 BGP 路由是否 `*>`（有效）→ 在 R1 上看是否 `next-hop-local` → 在 R4 上看是否有回程路由。
- BGP 只负责传递可达性信息，实际转发仍依赖 IGP 提供下一跳可达；这就是「BGP 是路径矢量协议、需要 IGP 承载」的含义。
- 常见失分点：① 只答「路由没生效」而不指出是哪一环；② 答「AS 号配错」——AS 号错就不会有这条路由；③ 忽略回程路由，只答单向。
- `[存疑]`：原题依赖拓扑细节（R2 是否为 iBGP 邻居、R1—R4 网段是否在 OSPF 内），公开版本无法完全还原；考场作答应结合图中邻居关系选择上述最贴合的一条主答，再补另一条。

**【考点】** iBGP 水平分割与路由黑洞；BGP 下一跳可达性；控制平面与转发平面的区别。

**问题3**（7 分）

管理员计划采用 BGP 路由反射功能解决上述问题。BGP 路由反射功能需要遵循如下三条规则：

从非客户机学到的路由，反射器发布给（1）；
从客户机学到的路由，反射器发布给（2）；
从 eBGP 邻居学到的路由，反射器发布给所有的非客户机和客户机。

```text
# BGP 反射器配置片段，配置 R1 为反射器、R2 为客户端……略去 R2 和 R1 建立 BGP 邻居配置
[R1-bgp] reflector cluster-id 12     // 该条命令的作用是（3）
[R1-bgp] peer (4) reflect-client
```

**参考答案**

| 空 | 答案 |
| -- | ---- |
| (1) | 所有的客户机（不能发给非客户机） |
| (2) | 所有的客户机和非客户机（即除该客户机外的所有 iBGP 邻居） |
| (3) | 配置路由反射器的集群 ID 为 12；同一集群内的客户机之间不互相反射，用于防止集群内环路（缺省时以 router-id 作为 cluster-id） |
| (4) | R2 的 BGP 邻居地址（R1 与 R2 互联接口上 R2 的地址，图中为 10.12.0.2）`[存疑]` |

三条规则的记忆表：

| 路由来源 | 反射给 |
| -------- | ------ |
| 非客户机（iBGP） | 客户机 |
| 客户机（iBGP） | 所有客户机 + 所有非客户机 |
| eBGP 邻居 | 所有客户机 + 所有非客户机 |

**解析**

考查路由反射器（RR）的三条反射规则与 cluster-id 的作用，本质是「打破 iBGP 水平分割」。

- 三条规则可以概括为「来自客户机的可以给所有人，来自非客户机的只能给客户机，来自 eBGP 的给所有人」。这样既避免了全互联，又不会产生环路。
- cluster-id 用于标识反射器集群：一个集群内可以有多个 RR 互为备份，集群 ID 相同可防止 RR 之间互相反射形成环。缺省取 router-id。
- 常见失分点：① 把「非客户机」与「客户机」的反射范围写反；② (3) 答「配置集群编号」但不说「防止环路」；③ (4) 写成 R2 的 router-id（应为邻居地址，除非 peer 用 loopback 建立）。

**【考点】** 路由反射器的角色（RR、客户机、非客户机、集群）；三条反射规则；cluster-id 的防环作用。

### 2.2 答题模板

**模板一：配置填空题（补全命令）**

1. 先看提示符，确定当前视图：`< >` 用户视图、`[ ]` 系统视图、`[设备-接口]` 接口视图、`[设备-协议]` 协议视图。
2. 看注释，注释往往直接写出该行功能，按「功能 → 命令」反查，而不是凭记忆背整段。
3. 数值型空（标签、优先级、ACL 号、端口号）从题干条件反推，并检查一致性（如上游 out-label = 下游 in-label）。
4. 写完通读一遍，确认视图切换（`quit`）与命令顺序合理。

**模板二：故障分析题**

按「现象 → 分层定位 → 根因 → 措施 → 验证」五步作答：

1. 现象：用题干给出的命令输出（会话表、路由表、ARP 表、ping 结果）描述异常点。
2. 分层：物理/链路 → IP/路由 → NAT/策略 → 应用，逐层排除，指出「哪一层正常、哪一层异常」。
3. 根因：一句话点明，如「未配置源 NAT」「iBGP 下一跳不可达」「ARP 表项被篡改」。
4. 措施：写清「在哪台设备、哪个视图、配什么命令、达到什么效果」。
5. 验证：给出一条验证命令（`display firewall session table`、`display bgp routing-table`、`display arp`）。

**模板三：方案设计题（冗余、隔离、认证、负载）**

1. 先分层：接入层、汇聚/核心层、出口层、终端侧，各层分别给手段。
2. 每层给「主手段 + 备选手段」，并说明适用条件与代价（如 STP 浪费带宽、堆叠受距离限制）。
3. 落到配置：至少给出一段关键命令或关键参数（vrid、优先级、隔离组、ACL 号）。
4. 收尾写验证与注意事项（如 VRRP 与 STP 的配合、DHCP Snooping 信任端口）。

**模板四：地址规划计算题**

1. 统计每个子网的主机数，按从大到小排序。
2. 主机位 h = ⌈log2(需求 + 2)⌉，前缀 = 32 - h。
3. 按块大小对齐分配，写出「网络地址/前缀、可用范围、广播地址、掩码」四元组。
4. 检查：块不重叠、网关在块内、预留地址（网关、服务器、VRRP 虚地址）已排除。
5. IPv6 题先确定给定前缀的子网位边界，再按业务切块，写出起止地址。

**易错点清单**

- VRRP 虚拟 IP 被写成某台设备的实地址；双活时两个 VLAN 的优先级没有互换。
- 只答「配置 STP」而不说清冗余链路的范围；把 VRRP 当成防环手段。
- NAT 与安全策略混为一谈；会话表已建立却仍答「策略未放行」。
- BGP 有路由就认为可达，忽略下一跳与回程。
- 静态 LSP 标签上下游不一致；漏配接口下的 `mpls`。
- 子网划分忘记减去网络地址与广播地址，或把网关划到子网外。
- IPv6 规划只按终端数量选前缀，忽略题目已给的 /49 层级。
