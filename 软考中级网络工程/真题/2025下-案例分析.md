### 1.2 案例2 L2TP VPDN 配置补全

> 考点：L2TP 控制/数据消息、UDP 1701、L2TP over IPSec、PPPoE 服务器、隧道认证与隧道名称

**【说明】**

某公司在其他城市设有多个分支机构，分支机构内部使用以太网络。为了便于分支机构开展工作，现计划在分支和总部之间部署 L2TP，以实现 VPDN 连接。网络拓扑图如下所示。

`[原文为图/表，需对照原卷]`（拓扑图未收录，L2TP-Server 的公网地址、两端接口地址需对照原卷）

**问题1**（2 分）

L2TP 协议有两种类型的消息，其中，（1）消息用于 L2TP 隧道和会话的建立、维护和拆除；数据消息用于封装 PPP 数据帧，基于传输层的（2）协议进行不可靠的数据传输。L2TP 不具备加密功能，在 VPN 应用中可结合（3）技术实现隧道传输和数据加密的完整解决方案。

**参考答案**

| 空号 | 答案 | 说明 |
| ---- | ---- | ---- |
| （1） | 控制（Control） | 控制消息负责隧道/会话的建立、维护、拆除，可靠传输 |
| （2） | UDP | 数据消息封装在 UDP 中（目的端口 1701），不保证可靠 |
| （3） | IPSec（IPSec VPN / L2TP over IPSec） | L2TP 只做隧道不做加密，由 IPSec 提供加密与完整性保护 |

**解析**

L2TP 的两类消息是必背点：**控制消息可靠**（在 L2TP 内部有序列号、重传机制），**数据消息不可靠**（跑在 UDP 上，靠上层 PPP/应用保证）。两者都用 UDP 1701，区别在于是否带可靠传输机制。

「L2TP + IPSec」是标准组合：L2TP 解决**多协议、多链路拨号的隧道封装**，IPSec 解决**机密性、完整性、源认证、抗重放**。只答 IPSec 不写「L2TP over IPSec」也算对，但写成 PPTP/SSL 则错。

```text
[L2TP-User-l2tp1] tunnel password cipher admin   //启用隧道认证功能并设置隧道认证字
[L2TP-User-l2tp1] quit
…略…

2.L2TP-Server配置
…略…
[L2TP-Server] l2tp-group 1
[L2TP-Server-l2tp1] tunnel name l2tp-server   //配置和指定两端隧道名称
[L2TP-Server-l2tp1] allow l2tp virtual-template 1 remote（8）
[L2TP-Server-l2tp1] tunnel authentication
[L2TP-Server-l2tp1] tunnel password cipher（9）
[L2TP-Server-l2tp1] quit
…略…
```

**参考答案**

| 空号 | 答案 | 说明 |
| ---- | ---- | ---- |
| （4） | `chap` | 题干指定 CHAP 认证 |
| （5） | `1` | 绑定 Virtual-Template 1（编号与上面创建的一致） |
| （6） | `enable` | `l2tp enable`，全局使能 L2TP |
| （7） | L2TP-Server 的公网 IP 地址（如 113.x.x.x，按原图） | `start l2tp ip <服务器地址> fullusername user1`，主动发起隧道 |
| （8） | `l2tp-user` | remote 后接**对端（L2TP-User）的隧道名称**，须与对端 `tunnel name` 完全一致 |
| （9） | `admin` | 隧道认证字必须两端一致（对端已设 `admin`） |

**解析**

本题的采分点集中在三组「两端必须一致」：

1. **隧道名称**：`tunnel name` 是标识，`remote` 填的是**对端的名字**而不是自己的，方向搞反是最高频错误；
2. **隧道认证字**：`tunnel password cipher` 两端必须相同，否则 Tunnel 建立时报认证失败；
3. **Virtual-Template 编号**：PPPoE 绑定与 L2TP 绑定都要指向同一个模板。

另外两个命令容易写错：`l2tp enable`（全局开关，漏了则隧道起不来）与 `start l2tp ip <address> fullusername user1`（`fullusername` 让服务端按「完整用户名」认证，配合服务端本地 AAA）。

PPPoE 侧 `ppp authentication-mode chap` 是**在 Virtual-Template 上**配置的，不是在物理口上；物理口只做 `pppoe-server bind virtual-template 1`。

**问题2**

配置 R1 与 R3 之间的 BFD 联动功能：

```text
#启用和配置BFD
[R1] bfd
[R1-bfd] quit
[R1] bfd 1to3 bind peer-ip（2）interface g0/0/3
#配置R1的静态和缺省路由，其中，到R3的缺省路由关联BFD，到R2的缺省路由优先级为100，实现链路感知快速切换。
[R1] ip route-static 10.2.2.0 255.255.255.0（3）    #通往异地分校走R2
[R1] ip route-static 0.0.0.0 0.0.0.0 10.12.12.2 preference（4）
[R1] ip route-static 0.0.0.0 0.0.0.0（5）track bfd-session（6）
```

**参考答案**

| 空号 | 答案 | 说明 |
| ---- | ---- | ---- |
| （2） | R3 侧与 R1 g0/0/3 直连的接口地址（按图 1） | `bind peer-ip` 填**对端（R3）的接口地址** |
| （3） | R2 侧与 R1 直连的接口地址（按图 1） | 通往 10.2.2.0/24 的下一跳为 R2 |
| （4） | `100` | 备份默认路由优先级设为 100（大于主路由默认 60，故不优选） |
| （5） | R3 侧与 R1 直连的接口地址（同（2）） | 主默认路由，下一跳指向 R3 |
| （6） | `1to3` | 与前面创建的 BFD 会话名一致 |

配置完整性说明（答题时可补）：

```text
[R1-bfd-session-1to3] discriminator local 1
[R1-bfd-session-1to3] discriminator remote 3
[R1-bfd-session-1to3] commit
```

- 主默认路由：优先级默认 60，绑定 BFD 会话 1to3；
- 备默认路由：`preference 100`，不绑 BFD，靠优先级实现「主挂备上」；
- 两条默认路由**目的相同、优先级不同**才是备份关系；优先级相同则变成负载分担。

**解析**

本题是「静态路由 + BFD」的经典组合，三个采分点：

1. **BFD 会话绑定对端 IP + 出接口**：`bfd 1to3 bind peer-ip x.x.x.x interface g0/0/3`，peer-ip 一定是**对端**地址；由于 R1—R3 之间隔了二层交换机 S1，必须显式指定出接口，否则无法确定路径；
2. **preference 的数值关系**：静态路由默认 60，备份必须设更大的值（100），数字写反就变成备份抢占主用；
3. **track 绑定**：`track bfd-session 1to3` 让路由跟随 BFD 状态，BFD 检测到链路故障（毫秒级）即撤销该静态路由，流量切到 R2，而不用等接口物理 Down 或 ARP 老化。

常见失分：把 BFD 的 peer-ip 写成本端地址；把 preference 写成 10 或 60；track 后跟 BFD 会话名写成接口名。

**问题3**

```text
#请补全识别外发目的地属于教育网网段202.112.0.0/16流量的ACL规则，网关为202.112.144.1
[R3] acl 3000
[R3-acl-adv-3000] rule permit ip（7）202.112.0.0 0.0.255.255
[R3] policy-based-route edu permit node 10
[R3-policy-based-route-edu-10] if-match acl 3000
[R3-policy-based-route-edu-10] apply ip-address next-hop（8）
```

异地分校通过 IPSec VPN 方式访问主校区资源，请简要说明使用 IPSec VPN 的优点（9）。

**参考答案**

| 空号 | 答案 | 说明 |
| ---- | ---- | ---- |
| （7） | `destination` | `rule permit ip destination 202.112.0.0 0.0.255.255`，匹配目的地址 |
| （8） | 教育网骨干出口的下一跳地址（按图 1） | PBR 的动作，指向教育网出口 |
| （9） | 见下 | IPSec VPN 优点 |

（9）IPSec VPN 的优点（答出 3～4 点）：

- **机密性**：ESP 加密载荷，数据在公网传输不被窃听；
- **完整性**：AH/ESP 的哈希校验，防止报文被篡改；
- **身份认证与抗重放**：IKE 双方认证 + 序列号防重放，防冒充；
- **成本低、部署快**：基于现有互联网链路，无需铺设专线，跨地域接入灵活；
- **支持站点到站点与移动接入**：分支、出差人员均可安全访问主校区资源；
- **可与路由/策略结合**：通过感兴趣流（ACL）精确控制哪些流量走隧道。

**解析**

（7）的关键是「**外发目的地**」四个字：ACL 3000 是高级 ACL，规则格式为 `rule permit ip source ... destination ...`，此处只给了目的地址，故填 `destination`。若填 `source` 则语义完全相反，一分不得。

（8）是 PBR 的 next-hop，必须指向**教育网出口的对端地址**；注意 PBR 只是在 R3 上给「命中 ACL 的流量」指定下一跳，未命中的仍按路由表走 Internet 默认路由，这正是题干「其他流量走 Internet 出口」的实现方式。

（9）要按「安全三性（机密性、完整性、认证）+ 工程性（成本、灵活、可扩展）」两组来答。只写「安全」不给分；把 IPSec 说成「加密隧道、比专线便宜」是最低配的两点。

**问题2**（6 分）

该园区网络按照层次化网络（三层）设计，请简述每层应实现的功能。

**参考答案**

| 层次 | 主要功能 |
| ---- | -------- |
| 核心层 | 高速数据转发（尽量不做复杂策略，保证线速转发）；作为园区路由核心，连接各汇聚区与数据中心、出口；提供设备与链路冗余（堆叠/VRRP、链路聚合）、快速收敛；承担跨区域流量的高速交换与 QoS 调度 |
| 汇聚层 | 汇聚接入层流量、收敛广播域；作为各 VLAN 的三层网关（VLAN 间路由）；实施安全与流量策略（ACL、QoS 标记、限速）；与核心层双上行并提供冗余；地址汇总，减少核心路由表规模 |
| 接入层 | 提供终端接入端口（高密度、PoE 供电）；划分 VLAN、端口隔离、接入认证（802.1X/Portal）；接入安全（端口安全、DHCP Snooping、风暴抑制）；AP 接入与供电；就近接入、成本控制 |

**解析**

三层架构的答题要点是「**核心求快、汇聚求策略、接入求密度与安全**」。常见失分是把 ACL、NAT 等策略堆到核心层——层次化设计的初衷就是让核心只做高速转发。

另一个加分点是「可靠性如何在各层落地」：核心用堆叠/VRRP + 链路聚合，汇聚双上行，接入双网卡/双链路。以及「广播域收敛在汇聚层」这一句，能体现对二层域规模的理解。

**问题3**（6 分）

核心交换机可采用 VRRP 或堆叠实现关键节点设备冗余，请简要说明 VRRP 和堆叠的区别。

**参考答案**

| 对比项 | VRRP | 堆叠（iStack/CSS） |
| ------ | ---- | ------------------ |
| 工作原理 | 两台独立设备组成备份组，通过 VRRP 报文选举 Master/Backup，共用虚拟 IP 与虚拟 MAC 作为网关 | 多台设备通过堆叠口/堆叠线缆虚拟成**一台逻辑设备**，控制面统一、转发表同步 |
| 转发方式 | 主备（或负载分担多组），**备用设备平时不转发**，带宽利用率低 | 双活转发，所有成员设备均可转发，**带宽可叠加** |
| 切换速度 | 秒级（依赖 VRRP 通告与 ARP 收敛，可结合 BFD 提速） | 毫秒级，成员故障由其他成员无缝接管 |
| 管理方式 | 两台设备**独立管理**，配置需分别维护、保持一致 | **单一管理面**，配置一次全网生效 |
| 链路利用 | 需配合 MSTP/多组 VRRP 才能部分利用备用链路 | 支持**跨设备链路聚合（M-LAG/ETH-Trunk 跨成员）**，消除二层环路，无需 STP 阻塞 |
| 适用与限制 | 设备型号可不同、距离可较远，组网易扩展 | 要求同型号/同版本、堆叠线缆距离受限，软件升级需整体进行，控制面耦合，故障域较大 |

**解析**

答题建议按「**原理—转发—切换—管理—限制**」五个维度对比，每个维度 1～1.5 分。只说「一个主备一个虚拟化」只得基础分。

易错点：① 认为 VRRP 能提升带宽（标准 VRRP 是主备，除非做多组负载分担）；② 忽略堆叠的**限制**（同型号、距离、升级窗口、控制面耦合），题目问「区别」，优缺点都要写；③ 把堆叠与链路聚合混为一谈——链路聚合是链路级冗余，堆叠是设备级虚拟化。

**问题4**（4 分）

请简要回答该数据中心的配电方案设计要点。

**参考答案**

- **双路市电 + 后备电源**：两路独立市电引入，配置 UPS（2N 或 N+1 冗余）与柴油发电机，保证市电中断后不间断供电；
- **UPS 容量与后备时间**：按 IT 负载 + 制冷/消防等辅助负载核算，预留 20%～30% 余量，后备时间满足发电机启动与安全关机；
- **机柜双路供电（A/B 路）**：服务器双电源分别接 A、B 两路 PDU，A/B 路分别来自不同 UPS，实现单路故障不断电；
- **配电层级清晰**：市电→变压器→低压配电→UPS→列头柜/配电柜→机柜 PDU，分级配置断路器，容量与线缆载流量匹配；
- **负载分区与计量**：IT 负载与空调、照明等动力负载分开配电；分路/分柜计量（PUE 监测），便于容量管理与扩容；
- **安全与运维**：防雷接地、等电位联结、短路/过载保护、配电监控告警（电流、温度、电量），标识清晰、检修可隔离。

**解析**

数据中心配电的采分骨架是「**两路电源 + UPS + 双路 PDU + 分级配电 + 监控**」。题干只问「要点」，4 分答 4～5 条即可，但每条要具体到设备或指标，例如写出「2N/N+1」「A/B 路 PDU」「列头柜」，而不是笼统的「保证供电可靠」。

常见失分：只写 UPS 不写双路市电与发电机；忽略机柜级 A/B 双路（这是「单点故障」的关键）；把「空调配电」与「IT 配电」混在一起。

### 2.2 高频结论速记

| 场景 | 结论 |
| ---- | ---- |
| L2TP 消息 | 控制消息可靠（建/维/拆隧道与会话）；数据消息走 UDP 1701，不可靠 |
| L2TP 加密 | 本身不加密，配 IPSec（L2TP over IPSec） |
| 隧道对接 | `tunnel name` 自定义，`remote` 填**对端**名字；认证字两端一致 |
| BFD 绑定 | `bfd 名 bind peer-ip <对端IP> interface <出接口>`，隔二层设备必须写出接口 |
| 主备默认路由 | 主 60（默认）、备 `preference 100`，主路由 `track bfd-session` |
| PBR | `acl 3000` + `rule permit ip destination ...` + `policy-based-route` + `apply ip-address next-hop` |
| 三层架构 | 核心快、汇聚策略、接入密度与安全；广播域收敛在汇聚 |
| VRRP vs 堆叠 | 主备 vs 双活；独立管理 vs 单一管理面；秒级 vs 毫秒级 |
| 数据中心配电 | 双路市电 + UPS（2N/N+1）+ 发电机 + 机柜 A/B 双 PDU + 分级计量 |
