### 1.2 可靠性的三个层面

网络的可靠性指当设备或者链路出现单点或者多点故障时，保证网络服务不间断的能力。讲义把它拆成三个层面：

| 层面 | 解决手段 | 典型技术 |
| ---- | -------- | -------- |
| 单板级 | 关键板卡冗余 | 双主控板、多交换网板、冗余电源与风扇 |
| 设备级 | 设备冗余 | 双上行、主备备份（配合 STP） |
| 链路级 | 链路冗余 | 多条物理链路、链路聚合 |

三者是叠加关系：单板冗余保证一台设备内部不出单点，设备冗余保证一台设备整机故障时业务不倒，链路冗余保证一条链路断开时流量仍有出口。

### 1.3 框式交换机的硬件可靠性

框式交换机由机框、电源模块、风扇模块、主控板、交换网板、线路板构成：

| 部件 | 英文/缩写 | 职责 |
| ---- | --------- | ---- |
| 机框 | chassis | 为各种板卡、模块提供插槽，实现板卡间通信 |
| 电源模块 | — | 设备的供电系统 |
| 风扇模块 | — | 设备的散热系统 |
| 主控板 | MPU，Main Processing Unit | 负责整个系统的控制平面和管理平面 |
| 交换网板 | SFU，Switch Fabric Unit | 负责整个系统的数据平面，提供高速无阻塞数据通道 |
| 线路板 | LPU，Line Processing Unit | 提供数据转发功能，提供不同速率的光口、电口 |

以 S12700E-8 为例：**8 个线路板槽位、4 个交换网板槽位、2 个主控板槽位、6 个电源模块槽位、4 个风扇模块槽位**。

故障影响范围：

| 故障部件 | 影响 |
| -------- | ---- |
| 单块主控板 | 不影响设备的控制平台正常工作（另一块接管） |
| 部分交换网板 | 数据平面依旧正常转发数据 |
| 线路板 | 该板卡上的接口无法正常转发数据 |
| 电源/风扇模块 | 冗余配置下由其余模块承担，全部故障则整机下电或过热保护 |

结论：**框式交换机配置多个主控板、交换网板，可保证设备自身的可靠性；单板冗余只能解决“板卡坏”，解决不了“整机坏”和“链路断”。**

### 1.4 设备级与链路级冗余的局限

**设备级：无备份 vs 主备备份**

| 方案 | 组网 | 故障后果 |
| ---- | ---- | -------- |
| 无备份 | 接入交换机单上行接入汇聚交换机 | 上行接口故障或设备故障，下游网络全部中断 |
| 主备备份 | 接入交换机双上行接入两台汇聚交换机，STP 选出一主一备 | 主链路上行接口或设备故障时切换到备份链路，由备份设备转发 |

**链路级：多条链路仍被 STP 阻断**

为保证设备间链路可靠性，在设备间部署多条物理线路；为防止环路，STP 只保留一条链路转发流量，其余链路成为备份链路。

由此产生三个问题，这正是链路聚合要解决的：

| 问题 | 表现 |
| ---- | ---- |
| 带宽无法叠加 | 多条千兆链路互联，实际只有一条在转发，带宽仍为 1 Gbps |
| 链路利用率低 | 备份链路长期空闲 |
| 故障恢复慢 | 依赖 STP 收敛，秒级中断 |

## 2.链路聚合基本原理

### 2.1 Eth-Trunk 的定义与作用

以太网链路聚合（Eth-Trunk，简称链路聚合）：通过将多个物理接口捆绑成为一个逻辑接口，在不进行硬件升级的条件下达到增加链路带宽的目的。

| 作用 | 说明 |
| ---- | ---- |
| 增加带宽 | 多条物理链路带宽叠加，突破单链路上限 |
| 提高可靠性 | 成员链路互为备份，一条断开其余继续转发 |
| 负载分担 | 流量在各成员链路间分担 |
| 节约成本 | 用多条低速链路替代一条高速链路，无需更换硬件 |

与 STP 方案的根本差异：STP 让冗余链路**阻塞**，Eth-Trunk 让冗余链路**同时转发**。

### 2.2 基本术语

| 术语 | 英文/缩写 | 含义 |
| ---- | --------- | ---- |
| 聚合组 | LAG，Link Aggregation Group | 若干条链路捆绑形成的逻辑链路，唯一对应一个逻辑接口 |
| 链路聚合接口 | Eth-Trunk 接口 | 聚合组对应的逻辑接口 |
| 成员接口 | member interface | 组成 Eth-Trunk 的各个物理接口 |
| 成员链路 | member link | 成员接口对应的链路 |
| 活动接口 | Selected interface | 参与数据转发的成员接口 |
| 活动链路 | Active link | 活动接口对应的链路 |
| 非活动接口 | Unselected interface | 不参与转发数据的成员接口 |
| 非活动链路 | Inactive link | 非活动接口对应的链路 |
| 聚合模式 | — | 按是否开启 LACP，分为手工模式和 LACP 模式 |
| 活动接口上限阈值 | max active-linknumber | 允许成为活动接口的最大数量，超出部分作备份 |
| 活动接口下限阈值 | least active-linknumber | 活动接口数低于该值时，Eth-Trunk 接口转为 Down |

### 2.3 聚合成立的条件

| 条件 | 说明 |
| ---- | ---- |
| 成员口属性一致 | 两端相连的物理接口数量、速率、双工方式、流控配置必须一致 |
| 同类型同速率 | 成员接口必须是同类型、同速率的以太网接口 |
| 两端同时加入 | 本端接口加入 Eth-Trunk，对端直连接口也必须加入 Eth-Trunk |
| 模式一致 | 两端必须同为手工模式或同为 LACP 模式 |
| VLAN 允许列表一致 | 两端 Eth-Trunk 的链路类型与允许通过的 VLAN 必须一致 |
| 成员口无业务配置 | 接口加入 Eth-Trunk 时原有配置会被清空，业务配置应直接配在 Eth-Trunk 上 |

补充说明：

- 缺省情况下，不同速率的端口不能加入同一个 Eth-Trunk；部分设备支持 `mixed-rate link enable`（V600 命令为 `lacp mixed-rate link enable`）放开该限制，但考场与工程实践中仍以同速率为准；
- 聚合组的负载分担计算**不以端口带宽速率作为权重**；
- 聚合后的理论带宽为各活动成员链路带宽之和，实际吞吐受负载分担算法与流量分布影响。

### 2.4 与 STP 方案的对比

| 比较项 | STP 冗余链路 | Eth-Trunk |
| ------ | ------------ | --------- |
| 转发链路数 | 只有一条（其余阻塞） | 全部活动链路同时转发 |
| 带宽 | 不叠加 | 叠加 |
| 链路利用率 | 低 | 接近 100% |
| 故障切换 | 依赖 STP 收敛，较慢 | 成员口故障即剔除，剩余链路继续转发 |
| 配置复杂度 | 需规划根桥、开销、端口角色 | 两端各建一个 Eth-Trunk 即可 |
| 环路 | 靠阻塞消除 | 逻辑上只有一条链路，本身无环 |

概念与配置基础详见 11.1 §2.1~2.2。

## 3.手工模式

### 3.1 工作机制

手工模式（Normal 模式、手动负载分担模式）：Eth-Trunk 的建立、成员接口的加入均由管理员手工配置，双方系统之间**不使用 LACP 协商**。

| 特征 | 说明 |
| ---- | ---- |
| 建立方式 | 纯静态绑定，无协议报文交互 |
| 成员口状态 | 正常情况下所有成员口都是活动接口，全部参与转发 |
| 流量分配 | 在各活动链路间平均分担 |
| 故障处理 | 某条活动链路故障，剩余活动链路自动重新平均分担 |
| 适用前提 | 聚合两端设备中至少有一端不支持 LACP，或设备老旧、低端 |

### 3.2 两个固有缺陷

**缺陷一：对端必须属于同一设备、同一聚合接口**

为使链路聚合接口正常工作，必须保证本端聚合接口中所有成员接口的对端接口满足两个条件：属于同一台设备、加入同一个链路聚合接口。手工模式下设备间没有报文交互，只能由管理员人工确认。

如果对端成员口分散在**两台不同的交换机**上，本端会把它们当作同一条逻辑链路的成员，实际转发时会出现报文从 A 设备出去、回包从 B 设备回来的错乱。

**缺陷二：只能靠物理层判断对端状态**

手工模式下设备只能通过物理层状态判断对端接口是否正常工作。若链路一端的光纤收方向故障、或中间传输设备单向不通，本端接口物理状态仍为 Up，但报文发出去后无法到达对端，形成**“接口 Up 但业务不通”**的隐性问题。

LACP 模式正是为解决这两个缺陷而设计。

### 3.3 配置命令

| 步骤 | 命令 | 视图 | 说明 |
| ---- | ---- | ---- | ---- |
| 1 | `interface eth-trunk trunk-id` | 系统 | 创建 Eth-Trunk 接口并进入其视图 |
| 2 | `mode manual load-balance` | Eth-Trunk | 配置为手工模式（缺省即手工模式） |
| 3 | `trunkport interface-type interface-number [ to interface-number ]` | Eth-Trunk | 批量加入成员接口 |
| 3' | `eth-trunk trunk-id` | 物理接口 | 逐个加入成员接口 |
| 4 | `port link-type trunk` | Eth-Trunk | 配置链路类型 |
| 5 | `port trunk allow-pass vlan vlan-list` | Eth-Trunk | 配置允许通过的 VLAN |

### 3.4 实验：两台交换机双链路聚合

**需求：** SW1、SW2 都连接着 VLAN10、VLAN20 的网络；两台交换机之间通过两根以太网链路互联，为提供链路冗余并保证传输可靠性，在 SW1、SW2 之间配置手工模式链路聚合。

**SW1 配置：**

```
[SW1] interface eth-trunk 1
[SW1-Eth-Trunk1] mode manual load-balance
[SW1-Eth-Trunk1] trunkport gigabitethernet 0/0/1 to 0/0/2
[SW1-Eth-Trunk1] port link-type trunk
[SW1-Eth-Trunk1] port trunk allow-pass vlan 10 20
[SW1-Eth-Trunk1] quit
```

**SW2 配置：**

```
[SW2] interface eth-trunk 1
[SW2-Eth-Trunk1] mode manual load-balance
[SW2-Eth-Trunk1] trunkport gigabitethernet 0/0/1 to 0/0/2
[SW2-Eth-Trunk1] port link-type trunk
[SW2-Eth-Trunk1] port trunk allow-pass vlan 10 20
[SW2-Eth-Trunk1] quit
```

**实验步骤与检查点：**

| 步骤 | 操作 | 检查点 |
| ---- | ---- | ------ |
| 1 | 创建 Eth-Trunk 1 | `display eth-trunk 1` 存在该接口 |
| 2 | 加入 GE0/0/1、GE0/0/2 | 回显中两端口 Status 为 Up |
| 3 | 配置 Trunk 与允许 VLAN | 两端允许列表完全一致 |
| 4 | 拔掉一条成员链路 | 业务不中断，`display eth-trunk 1` 中剩余端口仍 Up |
| 5 | 恢复链路 | 端口自动重新加入，无需额外配置 |

> 讲义示例只写了 `trunkport` 与 VLAN 配置，未写 `mode`。因为手工模式是缺省模式，省略也能成立；但考试与工程中建议显式写出，避免与 LACP 模式混淆。

### 3.5 验证

```

```

回显关键字段：

| 字段 | 手工模式取值 | 含义 |
| ---- | ------------ | ---- |

判读口诀：**看到 `WorkingMode: NORMAL` 就是手工模式，所有成员口都参与转发，没有 Selected/Unselect 之分。**

## 4.LACP 模式

### 4.1 LACPDU 与协商内容

LACP 模式采用 LACP 协议，设备间通过**链路聚合控制协议数据单元（LACPDU）**交互，通过协议协商确保对端是同一台设备、同一个聚合接口的成员接口。

LACPDU 中携带的关键字段：

| 字段 | 作用 |
| ---- | ---- |
| 设备优先级（系统 LACP 优先级） | 选举主动端的第一依据 |
| MAC 地址（系统 ID） | 优先级相同时比较，小者优先 |
| 接口优先级 | 选举活动接口的第一依据 |
| 接口号 | 接口优先级相同时比较，小者优先 |
| 端口状态、Key 等 | 描述成员口是否可加入同一聚合组 |

LACP 由 IEEE 802.3ad 定义，现由 IEEE 802.1AX 维护。协议报文使两端能够互相确认“对端是谁、哪些口属于同一聚合组”，从而解决手工模式的两个缺陷。

### 4.2 主动端选举

LACP 模式下，两端设备所选择的活动接口数目必须保持一致，否则链路聚合组无法建立。做法是让其中一端成为**主动端**，另一端（被动端）根据主动端的选择结果确定本端活动接口。

| 比较顺序 | 比较项 | 规则 | 缺省值 |
| -------- | ------ | ---- | ------ |
| 1 | 系统 LACP 优先级 | **数值越小优先级越高** | 32768 |
| 2 | 系统 MAC 地址 | 优先级相同时，**MAC 越小越优** | 设备自身 MAC |

要点：

- 系统 LACP 优先级默认 32768，通常保持默认；
- 优先级一致时通过比较 MAC 地址选择主动端，MAC 越小越优；
- 主动端一旦确定，**两端都以主动端的接口优先级来选择活动接口**，从而保证两端选择结果一致。

### 4.3 活动链路选举

选出主动端后，由主动端按下列顺序选举活动接口：

| 比较顺序 | 比较项 | 规则 | 缺省值 |
| -------- | ------ | ---- | ------ |
| 1 | 接口 LACP 优先级 | **数值越小优先级越高** | 32768 |
| 2 | 接口编号 | 优先级相同时，**编号越小越优** | — |

讲义给出的选举示例（SW1 的 Bridge MAC 为 `4c1f-cc58-6d64`，SW2 为 `4c1f-cc58-6d65`，两端最大活动接口数均为 2）：

| 步骤 | 动作 | 结果 |
| ---- | ---- | ---- |
| 1 | 比较系统优先级与 MAC | SW1 的 MAC 更小，SW1 成为主动端 |
| 2 | SW1 在本端比较接口优先级与接口号 | 1、2 号接口编号更小，成为活动接口 |
| 3 | SW1 通过 LACPDU 把选举结果告知 SW2 | SW2 获知对端的活动接口 |
| 4 | SW2 依据 SW1 的结果确定本端活动接口 | 本端 1、2 号口为活动接口，其余为备份 |

至此 Eth-Trunk 的活动链路选举完成。

### 4.4 最大与最小活动接口数

| 参数 | 命令 | 作用 | 缺省 | 适用模式 |
| ---- | ---- | ---- | ---- | -------- |
| 最大活动接口数 | `max active-linknumber link-number` | 成员口数超过该值时，按接口优先级、接口号选优，其余成为备份口 | 8（S5731/S6730 等部分型号为 16 或 32） | 仅 LACP 模式 |
| 最小活动接口数 | `least active-linknumber link-number` | 活动链路数低于该值时，Eth-Trunk 接口状态转为 Down | 1 | 手工模式与 LACP 模式 |

要点：

- 配置最大活动接口数时，**本端与对端必须一致**；
- 交换机只从活动接口收发报文，备份接口不转发业务流量；
- 活动链路故障时，从非活动链路中选出一条优先级最高的链路替换故障链路，实现**总体带宽不变化、业务不中断**；
- 最小活动接口数的目的是**保证最小带宽**：活动链路太少时宁可让整条 Eth-Trunk Down，也不让业务在半速状态下劣化；
- 配置最大活动接口数时，若已配置最小活动接口数，须保证最大值不小于最小值；
- 最小活动接口数本端与对端可以不同，实际以较大值为准；最大活动接口数则必须两端一致，否则活动口故障时 Eth-Trunk 状态会振荡。

### 4.5 配置命令

| 步骤 | 命令 | 视图 | 说明 |
| ---- | ---- | ---- | ---- |
| 1 | `interface eth-trunk trunk-id` | 系统 | 创建 Eth-Trunk 接口 |
| 2 | `mode lacp-static` | Eth-Trunk | 配置为静态 LACP 模式 |
| 3 | `max active-linknumber link-number` | Eth-Trunk | 配置活动接口上限 |
| 4 | `least active-linknumber link-number` | Eth-Trunk | 配置活动接口下限 |
| 5 | `trunkport gigabitethernet 0/0/1 to 0/0/3` | Eth-Trunk | 批量加入成员口 |
| 5' | `eth-trunk trunk-id` | 物理接口 | 逐个加入成员口 |
| 6 | `lacp priority priority` | 系统 | 配置系统 LACP 优先级，小者成为主动端 |
| 7 | `lacp priority priority` | 接口 | 配置接口 LACP 优先级，须先加入 Eth-Trunk |
| 8 | `load-balance { src-mac \| dst-mac \| src-dst-mac \| src-ip \| dst-ip \| src-dst-ip }` | Eth-Trunk | 配置负载分担模式 |

> 校正说明：讲义写作 `mode { lacp | manual load-balance }`，华为官方命令参考的完整取值为 `mode { lacp-static | manual load-balance }`，部分旧版本接受 `mode lacp` 作为简写。答题时以 `mode lacp-static` 为准，若题目给出 `mode lacp` 也应判断为 LACP 模式。
>
> 同理，讲义中 `max active-linknumber {number}`、`least active-linknumber {number}` 的参数名应为 `link-number`。

### 4.6 实验：三链路取二，手工指定主动端

**需求：** SW1、SW2 都连接着 VLAN10、VLAN20 的网络；两台交换机之间通过三根以太网链路互联；配置 LACP 模式链路聚合，手动调整优先级让 SW1 成为主动端，最大活动端口为 2，另一条链路作为备份。

**SW1 配置：**

```
[SW1] interface eth-trunk 1
[SW1-Eth-Trunk1] mode lacp-static
[SW1-Eth-Trunk1] max active-linknumber 2
[SW1-Eth-Trunk1] trunkport gigabitethernet 0/0/1 to 0/0/3
[SW1-Eth-Trunk1] port link-type trunk
[SW1-Eth-Trunk1] port trunk allow-pass vlan 10 20
[SW1-Eth-Trunk1] quit
[SW1] lacp priority 30000
```

**SW2 配置：**

```
[SW2] interface eth-trunk 1
[SW2-Eth-Trunk1] mode lacp-static
[SW2-Eth-Trunk1] max active-linknumber 2
[SW2-Eth-Trunk1] trunkport gigabitethernet 0/0/1 to 0/0/3
[SW2-Eth-Trunk1] port link-type trunk
[SW2-Eth-Trunk1] port trunk allow-pass vlan 10 20
[SW2-Eth-Trunk1] quit
```

| 设计意图 | 实现方式 |
| -------- | -------- |
| SW1 成为主动端 | SW1 的系统 LACP 优先级配为 30000，小于 SW2 的缺省 32768 |
| 只允许两条活动链路 | 两端 `max active-linknumber 2` |
| 第三条作备份 | 超出上限的成员口自动成为 Unselect |
| 业务 VLAN 一致 | 两端 Trunk 与 `allow-pass vlan 10 20` 完全相同 |

### 4.7 验证与回显判读

```
<SW1> display eth-trunk 1
```

| 字段 | LACP 模式取值 | 判读 |
| ---- | ------------- | ---- |
| `WorkingMode` | `STATIC` | 静态 LACP 模式 |
| `System Priority` | 30000 | 本端系统优先级 |
| `System ID` | 设备 MAC | 主动端比较的第二依据 |
| `Least Active-linknumber` | 1 | 下限阈值 |
| `Max Active-linknumber` | 2 | 上限阈值 |
| `Ports` | 3 | 成员口总数 |
| `Status` | `Selected` / `Unselect` | 活动 / 非活动 |
| `PortPri` | 32768 | 接口优先级 |
| `PortNo` | 接口编号 | 同优先级时比较 |

**故障切换实验：**

| 步骤 | 操作 | 预期 |
| ---- | ---- | ---- |
| 1 | 记录当前两条 Selected 链路 | 带宽为 2 条之和 |
| 2 | 断开其中一条活动链路 | 原 Unselect 链路自动变为 Selected |
| 3 | 查看 `Ports` 与 `Status` | 活动链路数仍为 2，总带宽不变 |
| 4 | 恢复链路 | 该链路回到 Unselect，除非开启抢占 |

补充：缺省情况下 LACP 活动链路**不抢占**，故障链路恢复后不会自动夺回活动地位。若希望恢复后立即回切，可在 Eth-Trunk 视图配置 `lacp preempt enable`，并用 `lacp preempt delay delay-time` 设置等待时间，避免链路抖动导致频繁切换。

## 5.负载分担

### 5.1 基于包与基于流

| 方式 | 做法 | 优点 | 缺点 |
| ---- | ---- | ---- | ---- |
| 基于包（逐包） | 每个数据帧依次从不同成员链路发出 | 负载最均匀 | 同一数据流的不同帧走不同路径，到达顺序可能错乱，导致上层重传 |
| 基于流（逐流） | 以“流”为单位，同一条流固定走一条成员链路 | 保证同流报文顺序，不产生乱序 | 流量分布取决于流的数量与哈希结果，流少时可能不均 |

Eth-Trunk **推荐采用逐流负载分担**：一条相同的流负载到一条链路，既保证同一数据流的数据帧在同一条物理链路转发，又实现流量在聚合组内各物理链路上的负载分担。

### 5.2 负载分担模式

Eth-Trunk 支持基于报文的 IP 地址或 MAC 地址进行负载分担，可配置不同模式。该配置**本地有效，且只对出方向报文生效**。

| 模式 | 关键字 | 哈希依据 |
| ---- | ------ | -------- |
| 源 MAC | `src-mac` | 源 MAC 地址 |
| 目的 MAC | `dst-mac` | 目的 MAC 地址 |
| 源目 MAC | `src-dst-mac` | 源 MAC 与目的 MAC 组合 |
| 源 IP | `src-ip` | 源 IP 地址 |
| 目的 IP | `dst-ip` | 目的 IP 地址 |
| 源目 IP | `src-dst-ip` | 源 IP 与目的 IP 组合 |

### 5.3 模式选择方法

选择原则：**业务流量中某种参数变化越频繁，选择与此参数相关的负载分担方式就越容易实现负载均衡。**

讲义的对比示例：

| 场景 | 采用源目 IP 模式 | 采用源目 MAC 模式 |
| ---- | ---------------- | ----------------- |
| 源目 MAC 相同、源目 IP 不同 | 哈希结果分散，流量均匀落到各成员链路 [正确] | 所有流量哈希到同一条链路，其余链路空闲 [错误] |

判断步骤：

1. 看流量特征中哪个字段在变化（源 IP、目的 IP、源 MAC、目的 MAC）；
2. 选择包含该字段的模式；
3. 若变化字段在 IP 层，选 `src-ip`、`dst-ip` 或 `src-dst-ip`；若在 MAC 层，选 MAC 类模式；
4. 注意配置只在本地出方向生效，两端可以不同。

### 5.4 配置

```
[SW1] interface eth-trunk 1
[SW1-Eth-Trunk1] load-balance src-dst-ip
[SW1-Eth-Trunk1] quit
```

| 命令片段 | 说明 |
| -------- | ---- |
| `load-balance` | 配置 Eth-Trunk 的负载分担模式 |
| `src-dst-ip` | 按源 IP 与目的 IP 组合哈希 |
| 缺省值 | 多数 S 系列交换机缺省为 `src-dst-ip`（旧版本或个别型号可能不同，以 `display eth-trunk` 的 `Hash Arithmetic` 为准） |

## 6.典型应用场景

| 场景 | 组网 | 目的 |
| ---- | ---- | ---- |
| 交换机之间 | 核心/汇聚/接入之间部署多条物理链路并使用 Eth-Trunk | 提高设备间链路带宽与可靠性 |
| 交换机与服务器之间 | 服务器双网卡或多网卡聚合成网卡组，与交换机建立链路聚合 | 提高服务器接入带宽与可靠性 |
| 交换机与堆叠系统 | 堆叠系统作为一台逻辑设备，与下游通过 Eth-Trunk 互联 | 组建高可靠、无环网络 |
| 防火墙双机热备心跳线 | 两台防火墙之间的心跳线使用 Eth-Trunk | 防止单端口、单链路故障导致状态监测错误 |

第四种场景容易被忽略：心跳线承载的是“对端设备是否存活”的探测报文，一旦心跳链路单点故障，双机热备可能误判对端已死而**双主**，因此心跳线本身也要做链路聚合。

## 7.堆叠 iStack

### 7.1 定义与特征

堆叠（iStack，Intelligent Stack）：多台支持堆叠特性的交换机通过堆叠线缆连接在一起，从逻辑上变成一台交换设备，作为一个整体参与数据转发。

| 特征 | 说明 |
| ---- | ---- |
| 设备数量 | 2 台及以上，盒式交换机常见 2~9 台 |
| 连接介质 | 专用堆叠线缆，或业务口 + 普通网线/光纤 |
| 逻辑形态 | 多虚一，对外表现为一台逻辑交换机 |
| 控制平面 | 合一，统一管理 |
| 转发平面 | 合一，转发信息共享并实时同步 |
| 跨设备链路聚合 | 跨物理设备的链路可聚合成一个 Eth-Trunk 端口 |

### 7.2 角色与选举

| 角色 | 数量 | 职责 |
| ---- | ---- | ---- |
| 主交换机（Master） | 1 台 | 负责管理整个堆叠系统，承担控制平面功能 |
| 备交换机（Standby/Backup） | 1 台 | 作为主的备份，主故障时接替 |
| 从交换机（Slave） | 可多台 | 承担业务转发；从交换机越多，堆叠系统转发性能越强 |

选举规则（按顺序比较）：

| 顺序 | 比较项 | 规则 | 缺省 |
| ---- | ------ | ---- | ---- |
| 1 | 运行状态 | 先启动并进入单机运行状态的设备优先 | — |
| 2 | 堆叠优先级 | **数值越大优先级越高** | 100 |
| 3 | 软件版本 | 版本较新的设备优先 | — |
| 4 | MAC 地址 | 上述相同时，MAC 越小越优 | — |

要点：

- 堆叠优先级取值范围通常为 1~255，缺省 100，用 `stack ... priority` 修改；
- 主交换机故障后由**备交换机**接替，不在从交换机中重新选举；
- 堆叠优先级是“大者优先”，与 LACP 系统优先级、STP 桥优先级的“小者优先”相反，是常见易错点。

角色选举的概念对照与例题详见 11.1 §1.3、§5.1。

### 7.3 堆叠 ID、优先级与堆叠口

| 概念 | 说明 |
| ---- | ---- |
| 堆叠 ID（slot ID） | 成员设备在堆叠系统中的编号，取值 0~8；V200 缺省为 0，V600 缺省为 1，冲突则无法堆叠，必须保证唯一 |
| 堆叠优先级 | 决定主备角色，大者优先，缺省 100 |
| 堆叠口（Stack-Port） | 逻辑端口，成员设备间用于堆叠互联；一个 Stack-Port 可绑定多个物理成员口 |
| 物理成员口 | 加入 Stack-Port 的业务口，加入后不再作为普通业务口使用 |

连接规则：

1. 本端设备的 `Stack-Port x/1` 必须与对端设备的 `Stack-Port y/2` 相连（1 号口对 2 号口；x、y 分别为两端各自的堆叠 ID）；
2. 一个 Stack-Port 可以绑定多个物理成员口以提高可靠性与带宽；只要其中一条物理链路保持连接，堆叠就不会分裂，但带宽相应降低；
3. 两端 Stack-Port 内都包含多个物理成员口时，对物理口的端口号无对应要求；
4. 3 台及以上成员组建堆叠时，建议采用环形组网，此时堆叠系统带宽取所有 Stack-Port 带宽的最小值；
5. 2 台成员组建堆叠时，建议每台只创建一个 Stack-Port，其中包含多个物理成员口。

### 7.4 连接拓扑

| 拓扑 | 特点 | 适用 |
| ---- | ---- | ---- |
| 链形（线形） | 设备首尾不相连，一条堆叠链路故障即导致堆叠分裂 | 设备间距远、布线难以成环 |
| 环形 | 首尾相连，单条堆叠链路故障不会造成通信中断 | 设备距离近、线缆短，**一般建议采用环形** |

堆叠分裂是堆叠系统最严重的故障：原为一台的逻辑设备被拆成两台，可能出现双主、IP 地址冲突、转发表不一致。因此环形连接与多物理成员口绑定都是为了提高堆叠链路的抗断能力。

### 7.5 配置命令

不同版本命令差异较大，考试以讲义与常见 V200 语法为主，新版本 V600 采用 `stack` 视图。

**V200 常见写法（`stack slot`）：**

```
<SW1> system-view
[SW1] stack slot 0 priority 150
[SW1] interface stack-port 0/1
[SW1-Stack-Port0/1] port interface xgigabitethernet 0/0/1 enable
[SW1-Stack-Port0/1] quit
[SW1] interface stack-port 0/2
[SW1-Stack-Port0/2] port interface xgigabitethernet 0/0/2 enable
[SW1-Stack-Port0/2] quit
```

**V600 常见写法（`stack` 视图 + `member-group`）：**

```
<DeviceA> system-view
[DeviceA] stack
[DeviceA-stack] stack member 1 priority 150
[DeviceA-stack] quit
[DeviceA] interface Stack-Port 1/1
[DeviceA-Stack-Port1/1] port member-group interface 10GE 1/0/1 10GE 1/0/2
[DeviceA-Stack-Port1/1] quit
```

修改堆叠 ID：

```
[DeviceB] stack
[DeviceB-stack] stack member 1 priority 100
[DeviceB-stack] stack member 1 renumber 2
Warning: All the configurations related to the slot ID will be lost after the slot ID is modified.
Do not frequently modify the slot ID because it will make the stack split. Continue? [Y/N]:y
[DeviceB-stack] quit
```

| 命令 | 作用 |
| ---- | ---- |
| `stack slot slot-id priority priority` / `stack member member-id priority priority` | 配置堆叠优先级，大者优先 |
| `stack slot slot-id renumber new-slot-id` / `stack member member-id renumber new-member-id` | 修改堆叠 ID |
| `interface stack-port slot-id/port-id` | 创建并进入逻辑堆叠口 |
| `port interface interface-type interface-number enable` | 把物理口加入堆叠口（V200） |
| `port member-group interface interface-type interface-number` | 把物理口加入堆叠口（V600） |
| `stack reserved-vlan vlan-id` | 配置堆叠保留 VLAN |
| `display stack` | 查看堆叠系统信息 |
| `display stack configuration` | 查看堆叠配置 |
| `display stack port` | 查看堆叠口状态 |

### 7.6 实验步骤

| 步骤 | 操作 | 注意 |
| ---- | ---- | ---- |
| 1 | 规划堆叠 ID、优先级、堆叠口与拓扑 | ID 必须唯一，优先级主设备最高 |
| 2 | 分别配置各台的堆叠 ID 与优先级 | 修改 ID 会清空该槽位相关配置 |
| 3 | 创建 Stack-Port 并绑定物理成员口 | 绑定会清空物理口原有配置 |
| 4 | 保存配置并下电 | `save` |
| 5 | 按规划连接堆叠线缆 | 本端 x/1 对应对端 y/2（1 号口接 2 号口） |
| 6 | 上电，等待堆叠建立 | 建议主设备先启动 |
| 7 | 验证堆叠系统 | `display stack` |

## 8.集群 CSS

### 8.1 定义与适用设备

集群（Cluster Switch System，CSS）：将两台支持集群特性的交换机设备组合在一起，从逻辑上组合成一台交换设备。

| 比较项 | iStack 堆叠 | CSS 集群 |
| ------ | ----------- | -------- |
| 成员数量 | 2 台及以上 | **只支持 2 台** |
| 典型设备 | 盒式交换机 | 框式交换机 |
| 连接 | 堆叠线缆/业务口 | 集群卡或业务口（CSS Link） |
| 控制平面 | 主、备、从 | 主、备 |
| 扩展形态 | 端口密度与带宽横向扩展 | 两台核心设备虚拟化 |

讲义原文：集群只支持两台设备，一般框式交换机支持 CSS，盒式设备支持 iStack。

### 8.2 实现方式

| 技术 | 实现方式 | 特点 |
| ---- | -------- | ---- |
| 传统 CSS | 主控板插集群卡，或使用业务口建立集群连接 | 占用主控板或业务板带宽 |
| CSS2 | 交换网板插集群卡，通过交换网一次转发 | 不占用主控板/业务板带宽；支持主控 1+N 备份；成员仍为两台框式交换机 |

选择要点：

- 集群卡集群必须保证两台交换机都配置为集群卡连接方式；
- 业务口集群使用业务板上的端口作为集群口，布线灵活但占用业务带宽；
- CSS2 在可靠性与转发效率上优于传统 CSS，但核心仍是“两台框式虚拟成一台”。

### 8.3 主备选举

集群建立时按下列顺序比较：

| 顺序 | 比较项 | 规则 | 缺省 |
| ---- | ------ | ---- | ---- |
| 1 | 运行状态 | 本框已运行 CSS 的优先 | — |
| 2 | 集群优先级 | **数值越大优先级越高** | 1 |
| 3 | MAC 地址 | 优先级相同时，MAC 越小越优 | — |
| 4 | 集群 ID | MAC 相同时，ID 越小越优 | 1 |

要点：

- 集群优先级缺省为 1，**大者优先**，与堆叠优先级方向一致，与 LACP 相反；
- 启动速度会影响选举：优先级再高，如果启动慢，也可能无法成为主；
- 可用 `css master force` 强制指定主交换机，但集群建立后可能再次触发主备倒换，不建议配置。

### 8.4 集群建立后的变化

| 变化 | 说明 |
| ---- | ---- |
| 系统 MAC | 首次建立时使用集群主交换机的 MAC |
| 接口编号 | 由三位变为四位，增加框号，例如 `G1/0/1` 变为 `G2/1/0/1` |
| 转发路径 | 可能出现跨设备转发 |
| 配置文件 | 自动备份为 `.cfg.bak`、`.zip.bak`；去使能集群后需手工恢复 |
| 本地流量 | 支持本地流量优先转发，减少跨框绕行 |

接口编号变化是高频考点：集群后原本的“槽位/子槽位/端口”三位编号前增加框号，读配置时必须按新编号理解。

### 8.5 配置命令

```
# SwitchA
<HUAWEI> system-view
[HUAWEI] sysname SwitchA
[SwitchA] set css mode lpu
[SwitchA] set css id 1
[SwitchA] set css priority 100
[SwitchA] interface eth-trunk 1
[SwitchA-Eth-Trunk1] trunkport ...

# SwitchB
<HUAWEI> system-view
[HUAWEI] sysname SwitchB
[SwitchB] set css mode lpu
[SwitchB] set css id 2
[SwitchB] set css priority 10

# 两台分别使能集群功能，使能后需重启生效
[SwitchA] css enable
[SwitchB] css enable
```

| 命令 | 视图 | 作用 |
| ---- | ---- | ---- |
| `set css mode { css-card \| lpu }` | 系统 | 配置集群连接方式：集群卡或业务口 |
| `set css id new-id` | 系统 | 配置集群 ID，两台必须不同 |
| `set css priority priority` | 系统 | 配置集群优先级，大者优先 |
| `css master force` | 系统 | 强制指定主交换机（不推荐） |
| `css enable` | 系统 | 使能集群功能，重启后生效 |
| `display css status [ saved ]` | 任意 | 查看集群状态 |

配置顺序要点：

1. 先 `set css mode` 确定连接方式，两台必须一致；
2. 再 `set css id`，两台 ID 不能相同，否则无法建立集群；
3. 再 `set css priority`，让预期的主设备优先级更高；
4. 最后 `css enable`，输入 `Y` 确认立即重启，否则配置不生效；
5. 建议主设备先启动，以提高其当选主的概率。

## 9.与 STP 的关系

### 9.1 STP 解决什么问题

STP 通过阻塞冗余端口消除二层环路。代价是：

| 代价 | 说明 |
| ---- | ---- |
| 带宽浪费 | 被阻塞链路不转发业务流量 |
| 收敛慢 | 拓扑变化需要重新计算，期间可能短暂中断 |
| 配置复杂 | 需规划根桥、路径开销、端口角色，多 VLAN 时还要 MSTP 实例 |

### 9.2 Eth-Trunk 如何替代 STP 的部分职责

Eth-Trunk 把多条物理链路绑定成**一条逻辑链路**，对 STP 而言只看到一个接口：

- 逻辑上不存在环路，因此不需要阻塞其中某条；
- 所有成员链路都能转发，带宽叠加、利用率 100%；
- 成员口故障时，聚合组内部完成剔除与切换，不触发 STP 重新计算，收敛更快。

注意：Eth-Trunk 只消除“同一对设备之间多条并行链路”造成的环路，**不能**消除多台设备互连形成的环形拓扑。

### 9.3 堆叠与集群如何消除环路

堆叠/集群把多台物理设备虚拟成**一台逻辑设备**，原本“设备 A 与设备 B 之间的环”变成“同一台设备内部的两条路径”，再配合跨设备 Eth-Trunk，物理上的环在逻辑上不存在。

| 传统组网 | 虚拟化组网 |
| -------- | ---------- |
| 核心两台 + MSTP + VRRP | 核心两台组成 CSS，上下行 Eth-Trunk |
| 汇聚两台 + STP 阻塞 | 汇聚两台组成 iStack，上下行 Eth-Trunk |
| 需要规划根桥、实例、VRRP 主备 | 逻辑一台设备，无需 MSTP、VRRP |
| 部分链路阻塞 | 全部链路转发，利用率 100% |

讲义的原话是：简化后的组网不再需要使用 MSTP、VRRP 等协议，简化了网络配置，同时依靠跨设备的链路聚合实现快速收敛，提高了可靠性。

### 9.4 仍需 STP 的场景

虚拟化不是万能的，下列情况仍需 STP：

| 场景 | 原因 |
| ---- | ---- |
| 接入层存在多条到不同汇聚设备的链路，且汇聚未虚拟化 | 物理环仍然存在 |
| 堆叠系统与非堆叠设备混合组网 | 环可能跨越虚拟化边界 |
| 临时接线、误接成环 | 需要 STP 兜底防环 |
| 堆叠分裂后 | 原逻辑设备变成两台，可能出现环路，需 STP 或双主检测 |

因此工程上常见做法是：**虚拟化 + Eth-Trunk 为主，STP 作为兜底**，而不是把 STP 完全关闭。

### 9.5 STP、Eth-Trunk、堆叠/集群三者对比

| 比较项 | STP | Eth-Trunk | 堆叠/集群 |
| ------ | --- | --------- | --------- |
| 解决的问题 | 二层环路 | 链路带宽与链路冗余 | 设备级冗余与组网简化 |
| 冗余链路是否转发 | 否，阻塞 | 是，全部活动链路转发 | 是，跨设备链路聚合 |
| 带宽叠加 | 不叠加 | 叠加 | 叠加 |
| 故障收敛 | 秒级 | 毫秒级（成员口剔除） | 毫秒级（跨设备聚合） |
| 设备级备份 | 依赖冗余拓扑 | 无 | 有，主备从 |
| 配置复杂度 | 高 | 低 | 中（需规划 ID、优先级、堆叠口） |
| 典型位置 | 任意二层网络 | 设备间互联 | 核心（CSS）、汇聚/接入（iStack） |

## 10.推荐组网架构

讲义给出的三层推荐架构：

| 层次 | 技术选择 | 组网方式 | 收益 |
| ---- | -------- | -------- | ---- |
| 核心层 | CSS 集群 | 两台框式组成集群，上下行均用 Eth-Trunk | 高可靠、无环，省去 MSTP 与 VRRP |
| 汇聚层 | iStack 堆叠 | 两台盒式堆叠，上下行均用 Eth-Trunk | 端口密度与带宽扩展，跨设备冗余 |
| 接入层 | iStack 堆叠 | 同一楼宇内位置接近的接入交换机堆叠 | 端口数量充足，管理简化，上联用 Eth-Trunk |

整体效果：逻辑上网络结构极简（每层就是一台设备 + 一条聚合链路），物理上仍保留设备与链路冗余；具有高可靠性、高上行带宽、快速收敛的优势。

堆叠/集群的其他实际应用：

| 需求 | 手段 |
| ---- | ---- |
| 端口密度不足 | 增加交换机与原交换机组成堆叠，扩展端口数量 |
| 上行带宽不足 | 多台成员交换机的上行链路配置成一个聚合组，提高上行带宽 |
| 需要设备级备份 | 堆叠成员互为备份，单台故障不影响业务 |
| 简化运维 | 逻辑一台设备，统一管理、统一配置 |

## 12.典型考题

### 12.1 题型一：LACP 主动端与活动链路选举

**题目：SW1 的 Bridge MAC 为 4c1f-cc58-6d64，SW2 为 4c1f-cc58-6d65，两端系统 LACP 优先级均为 32768，各配置 4 个成员口，最大活动接口数为 2。问主动端是哪台？活动接口如何选出？**

**答案：**

| 问题 | 结论 | 理由 |
| ---- | ---- | ---- |
| 主动端 | SW1 | 系统优先级相同，比较 MAC，SW1 的 MAC 更小 |
| 活动接口 | 由 SW1 按接口优先级、接口号选出编号最小的 2 个 | 接口优先级相同（缺省 32768），比较接口号，1、2 号口胜出 |
| SW2 如何确定 | 依据 SW1 通过 LACPDU 下发的选举结果 | 被动端跟随主动端，保证两端活动口数量一致 |

### 12.2 题型二：负载分担模式选择

**题目：聚合组内各数据流的源 MAC、目的 MAC 均相同，源 IP、目的 IP 各不相同。为获得较好的负载均衡效果，应选择的负载分担模式是（ ）。**

A. `src-mac`

B. `dst-mac`

C. `src-dst-mac`

D. `src-dst-ip`

**答案：D**

解析：

| 选项 | 判断 | 理由 |
| ---- | ---- | ---- |
| A | [错误] | 源 MAC 全部相同，哈希到同一条链路 |
| B | [错误] | 目的 MAC 全部相同，哈希到同一条链路 |
| C | [错误] | 源目 MAC 组合仍相同，无法分散 |
| D | [正确] | 源目 IP 不同，哈希结果分散，流量可均匀分布 |

要点：**哪个字段在变，就用哪个字段做哈希**。

### 12.3 题型三：手工模式与 LACP 模式的判读

**题目：某交换机执行 `display eth-trunk 1` 后，回显中 `WorkingMode` 为 `NORMAL`，成员口 Status 均为 `Up`。下列判断正确的是（ ）。**

A. 该聚合组采用 LACP 模式，存在备份链路

B. 该聚合组采用手工模式，所有成员口都参与转发

C. 该聚合组配置了最大活动接口数

D. 该聚合组的成员口一定分布在两台对端设备上

**答案：B**

解析：

| 选项 | 判断 | 理由 |
| ---- | ---- | ---- |
| A | [错误] | `NORMAL` 是手工模式；LACP 模式显示 `STATIC` |
| B | [正确] | 手工模式下所有成员口均为活动口，全部参与转发 |
| C | [错误] | `max active-linknumber` 只在 LACP 模式生效，手工模式无活动/非活动之分 |
| D | [错误] | 手工模式要求对端成员口属于同一设备、同一聚合口，分散在两台设备上会导致转发错乱 |

### 12.4 题型四：max 与 least 的区别

**题目：在 Eth-Trunk 1 上配置 `max active-linknumber 2` 与 `least active-linknumber 2`，下列描述正确的是（ ）。**

A. 两条命令作用相同，都是限制成员口数量

B. 成员口超过 2 个时，多余的口转为备份；活动口少于 2 个时，Eth-Trunk 接口转为 Down

C. `max` 命令在手工模式下也生效

D. `least` 命令只在 LACP 模式下生效

**答案：B**

解析：

| 选项 | 判断 | 理由 |
| ---- | ---- | ---- |
| A | [错误] | 一个是上限（控制活动口数量与备份），一个是下限（保证最小带宽） |
| B | [正确] | 上限超出转备份，下限不足则整条 Eth-Trunk Down |
| C | [错误] | `max active-linknumber` 仅在 LACP 模式生效 |
| D | [错误] | `least active-linknumber` 在手工模式与 LACP 模式都支持 |

### 12.5 题型五：iStack 与 CSS 的区别

**题目：下列关于堆叠与集群的说法，错误的是（ ）。**

A. 堆叠可支持两台以上设备，集群只支持两台

B. 堆叠优先级数值越大越优先成为主交换机

C. 集群建立后接口编号由三位变为四位

D. 堆叠与集群都必须使用专用堆叠卡和专用线缆

**答案：D**

解析：

| 选项 | 判断 | 理由 |
| ---- | ---- | ---- |
| A | [正确] | iStack 支持多台，CSS 只支持两台 |
| B | [正确] | 堆叠优先级大者优先，缺省 100 |
| C | [正确] | 增加框号，例如 G1/0/1 变为 G2/1/0/1 |
| D | [错误] | 除堆叠卡/集群卡方式外，还支持业务口堆叠与业务口集群，可用普通网线或光纤 |

### 12.6 讲义思考题解答

| 思考题 | 解答 |
| ------ | ---- |
| 基于包和基于流的负载分担有何区别 | 基于包逐帧分散到不同链路，负载均匀但会乱序；基于流以流为单位固定链路，保证同流有序，是推荐方式 |
| LACP 模式如何选举主动端 | 先比较系统 LACP 优先级，小者优先；相同则比较系统 MAC，小者优先 |
| CSS、iStack 有何优势 | 逻辑一台设备简化运维；单台故障由其他成员接管，避免单点；跨设备链路聚合形成物理无环网络，无需 STP；链路全部有效使用，利用率 100% |

## 13.本章小结

| 知识块 | 核心内容 |
| ------ | -------- |
| 1. 可靠性三层 | 单板（双主控、多网板）、设备（双上行主备）、链路（多链路聚合） |
| 2. 框式交换机组成 | 机框、电源、风扇、主控板 MPU、交换网板 SFU、线路板 LPU；S12700E-8 为 8 LPU、4 SFU、2 MPU、6 电源、4 风扇 |
| 3. Eth-Trunk 作用 | 多物理口捆绑为一个逻辑口，提升带宽、可靠性、负载分担，节约成本 |
| 4. 基本术语 | LAG、成员接口/链路、活动/非活动接口、Selected/Unselect、上下限阈值 |
| 5. 聚合条件 | 数量/速率/双工/流控一致、两端同时加入、模式一致、允许 VLAN 一致 |
| 6. 手工模式 | 无协商、全部成员口活动、故障后重新平均分担；对端须同设备同聚合口；只能靠物理层判断 |
| 7. LACP 模式 | LACPDU 携带系统优先级、MAC、接口优先级、接口号；协商确认对端身份 |
| 8. 主动端选举 | 系统 LACP 优先级小者优先（缺省 32768），相同比 MAC 小者 |
| 9. 活动链路选举 | 主动端按接口优先级小者优先（缺省 32768），相同比接口号小 |
| 10. 活动口阈值 | `max active-linknumber` 仅 LACP，缺省 8（部分型号 16/32）；`least active-linknumber` 两种模式都支持，缺省 1，不足则 Trunk Down |
| 11. 负载分担 | 基于流优于基于包；模式有源/目的/源目 MAC、源/目的/源目 IP；本地有效、出方向生效 |
| 12. 典型场景 | 交换机之间、交换机与服务器、交换机与堆叠系统、防火墙心跳线 |
| 13. iStack | 多台盒式虚拟成一台；主/备/从；优先级大者优先（缺省 100），再比软件版本与 MAC（小优）；堆叠 ID 唯一；本端 Stack-Port x/1 接对端 y/2；建议环形 |
| 14. CSS | 两台框式虚拟成一台；优先级大者优先（缺省 1）；`set css mode`、`set css id`、`set css priority`、`css enable`；接口编号三位变四位 |
| 15. 与 STP 关系 | STP 阻塞冗余链路；Eth-Trunk 让链路全转发；堆叠/集群消除设备间环，仍需 STP 兜底 |
| 16. 推荐架构 | 核心 CSS、汇聚 iStack、接入 iStack，层间全部 Eth-Trunk |

考试重点：

1. **LACP 主动端选举顺序**：系统优先级（小优）→ 系统 MAC（小优）。
2. **活动链路选举顺序**：接口优先级（小优）→ 接口编号（小优），且由主动端统一决定，两端一致。
3. **`max` 与 `least` 的区别**：上限超出的口转备份、仅 LACP 支持；下限不足则整条 Eth-Trunk Down、两种模式都支持。
4. **手工模式的两个缺陷**：对端必须同设备同聚合口、只能靠物理层判断对端状态。
5. **负载分担模式的选择**：哪个字段变化频繁就用哪个字段；基于流优于基于包。
6. **命令判读**：`WorkingMode` 为 `NORMAL` 是手工模式，`STATIC` 是 LACP 模式；`Selected` 为活动口，`Unselect` 为备份口。
7. **堆叠角色与选举**：主、备、从；优先级大者优先，再比软件版本，最后比 MAC 小；主故障由备接替。
8. **堆叠口连接规则**：本端 Stack-Port x/1 接对端 y/2（1 号口接 2 号口）；一个堆叠口可绑多个物理口；多台建议环形。
9. **iStack 与 CSS 的区别**：数量（多台/两台）、设备形态（盒式/框式）、角色（主备从/主备）。
10. **CSS 优先级方向**：数值越大越优先，缺省 1，与 LACP、STP 的“小者优先”相反。
11. **集群后的接口编号**：三位变四位，读配置时要加上框号。
12. **虚拟化与 STP 的关系**：跨设备 Eth-Trunk 使物理环在逻辑上消失，但混合组网、堆叠分裂等场景仍需 STP 兜底。
