## IO设备的分类

**例1（选择题）**：键盘属于______。
- A. 块设备　B. 字符设备　C. 存储设备　D. 高速设备
- 解析：键盘传输单位是字符 → **B**。

**例2（选择题）**：下列哪类设备可以随机读写任一块数据？
- A. 鼠标　B. 键盘　C. 磁盘　D. 打印机
- 解析：块设备可寻址、可随机读写 → **C**。

**例3（选择题）**：网卡按使用特性分类属于______。
- A. 人机交互设备　B. 存储设备　C. 网络通信设备　D. 字符设备
- 解析：用于网络通信 → **C**。

**例4（判断题）**：字符设备可寻址，可以随机访问任意字符。（×）
- 解析：**字符设备不可寻址**，只能顺序传输（块设备才可寻址）。

**例5（概念题）**：为什么 I/O 管理要解决"速度匹配"问题？
- 答：CPU 与内存的执行速度是纳秒级，而外设（键盘、磁盘）是毫秒级甚至更慢——如果 CPU 每访问一次设备都同步等待，绝大多数时间都在"空转"。因此 I/O 管理通过中断、DMA、通道、缓冲等手段让 CPU 与设备"各干各的"，在设备就绪时才交互，从而**提高 CPU 利用率与系统吞吐量**。

**例6（变式·综合打标签）**：分别指出下列设备在四个分类维度下的标签：① 显示器；② 移动硬盘；③ 调制解调器。
- 解：① 显示器 = **人机交互 + 低速 + 字符（或块，视接口而定，考试默认字符流）+ 输出型**；② 移动硬盘 = **存储 + 高速 + 块 + 双向**；③ 调制解调器 = **网络通信 + 中速 + 字符/块混合 + 双向**。易错点：**"输出型"不等于"字符设备"**——显示器是输出型人机交互设备；"块"和"字符"只看交换单位，不看方向。

**例7（变式·辨析）**：下列说法正确的是______。
- A. 块设备传输速率一定比字符设备慢
- B. 打印机是块设备（它按行/页输出）
- C. 磁盘既可寻址又可随机读写，属于块设备
- D. 网卡属于存储设备
- 解：**C**。A 错——块设备速率**高**；B 错——打印机按**字符/行**输出、不可寻址，是字符设备；D 错——网卡按使用特性属**网络通信设备**。易错点：**"输出的数据量大"不等于"块设备"**——判据是"是否可寻址 + 交换单位"，不是"一次输出多少"。

## IO控制器（I/O Controller）

**例1（选择题）**：存放 CPU 发来的 read/write 命令及参数的是______。
- A. 数据寄存器　B. 控制寄存器　C. 状态寄存器　D. 地址寄存器
- 解析：命令与参数 → 控制寄存器 → **B**。

**例2（选择题）**：内存映像 I/O 方式的优点是______。
- A. 不占内存地址空间　B. 可用访存指令操作控制器　C. 需要专门 I/O 指令　D. 编址更复杂
- 解析：统一编址 → 用访存指令 → **B**。

**例3（选择题）**：I/O 逻辑的主要功能是______。
- A. 执行具体机械操作　B. 接收并识别 CPU 的命令、对设备发命令　C. 存储文件数据　D. 管理磁盘块
- 解析：命令译码与转发 → **B**。

**例4（判断题）**：所有 I/O 控制器的状态寄存器都约定"1 表示空闲、0 表示忙碌"。（×）
- 解析：**不同厂家定义可能相反**，这正是需要驱动的原因。

**例5（概念题）**：CPU 为什么不能直接控制设备机械部件？
- 答：设备机械部件（磁臂、LED、按钮）工作在电气/机械层面，CPU 只能处理数字信号且无法驱动这些部件；且直接控制会让 CPU 陷于等待设备就绪的低效循环。所以通过**I/O 控制器**——CPU 只对控制器的寄存器读写（命令/数据/状态），控制器再去驱动机械部件并反馈状态，实现**间接、高效的设备控制**。

**例6（变式·编址冲突推导）**：系统采用独立编址，有 2 个控制器：控制器 A 含寄存器 0、1、2，控制器 B 含寄存器 0、1。CPU 用一条 I/O 指令访问"控制器 A 的寄存器 1"。① 为什么不能只用"寄存器地址 1"表示？② 该指令至少需要几位表示控制器、几位表示寄存器？
- 解：① 因为控制器 B 也有寄存器 1——**仅凭寄存器地址 1 无法区分是 A 的 1 号还是 B 的 1 号**，必须同时指定控制器编号；② 2 个控制器需 **1 位**（0/1），寄存器最多 3 个需 **2 位**（00/01/10）→ I/O 指令至少 **1 + 2 = 3 位**用于设备寻址。易错点：**独立编址下"寄存器地址"是控制器内局部概念**，全局唯一靠"控制器号 + 寄存器号"二元组。

**例7（变式·辨析）**：下列对内存映像 I/O 的说法错误的是______。
- A. 设备寄存器与内存统一编址
- B. 可以用访存指令读写设备寄存器
- C. 会占用内存地址空间
- D. 需要使用专门的 IN/OUT 指令
- 解析：**D 错**——专门的 IN/OUT 指令属于独立编址方式；内存映像 I/O 用访存指令（A/B 对）、统一编址会占内存地址空间（C 对）。易错点：**两种编址的"指令集"与"地址空间"两两对应，不要交叉记忆**。


## IO设备的控制方式

**例1（选择题）**：数据可以直接从设备传送到内存、无需经过 CPU 的控制方式是______。
- A. 程序直接控制　B. 中断驱动　C. DMA　D. 轮询
- 解析：DMA 数据不经过 CPU → **C**。

**例2（选择题）**：DMA 控制器中用于指明数据在内存中位置的是______。
- A. DR　B. MAR　C. DC　D. CR
- 解析：内存地址寄存器 MAR → **B**。

**例3（选择题）**：CPU 干预频率从高到低排列正确的是______。
- A. 轮询 > 中断 > DMA > 通道　B. 中断 > 轮询 > DMA > 通道　C. DMA > 中断 > 轮询 > 通道　D. 通道 > DMA > 中断 > 轮询
- 解析：极高 > 高 > 中 > 低 → **A**。

**例4（判断题）**：中断驱动方式中，数据直接从设备传送到内存。（×）
- 解析：中断驱动**每字都经 CPU 中转**（设备→CPU→内存）；直接到内存的是 DMA。

**例5（概念题）**：DMA 方式相比中断驱动方式有哪些改进？
- 答：①传输单位从"字"提升为"**块**"，中断次数大幅减少；②数据**直接设备↔内存**，**不再经过 CPU**（省去"读入 CPU 寄存器再写入主存"的两步）；③CPU 只在**传输开始/结束时**被干预一次，中间过程完全由 DMA 控制器完成——CPU 利用率显著提高。

**例6（变式·中断次数计算）**：某磁盘一次 I/O 传输 64KB 数据。分别用中断驱动与 DMA（块大小 4KB）方式，各产生多少次中断？若用程序直接控制，CPU 需干预多少次？
- 解：中断驱动以"字"为单位——若 1 字 = 2B，则 64KB = **32768 次中断**；DMA 以块为单位 → 64KB ÷ 4KB = **16 次中断**（每块传完中断一次）；程序直接控制则**每字轮询 + 搬移一次 = 32768 次 CPU 干预**，且全程忙等。对比：16 次 vs 32768 次——**传输单位每放大一层，中断开销缩小一个量级**。易错点：**中断次数 = 数据量 ÷ 每次传输单位**，与"读几次盘"是两回事。

**例7（变式·综合选择）**：某系统要连续读取磁盘上**不相邻**的 100 个数据块（每块 4KB）。下列叙述正确的是______。
- A. 用 DMA 一条指令即可全部读完
- B. DMA 方式下 CPU 需发出多条指令（每次针对一个连续区段），并多次中断
- C. 通道方式也只能每次读一个块
- D. 中断驱动方式读 100 块只需要 100 次中断
- 解析：**B**。A 错——**DMA 只能读写连续块**，离散块须多条指令、多次中断；C 错——通道程序的指令**可编排多条**，能处理离散块序列，一条通道指令启动后按程序执行；D 错——中断驱动以**字**为单位，100 块 × 每块字数 >> 100 次中断。易错点：**"DMA 快"不等于"DMA 全能"——离散块的调度正是通道相对 DMA 的优势**。

## IO软件层次

**例1（选择题）**："设置设备寄存器、检查设备状态"属于______。
- A. 用户层软件　B. 设备独立性软件　C. 设备驱动程序　D. 中断处理程序
- 解析：直接操作硬件寄存器 → **C**。

**例2（选择题）**："设备分配与回收、缓冲区管理"属于______。
- A. 设备驱动程序　B. 设备独立性软件　C. 中断处理程序　D. 用户层软件
- 解析：通用管理、不涉硬件 → **B**。

**例3（选择题）**：LUT 记录的信息包括______。
- A. 逻辑设备名、物理设备名、驱动程序入口地址　B. 文件名、路径、权限　C. 设备状态、缓冲区大小　D. 中断号、优先级
- 解析：LUT 三要素 → **A**。

**例4（判断题）**：多用户系统中，整个系统只设置一张逻辑设备表 LUT。（×）
- 解析：多用户系统**每个用户一张 LUT**（存于 PCB），逻辑设备名可重复。

**例5（概念题）**：为什么不同设备需要不同驱动程序？
- 答：设备的具体硬件特性（状态寄存器的含义、数据寄存器数量、命令格式等）**只有设备厂商才知道**，操作系统无法预知每款设备的细节。因此由厂商编写**设备驱动程序**，把操作系统统一的 read/write 命令翻译成该设备能理解的寄存器操作——驱动程序是"统一接口"与"具体硬件"之间的翻译层。

**例6（变式·判层）**：分别判断下列处理属于哪一层：① 打印机缺纸时把错误类型记录到系统日志；② 程序调用 printf 输出；③ 键盘中断后把字符从控制器数据寄存器读入内存；④ 根据逻辑设备名查 LUT 找到打印机驱动入口。
- 解：① 差错处理 → **设备独立性软件**；② 库函数封装 → **用户层软件**；③ 从控制器读数据 → **中断处理程序**；④ LUT 映射 → **设备独立性软件**。易错点：**"记录错误"是差错处理（独立性软件），"读设备寄存器"是中断程序/驱动**——别把"处理错误"误归驱动。

**例7（变式·综合辨析）**：某多用户系统中，用户 A 与用户 B 都把打印机命名为"打印机"，系统采用每人一张 LUT。① 两人的逻辑设备名冲突吗？② 用户 A 登录时其 LUT 存放在哪里？③ 若两人选中的物理打印机相同，是否允许？
- 解：① **不冲突**——每人一张 LUT，逻辑设备名可重复；② 存于用户 A 管理进程的 **PCB** 中，**登录时建立**；③ **允许**——多个用户可共享同一物理设备（由设备独立性软件的分配/回收统一管理）。易错点：**"逻辑名可重复"仅当每人一张 LUT；单用户系统才是一张全局 LUT（不允许重名）**。


## IO 应用程序接口和设备驱动程序接口

**例1（选择题）**：下列属于阻塞 I/O 典型例子的是______。
- A. 向磁盘写数据　B. 从键盘读入一个字符　C. 向网卡发送报文　D. 读取文件元数据
- 解析：键盘输入需等待用户按键，进程阻塞 → **B**。

**例2（选择题）**：设备独立性（设备无关性）的根本含义是______。
- A. 程序不区分任何设备类型　B. 程序用统一接口访问同类设备，换设备不必改程序　C. 不需要设备驱动程序　D. 设备不需要编址
- 解析：统一接口 + 换设备不改程序 → **B**。

**例3（选择题）**：下列关于驱动接口的说法正确的是______。
- A. 驱动接口由设备厂商自行决定　B. 不同 OS 的驱动接口标准完全相同　C. OS 制定统一驱动接口标准，厂商按其开发驱动　D. 用户直接调用驱动程序
- 解析：OS 定标准、厂商实现、用户不接触驱动 → **C**。

**例4（判断题）**：网络设备接口是单向的，只能接收数据。（×）
- 解析：网络接口**双向**——既收也发，面向报文/分组。

**例5（简答题）**：为什么说"write 到磁盘是非阻塞 I/O"？
- 答：`write` 系统调用把数据交给**内核缓冲区（页缓存）**后就返回，进程不必等数据真正写入磁盘扇区；磁盘落盘由内核按策略异步完成（write-back）。若进程需要确保落盘，可调用 `fsync`/`fdatasync` 强制刷盘并等待完成——那才属于阻塞等待。

**例6（变式·阻塞判定）**：判断下列每次系统调用的阻塞/非阻塞属性并说明理由：① 从键盘读取一个字符；② 向打印机输出一行字符（打印机正忙）；③ 读取磁盘上已缓存命中（页缓存中）的块；④ 从空 socket 接收报文。
- 解：① **阻塞**——必须等用户按键，进程挂起；② **阻塞**——打印机忙时数据无法进入缓冲即返回，进程等待设备空闲；③ **非阻塞**——页缓存命中，数据直接复制返回；④ **阻塞**——无报文可收，进程挂起直到数据到达。易错点：**同一设备不同调用也可能一个阻塞一个非阻塞**——判据是"本次调用能否立即拿到结果"。

**例7（变式·综合辨析）**：关于"统一驱动接口"的意义，下列说法错误的是______。
- A. 用户程序面对统一 API，换同类设备不用改程序
- B. 设备厂商必须按目标 OS 的驱动接口标准开发驱动
- C. 不同 OS 的驱动接口标准完全相同，一个驱动到处可用
- D. 驱动接口位于设备独立性软件与驱动程序之间
- 解析：**C 错**——Windows（WDM/WDF）与 Linux 的驱动接口标准**并不相同**，厂商需为不同 OS 分别开发驱动（B 对）；A 是设备独立性（对）；D 是驱动接口的位置（对）。易错点：**"接口标准化"是"OS 内统一"，不是"跨 OS 统一"**。

## IO 核心子系统

**例1（选择题）**：下列功能中，在用户层软件中实现的是______。
- A. I/O 调度　B. 设备保护　C. 假脱机技术　D. 缓冲区管理
- 解析：SPOOLing 在用户层，其余四项在设备独立性软件 → **C**。

**例2（选择题）**：I/O 调度的对象是______。
- A. 进程　B. CPU　C. 设备的 I/O 请求　D. 作业
- 解析：I/O 调度针对设备请求顺序 → **C**。

**例3（选择题）**：UNIX 中实现设备保护所依据的权限信息存放在______。
- A. 设备驱动程序　B. 设备对应的 FCB　C. 内存管理单元　D. 中断向量表
- 解析：设备被看作特殊文件，权限在 FCB → **B**。

**例4（判断题）**：I/O 核心子系统只包括设备独立性软件一层。（×）
- 解析：核心子系统 = **设备独立性软件 + 设备驱动程序 + 中断处理程序**三层（中间三层）。

**例5（简答题）**：为什么 SPOOLing 技术在用户层软件实现，而 I/O 调度在设备独立性软件层？
- 答：SPOOLing 的核心是**在磁盘上开辟缓冲空间**、模拟独占设备的输入井/输出井，并向用户提供排队打印等接口——它需要用户进程参与（提交打印任务）并请求磁盘服务的系统调用，故在**用户层软件**（配合磁盘设备独立性软件服务）。而 I/O 调度是**对所有设备请求排队通用的管理操作**，不涉及具体硬件细节，故在**设备独立性软件**层实现。

**例6（变式·功能归属）**：下列功能中属于设备独立性软件层实现的有______（多选）。
- A. 磁盘 I/O 请求按 SCAN 算法排序
- B. 检查用户对打印机的访问权限
- C. 打印任务先写入磁盘输出井再排队
- D. 用双缓冲消除设备间速度差异
- 解：**A、B、D**。A = I/O 调度、B = 设备保护、D = 缓冲区管理，均在设备独立性软件层；C = SPOOLing，在**用户层软件**实现。易错点：**见到"排队打印/输出井"这类词即定位 SPOOLing → 用户层**。

**例7（变式·综合辨析）**：判断正误：① I/O 调度与进程调度是同一件事，只是说法不同；② 设备保护机制与文件保护完全无关；③ I/O 核心子系统由设备独立性软件、设备驱动程序、中断处理程序三层构成；④ SPOOLing 属于 I/O 核心子系统的组成部分。
- 解：①（×）调度**对象**不同——I/O 请求 vs CPU 使用权；②（×）设备被看作特殊文件，**借 FCB 权限机制**实现保护（同一套机制）；③（√）核心子系统 = 中间三层；④（×）SPOOLing 在**用户层软件**实现，不属核心子系统三层。易错点：**"核心子系统管 SPOOLing 的底层支持" ≠ "SPOOLing 在核心子系统中实现"**——归属看实现层，不看服务对象。


## 假脱机

**例1（选择题）**：SPOOLing 技术中，输入井和输出井位于______。
- A. 内存　B. 磁盘　C. 打印机　D. 高速缓存
- 解析：井在磁盘（模拟磁带）→ **B**。

**例2（选择题）**：SPOOLing 的输入进程模拟的是______。
- A. 磁带　B. 外围控制机　C. 打印机　D. 井管理程序
- 解析：输入/输出进程模拟外围控制机 → **B**。

**例3（选择题）**：打印请求表挂在______上。
- A. 输入井　B. 输出缓冲区　C. 假脱机文件队列（打印任务队列）D. 内存页表
- 解析：请求表挂到打印任务队列 → **C**。

**例4（判断题）**：SPOOLing 技术可以把独占设备改造成共享设备。（√）
- 解析：核心价值就是"独占→共享"，如打印机。

**例5（简答题）**：简述 SPOOLing 实现共享打印机的过程。
- 答：①多个进程请求打印时，假脱机管理进程并不真正分配打印机，而是在磁盘**输出井**为每个进程申请空闲区存放打印数据，并申请一张**打印请求表**记下数据位置，挂到**打印任务队列**；②打印机空闲时，**输出进程**从队列队头取出请求表，把对应数据从输出井读到**输出缓冲区**，再送打印机打印。这样每个进程都感觉独占了一台打印机，实际是排队共享——实现了"独占设备共享化"。

**例6（变式·部件辨析）**：判断下列说法的正误：① 输入缓冲区位于磁盘上；② 输出井位于内存中；③ 输入进程的职责是把数据从输入设备经输入缓冲区送入输入井；④ 井管理程序负责打印队列的调度。
- 解：①（×）缓冲区在**内存**；②（×）井在**磁盘**；③（√）输入进程管"设备→缓冲区→井"；④（×）井管理程序管**井空间分配/回收**，打印队列调度是**输出进程**的职责。易错点：**"谁管井空间（井管理程序）"与"谁取任务打印（输出进程）"两件事**，别混。

**例7（变式·综合）**：某系统只有 1 台打印机，4 个进程同时请求打印（各自 20ms 即可生成并写完打印数据，打印每份需 40ms）。采用 SPOOLing 后：① 4 个进程各需要约多久"完成"（交数据即算完成）？② 打印机全部打完需多久？③ 若无 SPOOLing 直接排队打印，第 4 个进程需等多久才能开始打印？
- 解：① 各进程 ≈ **20ms + 写井开销**（几乎同时"完成"，不等打印机）；② 打印机串行 4 × 40 = **160ms** 打完；③ 无 SPOOLing 时第 4 个进程要等前 3 份打完 = 3 × 40 = **120ms** 才能开始（加上自身生成 20ms 共约 140ms 完成）。对比可见：SPOOLing **消除进程侧等待**、但**不改变设备服务时间**——设备仍是串行瓶颈。


## 设备分配与回收

**例1（选择题）**：设备分配时，系统首先根据请求查找______。
- A. DCT　B. COCT　C. SDT　D. CHCT
- 解析：分配从 SDT（系统设备表）开始 → **C**。

**例2（选择题）**：设备控制表 DCT 中不包含______。
- A. 设备类型　B. 设备状态　C. 等待该设备的进程队列指针　D. 内存页表指针
- 解析：DCT 含类型/状态/队列指针等，不含页表 → **D**。

**例3（选择题）**：安全分配方式不会发生死锁的原因是______。
- A. 破坏"互斥"条件　B. 破坏"请求和保持"条件　C. 破坏"不可剥夺"条件　D. 破坏"循环等待"条件
- 解析：分配后立即阻塞、一进程一段只用一设备 → 破坏"请求和保持" → **B**。

**例4（判断题）**：设备分配中，只要设备空闲即可完成分配，无需考虑控制器与通道。（×）
- 解析：**三者必须同时分配成功**才可启动 I/O。

**例5（简答题）**：为什么用逻辑设备名改进设备分配？
- 答：基础版要求用户用物理设备名编程，导致三个问题：暴露底层细节、更换设备后程序无法运行、同类型空闲设备存在时仍需阻塞等待。改为逻辑设备名后：用户只需说明设备**类型**，系统从 SDT 中找到该类型空闲设备分配，并在 **LUT** 中登记映射；再次请求时 LUT 直接定位——实现**设备独立性**，程序与具体物理设备解耦，资源利用率也更高。

**例6（变式·分配追踪）**：进程 P 请求打印机。设 SDT 指向打印机 DCT，DCT 显示打印机空闲并指向控制器 COCT；COCT 显示控制器忙碌。P 将被如何处理？被阻塞后 PCB 挂在哪里？若控制器变为空闲，P 后续还要检查什么？
- 解：设备分配成功、**控制器分配失败** → P 的 PCB 挂到**控制器等待队列**（DCT 中设备的"已分配"状态保留）；控制器空闲后 P 从队列唤醒，**从控制器这一级继续**（设备已分配，不需重查设备），再查 CHCT 是否空闲，通道空闲才完成三级分配并启动 I/O。易错点：**分级分配中"卡在哪一级就挂哪一级的队列"**——不是整体失败回退。

**例7（变式·死锁与分配方式）**：进程 P1、P2 各需 1 台打印机和 1 台绘图仪，系统共有各 1 台。采用不安全分配方式：P1 先申请到打印机、P2 先申请到绘图仪，随后 P1 申请绘图仪、P2 申请打印机——会发生什么？若改用安全分配方式呢？
- 解：不安全分配下两进程各自持有一个设备又互相等待对方设备 → **死锁**（循环等待，且持有并等待）；安全分配方式下，进程**获得一个设备后立即阻塞、完成 I/O 才释放再申请下一个**，不存在"持有并等待"→ **不会死锁**（破坏请求和保持条件）。易错点：**死锁与否取决于分配策略**，与设备总数无关——安全分配牺牲并行性换死锁免疫。


## 缓冲区管理

**例1（选择题）**：单缓冲中处理一块数据的平均时间为______。
- A. Max(C,T)+M　B. Max(T,C+M)　C. T+M+C　D. Max(C,M)+T
- 解析：单缓冲 = Max(C,T)+M → **A**。

**例2（选择题）**：设 T=100μs、M=10μs、C=30μs，采用双缓冲，每块平均耗时______。
- A. 110μs　B. 100μs　C. 140μs　D. 90μs
- 解析：双缓冲 = Max(T,C+M) = Max(100,40) = 100μs → **B**。

**例3（选择题）**：缓冲池中"hin"工作缓冲区的作用是______。
- A. 提取输入　B. 收容输入　C. 提取输出　D. 收容输出
- 解析：h=收容，hin=收容输入 → **B**。

**例4（判断题）**：单缓冲下，同一时刻 CPU 与设备可以并行工作。（×）
- 解析：单缓冲时第 2 块输入要等缓冲区腾空，T 与 C+M 只能**串行取大**；**双缓冲**才能让输入与处理并行。

**例5（计算题）**：某系统采用双缓冲，设备输入一块需 T=80ms，缓冲→工作区传送需 M=5ms，CPU 处理需 C=20ms，求处理 10 块数据的总时间。
- 答：每块耗时 = Max(T, C+M) = Max(80, 25) = **80ms**；处理 10 块总时间 ≈ **10 × 80 = 800ms**（第一块略有启动开销，通常按此近似）。

**例6（变式·T < C 的单缓冲）**：设备输入一块 T=20μs、缓冲区→工作区 M=10μs、CPU 处理 C=60μs，采用单缓冲。每块平均耗时多少？瓶颈是谁？
- 解：每块耗时 = Max(C,T)+M = Max(60,20)+10 = **70μs**。此时 T < C：缓冲区冲满后必须等 CPU 处理完（C 完成、缓冲腾空）才能冲下一块 → **CPU 是瓶颈**（设备常在等待）。若同样参数用双缓冲：Max(T, C+M) = Max(20, 70) = **70μs**——双缓冲并未变快，因为瓶颈在 CPU 的 C+M 而非输入。易错点：**双缓冲只消除"设备等待 CPU"类瓶颈，消除不了"CPU 太慢"类瓶颈**。

**例7（变式·综合计算）**：某系统采用双缓冲处理 10 块数据：T=50ms、M=10ms、C=30ms。① 每块平均耗时？② 总耗时？③ 改用单缓冲后每块耗时与总耗时分别是多少？
- 解：① 双缓冲 = Max(T, C+M) = Max(50, 40) = **50ms**；② 总耗时 ≈ 10 × 50 = **500ms**；③ 单缓冲 = Max(C,T)+M = Max(30,50)+10 = **60ms**，总耗时 ≈ 10 × 60 = **600ms**。结论：双缓冲比单缓冲每块省 10ms（省掉的正是 M 与 T 并行化的部分）。易错点：**M 在单缓冲中永远串行、在双缓冲中被并行吸收**——这就是两个公式差一个"M 的位置"的原因。


## 磁盘结构

**例1（选择题）**：磁盘地址由哪三维组成______。
- A. 柱面号、盘面号、扇区号　B. 磁道号、块号、扇区号　C. 柱面号、磁头号、磁道号　D. 盘面号、柱面号、字节号
- 解析：磁盘地址 =（柱面号，盘面号，扇区号）→ **A**。

**例2（选择题）**：下列关于扇区的说法正确的是______。
- A. 最外侧磁道上的扇区数据密度最大　B. 各扇区容量相同，最内侧磁道扇区面积最小、密度最大　C. 扇区大小随磁道位置变化　D. 扇区就是磁道
- 解析：容量相同、内侧面积小密度大 → **B**。

**例3（选择题）**：固定头磁盘的特点是______。
- A. 每个磁道一个磁头，磁头不可移动　B. 磁臂可来回移动　C. 盘片可更换　D. 只有一块盘片
- 解析：固定头 = 每磁道一磁头、不可移动 → **A**。

**例4（计算题）**：某磁盘有 8 个盘面（16 个磁头）、每个盘面 2048 个磁道、每个磁道 128 个扇区，问定位一个磁盘块需多少位地址？
- 答：柱面数 = 磁道数 = 2048 → 11 位；盘面号 = 磁头数 = 16 → 4 位；扇区号 = 128 → 7 位；总位数 = **11+4+7 = 22 位**。

**例5（简答题）**：简述读取磁盘上一个数据块的完整步骤。
- 答：①根据**柱面号**移动磁臂，使磁头定位到目标柱面（寻道）；②**激活**目标**盘面**对应的磁头；③等待磁盘旋转，使目标**扇区**从磁头下划过，完成数据的读/写。

**例6（变式·容量计算）**：某磁盘有 4 个盘片（8 个磁头）、每个盘面有 5000 个磁道、每磁道 400 个扇区、每扇区 512B。① 磁盘总容量？② 磁盘块总数？③ 定位一个磁盘块需多少位地址？
- 解：① 容量 = 8 × 5000 × 400 × 512B = 8×5000×400×2^9 = 16×10^9 B ≈ **16GB**（注：8 磁头 × 5000 磁道 × 400 扇区 = 1.6×10^7 块 × 512B）；② 块数 = **1.6×10^7** 块；③ 地址位数 = ⌈log₂8⌉ + ⌈log₂5000⌉ + ⌈log₂400⌉ = 3 + 13 + 9 = **25 位**。易错点：**盘片数 ≠ 盘面数**——每个盘片上下两面各一个磁头（本盘 4 片 = 8 面）；算盘面号位数用磁头数。

**例7（变式·综合辨析）**：判断正误：① 柱面是同一盘面上所有磁道的集合；② 最外侧磁道的扇区密度最大；③ 固定头磁盘不需要寻道；④ 磁盘块号就是（柱面号，盘面号，扇区号）三个编号拼起来的线性序号。
- 解：①（×）柱面是**所有盘面**上同半径磁道的集合；②（×）**最内侧**磁道面积最小、密度最大；③（√）固定头磁盘每磁道一个磁头，无需移动磁臂（无寻道，只需选磁头 + 旋转）；④（√）块号可由三维地址线性化（如按"柱面优先"排列），文件系统用块号、磁盘用三维地址，二者可换算。易错点：**"固定头省寻道、活动头有寻道"是活动/固定分类的直接推论**。


## 磁盘调度算法

**例1（FCFS）**：严格按队列 53→98→183→37→122→14→124→65→67
```
|98-53|=45 |183-98|=85 |37-183|=146 |122-37|=85 |14-122|=108 |124-14|=110 |65-124|=59 |67-65|=2
总寻道长度 = 45+85+146+85+108+110+59+2 = 640（磁道）
平均寻道长度 = 640/9 ≈ 71.1
```

**例2（SSTF）**：从 53 起每次找**离当前位置最近**的
```
服务顺序：53→65→67→37→14→98→122→124→183
12 + 2 + 30 + 23 + 84 + 24 + 2 + 59 = 236
平均寻道长度 = 236/9 ≈ 26.2
★ 注意 67 之后最近的是 37 而非 98（这是 SSTF 最易算错处）
```

**例3（SCAN）**：初始向增大方向，服务 65,67,98,122,124,183，到最外边缘 **199** 掉头，再服务 37,14
```
服务顺序：53→65→67→98→122→124→183→199→37→14
总寻道长度 = (199-53) + (199-14) = 146 + 185 = 331
平均寻道长度 = 331/9 ≈ 36.8
```

**例4（C-SCAN）**：向上服务 65,67,98,122,124,183，到边缘 199 后快速返回 **0**（不服务），再从 0 向上服务 14,37
```
服务顺序：53→65→67→98→122→124→183→199→0→14→37
总寻道长度 = (199-53) + (199-0) + (37-0) = 146 + 199 + 37 = 382
平均寻道长度 = 382/9 ≈ 42.4
```

**例5（LOOK 与 C-LOOK 对比）**：
```
LOOK：  53→65→67→98→122→124→183→37→14，总长 (183-53)+(183-14) = 130+169 = 299
C-LOOK：53→65→67→98→122→124→183→14→37，总长 (183-53)+(183-14)+(37-14) = 130+169+23 = 322
```

**例6（综合比较题）**：上述例题中各算法平均寻道长度排序？
- 答：SSTF（≈26.2）< LOOK（299/9≈33.2）< SCAN（≈36.8）< C-LOOK（322/9≈35.8）< C-SCAN（≈42.4）< FCFS（≈71.1）。本例中 **SSTF 最优、FCFS 最差**；但 SSTF 有饥饿风险，需结合场景权衡。

**例7（时间计算题）**：磁盘转速 7200 转/分，求平均旋转延迟时间。
- 答：r = 7200/60 = 120 转/秒；平均延迟 = 1/(2r) = 1/240 ≈ **4.17ms**。


## 减少磁盘延迟时间

**例1（选择题）**：扇区交替编号（interleaving）的目的是______。
- A. 减少寻道时间　B. 减少同一磁道内连续读扇区时的延迟时间　C. 增加磁盘容量　D. 加快磁头定位
- 解析：交替编号解决同一磁道内连续扇区的延迟 → **B**。

**例2（选择题）**：错位命名（cylinder skew）主要解决______。
- A. 同磁道扇区间隔　B. 相邻盘面或相邻磁道之间切换时的延迟　C. 磁盘转速过慢　D. 扇区容量不同
- 解析：错位命名解决跨盘面/跨磁道切换延迟 → **B**。

**例3（选择题）**：磁盘物理地址采用（柱面号，盘面号，扇区号）的好处是______。
- A. 减少扇区容量　B. 连续读时优先在同一柱面内换盘面、减少磁头移动　C. 提高磁盘转速　D. 简化磁盘编号
- 解析：柱面号在前 → 少移磁臂 → 减少寻道 → **B**。

**例4（判断题）**：逻辑上相邻的扇区在物理上也相邻排列时，连续读取效率最高。（×）
- 解析：磁头读完要处理数据、盘片仍转——物理相邻反而要**等一圈**，逻辑相邻要物理**隔开**（交替编号）。

**例5（简答题）**：为什么连续读取时"逻辑相邻、物理也相邻"会造成很大延迟？
- 答：磁头读入一个扇区后需要**一小段时间处理数据**（将其送入内存等），而**盘片仍在旋转**。若下一个逻辑扇区在物理上紧邻，此时它已经转过磁头位置，只能等盘片**再转一整圈**让它再次划过磁头才能读取——相当于每次连续读都要浪费接近一圈的旋转时间。通过交替编号（同磁道）与错位命名（跨盘面/磁道）让"处理完时下一扇区恰好转到磁头下"，即可显著减少这类延迟。

**例6（变式·交错因子计算）**：某磁盘转速 5400 转/分、每磁道 8 个扇区、磁头读完一个扇区后需 4ms 处理数据。① 交错因子 K 最小取多少？② 若采用该交错因子，顺序读完整条磁道 8 个扇区需转几圈？
- 解：① r = 5400/60 = 90 转/秒；T_sector = 1/(r×S) = 1/(90×8) ≈ 1.389ms；需 (K−1)×1.389 ≥ 4 → K−1 ≥ 2.88 → **K = 4**（逻辑相邻隔 3 个物理扇区）；
- ② 每读一个扇区等 (K−1)=3 个扇区转过，等价于每扇区花 4×T_sector 时间 → 8 扇区 = 32×T_sector = 32/720 ≈ 44.4ms = **4 圈**。易错点：**交错因子 K=4 表示读完整圈要 K 圈**（每扇区需等 K 个扇区位置的时间，含自身）。若不交错（K=1 且处理时间 4ms > 扇区转过 1.389ms）则每读一个扇区都要等一圈——8 扇区要 8 圈，差距巨大。

**例7（变式·地址结构辨析）**：某磁盘 16 柱面、4 盘面、16 扇区，采用（柱面号，盘面号，扇区号）编址。① 连续读（0000,00,0000）~（0000,11,1111）需移动磁臂吗？② 若改用（盘面号，柱面号，扇区号），连续读同一地址区间要移动磁臂几次？③ 从（0000,00,0000）读到（0000,00,1111）共需转过几个扇区位置？
- 解：① 柱面号相同、只需**依次激活 0~3 号盘面磁头**，不移动磁臂；② （盘面号放最前）则 0 号盘面读完 16 个扇区后盘面号不变、柱面号 +1 → 每次换柱面都要**移动磁臂**，读完 4 盘面×16 扇区需移磁臂 **3 次**（换 4 个柱面之间共 3 次移动）；③ 每磁道 16 扇区，从（0000,00,0000）读到（0000,00,1111）即一个磁道内的连续 16 个扇区 → 转 **1 圈**。易错点：**地址分量排列顺序决定"相邻地址是否跨磁臂"，这就是柱面号放首位的本质理由**。


## 磁盘管理

**例1（选择题）**：低级格式化（物理格式化）的主要工作是______。
- A. 建立根目录　B. 划分扇区并为每个扇区分出头/数据区/尾　C. 创建位示图　D. 划分柱面分区
- 解析：低级格式化把磁道划分为扇区 → **B**。

**例2（选择题）**：逻辑格式化（创建文件系统）不包括______。
- A. 创建根目录　B. 初始化空闲分区表　C. 创建位示图　D. 划分扇区
- 解析：划分扇区是低级格式化的事 → **D**。

**例3（选择题）**：对操作系统透明（OS 无需感知）的坏块管理方式是______。
- A. FAT 表标记　B. 磁盘控制器维护坏块链表并用备用扇区替换　C. 逻辑格式化时整盘检查　D. 用户手动标记
- 解析：控制器内部处理 → OS 透明 → **B**。

**例4（判断题）**：ROM 中存放完整的自举程序以完成开机初始化。（×）
- 解析：ROM 只放**很小的自举装入程序**；完整自举程序在**磁盘引导块**上（ROM 不可改写，更新不便）。

**例5（简答题）**：简述两级引导（ROM 装入程序 + 磁盘引导块）的设计思想。
- 答：自举程序较复杂、需要随系统更新；ROM 内容出厂固化、无法改写。因此把**很小的自举装入程序**放在 ROM 中（固化、可靠），而把**完整的自举程序**放在磁盘的引导块（固定位置）上，可随磁盘更新。开机时 CPU 先执行 ROM 中的装入程序，由它把磁盘引导块中的完整自举程序读入内存执行，再加载操作系统——兼顾了"开机首段程序必须可靠"与"引导程序可更新"两个要求。

**例6（变式·引导块辨析）**：判断正误：① ROM 中存放完整自举程序；② 引导块在磁盘上的位置固定；③ 启动磁盘就是 C 盘（系统盘）；④ MBR 是磁盘的最后一个扇区。
- 解：①（×）ROM 只放**自举装入程序**（很小），完整自举程序在**磁盘引导块**；②（√）引导块位于磁盘**固定位置**，否则装入程序无法定位；③（√）拥有启动分区的磁盘即启动磁盘/系统磁盘；④（×）MBR 是硬盘开机后读取的**首个扇区**（0 号扇区），不是最后一个。易错点：**"引导块固定位置"与"MBR 首扇区"是同一个设计思想的两处体现**——引导代码必须能被无状态地找到。

**例7（变式·综合辨析）**：某磁盘采用复杂磁盘的坏块管理方式。① 一块备用扇区替换了坏扇区后，OS 访问该逻辑扇区号会失败吗？② 若改用简单磁盘的 FAT 标记法，OS 在坏扇区标记前后各扮演什么角色？③ 两种方式下，坏扇区上的旧数据命运有何不同？
- 解：① 不会失败——控制器把坏扇区**重映射到备用扇区**，逻辑扇区号不变，OS 无感知（**透明**）；② 标记前 OS（逻辑格式化时）执行**整盘坏块检查**，标记后 OS 在 **FAT 表**中标注该扇区不可用（**不透明**）；③ 复杂磁盘：坏块被换出后旧数据不可读，但该逻辑位置仍可用（新数据写入备用扇区）；简单磁盘：该逻辑扇区被永久标记不可用，其上的数据随之作废。易错点：**"透明"指 OS 不需要知道替换动作，不表示数据不丢**——坏块上的数据无论哪种方式都已损坏（能否自动修复取决于是否有冗余如 RAID）。


## SSD

**例1（选择题）**：SSD 中数据的读写单位是______。
- A. 块　B. 页　C. 磁道　D. 柱面
- 解析：**读/写以页为单位**，擦除以块为单位 → **B**。

**例2（选择题）**：磨损均衡的主要目的是______。
- A. 提高读写速度　B. 让各闪存块擦写次数均衡、避免某些块先坏　C. 增加磁盘容量　D. 减少寻道时间
- 解析：分散写入、均衡磨损 → 延长整体寿命 → **B**。

**例3（计算题）**：某 SSD 容量 2^40B、块擦写寿命 2^11 次，日均写入 2^38B，磨损均衡下最理想可用多久？
- 答：容量/日均 = 2^40/2^38 = 4 天；寿命 = 4 × 2^11 = 2^13 = **8192 天 ≈ 22.4 年**。

**例4（判断题）**：SSD 可以对同一页进行原地覆盖写入。（×）
- 解析：闪存**必须先擦除再写入，不能原地覆盖**——所以 SSD 主控要做垃圾回收与磨损均衡。

**例5（简答题）**：为什么 SSD 随机读写性能远超 HDD？
- 答：HDD 随机访问要**寻道（移动磁臂）+ 旋转延迟（等目标扇区转过来）**，都是毫秒级机械动作；SSD **无机械部件**，访问任意页都只需电子寻址（微秒级）。所以随机 I/O 场景下 SSD 性能优势巨大——这也是磁盘调度算法（5.3_2，优化寻道）对 SSD 不再重要的原因。

**例6（变式·单位换算陷阱）**：某 SSD 容量 1TB（按 2^40B 计）、块擦写寿命 2^10 次。① 用户日均写入 2^35B，磨损均衡下最理想寿命？② 若用户每天把整盘写满 2 次（即日均写入 2^41B），寿命又为多少？
- 解：① 容量/日均 = 2^40/2^35 = 2^5 = 32 天；寿命 = 32 × 2^10 = 2^15 = **32768 天 ≈ 89.8 年**；② 日均 2^41B > 容量 2^40B → 容量/日均 = 1/2 天（即每半天整盘写一遍）；寿命 = 0.5 × 2^10 = **512 天 ≈ 1.4 年**。易错点：**"每天写满 2 次"直接把寿命砍到约 1.4 年**——容量小于日均写入量时先算全盘写一遍的间隔（可小于 1 天），再乘擦写寿命，不要算出负数或"立即报废"。

**例7（变式·闪存类型选择）**：同制程下，TLC 每单元 3 位、写入寿命约为 SLC 的 1/3。某 SSD 用 SLC 模式预计寿命 6 年，改用 TLC 模式（容量翻 3 倍）后：① 在总写入量相同的用户场景下寿命约几年？② 若用户写入量不变、但 TLC 容量翻 3 倍使"容量/日均写入"也翻 3 倍，寿命如何变化？
- 解：① TLC 每单元位数多 → 写寿命约为 SLC 的 1/3 → 同容量下寿命 ≈ **2 年**（6 × 1/3）；② 容量翻 3 倍 → 全盘写一遍间隔翻 3 倍 → 寿命 = 2 年 × 3 = **6 年**——与 SLC 打平。易错点：**"单位寿命降 1/3"与"容量×3"两个效应互相抵消**——这正是厂商用大容量 TLC/QLC 弥补寿命劣势的策略；计算时先写"寿命 = (容量/日均) × 擦写寿命"，再代入两个倍率。
