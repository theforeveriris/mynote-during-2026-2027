
## 1.基本概念

应用层对应用程序的通信提供服务。

应用层协议定义（四要素）：
- 报文类型：应用进程交换的报文类型，请求还是响应？
- 语法：各种报文类型的语法，如报文中的各个字段及其详细描述。
- 语义：字段的语义，即包含在字段中的信息的含义。
- 时序：进程何时、如何发送报文，以及对报文进行响应的规则。

应用层的功能：
- 文件传输、访问和管理
- 电子邮件
- 虚拟终端
- 查询服务和远程作业登录

应用层的重要协议：
- FTP、TFTP
- SMTP、POP3、IMAP
- HTTP、HTTPS
- DNS
- SNMP
- Telnet
- DHCP
- P2P
- VoIP

网络应用模型分为：
- 客户/服务器模型（Client/Server，C/S）
    - 服务器提供计算服务的设备。
        - 永久提供服务
        - 永久性访问地址/域名
    - 客户机请求计算服务的主机。
        - 与服务器通信，使用服务器提供的服务
        - 间歇性接入网络
    - 可能使用动态IP地址
    - 不与其他客户机直接通信
    - 典型应用：Web、文件传输FTP、远程登录、电子邮件
- P2P模型（Peer-to-peer）
    - 不存在永远在线的服务器
    - 每个主机既可以提供服务，也可以请求服务
    - 任意端系统/节点之间可以直接通讯
    - 节点间歇性接入网络
    - 节点可能改变IP地址
    - 可扩展性好
    - 网络健壮性强

| 协议         | 功能      | 传输层     | 端口               | 模型  | 关键记忆点           |
| ---------- | ------- | ------- | ---------------- | --- | --------------- |
| **DNS**    | 域名 → IP | UDP/TCP | 53               | C/S | 普通 UDP，区域传送 TCP |
| **FTP**    | 文件传输    | TCP     | 21（控制）<br>20（数据） | C/S | 双连接，控制全程开       |
| **TFTP**   | 简单文件传输  | UDP     | 69               | C/S | 简单、无认证、UDP      |
| **SMTP**   | 发送邮件    | TCP     | 25               | C/S | 只传 ASCII        |
| **POP3**   | 读取邮件    | TCP     | 110              | C/S | 下载后默认删除         |
| **IMAP**   | 读取邮件    | TCP     | 143              | C/S | 服务器端管理          |
| **MIME**   | 扩展邮件格式  | —       | —                | —   | Base64 编码       |
| **HTTP**   | Web 访问  | TCP     | 80               | C/S | 无状态，Cookie      |
| **HTTPS**  | 安全 Web  | TCP     | 443              | C/S | HTTP + TLS/SSL  |
| **Telnet** | 远程登录    | TCP     | 23               | C/S | 明文，不安全          |
| **SSH**    | 安全远程登录  | TCP     | 22               | C/S | 加密替代 Telnet     |
| **SNMP**   | 网络管理    | UDP     | 161/162          | C/S | MIB、Trap        |
| **DHCP**   | 自动配置 IP | UDP     | 67/68            | C/S | DORA 四步、租约      |
| **SIP**    | 会话控制    | UDP/TCP | 5060             | C/S | VoIP 信令         |
| **RTP**    | 实时数据传输  | UDP     | 动态               | —   | 承载语音视频          |


## 2.域名解析系统（DNS，Domain Name System）

DNS服务的作用：将域名解析成IP地址。

### 2.1 域名结构（层次化）
示例：www.theforeveriris.com
- www：三级域名
- theforeveriris：二级域名
- com：顶级域名

| 层次       | 说明                                                                                                                        |
| -------- | ------------------------------------------------------------------------------------------------------------------------- |
| **根**    | `.`                                                                                                                       |
| **顶级域名** | 国家顶级域名：`cn`, `us`, `uk` 等<br>通用顶级域名：`com`, `net`, `org`, `gov`, `int`, `aero`, `museum`, `travel` 等<br>基础结构域名/反向域名：`arpa` |
| **二级域名** | 类别域名：`ac`, `com`, `edu`, `gov`, `mil`, `net`, `org`<br>行政区域名：用于我国各省、自治区、直辖市，如 `bj`, `js`                                  |
| **三级域名** | 如 `www`, `mail`                                                                                                           |
| **四级域名** | 如 `mail.hust.edu.cn` 中的主机名                                                                                                |

> 注意：域名中的标号不区分大小写，除连字符 - 外不能使用其他标点符号，每个标号不超过 63 个字符，完整域名不超过 255 个字符。

### 2.2 域名解析过程

| 类型          | 说明                                                             |
| ----------- | -------------------------------------------------------------- |
| **根域名服务器**  | 最高层次的域名服务器，知道所有顶级域名服务器的域名和IP地址                                 |
| **顶级域名服务器** | 管理该顶级域名下注册的所有二级域名<br>（如 `org` 域名服务器、`com` 域名服务器、`edu` 域名服务器）   |
| **权限域名服务器** | 负责一个**区**（zone）的域名服务器<br>（如 `abc.org` 域名服务器、`y.abc.org` 域名服务器） |
| **本地域名服务器** | 当一个主机发出DNS查询请求时，这个查询请求报文就发给本地域名服务器                             |

在 DNS 查询过程中，域名服务器之间的查询方式有两种：

| 方式       | 特点                           | 记忆口诀    |
| -------- | ---------------------------- | ------- |
| **递归查询** | 本地域名服务器代替主机去查询，直到得到结果再返回给主机  | **靠别人** |
| **迭代查询** | 本地域名服务器自己逐级去查询，每次获得下一级服务器的地址 | **靠自己** |

实际使用的解析方式：
- 主机 → 本地域名服务器：通常采用递归查询
- 本地域名服务器 → 其他域名服务器：通常采用迭代查询（也可配置为递归）
- 高速缓存：本地域名服务器会缓存之前查询过的记录，提高解析效率

以查询 y.abc.com 的IP地址为例：

方式一：纯递归查询（较少用）
```
主机 m.xyz.com
  ↓ ① 递归查询
本地域名服务器 dns.xyz.com
  ↓ ② 递归查询
根域名服务器
  ↓ ③ 递归查询
顶级域名服务器 dns.com
  ↓ ④ 递归查询
权限域名服务器 dns.abc.com
  ↓ ⑤ 返回 y.abc.com 的IP地址
顶级域名服务器
  ↓ ⑥ 返回
根域名服务器
  ↓ ⑦ 返回
本地域名服务器
  ↓ ⑧ 返回给主机
主机获得 y.abc.com 的IP地址
```

方式二：递归与迭代相结合（常用）
```
主机 m.xyz.com
  ↓ ① 递归查询
本地域名服务器 dns.xyz.com
  ↓ ② 迭代查询 → 根域名服务器
  ← ③ 返回顶级域名服务器 dns.com 的地址
  ↓ ④ 迭代查询 → 顶级域名服务器 dns.com
  ← ⑤ 返回权限域名服务器 dns.abc.com 的地址
  ↓ ⑥ 迭代查询 → 权限域名服务器 dns.abc.com
  ← ⑦ 返回 y.abc.com 的IP地址
  ↓ ⑧ 返回给主机
主机获得 y.abc.com 的IP地址
```

## 3.文件传输协议（FTP，File Transfer Protocol）和简单文件传输协议（TFTP，Trivial File Transfer Protocol）

FTP 提供交互式的文件访问，允许客户指明文件类型和格式，允许文件具有存取权限。采用 C/S 模型，使用 TCP 可靠传输。

一个 FTP 服务器进程可同时为多个客户服务：
- 一个主进程：负责接收新的请求
- 若干个从属进程：负责处理单个请求
    - 控制进程（1个）
    - 数据传送进程（1个或多个）

| 连接       | 端口                              | 作用                                  | 生命周期                  |
| -------- | ------------------------------- | ----------------------------------- | --------------------- |
| **控制连接** | **21**                          | 传输控制命令和响应（如 USER, PASS, RETR, STOR） | 整个会话期间**保持打开**        |
| **数据连接** | **20**（主动模式）<br>或**随机端口**（被动模式） | 实际传输文件数据                            | 传输一次文件后**关闭**，下次传输再建立 |


| 模式             | 控制连接        | 数据连接            | 特点                  |
| -------------- | ----------- | --------------- | ------------------- |
| **主动模式（PORT）** | 客户 → 服务器:21 | 服务器:20 → 客户随机端口 | 服务器主动发起数据连接，易被防火墙阻挡 |
| **被动模式（PASV）** | 客户 → 服务器:21 | 客户 → 服务器随机端口    | 服务器被动等待，穿透防火墙能力更强   |

| 项目   | 内容                       |
| ---- | ------------------------ |
| 全称   | 简单文件传输协议                 |
| 传输层  | **UDP**                  |
| 端口   | **69**                   |
| 特点   | 代码简单、开销小、**无认证**、**不可靠** |
| 适用场景 | 无盘工作站启动、嵌入式设备升级、小文件传输    |
| 工作方式 | 类似停止-等待协议，每发一个数据块等确认     |

| 对比项 | FTP     | TFTP        |
| --- | ------- | ----------- |
| 传输层 | TCP     | UDP         |
| 端口  | 21/20   | 69          |
| 可靠性 | 可靠      | 不可靠（自己实现确认） |
| 认证  | 有用户名/密码 | 无认证         |
| 复杂度 | 复杂      | 极简单         |
| 适用  | 互联网文件传输 | 局域网/无盘启动    |



## 4.电子邮件系统(SMTP/POP3/IMAP)

| 组成           | 说明                                 |
| ------------ | ---------------------------------- |
| **用户代理（UA）** | 用户与电子邮件系统的接口，如 Outlook、Foxmail、浏览器 |
| **邮件服务器**    | 发送 & 接收邮件，向发件人报告结果，采用 C/S 模型       |
| **邮件协议**     | 发送协议（SMTP）+ 读取协议（POP3/IMAP）        |

电子邮件格式如下：

```
信封
└── 收件人地址

内容 = 首部 + 主体
├── 首部（Header）
│   ├── From：发件人
│   ├── To：收件人
│   ├── Subject：主题
│   ├── Date：日期
│   └── Cc：抄送
└── 主体（Body）
    └── 邮件正文
```

### 4.1 SMTP（Simple Mail Transfer Protocol 简单邮件传输协议）

| 项目   | 内容                  |
| ---- | ------------------- |
| 作用   | **发送**邮件（推，Push）    |
| 传输层  | TCP                 |
| 端口   | **25**              |
| 连接对象 | 发送方邮件服务器 → 接收方邮件服务器 |

- 只能传输 7 位 ASCII 码文本
- 不支持非 ASCII 内容（图片、音频、中文等）
- 使用 MIME 扩展以支持多媒体

SMTP 通信三阶段：
- 连接建立：TCP 连接，端口 25
- 邮件传送：使用 SMTP 命令交互
- 连接释放：QUIT 命令，释放 TCP 连接

### 4.2 MIME(Multipurpose Internet Mail Extensions 多用途互联网邮件扩展)

扩展 SMTP，使其支持非 ASCII 内容。

| 功能            | 说明                                 |
| ------------- | ---------------------------------- |
| 增加 5 个新邮件首部字段 | 如 `MIME-Version`, `Content-Type` 等 |
| 定义许多**内容格式**  | 标准化表示非 ASCII 内容                    |
| 定义**传送编码**    | Base64、Quoted-printable            |

将二进制数据转换为 ASCII 字符串，每 6 位一组映射为 64 个可打印字符。

### 4.3 主流的邮件读取协议（POP3(Post Office Protocol,邮局协议)/IMAP（Internet Message Access Protocol，互联网邮件访问协议））

| 协议    | POP3         | IMAP          |
| ----- | ------------ | ------------- |
| 全称    | 邮局协议第 3 版    | 互联网邮件访问协议     |
| 端口    | 110          | 143           |
| 传输层   | TCP          | TCP           |
| 方式    | 拉（Pull）      | 拉（Pull）       |
| 操作位置  | **下载到本地**后操作 | **直接在服务器**上操作 |
| 删除策略  | 默认下载后删除服务器副本 | 不自动删除         |
| 文件夹支持 | 不支持          | 支持多文件夹        |
| 状态保持  | 无状态          | 有状态           |
| 适用场景  | 单机用户         | 多设备同步         |

### 4.4 基于万维网的电子邮件

用户通过浏览器收发邮件（如 Gmail、QQ邮箱网页版）：
- 发件：浏览器 → 邮件服务器 使用 HTTP
- 邮件服务器之间 仍使用 SMTP
- 收件：邮件服务器 → 浏览器 使用 HTTP

## 5.万维网（WWW）与HTTP（HyperText Transfer Protocol，超文本传输协议）、HTTPs(HyperText Transfer Protocol Secure，安全超文本传输协议)

| 概念       | 说明                                    |
| -------- | ------------------------------------- |
| **URL**  | 统一资源定位符，标识互联网资源<br>格式：`协议://主机:端口/路径` |
| **HTTP** | 超文本传输协议，Web 的核心应用层协议                  |
| **HTML** | 超文本标记语言，描述 Web 页面                     |
| **浏览器**  | 用户代理，解释显示页面                           |

### 5.1 HTTP 协议简介

| 特点       | 说明                       |
| -------- | ------------------------ |
| **无状态**  | 服务器不记得之前处理过的请求           |
| **无连接**  | HTTP/1.0 每次请求都要新建 TCP 连接 |
| **面向文本** | 报文中每个字段都是 ASCII 码串       |


无状态的解决：使用 Cookie 在客户端存储会话信息。
- 用户首次访问网站，服务器在响应报文中加入 Set-Cookie 首部
- 浏览器将 Cookie 保存在本地
- 以后每次请求该网站，浏览器自动在请求报文中加入 Cookie 首部
- 服务器识别 Cookie，恢复用户状态

| 连接类型      | HTTP/1.0 | HTTP/1.1       |
| --------- | -------- | -------------- |
| **非持久连接** | 默认       | 可选             |
| **持久连接**  | 不支持      | 默认（Keep-Alive） |

- 非持久连接：每个对象（HTML、图片、CSS）都要单独建立 TCP 连接，开销极大。
- 持久连接：
    - 非流水线（without pipelining）：客户收到前一个响应后才能发下一个请求，RTT 浪费
    - 流水线（with pipelining）：客户可连续发多个请求，服务器按序响应，效率最高

请求报文格式如下：

```
请求行
├── 方法（GET/POST/HEAD/PUT/DELETE/CONNECT/OPTIONS/TRACE/PATCH）
├── URL
└── HTTP版本（HTTP/1.0 或 HTTP/1.1）

首部行
├── Host：目标主机（HTTP/1.1 必须）
├── Connection：连接方式（Keep-Alive / close）
├── User-Agent：浏览器类型
├── Accept：可接受的媒体类型
├── Cookie
└── ...

空行

实体主体（GET 通常无，POST 有表单数据）
响应报文
```

响应报文格式如下：

```
状态行
├── HTTP版本
├── 状态码（3位数字）
└── 原因短语

首部行
├── Date：响应时间
├── Server：服务器信息
├── Last-Modified：最后修改时间
├── Content-Type：实体主体类型
├── Content-Length：实体主体长度
├── Set-Cookie
└── ...

空行

实体主体（HTML 文档、图片等）

```

| 方法          | 作用             | 特点              |
| ----------- | -------------- | --------------- |
| **GET**     | 请求读取 URL 标识的信息 | 幂等、安全，数据在 URL 中 |
| **POST**    | 给服务器添加信息（如表单）  | 非幂等，数据在实体主体中    |
| **HEAD**    | 请求读取首部，不返回主体   | 用于测试链接有效性       |
| **PUT**     | 上传文件，覆盖目标资源    | 幂等              |
| **DELETE**  | 删除 URL 标识的资源   | 幂等              |
| **CONNECT** | 用于代理服务器        | 建立隧道            |
| **OPTIONS** | 查询支持的选项        | 预检请求            |
| **TRACE**   | 回显服务器收到的请求     | 测试/诊断           |


| 类别  | 范围      | 含义                     |
| --- | ------- | ---------------------- |
| 1xx | 100-199 | 信息性状态码（如 100 Continue） |
| 2xx | 200-299 | 成功                     |
| 3xx | 300-399 | 重定向                    |
| 4xx | 400-499 | 客户端错误                  |
| 5xx | 500-599 | 服务器错误                  |


| 状态码 | 含义                    | 场景               |
| --- | --------------------- | ---------------- |
| 200 | OK                    | 请求成功             |
| 301 | Moved Permanently     | 永久重定向，自动跳转到新 URL |
| 302 | Found                 | 临时重定向            |
| 304 | Not Modified          | 协商缓存命中，无需重新传输    |
| 400 | Bad Request           | 请求报文语法错误         |
| 401 | Unauthorized          | 未授权              |
| 403 | Forbidden             | 服务器拒绝访问          |
| 404 | Not Found             | 服务器上没有请求的资源      |
| 500 | Internal Server Error | 服务器内部错误          |
| 502 | Bad Gateway           | 网关/代理从上游收到无效响应   |
| 503 | Service Unavailable   | 服务器暂时过载或维护       |


| 特性    | HTTP/1.0 | HTTP/1.1   | HTTP/2                  |
| ----- | -------- | ---------- | ----------------------- |
| 持久连接  | 不支持      | 默认支持       | 基于 TCP，单一长连接            |
| 流水线   | 不支持      | 支持         | 支持多路复用                  |
| 主机头   | 不支持      | 必须 Host 首部 | 必须                      |
| 分块传输  | 不支持      | 支持         | 支持                      |
| 多路复用  | 无        | 无          | **有**（单一 TCP 连接并行传输多个流） |
| 头部压缩  | 无        | 无          | **HPACK**               |
| 服务器推送 | 无        | 无          | **支持**                  |

### 5.2 HTTPS（HTTP Secure）

| 项目  | 内容                                               |
| --- | ------------------------------------------------ |
| 本质  | **HTTP + SSL/TLS**（不是独立协议）                       |
| 端口  | **443**                                          |
| 传输层 | TCP                                              |
| 功能  | **加密**、**身份认证**、**完整性保护**                        |
| 过程  | 先建立 TCP 连接 → SSL/TLS 握手（协商密钥、验证证书）→ 加密传输 HTTP 数据 |

> 注意：HTTPS 的加密发生在应用层与传输层之间（TLS 层），传输层仍是 TCP。

## 6.远程连接（Telnet和SSH（Secure Shell））

Telnet 是远程登录协议，允许用户通过网络登录远程主机，使用远程主机的资源。采用 C/S 模型，使用 TCP 可靠传输。

| 项目  | 内容                                |
| --- | --------------------------------- |
| 全称  | 远程终端协议（Telecommunication Network） |
| 传输层 | TCP                               |
| 端口  | **23**                            |
| 特点  | 明文传输，**不安全**                      |
| 原理  | 本地终端 → NVT（网络虚拟终端）格式转换 → 远程服务器    |
| 现状  | 已逐渐被 SSH 取代                       |

SSH 是安全远程登录协议，允许用户通过网络安全地登录远程主机，使用远程主机的资源。采用 C/S 模型，使用 TCP 可靠传输。

| 项目  | 内容                             |
| --- | ------------------------------ |
| 传输层 | TCP                            |
| 端口  | **22**                         |
| 特点  | **加密传输**，替代 Telnet 和 FTP 的安全版本 |
| 功能  | 远程登录、安全文件传输（SFTP/SCP）          |

## 7.SNMP（Simple Network Management Protocol，简单网络管理协议）

SNMP 是一种用于网络设备管理和监控的协议，它允许网络管理员收集和修改网络设备的信息。采用 C/S 模型，使用 UDP 传输。

| 项目  | 内容                                                |
| --- | ------------------------------------------------- |
| 全称  | 简单网络管理协议                                          |
| 传输层 | **UDP**                                           |
| 端口  | **161**（管理站查询 Agent）<br>**162**（Agent 向管理站发 Trap） |
| 模型  | C/S（Manager/Agent）                                |
| 核心  | **MIB**（管理信息库）：被管对象的集合                            |

组成部分：
- 管理站（Manager）：运行 SNMP 客户端程序，向代理发请求
- 代理（Agent）：运行在被管设备上，维护本地 MIB，响应管理站
- MIB：树形结构，每个被管对象有唯一 OID

操作类型：
- Get：管理站查询代理的一个或多个对象值
- Set：管理站设置代理的对象值
- Trap：代理主动向管理站报告异常事件（异步）

版本演进：
- SNMPv1：社区字符串认证，安全性弱
- SNMPv2c：支持批量查询（GetBulk），仍用社区字符串
- SNMPv3：增加认证、加密、访问控制，安全性大幅提升

## 8.DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）

| 项目  | 内容                           |
| --- | ---------------------------- |
| 作用  | 自动分配 IP 地址、子网掩码、默认网关、DNS 服务器 |
| 传输层 | **UDP**                      |
| 端口  | **67**（服务器）、**68**（客户端）      |
| 模型  | C/S                          |

| 步骤 | 报文                | 说明                                              |
| -- | ----------------- | ----------------------------------------------- |
| ①  | **DHCP Discover** | 客户端广播（源 0.0.0.0，目的 255.255.255.255），寻找 DHCP 服务器 |
| ②  | **DHCP Offer**    | 服务器响应，提供 IP 地址等配置信息                             |
| ③  | **DHCP Request**  | 客户端广播（告知所有服务器选择了哪个 Offer）                       |
| ④  | **DHCP ACK**      | 服务器确认，正式分配 IP                                   |

## 9.多媒体应用VoIP（Voice over IP）

在 IP 网络上传输语音/视频数据。

| 协议/标准     | 作用                   | 传输层     | 端口           |
| --------- | -------------------- | ------- | ------------ |
| **SIP**   | 会话初始协议，建立、修改、终止多媒体会话 | UDP/TCP | **5060**     |
| **H.323** | ITU 标准，较复杂，用于视频会议    | TCP     | 多种           |
| **RTP**   | 实时传输协议，承载语音/视频数据     | **UDP** | 动态分配（通常偶数端口） |
| **RTCP**  | RTP 控制协议，传输质量反馈      | **UDP** | RTP 端口 + 1   |

SIP 功能：
- 用户定位：确定通信对方位置
- 会话建立：握手协商媒体参数
- 会话管理：修改、终止会话
RTP 通常被认为在应用层（或介于应用层与传输层之间），因为它封装在 UDP 之上，但提供应用层所需的实时功能。

## 10.P2P 应用与协议

BitTorrent 是一种 P2P 文件共享协议，允许用户在网络中直接交换文件，而无需依赖中心服务器。

| 项目      | 内容                                |
| ------- | --------------------------------- |
| 文件分发    | 将大文件分割成等大的**块（chunk，通常 256KB）**   |
| 种子文件    | `.torrent` 文件，包含 Tracker 地址和文件块信息 |
| Tracker | 跟踪参与下载的 Peer 列表                   |
| 工作方式    | 用户下载同时上传已拥有的块，"下载人越多越快"           |

机制：
- 稀有优先：优先下载网络中稀缺的块
- 阻塞算法（Choking）：限制上传连接数，激励用户分享
- DHT（分布式哈希表）：无 Tracker 时，通过 DHT 网络发现 Peer
