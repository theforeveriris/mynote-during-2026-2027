移动IP（Mobile IP）是IETF制定的标准协议（RFC 3344），核心目标是让移动设备在跨越不同网段漫游时，依然使用固定的永久IP地址通信，且上层应用（如TCP连接）完全感知不到位置变化。以下从概念到机制逐层深入。

传统IP地址具有双重语义：既标识身份（我是谁），又标识位置（我在哪）。当设备从一个子网移动到另一个子网时，必须更换IP地址，导致：
- 所有现有TCP连接中断。
- 应用层会话（如视频通话、下载）被迫终止。
- 网络权限（如防火墙白名单、VPN策略）失效。

移动IP的解决思路是将"身份"与"位置"解耦：设备始终对外宣称自己的永久地址（身份），但网络层内部通过"转交地址"（位置）完成实际寻址。

## 1.核心概念详解

| 概念       | 英文                    | 角色定位        | 深入说明                                                                                                                                              |
| -------- | --------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **移动结点** | Mobile Node           | 主角          | 具有永久IP地址的移动设备。它同时维护两个地址：**永久地址**（Home Address，对外身份）和**转交地址**（Care-of Address，实际位置）。                                                               |
| **归属网络** | Home Network          | 老家          | 移动结点最初注册所在的网络，其网络前缀与永久地址匹配。                                                                                                                       |
| **归属代理** | Home Agent (HA)       | 老家的"村长"/路由器 | 通常是归属网络中的一台路由器。它维护一张**绑定表（Binding Cache）**，记录"永久地址 ↔ 转交地址"的映射。当移动节点外出时，HA负责**截获**所有发往永久地址的数据报，并通过**隧道**转发到转交地址。                                   |
| **永久地址** | Home Address          | 身份证号        | 在归属网络中分配的原始IP地址，**终身不变**，是移动节点对外暴露的唯一标识。                                                                                                          |
| **外部网络** | Foreign Network       | 外地          | 移动节点当前漫游所在的非归属网络。                                                                                                                                 |
| **外部代理** | Foreign Agent (FA)    | 外地的"招待所"    | 外部网络中的路由器，负责向移动节点**通告自己的存在**，提供**转交地址**，并接收来自HA的隧道数据报，解封装后交付给移动节点。                                                                                |
| **转交地址** | Care-of Address (CoA) | 临时住址        | 移动节点在外部网络中的临时IP地址，分为两种：<br>① **外部代理转交地址**（FA CoA）：外部代理的IP地址，多个移动节点可共享，通过端口号区分；<br>② **同置转交地址**（Co-located CoA）：移动节点自己通过DHCP在外部网络获取的独立地址，无需外部代理参与。 |

王道考研的PPT中的"葫芦娃"比喻：归属代理是村子（葫芦娃的家），移动节点是爷爷，永久地址是爷爷的"身份证"，外部代理是盘丝洞（妖精的地盘），转交地址就是"盘丝洞的地址"。葫芦娃给爷爷写信（发往永久地址），信先到村子（归属代理），村子再把信转寄到盘丝洞（外部代理），盘丝洞最后把信交给爷爷。

## 2.通信过程

### 2.1 阶段0：代理发现（Agent Discovery）

在正式通信前，移动节点需要知道附近有没有归属代理或外部代理。这通过扩展ICMP路由器发现机制完成：
- 代理通告（Agent Advertisement）：HA和FA周期性广播/组播报文，宣告自己的类型（HA/FA）、IP地址、转交地址、是否需要注册等。
- 代理请求（Agent Solicitation）：移动节点也可主动发送请求，加速发现过程。  

移动节点通过比较报文中的网络前缀，判断自己当前在归属网络还是外部网络。

### 2.2 场景A：刚进入外部网络（注册与隧道建立）

这是移动IP最核心的流程，分为四步：
- 第 1步：获得转交地址：移动节点进入外部网络后，通过代理发现收到外部代理的通告报文，从中提取转交地址（FA CoA）。如果是同置模式，则通过DHCP自行获取一个本地地址作为CoA。
- 第 2步：注册（Registration）：移动节点向归属代理发送注册请求报文（UDP端口434），报文内容包含：
  - 永久地址（Home Address）
  - 转交地址（Care-of Address）
  - 归属代理地址
  - 生存期（Lifetime）：绑定有效期
  - 标识（Identification）：用于防止重放攻击
- 第 3步：绑定与隧道建立，归属代理收到注册请求后：
  - 认证：确认该移动节点是否合法。
  - 建立绑定：在绑定表中记录"永久地址 ↔ 转交地址"的映射。
  - 代理截获：归属代理开始代理ARP（或代理NDP，IPv6场景）响应，或利用路由机制，截获所有发往该永久地址的数据报。
  - 封装与隧道：归属代理将截获的数据报进行IP-in-IP封装：
    - 外层IP首部：源地址=归属代理，目的地址=转交地址
    - 内层IP首部：源地址=通信对端，目的地址=永久地址（保持不变）
  - 封装后的数据报通过隧道发送到转交地址。归属代理向移动节点返回注册响应（经外部代理转发）。
- 第 4步：解封装与交付,外部代理收到隧道数据报后：
  - 检查外层目的地址是自己的转交地址。
  - 解封装，提取内层数据报。
  - 将内层数据报（目的地址为移动节点的永久地址）交付给移动节点。
  - 此时，数据流向：通信对端 → 归属代理（截获）→（隧道）→ 外部代理（解封装）→ 移动节点

### 2.3 场景B：移动到下一个外部网络（切换与绑定更新）

当移动节点从外部网络A漫游到外部网络B时：
- 新代理发现：移动节点通过新链路的代理通告，发现新的外部代理，获得新的转交地址。
- 重新注册：移动节点（或新外部代理）向归属代理发送新的注册请求，包含新的转交地址。
- 绑定更新：归属代理收到后，覆盖旧的绑定（永久地址 ↔ 旧CoA 更新为 永久地址 ↔ 新CoA）。
- 隧道切换：此后，归属代理将隧道终点切换到新的转交地址，数据流无缝转移到新路径。
- 旧绑定老化：旧的绑定记录通常保留短暂时间（软状态），以防在途数据报丢失，随后自动删除。
- 关键特性：整个切换过程中，移动节点的永久地址不变，上层TCP连接无需重新建立。

### 2.4 场景C：回到归属网络（注销与直接交付）

当移动节点返回归属网络时：
- 网络检测：移动节点收到归属代理的通告，发现网络前缀与归属网络匹配。
- 发送注销：向归属代理发送注册请求，将生存期设为0，表示注销转交地址。
- 删除绑定：归属代理从绑定表中删除该移动节点的所有绑定记录。
- 恢复直接交付：
  - 归属代理停止截获发往该永久地址的数据报。
  - 数据报通过正常的局域网二层交换/直接交付到达移动节点。
- 不再使用隧道，也不再经过外部代理。
- 移动节点停止使用转交地址，恢复为普通固定主机模式。
