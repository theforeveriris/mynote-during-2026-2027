# Internet基本服务

## 考点速记


### 二、Internet 基础与互联

1. 异构网络互联设备：路由器（网络与网络连接的桥梁）。
2. Internet 核心属性：是TCP/IP 互联网、信息资源网，非局域网；用户无需知晓内部结构，联网计算机统称主机。
3. Internet 核心协议：IP（网络互联协议）。
4. Internet 核心设备作用：主机是信息资源和网络服务的载体；集线器/ 中继器仅放大、中继传输信号，无互联功能。

### 三、客户机/ 服务器（C/S）模型

1. 核心交互方式：客户机主动发起请求，服务器被动等待。
2. 服务器响应请求方案：并发服务器方案、重复服务器方案（SNMP 服务采用重复服务器）。

### 四、电子邮件服务协议

1. SMTP 协议：用于发送邮件，客户机/ 服务器模式，基于TCP；规定邮件发送命令，不定义接收存储规则；邮件传递分连接建立、邮件传送、连接关闭三阶段；服务器响应以3 位十进制数开头；邮件服务器之间传递邮件使用SMTP。
2. POP3 协议：用于接收/ 检索邮件，基于TCP；工作分认证、事务处理、更新三阶段；核心命令：STAT（查询报文总数和长度）、RETR（获取指定编号邮件）、DELE （标记删除邮件）、RSET（清除删除标记）、QUIT（彻底删除标记邮件）、LIST（事务处理阶段查看邮件）；服务器响应以“+”/“-” 开头。
3. 多媒体邮件传输：MIME 协议扩充RFC822，支持二进制信息传输；base64 编码将二进制码转为ASCII 码，紧跟在Content-Transfer-Encoding 邮件头后。
4. SMTP 核心命令：HELO（握手）、MAIL FROM（发件人）、RCPT TO（收件人）、DATA （发送邮件内容）。

### 五、Telnet 协议

1. 核心功能：使本地主机成为远程主机的仿真终端，C/S 模式。
2. 关键技术：NVT（网络虚拟终端），屏蔽不同主机系统对键盘输入/ 解释的差异。
3. 常见错误点：非使远程服务器成为本地终端，不用于文件下载，无需客户端和服务器操作系统相同。

### 六、FTP 协议

1. 双重连接：控制连接（始终保持）、数据连接（传输时建立），均基于TCP。
2. 数据连接模式：主动模式（客户发PORT 命令告知端口，服务器发起连接）、被动模式（客户发PASV/PASSIVE 命令，服务器告知端口，客户发起连接）。
3. 文件传输方式：文本方式（转NVT ASCII 码，可能修改文件）、二进制方式（原格式传输，无修改，适用于图像/ 非文本文件）；核心命令：ASCII（进入文本模式）、TYPE（指定传输类型）。
4. 核心用户接口命令：PASS（发送口令）、pwd（显示远程主机当前目录）、REST（断点续传，指定下载起始点）、open（连接服务器）、cdup（返回上级目录）、get （下载文件）、mput（批量上传）、passive（进入被动模式）、ABOR（中断传输）。
5. FTP 服务器：匿名FTP 账号默认anonymous。

### 七、DNS 域名系统

1. 命名机制：层次型树状结构，非扁平/ 无层次结构。
2. 解析服务器：由一组独立协作的域名服务器组成，逻辑为树型；解析器为客户端程序，不保存域名数据库；域名服务器非域名解析器。
3. 解析方式：递归解析（服务器一次性完成名字- 地址变换）、反复解析；解析通常从本地域名服务器开始，不一定从根服务器开始。
4. 解析效率优化：本地服务器解析、服务器/ 本地主机启用高速缓冲技术；减小TTL 值、从根服务器开始解析、拒绝非权威性响应会降低效率。
5. 非权威性响应：解析由非该域名管理机构的服务器完成，信息可能不准确，而非服务器或请求错误。📌<sup>已订正：句子截断、缺主语（单选题第 43 题答案 B）</sup>
6. 资源记录：
    - 类别IN：Internet 协议类别；
    - 类型A：主机地址、类型MX：邮件交换机、类型CNAME：别名、类型SOA：授权开始、类型HINFO：主机描述信息、类型TXT：文本信息；
    - CNAME 记录需解析至对应A 记录的IP 地址。

7. 域名配置：本地主机应优先配置所属网络的域名服务器（如 dns.a.edu.cn）📌<sup>已订正：题库标准答案为域名形式而非 IP（单选题第 71 题答案 B）</sup>。
8. 域名后缀：com（商业组织）、edu（教育机构）、gov（政府部门）、mil（军事部门）。

### 八、Web 服务（HTTP/HTML/ 浏览器）

1. 核心模式：C/S 模式，非对等模式；页面链接由URL 维持，以超文本方式组织信息。
2. HTTP 协议：基于TCP，定义请求/ 响应报文格式；请求报文含请求行+ 若干报头行，可带报文体；响应报文含状态行+ 若干报头行，可带报文体；状态码为3 位十进制数；Web 服务器需实现HTTP 协议。
3. HTML 语言：用于描述Web 文档结构，标记不区分大小写，部分成对出现，属性间用空格分隔；核心标记：<P>（段落标记）；非传输协议。
4. 浏览器组成：控制单元（接收/ 解释用户键盘/ 鼠标输入）、客户单元（与Web 服务器通信，发送HTTP 请求）、解释单元（解析HTML 页面，解释服务器返回页面）；无QoS 单元。
5. Web 安全：
    - 验证Web 站点真实性：索要/ 验证站点数字证书，服务器安装自身证书；
    - 防止他人假冒自己：浏览器安装个人数字证书；
    - 防止第三方偷看传输内容：使用SSL 协议（HTTPS:// 开头）；
    - 保护本地计算机：将Internet 划分为Internet、本地Intranet、可信、受限区域；
    - Web 服务器无需具备编辑页面功能。


### 九、网络安全相关

1. SSL 协议：实现浏览器与Web 服务器的安全交互，服务器需安装自身数字证书； HTTPS 为带SSL 的HTTP，URL 以https:// 开头。
2. 数字证书：浏览器安装个人证书用于证明自身身份，验证站点需站点证书；服务器安装证书用于验证自身身份，接收浏览器身份验证需验证浏览器证书。

### 十、常见网络服务端口/ 应用对应

1. Telnet：远程仿真终端，基于NVT 技术；
2. FTP：文件传输，双重连接+ 两种传输/ 连接模式；
3. HTTP/HTTPS：Web 访问，基于TCP，HTTPS 带SSL；
4. SMTP/POP3：电子邮件收发，服务器间用SMTP；
5. DNS：域名解析，树型服务器结构，递归/ 反复解析；
6. SNMP：网络管理，采用重复服务器解决方案。
1. 分布式结构化P2P 网络：采用DHT 表组织结构，支持精确关键词匹配查询，无中心服务器。
2. 分布式非结构化P2P 网络：采用随机图组织，洪泛式搜索，支持复杂查询，无中心服务器；早期Napster 为集中式P2P，非该类型。
3. P2P 网络主要结构类型：集中式、分布式非结构化、分布式结构化、混合式。
4. 混合式P2P 网络结点类型：用户结点、搜索结点、索引结点。
5. 集中式P2P 网络：中心服务器保存索引信息。
6. P2P 对等计算：直接交换共享主机资源，无客户机/ 服务器划分，BT 为典型应用；分布式结构化网络基于DHT 查询，非结构化基于广播查询，二者均无中心服务器。

## Internet 基础概念

1. Internet 本质：TCP/IP 互联网、信息资源网，不是局域网。
2. 核心互联设备：路由器（连接异构网络、路径选择）。
3. 信息资源载体：主机（PC、手机、平板）；路由器/交换机/集线器不是载体。
4. 核心协议：IP 协议。

## P2P 网络结构（必考）

1. 对等计算没有传统的服务器和客户端之分。
2. 四类结构：集中式、分布式非结构化、分布式结构化、混合式。
3. 集中式P2P：有中心服务器，保存索引（如Napster）。
4. 分布式非结构化P2P：随机图、洪泛搜索、支持复杂查询、无中心服务器。
5. 分布式结构化P2P：采用DHT（分布式哈希表）、精确查询、无中心服务器。
6. 混合式P2P 节点：用户结点、搜索结点、索引结点。

## 客户机/服务器模型

1. 工作模式：客户机主动请求，服务器被动等待。
2. 服务器两种方案：重复服务器、并发服务器。
3. 服务器通常采用TCP 或UDP 的端口号标识特定的服务。
4. 采用重复服务器：SNMP 服务。

## DNS 域名系统

1. 结构：层次型、树状命名。
2. 解析方式：递归解析（一次性转换）、反复解析；解析可从任一域名服务器开始。
3. 提高解析效率：从本地DNS 域名服务器开始、使用高速缓存、不减小TTL。
4. 资源记录类型 A：主机地址。 MX：邮件交换机。 HINFO：主机描述。 IN：Internet 类别。 SOA：授权开始。
5. 非权威响应：响应服务器不是该域名的授权管理者，提供的信息可能不准。
6. 域名服务器≠解析器。

## Telnet 远程登录

1. 目的：本地主机成为远程主机的仿真终端。
2. 核心技术：NVT（网络虚拟终端），屏蔽不同系统对键盘输入差异。
3. 模式：客户机/服务器。
4. 数据传输：利用传输层的TCP 协议进行数据传输。

## FTP 文件传输协议

1. 双连接：控制连接（一直保持）、数据连接（传输时建立）。
2. 数据连接模式 主动模式：客户端发送 PORT 命令告知端口，服务器建立连接📌<sup>已订正：PORT/PASV 均由客户端发出（单选题第 75 题答案 C）</sup>。 被动模式：客户端发送PASV 命令，客户端建立连接。 主动模式和被动模式都使用TCP。
3. 传输方式 ASCII（文本）：转换格式。 Binary（二进制）：原样传输（图片、压缩包用）。
4. 常用命令 PASV（passive）：进入被动模式。 PORT：主动模式端口告知。 REST：断点续传起始点。 pwd：显示远程主机的当前目录。 close：中断与服务器的连接。 ascii：使用ASCII 类型传输方式。 PASS：发送口令。 ftp：进入ftp 会话状态。 quit：退出ftp 会话。 delete：删除远程主机上的文件。

## 电子邮件E-mail（协议必背）

1. 发送邮件：SMTP（客户机→服务器、服务器→服务器）。
2. 接收邮件：POP3、IMAP。
3. 多媒体邮件：MIME（扩展RFC822）。
4. 编码方法： Base64 在Content-Transfer-Encoding 后；将二进制码转换成ASCII 码。 Quoted-printable。
5. POP3 三阶段：认证→事务处理→更新。
6. POP3 命令(客户机检索邮件服务器上的邮件) STAT：查询邮件总数/长度。 RETR：接收指定邮件。 LIST：列出报文的长度。 DELE：标记删除。 上面四个是事务处理阶段用到的。 RSET：取消删除。 QUIT：确认删除。
7. SMTP 三阶段：连接建立→邮件传送→连接关闭。
8. SMTP 命令(向邮件服务器发送邮件) RCPT·TO：指定接收者。 DATA：开始发送邮件内容。 MAIL·FROM：指名邮件发送人地址。
9. 响应格式 POP3：+OK/-ERR。 SMTP：3 位数字。

## Web 服务与HTTP/HTML

1. 模式：客户机/服务器。
2. 核心：HTTP 协议、HTML 页面规范、URL 定位（维持页面到页面的链接信息）。
3. 浏览器三单元：控制单元、客户单元、解释单元。 控制单元：接收和解释用户的键盘和鼠标输入。 客户单元：负责与远端Web 服务器进行通信。 解释单元：解释HTML 页面。
4. Web 客户机称为Web 浏览器，最早由Tim-Berners-Lee 开发。
5. Mosaic 是第一个图形界面的Web 浏览器。
6. 安全 HTTPS=HTTP+SSL。 安装用户证书：防假冒身份。 验证站点：索要服务器证书。 区域划分：保护本机。
7. HTML：标记不区分大小写，<P>是段落标记。页面通常符合HTML 规范、标记成对出 现、有些标记具有可选的属性，主要用于描述Web 文档结构。
8. HTTP：是浏览器与Web 服务器之间的传输协议，基于TCP 的基础，定义了请求报文 和响应报文的格式；请求报文含一个请求行和若干报头行，响应报文含一个状态行 和若干报头行，应答报文中的状态码由3 位数字组成。

## 网络安全与认证

1. 用户数字证书：证明自己身份，防止被假冒。
2. 服务器证书：验证网站真实可信。
3. SSL：保障传输加密、防止第三方偷看；使用SSL 前期需要安装数字证书。
4. 浏览器区域划分：保护本机安全。
