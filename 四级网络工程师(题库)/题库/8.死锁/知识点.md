# 死锁

## 考点速记

1. 定义：进程间相互等待对方资源，进入阻塞且无法唤醒的状态
2. 产生原因：资源分配不当、进程推进顺序不当
3. 独占设备防死锁最佳策略：静态分配 + 分配时加锁📌<sup>已订正：（与后文同义，统一措辞，无实质改动）</sup>
4. 死锁定理：资源分配图不可完全化简时，系统存在死锁
5. 资源分配图判定：无环路必无死锁，有环路可能死锁

### 二、死锁四大必要条件

1. 互斥：资源为独占使用，不可共享
2. 请求和保持：进程持有已分配资源，同时申请新资源
3. 不可剥夺：进程未主动释放的资源，其他进程无法强行获取
4. 循环等待：进程间形成资源请求的环形链，相互等待

### 三、死锁四大处理策略

1. 预防（破坏任一必要条件） 一次性分配全部资源：破坏请求和保持 资源按序分配：破坏循环等待 SPOOLing 技术：将独占设备虚拟为共享，破坏互斥 进程非运行时释放资源/ 剥夺进程资源：破坏不可剥夺 同时申请多个资源，不逐个申请：破坏请求和保持
2. 避免（维持必要条件，确保安全状态） 核心：银行家算法，动态检测系统状态 关键概念：Need=Max-Allocation；Work 初始值= Available；安全序列 状态关系：安全状态必无死锁，不安全状态可能导致死锁
3. 检测（允许暂存死锁，定时检测） 方式：定时设进程还原点、资源分析程序检测资源分配图
4. 解除（检测到死锁后恢复系统） 方法：剥夺死锁进程资源、撤销死锁进程、重启系统；主动释放已占资源

### 四、经典同步问题（死锁典型场景）

1. 哲学家进餐问题！！！ 死锁原因：各持一根筷子，循环等待另一根 预防：同时取左右筷子、最多4 人同时申请、奇偶编号取筷顺序相反、增配筷子 破条件对应：一次性取筷（请求和保持）、取不到则放弃（不可剥夺）、定取筷顺序（循环等待） 恢复：主动放筷子、剥夺他人筷子
2. 交叉路口死锁 红绿灯：破坏请求和保持；立交桥：破坏互斥 单向行驶：破坏循环等待；可倒车缓冲区：破坏不可剥夺
3. 进程互持设备死锁 典型：P1 持A 求B，P2 持B 求A，可能死锁非必定 预防：按序申请、同时申请、SPOOLing 管理、增加设备、暂停一个进程申请

### 五、资源分配计算（防死锁）

1. 通用公式：设 n 个进程共享 m 个同类资源，每个进程最多申请 k 个，则不发生死锁的充分条件为 n×k-n+1 ≤ m，即 k ≤ (m+n-1)/n 向下取整📌<sup>已订正：统一公式口径，使与「(m+n-1)/n 取整」写法一致</sup>
2. 多类资源：结合银行家算法，计算剩余资源、需求矩阵，判断安全序列

### 六、活锁、饥饿（与死锁区分）

1. 活锁：进程未阻塞、可调度，但始终无执行进展
2. 饥饿：进程未阻塞，但调度被无限推后，长期无法获取资源/ CPU
3. 典型：读者- 写者模型中，读者持续涌入会导致写者饥饿

### 七、生产者- 消费者模型（信号量与死锁）

1. 正确顺序：生产者先 P(mutex) 再 P(empty)；消费者先 P(mutex) 再 P(full)，可正常运行📌<sup>已订正：与上位笔记 5.死锁.md 第 103 行「应先 P(互斥) 再 P(同步)」冲突；先互斥后同步才可避免死锁</sup>
2. 错误顺序：颠倒资源信号量与互斥信号量的P 操作，可能引发死锁
3. 信号量作用：mutex 保护缓冲区互斥访问；empty/full 控制缓冲区空/ 满状态

## 死锁基础

1. 产生原因：资源分配不当+进程推进顺序不当。
2. 死锁定义：进程阻塞且无法唤醒，无限等待。
3. 活锁：进程可调度、未阻塞，但一直无进展。
4. 饥饿：进程可调度，但长期得不到资源/调度。
5. 死锁定理：资源分配图不可完全化简→死锁。
6. 资源分配图：无环路→无死锁；有环路→可能死锁。

## 死锁4 个必要条件

1. 互斥：独占使用（如打印机）。
2. 请求和保持：持有资源又申请新资源。
3. 不可剥夺：资源只能主动释放，不能被抢占。
4. 循环等待：进程形成循环等待链。

## 死锁处理策略

1. 死锁预防（破坏条件） 破坏互斥：SPOOLing 技术。 破坏请求和保持：一次性分配所有资源。 破坏不可剥夺：允许抢占资源。 破坏循环等待：资源按序分配。
2. 死锁避免 核心算法：银行家算法。 安全状态：一定不会死锁。 不安全状态：可能死锁。
3. 死锁检测 允许发生死锁，定期检查资源分配图。
4. 死锁解除（恢复） 剥夺资源。 撤销进程。 重启系统。 还原到还原点。

## 独占设备分配策略

预防死锁最佳策略：静态分配，分配时加锁。


## 安全计算公式

n 进程共享 m 个同类资源，每个进程最多申请 (m+n-1)/n 向下取整（即 n×k-n+1≤m 时取 k）。例：9 个资源 3 个进程最多申请 3 个；7 个资源 3 个进程最多申请 3 个。📌<sup>已订正：与本文件通用公式不等价：m 为 n 的倍数时两种写法冲突</sup>
