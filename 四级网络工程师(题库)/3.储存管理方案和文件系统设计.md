
## 1.进程同步与互斥基础

进程互斥的解决办法
- 平等协商：竞争各方自行协调（如Peterson算法）。
- 引入进程管理者：通过操作系统或同步机制（如信号量、管程）统一管理

可以实现进程互斥的算法:
Peterson 算法、TS 指令、Swap 或 Exchange 命令、信号量。

|   层次   | 核心问题        | 特点                                    |
| :----: | :---------- | :------------------------------------ |
| **互斥** | 临界资源访问冲突    | 硬件方法简单、支持多临界区、适用范围广；**缺点：不能实现"让权等待"** |
| **死锁** | 多个进程循环等待资源  | 需预防、避免、检测与解除                          |
| **饥饿** | 某些进程长期得不到资源 | 需公平调度策略                               |

临界资源的四个部分:
- 进入区:检查能否进入临界区，执行 P 原语	
- 临界区:访问临界资源的代码段	
- 退出区:释放临界资源，执行 V 原语	
- 剩余区:代码其余部分	

进程同步机制准则:
- 空闲则入:如果临界区空闲，则进程直接进入临界区。
- 忙则等待:如果临界区有进程占用，进程进入等待队列。
- 有限等待:进程在等待队列中等待的时间是有限的，不会无限等待。
- 让权等待:当进程不能进入临界区时，应立即释放 CPU，避免忙等（自旋）

进程间的通信方式:

| 方式       | 说明                                                                         |
| -------- | -------------------------------------------------------------------------- |
| **共享内存** | 用于多个进程并发执行且相互通信，适合传输大量信息；设置一个公共内存区，一组向其中写，一组从公共内存读；不需要在系统中产生多份相同的拷贝。       |
| **消息机制** | 利用内存中若干缓存区组织成队列，依赖进程或基础框架来调用实际执行的代码；缓冲区中包括：消息缓冲区、消息指针、互斥信息量、同步信息量、发送和接收原语。 |
| **管道通信** | 通过两个进程，打开一个共享文件，实现进程间的通信；字符流形式联系，不足是通信速度较慢。                                |
| **信箱通信** | 发送进程首先创建一个链接两个进程的通信机制，然后把信息送入该机制；发送进程和接受进程不直接联系，接收进程可以在任何时刻从该机制中取出信息。      |

### 1.1 信号量(Semaphore)

关于信号量的使用:
- 访问方式：只能通过初始化和两个标准原语（P/V）访问
- 初始化：非负整数值表示空闲资源总数；若为负值，绝对值表示等待进程数
    - 同步示例：P(empty) / V(full)
- 同步信号量：empty 初始值 K，full 初始值 0
- 互斥信号量：mutex 初始值 1（占用为 1，空闲为 0 的理解需注意：通常 1 表示可用，0 表示已被占用）
- 系统直接通信原语：send(receiver, message)

关于信号量的值：
- 信号量的值 = 可用资源的数量。
    - 当信号量值 > 0：代表还有多少个资源空闲可用。
    - 当信号量值 = 0：代表资源刚好全被占用，没剩余。
    - 当信号量值 < 0：代表资源不仅全被占用，绝对值还代表有多少个进程在门口排队等着。
- 以停车场为例：
    - 停车场有 1 个厕所（互斥资源），初始值 mutex = 1（空着）。
    - 进程 A 来了，执行 P(mutex)：值变为 0（占用，没排队）。A 进去。
    - 进程 B 来了，执行 P(mutex)：值变为 -1（占用，且有 1 人在排队）。B 在外面等。
    - 进程 A 出来，执行 V(mutex)：值变为 0（空出来了，排队的人减少 1 个）。唤醒 B 进去。

关于P/V原语：
- 原语 P(mutex)：
    - 先把值减 1。
    - 如果减完后 大于等于 0，说明拿资源成功，继续执行。
    - 如果减完后 小于 0，说明资源没了，把自己挂起（阻塞），加入等待队列。
- 原语 V(mutex)：
    - 先把值加 1。
    - 如果加完后 大于 0，说明归还成功（原来肯定有空位）。
    - 如果加完后 小于等于 0，说明原来有人在排队，赶紧从等待队列里叫醒一个进来。

关于同步（empty/full）和互斥（mutex）
- 同步信号量（empty 和 full）：控制“顺序”，保证东西放进去才能拿出来。
    - empty 初始值 = 快递柜总数（K）。没放的格子数。
    - full 初始值 = 0。已放的包裹数。
    - 生产者（放快递）：必须先 P(empty)（占一个空柜子），放完 V(full)（通知包裹数+1）。
    - 消费者（取快递）：必须先 P(full)（看看有没有包裹，没有就等着），取完 V(empty)（释放一个空柜子）。
- 互斥信号量（mutex）：控制“排他”，保证取放操作不打架。
    - 初始值 = 1。
    - 无论生产者还是消费者，在操作柜门（访问临界区）之前，都必须先 P(mutex)，操作完再 V(mutex)，其意义在于：
        - 如果P(mutex)结果为负数，说明有其他进程正在操作柜门，必须等待并立刻V(mutex)。
        - 如果P(mutex)结果为非负数，说明柜门空闲，直接进入临界区，操作完后立刻 V(mutex)。

> 笔记最后提了“系统直接通信原语”，这是消息传递机制，属于信号量之外的另一种进程通信方式。它俩的关系是：信号量是“抢停车位（公共资源）”，而 send/receive 是“发微信（显式消息）”。考试中通常把两者分开考，记清楚它们不属于 P/V 操作即可


### 1.2 管程（Monitor）

定义了一个数据结构和能为并发进程所执行的一组操作。进程可在任何需要的时候调用管程中的过程，但它们不能在管程之外的过程中直接访问管程数据结构。
- 管程能保障共享资源互斥执行
- 是一种同步机制
- 将共享变量及对共享变量的操作封装在一起
- 管程能保障共享资源互斥执行
- 是一种同步机制
- 将共享变量及对共享变量的操作封装在一起


### 1.3 地址重定位

将逻辑地址转换成绝对地址。
- 动态重定位：每条指令执行时转换；需要软硬件相互配合实现，其中硬件包括基址寄存器和一个地址转换线路组成。
- 静态重定位：程序执行前已转换好地址。


## 2.内存管理

### 2.1 一些基本概念

#### 按照内存管理方式分类：

- 单一用户管理：一个时间内，一个用户进程独占内存。
- 分区管理：可以分为固定分区和可变分区
    - 固定分区：每个进程分配固定大小的内存空间，进程之间不能共享内存。
    - 可变分区：每个进程分配可变大小的内存空间，进程之间可以共享内存。
        - 空闲分区策略：最先适应算法、最优适应算法、最坏适应算法、下次适应算法
    - 特点：可以满足多道程序设计且设计上最简单；内存使用不充分、较为严重碎片、不能提供虚拟内存、受物理内存不足限制
    - 移动技术：可以实现碎片整合。
    - 交换技术：在磁盘上保存内存放不下的进程（代码、PCB 和数据），需要时再装入内存中，是由操作系统控制。

#### 按内存分配方式分类，有页式管理和段式管理。

其中，页式管理的定义与特性如下：


页式管理：将内存分为多个页，每个页的大小固定。进程在执行时，将逻辑地址转换为物理地址，再访问内存。
- 把一个逻辑地址连续分散存放到几个不连续的内存区域。
- 不要求作业或进程的程序段和数据在内存中连续存放，从而有效解决"碎片"多的问题。
- 动态页式管理提供了内存和外存统一管理的虚存实现方式，提高了存储空间利用率。
- 页面大小可以改变，但用户不可以动态改变页面大小。
- 通常管理空闲物理内存的方法有：空闲块链表法、位示图、空闲页面表。


空闲块的分配和回收
- 采用主存分配表、位示图和页表方式。
- 页表中，存储块号与页号一一对应。
- 一级页表：共需访问内存 2 次完成数据提取。
- 二级页表：每执行一条指令至少需要访问 3 次内存。

快表（TLB）
- 存放在高速缓存（介于主存和 CPU 之间的存储器）中。
- 高速缓存器与内存之间信息调度和传送是通过硬件完成的。
- 页式虚拟存储管理：部分页在内存中，其余在外存中（磁盘文件区）。
- 需要用到：请求调用页和预调页策略。

置换策略:

| 策略       | 说明              |
| -------- | --------------- |
| 固定分配局部置换 | 块数固定，置换范围限于作业以内 |
| 可变分配全局置换 | 块数可变，置换范围可在作业以外 |
| 可变分配局部置换 | 块数可变，置换范围限于作业以内 |


页面置换算法：

| 算法           | 说明                                     |
| ------------ | -------------------------------------- |
| **FIFO**     | 会出现 **Belady 现象**，随着分配给进程的物理页面增加，缺页率增加 |
| **LRU**      | 最近最久未使用算法，需要记录访问位                      |
| **LFU**      | 最近最不经常使用算法，当前时间访问次数最少，需要访问计数器          |
| **NRU**      | 最近未使用页面置换算法，需要记录访问位                    |
| **CLOCK**    | 时钟算法，需要记录访问位                           |
| **理想页面置换算法** | —                                      |


而，段式管理的定义为存储以段划分， 段页式管理先分段、再分页、每页对应块、可连续可不连续存储。

> 页式、段式和段页式管理可以与虚拟存储技术结合使用。

> 链接是提高检索速度、节省存储空间的软链接，把所有编译后得到的目标模块连接装配起来，再与函数库相连接成一个整体的过程。

#### 关于碎片

| 类型      | 定义           | 出现的管理方式     |
| ------- | ------------ | ----------- |
| **内碎片** | 分配出内存，没有得到利用 | 固定分区、页式、段页式 |
| **外碎片** | 内存空间无法满足分配要求 | 可变分区、虚拟段式   |

#### 页表项的修改（各种场景）

| 场景               | 需要修改的位                      |
| ---------------- | --------------------------- |
| 进程中断，选中一个页面进行淘汰时 | 只需将页面移除，修改页面**有效位**，其余标志位不变 |
| 创建一个新进程，装入一个页面   | **内存号**、**驻留位**、**访问位**     |
| 页面被修改时           | **访问位**、**修改位**             |
| 将页面调入内存          | **内存号**、**驻留位**、**访问位**     |

#### 程序的局部性

分空间局部性和时间局部性。
- 空间局部性：一旦程序访问了某个存储单元，其附近的存储单元也将被访问，程序代码执行具有顺序性。
- 时间局部性：程序在执行时呈现出局部性规律，即在一段时间内，整个程序的执行仅限于程序中的某一部分。

### 2.2 虚拟页面存储管理

虚拟内存系统在不同层面的“困境”：
- 缺页中断（Page Fault）—— 根源
    - 强制缺页：首次访问某页（如代码刚加载），必须从磁盘读入，不可避免。
    - 容量缺页：工作集大于物理内存，频繁换进换出。
    - 冲突缺页（TLB/页表冲突）：在非全相联映射中，多个虚页竞争同一个物理页框
- 页面抖动（Thrashing）—— 恶性循环
    - 现象：CPU利用率急剧下降，磁盘I/O极度繁忙（“磁盘灯常亮”）
    - 本质：进程频繁缺页，导致CPU总是阻塞等待磁盘I/O。操作系统误以为CPU空闲，引入更多进程，反而使内存更紧缺，形成正反馈死锁
- Belady 现象 —— 算法陷阱
    - 本质：FIFO算法在缺页率增加时，缺页率会继续增加，而不是减少。
    - 反直觉原因：FIFO淘汰的是最早装入的（可能是频繁使用的核心代码），而新调入的页马上又被淘汰，破坏了程序的局部性原理。LRU（最近最少使用）和OPT（最优）算法不会出现此现象。
- 页面写错误（Write Fault / Dirty Page Handling）
    - 写时拷贝（Copy-on-Write, COW）：fork() 子进程时，父子共享只读物理页。当任意一方尝试写入时，MMU触发写保护缺页中断，操作系统才会复制物理页并修改页表权限。
    - 脏页换出：当置换算法选中一个脏页（Dirty Bit=1）时，需先发起磁盘写操作（换出），此时若磁盘满或I/O错误，会引发“写错误”。这是换出流程中最耗时的环节。

解决办法：

采用工作集算法可以缓解页面抖动（操作系统为每一个进程保持一个工作集，工作集随时间而变化，每个进程提供与工作集大小相等的物理页面）。

需要的硬件支持：
- 足够大的内外存
- 虚拟地址到物理地址映射机制
- 缺页中断处理机制


## 3.文件系统设计与实现技术

### 3.1 文件相关概念

#### 文件分类 
 

| 分类依据      | 类型                                                                             |
| --------- | ------------------------------------------------------------------------------ |
| **按用途**   | 系统文件、用户文件、库函数文件                                                                |
| **按组织形式** | 普通文件、目录文件、特殊文件（Unix 中 I/O 设备被视为特殊文件）                                           |
| **保护方式**  | 只读文件、读写文件、可执行文件、无保护文件                                                          |
| **存放时限**  | 临时文件、永久文件、档案文件                                                                 |
| **组织结构**  | **逻辑文件**（用户可见；无结构的字符流式文件、定长记录文件和不定长记录文件构成的记录树）、**物理文件**（存放在磁盘上：顺序文件、链式文件、索引文件） |

#### 文件存储介质

| 存储介质 | 物理结构           | 存取结构  |
| ---- | -------------- | ----- |
| 磁带   | 连续结构           | 顺序    |
| 磁盘   | 连续、链接、索引（多级索引） | 顺序、随机 |


#### 关于磁盘

寻访时间：
- 寻道时间（最长）
- 延迟时间（次长）
- 传输时间（最短）

磁盘调度算法：

| 算法         | 说明              |
| ---------- | --------------- |
| **FCFS**   | 先来先服务           |
| **SSTF**   | 最短寻道时间，容易引起饥饿现象 |
| **SCAN**   | 电梯算法，来回服务       |
| **C-SCAN** | 循环扫描，单向         |


#### 文件目录

实现按名存取，包含文件名和文件的起始地址，用以建立文件名（< 255 字符）与存储地址的对应关系。必须信息：FCB、文件结构信息和文件管理信息。
- FCB 包含文件名、文件号、用户名、文件物理地址、文件长度、口令、修改/访问/建立时间。
- 管理形式
    - 一级目录
    - 二级目录
    - 树型目录（搜索快；层次清楚；解决不同用户文件重命名问题；用户不可以创建根目录）
- 路径名搜索
    - 全路径名
    - 相对路径（加快搜索速度）
- 存储空间的分配与回收（文件存储空间的管理方法）：位示图、空闲块表、空闲链表、成组链接表（UNIX）

### 3.2 文件系统

| 方面         | 内容                                      |
| ---------- | --------------------------------------- |
| **优化**     | 块高速缓存；合理分配磁盘时间；磁盘驱动调度；目录项分解             |
| **FAT**    | 是文件分配表；链接结构；FAT16 表示 16 位簇号，支持 8 个字符文件名 |
| **安全**     | 建立副本、定时转存、规定文件的存取权限                     |
| **文件存储空间** | 分配单位数据块                                 |
| **用户角度**   | 建立文件系统的目标是实现"**按名存取**"                  |
| **系统角度**   | 主要关注文件存储位置                              |


打开文件时，系统要完成的工作
- 根据文件名查找目录，找到 FCB；（打开文件第一步，继续 open() 操作，将 FCB 写入内存）
- 根据打开方式、共享说明和用户身份检查，访问合格性；
- 根据文件号，打开文件表，看文件是否被打开；
- 在用户打开文件中取一空表项，填写打开方式等，并指向系统打开文件表对应的表项。

外存储存取过程：读状态 → 置数据 → 置地址 → 置控制 → 读状态 

创建文件操作过程
- 检查文件名是否合法；
- 同目录下是否重名；
- 目录中是否有空闲位置；
- 填写目录项内容（文件名、用户名、存取权限、长度置零、首地址）。


文件描述符
- 内核利用文件描述符来访问文件。
- 文件描述符是非负整数，打开现存文件或新建文件时，内核会返回一个文件描述符，读写文件也需要使用文件描述符来指定待读写的文件。
- 实际上，它是一个索引值，指向内核为每一个进程所维护的该进程打开文件的记录表。
- 当程序打开一个现有文件或者创建一个新文件时，内核向进程返回一个文件描述符。

对文件的操作：

| 操作       | 过程                                                          |
| -------- | ----------------------------------------------------------- |
| **关闭文件** | 系统根据用户提供的文件名/文件标识符查找 FCB；在该 FCB 的相关内容做修改；置 FCB 为"非活跃"；写回磁盘。 |
| **删除文件** | 查找文件；检查删除合法性；收回 FCB 资源；收回文件存储空间。                            |
| **访问文件** | 首次访问时通常访问文件路径名，之后对文件访问通常使用文件描述符。                            |
