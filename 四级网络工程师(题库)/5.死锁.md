
## 1.死锁

死锁是指两个或两个以上的进程，因竞争资源或彼此通信，而形成一种互相永久等待的局面；若无外力干预，这些进程都将永远无法继续推进。本质是对资源的管理、分配和使用不当所产生。

产生原因:

| 原因            | 说明                     |
| ------------- | ---------------------- |
| **竞争资源**      | 系统中资源数量有限，多个进程同时请求同一资源 |
| **进程推进顺序不合理** | 进程申请/释放资源的时序不当，形成循环依赖  |
| *调度不合理*    | **不是**死锁产生的原因（注意区分）    |

死锁的四个必要条件（必须同时满足）
(四个条件缺一不可，只要破坏其中任意一个，即可预防死锁。)

| 条件                  | 含义                                 | 通俗理解          |
| ------------------- | ---------------------------------- | ------------- |
| **① 互斥条件**          | 资源一次只能被一个进程占用                      | "独占使用"        |
| **② 不可剥夺条件**        | 已分配给进程的资源，在未使用完前不能被强行剥夺            | "拿了就不能抢"      |
| **③ 请求和保持条件**（部分分配） | 进程已占有部分资源，又申请新的资源，同时不释放已占资源        | "吃着碗里的看着锅里的"  |
| **④ 循环等待条件**        | 存在一个进程等待链，链中每个进程等待下一个进程所占有的资源，形成环路 | "你等我、我等他、他等你" |


死锁进程的状态特征
- 进程进入阻塞状态（Blocked/Waiting）
- 无法被唤醒：因为等待的事件由其他死锁进程触发，而其他进程也处于阻塞态
- 不消耗 CPU，但永久占用已分配的资源


## 2.与死锁相关的其他现象

饥饿（Starvation）
- 定义：进程因长期得不到所需资源或 CPU 时间，导致其推进被无限期推迟，响应受到明显影响。
- 状态：通常处于就绪态或阻塞态，可被调度（理论上），但始终轮不到它执行。
- 特点：进程主动放弃 CPU（如时间片到），但调度策略始终不选中它。
- 举例：短作业优先（SJF）调度中，一个长作业可能永远被后来的短作业抢占，导致饥饿。

活锁（Livelock）
- 定义：进程没有被阻塞，也能被调度运行，但始终没有任何实质进展，在原地空转。
- 状态：处于运行态或就绪态，没有进入阻塞。
- 特点："忙等待式"，不主动放弃 CPU，不断改变状态但无法完成任务。
- 举例：两人走廊相遇，同时向左让、又同时向右让，永远让不开。

| 特性             | 死锁  | 活锁       | 饥饿         |
| -------------- | --- | -------- | ---------- |
| **进程状态**       | 阻塞态 | 运行/就绪态   | 就绪/阻塞态     |
| **能否调度**       | 否   | 能        | 能（理论上）     |
| **有无进展**       | 无   | 无        | 无          |
| **CPU 占用**     | 不占用 | 占用（忙等）   | 不占用（被忽略）   |
| **是否主动放弃 CPU** | —   | 否        | 是          |
| **能否自行解除**     | 否   | 可能（改变策略） | 可能（改变调度策略） |


## 3.死锁的解决

### 3.1 预防死锁（Prevention）

通过破坏死锁四个必要条件之一，从根本上杜绝死锁

| 方法              | 破坏的条件 | 说明                        |
| --------------- | ----- | ------------------------- |
| **一次分配所有资源**    | 请求和保持 | 进程运行前一次性申请全部所需资源，否则不分配    |
| **资源有序分配法**     | 循环等待  | 给所有资源编号，进程必须按编号递增顺序申请     |
| **剥夺其他进程的资源**   | 不可剥夺  | 当进程申请不到资源时，强制剥夺其已占资源      |
| **SPOOLing 技术** | 互斥    | 将独占设备改造为共享设备（如打印机缓冲），消除互斥 |

特点：静态分配，在资源分配阶段就加锁，简单但资源利用率低。


### 3.2 避免死锁（Avoidance）

在资源分配前进行安全性检查，仅当系统处于安全状态时才分配资源。银行家算法模拟分配后检查是否存在安全序列；若存在则分配，否则拒绝.

特点：不需要预先破坏条件，动态检测，资源利用率高于预防，但开销较大。

### 3.3 死锁检测与恢复（Detection & Recovery）

允许死锁发生，但定期检测，发现后再处理。

| 环节     | 方法                                                                                       |
| ------ | ---------------------------------------------------------------------------------------- |
| **检测** | 定时运行资源分析程序（如资源分配图化简、死锁检测算法）                                                              |
| **恢复** | ① **剥夺资源法**：从死锁进程中强行夺取资源分配给其他进程<br>② **撤销进程法**：终止一个或多个死锁进程，释放资源<br>③ **重启**：最简单粗暴，直接重启系统 |


特点：检测与恢复分离，资源利用率最高，但恢复代价大。

## 4.死锁的常见类型

同类资源死锁
- 场景：多个进程竞争同一类资源，且资源数量有限。
- 例子：P1 申请一页内存，P2 申请一页内存，P3 申请一页内存……若内存页已分配完，后续进程等待，且已占有内存的进程又互相等待对方释放，形成死锁。

不同类资源死锁
- 场景：进程占有不同类别的资源，并互相请求对方占有的资源。
- 例子：P1 拥有设备 A，请求设备 B；P2 拥有设备 B，请求设备 A。

PV 操作互斥死锁
- 场景：使用信号量（P/V 操作）时，操作顺序不当导致。
- 典型错误：P1、P2 先对同步信号量执行 P 操作，再对互斥信号量执行 P 操作。
- 后果：若同步条件不满足，进程阻塞在同步信号量上，且已占有互斥锁，其他进程无法进入，形成死锁。
- 正确做法：应先 P(互斥) 再 P(同步)，或确保不会交叉持有。

临时资源死锁（通信死锁）
- 场景：进程间通信产生的临时性资源（如消息、信件）形成循环等待。
- 例子：P1 等待 P2 发来信件 Q 后，才向 P2 发送信件 R；而 P2 等待 P1 发来信件 R 后，才向 P1 发送信件 Q。双方互相等待对方先发送，形成死锁。
