
## 1. 即时通信（IM）

即时通信（Instant Messaging）是一种基于互联网的实时通信服务，支持文本、语音、视频、文件等多种媒体形式的即时交互。

标准化进程
- 由IMPP（Instant Messaging and Presence Protocol）工作组提出
- IETF（互联网工程任务组）批准成为正式RFC文件
- RFC 2778文件描述了即时通信系统的功能模型和抽象架构
- RFC 2778仅定义了IM系统的抽象模型和统一术语，并未规定即时通信系统必须使用同一标准协议，各厂商仍可开发自己的私有协议

通信模式
- 客户机/服务器模式（C/S）：客户端通过服务器进行消息转发和状态管理，服务器作为通信中枢
- 客户机/客户机模式（P2P）：客户端之间直接建立连接进行通信，无需服务器中转消息内容


RFC 2778定义的核心角色与服务
- 在线状态服务（Presence Service）：负责接受、存储和分发用户的在线状态信息（如在线、离线、忙碌等）
- 即时消息服务（Instant Message Service）：负责接收发送方的消息并投递到接收方的即时消息收件箱
- 两种服务相互解耦，通过状态信息中的通信地址产生关联

## 2.QQ即时通信系统

QQ是腾讯公司开发的即时通信软件，具有以下技术特点：

通信方式
- 采用UDP为主、TCP为辅的传输策略
    - UDP 用于实时性要求高的场景（如语音、视频通话），传输效率高但不可靠
    - TCP 用于可靠性要求高的场景（如文件传输、消息确认），保证数据完整到达
- 当两个客户端无法直接建立连接时（如双方均位于NAT/防火墙之后），采用服务器中转方式进行通信

协议特点
- 采用腾讯自己私有的即时通信协议，不遵循公开的IM标准协议
- 每次登录时，客户机会从服务器获得一个会话密钥，用于后续通信的加密和解密，保障通信安全


## 3.3. 即时通信协议
目前主流的即时通信协议主要包括基于SIP的SIMPLE和基于Jabber的XMPP两大体系。


SIP协议（Session Initiation Protocol）
- 工作在应用层，由IETF提出
- 可在TCP或UDP上传输，默认端口号为5060
- 支持多种信息类型：文本、文件、视频、图像等多媒体内容
- 用于创建、修改和释放一个或多个用户的会话

SIP系统组成：
- 用户代理（User Agent, UA）：发起和接收SIP请求的端点，分为用户代理客户端（UAC）和用户代理服务端（UAS）
- 代理服务器（Proxy Server）：接收SIP请求并转发到下一个服务器或用户代理
- 重定向服务器（Redirect Server）：用于规划SIP路径，返回目标地址信息，让客户端直接联系目标，可与其他服务器共存于一个设备中  
- 注册服务器（Registrar）：接收用户的REGISTER请求，记录用户当前位置（IP地址）

SIP消息组成：
- 起始行（Start-Line）：请求消息为请求行，响应消息为状态行
- 消息头（Message-Header）：包含Via、From、To、Call-ID等路由和标识信息
- 一个标志消息头结束的空行（CRLF）
- 消息体（Message-Body）：可选，通常携带SDP会话描述信息

SIP定义的6种请求消息：

| 请求方法 | 功能说明 |
|---------|---------|
| INVITE | 邀请用户/服务器参加一个会话，发起呼叫 |
| ACK | 确认收到对INVITE的最终响应，完成三次握手 |
| OPTIONS | 获取服务器的相关能力信息，不建立会话 |
| BYE | 终止一次已建立的会话 |
| CANCEL | 取消尚未建立的挂起呼叫 |
| REGISTER | 向注册服务器注册用户当前位置 |


- SIP消息分为两类：从客户机到服务器的请求消息和从服务器到客户机的响应消息
- 响应消息的状态码分为6类：1xx（临时响应）、2xx（成功）、3xx（重定向）、4xx（客户端错误）、5xx（服务器错误）、6xx（全局失败）

SIMPLE协议（SIP for Instant Messaging and Presence Leveraging Extensions）
- 以SIP协议为基础，由IETF的SIMPLE工作组制定
- 不需要建立会话即可传输即时消息
- 支持多媒体会话
- IM消息以MESSAGE命令为载体进行传输，每条IM消息由单独的MESSAGE命令传输，彼此独立T


XMPP协议（Extensible Messaging and Presence Protocol）
- 工作在应用层，基于Jabber协议，由IETF制定
- 由4个RFC文档组成核心规范
- 设计上延续电子邮件系统的思想，采用存储转发机制
- 系统组成：用户客户端、XMPP服务器、XMPP协议网关
- 核心特点：
    - 以XML为核心，所有消息均以XML格式编码
    - 采用统一的寻址方案，实体地址称为JID（Jabber ID）
    - JID格式：localpart@domainpart/resourcepart，类似于电子邮件地址
    - 本地部分（localpart）：用户标识
    - 域部分（domainpart）：服务器域名或IP地址
    - 资源部分（resourcepart）：标识用户的特定设备或会话
- 支持扩展性强，可通过XEP（XMPP Extension Protocols）扩展功能

IM协议基本服务
- 呈现服务（Presence Service）：提供用户在线状态信息（在线、离线、忙碌、离开等）
- 即时消息服务（Instant Messaging Service）：实现用户之间的实时消息传递

| 特性 | SIP/SIMPLE | XMPP |
|------|-----------|------|
| 基础协议 | SIP | Jabber |
| 消息格式 | 文本（SDP） | XML |
| 寻址方式 | SIP URI | JID |
| 会话模式 | 需要建立会话（SIMPLE除外） | 不需要建立会话 |
| 扩展性 | 一般 | 强 |
| 标准化组织 | IETF | IETF |



## 4. 网络文件共享

NFS（Network File System，网络文件系统）
- 由Sun Microsystems开发，是一种分布式文件系统协议
- 可在Linux和Windows系统上使用（Windows需安装NFS客户端）
- 与主机操作系统无关，实现了异构系统之间的文件共享
- 采用C/S（客户端/服务器）结构
- 挂载方式：客户端通过mount命令将远程主机的文件系统挂载到本地目录
- 命令格式：mount 远程主机IP:远程目录 本地挂载点
    - 示例：mount B:/usr/lib /usr/lib，将远程主机B的/usr/lib目录挂载到本机的/usr/lib目录
- 配置文件：NFS服务器共享出来的文件或目录都记录在/etc/exports文件中
    - 每行定义一个共享规则，格式为：共享目录路径 客户端标识(选项1,选项2,...)
    - 常用选项：ro（只读）、rw（读写）、sync（同步写入）、async（异步写入）、root_squash（将客户端root映射为匿名用户）等
    - 配置文件修改后，使用exportfs -rv命令重新加载配置使其生效，无需重启NFS服务


Windows LAN文件共享
- Windows 2000以前的系统：使用NetBIOS协议进行文件共享
    - NetBIOS工作在会话层和传输层之间，提供名称解析、会话建立和数据报服务
    - 基于NetBIOS的SMB协议通常使用端口139
- Windows 2000及以后的系统：使用CIFS协议（Common Internet File System）
    - CIFS是SMB（Server Message Block）协议的增强版本，由微软于1996年提出
    - 支持直接运行在TCP/IP之上（端口445），无需依赖NetBIOS
    - 支持Unicode文件名、用户权限控制、文件锁定及断线重连等特性
SMB/CIFS采用客户端/服务器、请求/响应模式，允许用户访问远程服务器上的文件、打印机等资源


## 5. P2P文件共享

P2P（Peer-to-Peer）文件共享是对等网络技术在文件分发领域的应用，节点之间直接传输文件，无需经过中心服务器。

BitTorrent（BT）系统
- 起源于Napster，由Bram Cohen开发，源于MIT的开源系统
- 中心服务器（Tracker）：存放用户信息，协调Peer之间的连接，但不存储实际文件内容
- 种子文件（.torrent）：包含共享文件的元数据信息，采用Bencode编码格式，整体为字典结构
    - 包含以下字段：
        - announce（必填）：Tracker服务器的URL
        - info（必填）：文件核心信息，包括文件名、文件大小、分块大小、各块的SHA-1哈希值等
        - announce-list（可选）：备用Tracker列表
        - creation date（可选）：创建时间的Unix时间戳
        - comment（可选）：DHT初始节点的IP和端口列表
- DHT支持：BT系统加入DHT（分布式散列表）技术后，可实现无Tracker-服务器的文件传输，提高系统的去中心化程度和鲁棒性
- 理论基础：基于"六度分隔理论"、"小世界理论假设"等社交网络理论



Maze系统
- 由北京大学开发的一款P2P文件共享系统
- 功能特点：
    - 支持即时通信功能
    - 参考Kerberos机制实现安全认证
    - 支持在线资源搜索和文件目录视图
    - 支持多点下载和断点续传
    - 基于积点的资源交易体系，用户通过分享文件获得积点，下载文件消耗积点
    - 有种子机制，保证文件的完整性和可用性
- 分布式认证机制：类似于信用卡机制，记录用户的信用和交易历史
- 文件定位：使用类似URL的方式表示文件位置
- 系统架构：混合型P2P系统，包括以下服务器组件：
    - 集中式的用户管理服务器（负责注册、登录）
    - 目录收集服务器
    - 检索服务器
    - 心跳服务器（监测节点在线状态）
    - 种子服务器

| 特性 | 传统P2P | BT系统 |
|------|---------|--------|
| 种子机制 | 不支持 | 支持 |
| 积点机制 | 支持（如Maze） | 不支持 |
| 传输方式 | 用户之间直接传输 | 用户之间直接传输 |
| Tracker依赖 | 部分依赖 | 后期可实现无Tracker传输（DHT） |
| 兼容性 | 两者相互不兼容 | 两者相互不兼容 |



## 6. IPTV（网络电视）

IPTV（Internet Protocol Television）是利用IP网络传输电视节目的服务。

NVOD（Near Video-On-Demand，近似点播/就近式点播）
    - 多个视频流依次间隔一定时间（如10分钟、15分钟）发送相同的内容
    - 用户需等待最近的时间起点开始收看，不能完全自由选择播放时间
    - 无用户数量限制，单位成本较低
    - 不支持暂停、快进、倒回等交互操作

TVOD（True Video-On-Demand，真实点播电视）
    - 基于双向网络，支持即点即放
    - 每个视频流专为单个用户服务
    - 并发流数量有限，单位用户成本较高
    - 用户可完全控制播放进度

IVOD（Interactive Video-On-Demand，交互式点播）
    - 在TVOD基础上增加交互控制功能
    - 支持暂停、倒回、快进、自动搜索等操作
    - 提供最强的用户交互体验

媒体内容分发（MCDN）技术
- MCDN（Media Content Distribution Network）是IPTV大规模应用的重要技术保障，可降低服务器和带宽资源的浪费，提高服务质量。其技术组成包括：
    - 内容发布（Content Publishing）
        - 借助相关技术，将内容发布或投递到距离用户最近的远程服务点（边缘节点）
        - 确保内容在用户请求之前已预置到合适的位置
    - 内容路由（Content Routing）
        - 采用网络负载均衡技术
        - 通过重定向机制，将用户请求导向最近的内容源进行响应
        - 根据用户的地理位置、网络状况等因素选择最优节点
    - 内容交换（Content Switching）
        - 根据内容可用性、服务器可用性等因素
        - 利用应用层交换技术，智能平衡负载流量
        - 避免单点过载，提高系统整体性能
    - 性能管理（Performance Management）
        - 保证网络处于最佳状态
        - 测量内容发布的端到端性能
        - 监控服务质量（QoS），及时发现和处理网络问题

## 7. VoIP（基于IP网络的语音传输技术）

VoIP（Voice over IP）是将语音信号数字化后通过IP网络进行传输的技术。

系统组成
- 终端设备（Terminal）：IP电话机、软电话软件等，用于发起和接收语音呼叫
- 网关（Gateway）：实现VoIP网络与PSTN（公共交换电话网）、PBX（专用交换机）或模拟设备之间的互联
    - 主要功能：
        - 号码查询和地址解析
        - 建立和释放通信连接
        - 信号调制与解调
        - 语音数据的压缩和解压缩（编解码）
        - 路由寻址，选择最佳传输路径
        - 传输格式和协议转换
- 多点控制单元（MCU，Multipoint Control Unit）
    - 支持多终端同时参与的多方会议通信
    - 负责媒体流的混合、切换和分发
- 网守（Gatekeeper）
    - VoIP网络的中央控制实体
    - 主要功能：
        - 用户注册和管理（RAS功能）
        - 消息控制中心，处理呼叫信令
        - 地址解析，确定网关地址
        - 带宽管理，控制网络资源使用
        - 计费管理，记录通话时长和费用
        - 留存呼叫详细记录（CDR）
        - 区域管理和安全管理

Skype
- 结合VoIP和P2P技术，采用混合式网络结构
    - 安全机制：
        - 采用AES算法进行加密，密钥长度为256bit
        - 使用RSA公钥密码系统进行身份验证和密钥交换
        - 加密保存好友列表，保护用户隐私
        - 会话密钥由通信双方通过专有密钥协商协议动态生成
    - 通信特性：
        - 支持免费多方通信（多人语音/视频会议）
        - 采用iLBC和iSAC编码技术，适应不同网络带宽条件
        - 系统中的SN（Super Node，超级节点）是动态生成的
        - 支持NAT穿越，能够在防火墙和NAT设备后面正常通信


## 8. 搜索引擎

搜索引擎是用于从互联网海量信息中检索用户所需信息的系统。

组成结构
- 搜索引擎由四个核心功能模块组成：
- 搜索器（Crawler/Spider）
    - 也称为网络蜘蛛或网络爬虫
    - 自动在互联网上爬行和抓取网页
    - 通过超链接遍历Web空间，不断发现和抓取新的网页内容
    - 定期回访已抓取的网页，保证信息的时效性
- 索引器（Indexer）
    - 对搜索器抓取的原始网页进行预处理
    - 进行分词、去重、权重计算等操作
    - 建立倒排索引等索引数据库
    - 将非结构化的网页内容转换为结构化的索引数据
- 检索器（Retriever）
    - 根据用户的查询词在索引库中快速匹配相关文档
    - 进行文档与查询的相关度评价
    - 对搜索结果进行排序，将最相关的结果排在前面
    - 支持复杂的查询语法和高级搜索功能
- 用户接口（User Interface）
    - 提供可视化的查询输入界面（搜索框）
    - 展示搜索结果输出界面
    - 支持搜索建议、拼写纠错、相关搜索等辅助功能

工作流程
- 信息采集（搜索器抓取）→ 信息分析（索引器建库）→ 信息查询（检索器匹配排序）→ 结果呈现（用户接口展示）


## 10. 网络管理模型

网络管理采用网络管理者-网管代理模型（Manager-Agent Model），类似于客户机/服务器模式。

基本架构
- 网络管理者（Manager）
    - 实际上是运行在计算机操作系统上的一组应用程序
    - 通常位于网络系统的主干或接近主干位置
    - 负责发出管理操作指令，接收来自代理的信息
    - 定期查询代理收集的设备运行状态、配置及性能数据
    - 可以和多个代理之间进行信息交换
    - 一个管理者可以和多个代理之间进行信息交换
- 网络管代理（Agent）
    - 位于被管理的设备内部
    - 负责将来自网络管理站的命令转换为本设备特有的指令
    - 执行管理站的指示，返回设备信息
    - 可主动将系统中发生的重要事件通知给网络管理站
    - 也可能因某种原因拒绝网络管理站的指令

网络管理模型的三个层次
- 组织模型（Organization Model）
    - 描述网管系统的组成部分
    - 定义管理者（Manager）、代理（Agent）和被管对象（MO）之间的相互关系
    - 反映管理者和代理者的能力以及它们之间的信息交互方式
- 信息模型（Information Model）
    - 描述网管系统的对象命名方式
    - 被管系统中的资源抽象为被管对象（MO）
    - MO类实例的集合组成管理信息库（MIB，Management Information Base）
    - 采用树型结构（对象命名树），每个对象通过对象标识符（OID）唯一标识
- 通信模型（Communication Model）
    - 描述网管系统的管理协议
    - 用于网络管理站和管理代理之间传递信息
    - 完成信息交换的安全控制
    - 通过协议数据单元（PDU）进行信息交换

目前最有影响的网络管理协议是SNMP（Simple Network Management Protocol）和CMIS/CMIP，其中SNMP流传最广、应用最多，已成为事实上的工业标准
    - 工作在应用层，以UDP报文为承载
    - 采用轮询机制，管理站向代理发送请求，代理返回响应
    - 代理也可主动发送Trap或Inform报文通知管理站紧急事件
    - SNMP版本：SNMPv1基于团体名认证，安全性较差；SNMPv3提供了认证加密和访问控制，安全性最高
