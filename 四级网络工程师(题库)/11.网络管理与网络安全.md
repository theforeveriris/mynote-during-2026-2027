
## 1. 网络管理概述

网络管理是对网络资源进行监视、控制、配置、优化和维护的综合性活动，旨在保障网络系统稳定、高效、安全地运行。

管理对象
- 硬件资源：物理介质（双绞线、光纤等）、计算机设备（服务器、工作站）和网络互连设备（路由器、交换机、集线器等）
- 软件资源：操作系统、应用软件和通信软件

管理目标
- 确保网络的有效性、可靠性、开放性、综合性、安全性和经济性，满足用户及运营商对网络服务质量的需求。
- 确保网络的有效性、可靠性、开放性、综合性、安全性和经济性，满足用户及运营商对网络服务质量的需求。

管理模式
- 集中式管理：由单一网络管理站对整个网络进行统一监控和管理，结构简单但存在单点故障风险
- 分布式管理：多个管理站协同工作，时效性好，可扩展性强，适合大型复杂网络


## 2. 网络管理功能

网络管理包含五大功能域，通常称为FCAPS模型。

配置管理（Configuration Management）
- 负责网络建设、业务展开和配置维护，达到网络性能最优。包含两个阶段：
- 初始配置管理阶段：网络初次运行时的配置建立
- 工作配置管理阶段：网络正常运行期间的配置维护
- 具体任务包括：
    - 设置系统中有关路由操作的参数
    - 被管理对象的名字管理
    - 初始化或关闭被管对象
    - 根据要求收集系统当前状态的有关信息
    - 获取系统重要变化信息
    - 更改系统配置
    - 生成网络拓扑结构图

故障管理（Fault Management）
- 核心目标是快速发现、定位和排除网络故障，最小化故障对网络服务的影响。
- 发现和排除网络故障
- 维护和监测错误日志
- 接收错误响应信息
- 跟踪辨别错误来源和性质
- 自动或手动恢复故障

性能管理（Performance Management）
- 监控和评估网络运行状态，确保网络资源持续保持最佳性能。
- 收集统计信息（带宽利用率、时延、丢包率等）
- 监控网络使用状况
- 维护和分析网络性能数据
- 进行容量规划和性能优化
- 记录和分析资源使用情况


计费管理（Accounting Management）
- 记录网络资源使用情况，用于内部核算或外部计费。
- 统计用户流量、连接时长等资源使用数据
- 生成计费报告
- 支持按使用量收费或配额管理

安全管理（Security Management）
- 保护网络管理系统本身以及网络资源的安全。
- 管理授权机制
- 实施访问控制策略
- 管理加密和解密密钥
- 安全审计和日志分析
- 威胁检测与防护

## 3. 网络管理协议

CMIS/CMIP（通用管理信息服务/协议）
- 由ISO（国际标准化组织）制定，基于OSI参考模型设计
- 所有功能都要映射到应用层
- 采用报告机制（委托管理制）：代理主动向管理者报告事件，而非被动等待查询
- 内置安全机制，包括访问控制、认证和安全日志
- 功能强大，在单个请求下可实现多种操作
- 缺点：实施复杂且花费高，未得到广泛普及


CMOT（CMIP over TCP/IP）是将其移植到TCP/IP环境的过渡方案，最终被SNMP取代

SNMP（简单网络管理协议）
- 工作在应用层，由IETF制定，基于UDP传输（端口161/162）
- 遵循ISO的管理模型，可应用于TCP/IP环境下
- 结构简单、资源消耗低，已成为事实上的工业标准


数据收集方式:
| 方式 | 特点 | 优缺点 |
|------|------|--------|
| 轮询（Polling） | 管理站不断按顺序查询各代理，数据存储在MIB中 | 实现简单，但时效低，网络开销大 |
| 基于中断（Interrupt） | 代理在发生重要事件时主动通知管理站 | 时效高，但需要转发大量信息，消耗管理设备资源 |
| Trap（改进方案） | 代理仅在特定事件发生时发送Trap报文通知管理站 | 兼顾时效性和资源效率，是SNMP的核心机制之一 |


SNMP版本演进:
| 版本 | 安全性 | 主要特点 |
|------|--------|----------|
| SNMPv1 | 安全性差，使用团体名（Community String）明文认证 | 基本功能：Get、GetNext、Set、Trap |
| SNMPv2c | 有所改进，增加GetBulk操作，但仍使用团体名认证 | 性能提升，支持批量数据获取 |
| SNMPv3 | 安全性最高，提供验证、加密和时间同步机制 | 引入USM（用户安全模型）和VACM（基于视图的访问控制模型），在安全性和更有效的传递管理信息方面加以改进 |


SNMP基本操作
- Get：提取特定的网络管理信息
- GetNext：通过遍历活动提供强大的管理信息提取能力
- Set：修改、设置管理信息
- Trap：代理向管理站报告重要事件


## 4. 信息安全等级

美国标准（DOD 5200.28-STD / TCSEC）
- TCSEC（Trusted Computer System Evaluation Criteria，可信计算机系统评估准则）由美国国防部制定，将安全等级分为4大类、7个级别（D类仅1级，共8级）。

| 类别 | 级别 | 名称 | 特点 |
|------|------|------|------|
| 非安全保护类 | D | 最小保护 | 客户机系统，无安全保护要求 |
| 自主保护类 | C1 | 自主安全保护 | 基本存取控制，以用户组为单位 |
| | C2 | 受控访问保护 | 更细粒度的存取控制，以用户为单位，有审计机制 |
| 强制性安全保护类 | B1 | 标记安全保护 | 强制访问控制，数据带有安全标记 |
| | B2 | 结构化安全保护 | 形式化安全策略模型，系统结构清晰 |
| | B3 | 安全域机制保护 | 安全内核设计，引用监控器 |
| 验证保护类 | A1 | 验证设计 | 最高安全级别，数学模型可证明 |


中国标准
- 中国制定网络安全等级保护制度，分为五个级别：
    - 第1级：自主保护级 — 一般信息系统，自主进行安全保护
    - 第2级：指导保护级 — 重要信息系统，在指导下进行安全保护
    - 第3级：监督保护级 — 涉及国家安全等重要系统，接受监督保护
    - 第4级：强制保护级 — 特别重要系统，强制实施安全保护
    - 第5级：专控保护级 — 极端重要系统，专门控制保护


## 5. OSI安全框架（X.800）

ITU-T推荐方案X.800即OSI安全框架，从安全攻击、安全机制、安全服务三个方面研究安全问题。

安全攻击类型

| 分类 | 攻击类型 | 特点 | 防护重点 |
|------|----------|------|----------|
| 被动攻击 | 信息内容泄漏 | 窃听传输内容，不更改信息 | 重在预防（加密） |
| | 流量分析 | 分析通信模式、频率、长度等，判断通信性质 | 重在预防 |
| 主动攻击 | 伪装 | 攻击者冒充合法用户或服务器 | 重在检测 |
| | 重放 | 截获消息后再次发送以获取非授权利益 | 重在检测 |
| | 消息篡改 | 篡改合法消息的内容或属性 | 重在检测 |
| | 拒绝服务（DoS） | 使服务设备失效，消耗服务器资源 | 重在检测 |


服务攻击与非服务攻击

| 类型 | 定义 | 典型示例 |
|------|------|----------|
| 服务攻击 | 针对特定网络服务的攻击 | 邮件炸弹、端口攻击、分布式拒绝服务攻击（DDoS） |
| 非服务攻击 | 基于网络层或底层协议漏洞的攻击，与特定服务无关，更为隐蔽 | 源路由攻击、地址欺骗、NetXray攻击 |


安全机制（X.800定义）
- 特定安全机制：加密、数字签名、访问控制、数据完整性、认证交换、流量填充、路由控制、公证
- 普遍安全机制：可信功能、安全标签、事件检测、安全审计跟踪、安全恢复

安全服务
- 认证服务（同等实体认证、数据源认证）
- 访问控制服务
- 数据保密性服务（连接保密性、无连接保密性、选择域保密性、流量保密性）
- 数据完整性服务
- 不可否认性服务


## 6. 对称密码（私钥密码）

对称加密是加密与解密使用同一密钥的加密技术，核心特点是运算速度快，但密钥需安全共享。

| 算法 | 分组长度 | 密钥长度 | 特点 |
|------|----------|----------|------|
| DES（数据加密标准） | 64位 | 56位（实际有效，64位中含8位校验位） | 美国NIST采纳；采用"替换+移位"的分组加密，16轮编码变换；密钥太短，现已被破解，安全性不足，已淘汰 |
| 三重DES（3DES） | 64位 | 112位（2个56位密钥）或168位（3个密钥） | 采用"加密→解密→加密"三重流程；安全性高于DES，但运算速度较慢；DES淘汰后的过渡方案，逐步被AES替代 |
| AES（高级加密标准） | 128位 | 128/192/256位 | 基于"排列+置换"运算；轮数分别为10/12/14轮；安全性极高、运算速度快；当前主流标准，性能不低于三重DES |
| Blowfish | 64位 | 可变长度（32~448位） | 由Bruce Schneier设计；速度快，适合软件实现 |
| RC5 | 可变（32/64/128位） | 可变（0~2040位） | 由Ron Rivest开发；分组长度和密钥长度均可变；轮数也可变（0~255轮）；灵活性高 |


## 7. 非对称密钥（公钥密码）

非对称加密使用"公钥（公开共享）+ 私钥（私密持有）"配对密钥，公钥加密的内容仅能通过对应私钥解密，私钥加密的内容仅能通过对应公钥解密。

RSA算法
- 以发明者Rivest、Shamir、Adleman三人姓氏首字母命名，1977年提出
- 分组密码体制
- 基于大整数因子分解难题：两个大素数相乘容易，但将乘积分解极其困难
- 加密强度取决于密钥长度（概率加密方法）；质数值越大，破解越难
- 密钥长度建议：512位已不安全，1024位面临严重威胁，目前推荐2048位或4096位
- 运算速度较慢，比同安全级别的对称密码算法慢约1000倍，通常仅用于少量数据加密或密钥交换
- 既能用于数据加密也能用于数字签名

ElGamal算法
- 公钥密码体制，基于离散对数难题
- 常用于数字签名
- 密文长度是明文的两倍（加密后数据膨胀）
- 与椭圆曲线加密体系（ECC）有密切关系

背包加密算法
- 由Merkle和Hellman开发，基于NP完全的背包难题
- 将超递增背包问题转化为普通背包问题实现加密
- 目前已被攻破，一次背包不安全
- 历史意义：证明了如何将NP完全问题用于公开密钥密码学


## 8. 密钥的验证与认证中心（CA）


认证中心（CA）的核心职能
- 验证实体身份：严格核实申请者的真实身份
- 产生数字证书：将公钥和身份绑定，形成数字证书
- 数字签名：证书由CA使用私钥进行数字签名，确保证书不可篡改
- 公钥发布：认证后公钥的发布不受限制
- 密钥保管：保管用户的公钥，管理密钥生命周期
- 证书吊销：通过CRL（证书吊销列表）或OCSP（在线证书状态协议）声明无效证书
- 数字证书结构（X.509标准）
  - 版本号
  - 序列号（CA颁发的唯一标识）
  - 签名算法
  - 颁发者（CA机构）
  - 有效期
  - 主体（公钥持有者信息）
  - 主体公钥    
  - CA签名



证书验证流程
- 获取数字证书
- 用CA的公钥解密证书中的"CA签名"，得到摘要A
- 对证书内容用同一哈希函数生成摘要B
- 对比A和B：若A=B则证书有效，公钥合法；若A≠B则证书被伪造或篡改

## 9. 认证技术

消息认证
- 目的：确认消息来源合法、信息完整、序号和时间正确。
    - 认证消息来源
    - 认证信息的完整性（未被篡改）
    - 认证信息的序号和时间（防止重放攻击）

认证模式
- 单向认证：仅一方验证另一方身份
- 双向认证：双方互相验证身份

认证函数
| 类型 | 说明 |
|------|------|
| 信息加密函数 | 对整个消息进行加密，密文本身即认证信息 |
| 消息认证码（MAC） | 基于对称密钥生成固定长度的认证标签，验证来源和完整性 |
| 散列函数（Hash） | 消息通过散列函数生成固定长度的摘要；MD5可得到128位摘要；SHA-1得到160位摘要 |


数字签名
- 基于公钥密码技术
- 发送方用私钥对消息摘要进行签名
- 接收方用发送方公钥验证签名
- 核心作用：防止抵赖（不可否认性）、验证完整性和来源

身份认证

| 方式 | 说明 |
|------|------|
| 口令认证 | 基于用户知道的秘密（密码） |
| 持证认证 | 基于用户拥有的物品（智能卡、USB Key等） |
| 生物识别 | 基于用户固有的特征（指纹、虹膜、人脸等） |

认证协议

| 协议 | 密钥类型 | 制定组织 | 特点 |
|------|----------|----------|------|
| Kerberos | 对称密钥 | 美国麻省理工学院（MIT） | 适用于TCP/IP环境；基于票据（Ticket）机制；KDC（密钥分发中心）为核心组件 |
| X.509 | 公钥体制 | CCITT（现ITU-T） | 基于数字证书；定义证书格式和认证框架；广泛用于SSL/TLS、S/MIME等 |


## 10.安全电子邮件

安全电子邮件在应用层提供邮件的机密性、完整性和身份认证。

PGP（Pretty Good Privacy）
- 由Phil Zimmermann于1991年发明
- 基于Web of Trust（信任网）去中心化信任模型
- 数字签名：采用DSS/SHA或RSA/SHA
- 压缩：使用ZIP算法压缩数据
- 兼容性：使用Base64编码（64-BASE），确保二进制数据在ASCII邮件系统中正确传输
- 采用混合加密系统：对称加密（如IDEA、AES）加密邮件内容，非对称加密（RSA）加密会话密钥

S/MIME（Secure/Multipurpose Internet Mail Extensions）
- 基于PKI体系，依赖CA签发的X.509数字证书
- 支持数据加密和数字签名
- 采用CMS（密码消息语法）格式封装安全邮件
- 广泛集成于Outlook、Apple Mail等主流邮件客户端
- 适用于企业环境，信任模型为层次化的CA体系

| 特性 | PGP | S/MIME |
|------|-----|--------|
| 信任模型 | Web of Trust（去中心化） | 层次化CA体系（中心化） |
| 证书管理 | 用户手动交换公钥 | CA自动签发和管理 |
| 集成度 | 需额外安装软件 | 广泛集成于主流客户端 |
| 适用场景 | 个人及高安全性跨平台通信 | 企业环境 |



## 11. IPSec（IP层安全协议）

IPSec是IETF制定的网络层安全协议，将互联层改造为具有逻辑连接的层，为IP通信提供机密性、完整性、来源真实性及防重放攻击保障。

| 协议 | 全称 | 协议号 | 提供的安全服务 |
|------|------|--------|----------------|
| AH | 认证头（Authentication Header） | 51 | 提供源身份认证、数据完整性和防重放；不提供秘密性（加密）；验证范围覆盖整个IP报文 |
| ESP | 封装安全负载（Encapsulating Security Payload） | 50 | 提供源身份认证、数据完整性、防重放和秘密性（加密）；传输模式下不验证外层IP头 |


安全关联（SA）
- 源主机与目标主机进行握手并建立网络逻辑连接，该逻辑通道称为安全关联（SA）
- SA是单工的（单向的），双向通信需建立两个SA（一个用于入站，一个用于出站）
- SA由三元组唯一确定：
  - 安全参数索引（SPI）：32位标识符，由AH和ESP携带，使接收方能选择合适的SA
  - IP目的地址：SA的目的地址
  - 安全协议标识：标识该SA是AH还是ESP

工作模式
- 传输模式：保护传输层负载，适用于主机间通信
- 隧道模式：保护整个原始IP包，新增外层IP头，适用于网关间或主机与网关间通信

密钥管理
- 支持手工配置和IKE（Internet Key Exchange）自动协商
- IKE基于ISAKMP框架，采用DH算法在不安全网络中安全交换密钥材料

## 12. 防火墙

防火墙是位于内部可信网络与外部不可信网络之间的安全封锁工具，用于阻断来自外部的威胁和入侵。

| 类型 | 工作层次 | 特点 |
|------|----------|------|
| 包过滤路由器 | 网络层 | 根据IP数据包的源/目的IP、端口号、协议类型等进行过滤，决定转发或丢弃；速度快但无法检查应用层内容 |
| 应用级网关（代理服务器） | 应用层 | 作为代理服务器，完全理解应用层协议；安全性高但性能开销大 |
| 电路级网关 | 传输层 | 不允许端到端直接TCP连接；监控TCP握手过程（SYN、ACK等），判断会话是否合法；会话建立后仅复制传递数据，不进行深度过滤 |
| 堡垒主机 | — | 内部网络中唯一能被外部访问的主机；作为内外网络通信的唯一入口；通常部署在DMZ（非军事化区）中 |


防火墙体系结构
- 屏蔽路由器结构：单一包过滤路由器作为内外连接的唯一通道
- 双宿主主机结构：主机至少有两个网络接口，结合包过滤和代理服务
- 屏蔽主机结构：屏蔽路由器 + 堡垒主机
- 屏蔽子网结构：外部屏蔽路由器 + 内部屏蔽路由器 + 堡垒主机，形成DMZ子网，安全性最高

## 13. PKI（公钥基础设施）

PKI（Public Key Infrastructure）是利用公钥加密和数字签名技术建立的安全基础设施，核心目的是解决数字世界中的信任问题。
