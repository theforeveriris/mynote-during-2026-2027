
## 1.定义

顺序表（Sequential List）又称顺序存储结构，是线性表的一种，专门存储逻辑关系为“一对一”的数据。顺序表存储数据的具体实现方案是：将数据全部存储到一整块内存空间中，数据元素之间按照次序挨个存放。

实现思路即为：把逻辑上相邻的元素存储在物理位置上也相邻的存储单元中，元素之间的逻辑关系由存储单元的邻接关系来体现。

设线性表第一个元素的存放位置为 LOC(L) ，则线性表中第 i 个元素的存放位置为：

```c
LOC(a_i) = LOC(L) + (i-1) * sizeof(ElemType)
```

其中：
- LOC(a_i) ：第 i 个元素的存放位置
- LOC(L) ：线性表第一个元素的存放位置
- sizeof(ElemType) ：数据元素所占存储单元的大小
- ElemType ：顺序表中存放的数据元素类型（可替换为 int、char、struct 等）
- 获取元素大小：C语言使用 sizeof(ElemType)


```c
typedef struct{
    ElemType * head; //定义一个名为head的长度不确定的数组，也叫“动态数组”
    int length; //记录当前顺序表的长度
    int size; //记录顺序表的存储容量
}Table;
```

> 使用顺序表存储数据，除了存储数据本身的值以外，通常还会记录以下两样数据：
> - 顺序表的最大存储容量：顺序表最多可以存储的数据个数；
> - 顺序表的长度：当前顺序表中存储的数据个数。


为什么要使用length和size两个变量来记录顺序表的长度和容量呢？因为顺序表的长度是动态变化的，而容量是固定的。通过length可以知道当前顺序表中有多少个元素，而通过size可以知道顺序表最多可以存储多少个元素，从而在插入新元素时判断是否需要扩容。

即解决了「动态扩容、均摊 O(1) 插入」的功能。

| 字段       | 含义                  | 类比             |
| -------- | ------------------- | -------------- |
| `length` | 当前**实际存了多少个**元素     | 书包里**已经装了**几本书 |
| `size`   | 当前**最多能存多少个**元素（容量） | 书包**总共能装**几本书  |

没有这两个字段就会导致：

- 无法判断「是否还有空位」
- 无法做到「批量扩容、均摊 O(1)」（动态数组的精髓是：空间不够时，一次性多申请一些（比如翻倍），而不是来一个元素申请一次。）
    - size = 10，length = 10 → 满了，扩容到 size = 20
    - 接下来再插入 10 个元素，都不需要再 realloc，直接往里放
    - 这样 n 次插入的总开销是 O(n)，均摊到每次是 O(1)



## 2.顺序表的两种实现方式

### 2.1 静态分配

使用定长数组实现，表的最大容量在编译时确定。

```c
#define MaxSize 10       // 定义最大长度

typedef struct {
    ElemType data[MaxSize];  // 用静态的"数组"存放数据元素
    int length;              // 顺序表的当前长度
} SqList;                    // 顺序表的类型定义（静态分配方式）

// Sq: sequence —— 顺序，序列
```

内存中分配连续的存储空间，总大小为 MaxSize × sizeof(ElemType)

```c
// 基本操作——初始化一个顺序表
void InitList(SqList &L) {
    for(int i = 0; i < MaxSize; i++)
        L.data[i] = 0;    // 将所有数据元素设置为默认初始值（可省略，但推荐）
    L.length = 0;         // 顺序表初始长度为0
}
```

完整步骤为：
- 在内存中分配存储顺序表 L  的空间（包括数据区 MaxSize×sizeof(ElemType) 和 length 变量）
- 将各个数据元素的值设为默认值（刷0，防止脏数据）
- 将 Length 的值设为 0

### 2.2 动态分配

使用指针 + malloc实现，表的最大容量可在运行时动态扩展。

```c
#define InitSize 10      // 顺序表的初始长度

typedef struct {
    ElemType *data;      // 指示动态分配数组的指针
    int MaxSize;         // 顺序表的最大容量
    int length;          // 顺序表的当前长度
} SeqList;               // 顺序表的类型定义（动态分配方式）
```

我们下面使用malloc进行初始化：

```c
void InitList(SeqList &L) {
    // 用 malloc 申请一片连续的存储空间
    L.data = (ElemType *)malloc(InitSize * sizeof(ElemType));
    L.length = 0;
    L.MaxSize = InitSize;
}
```

ElemType *data 这不是真的存了数据，它只是一个指向某块内存起始位置的指针。

L.data = (ElemType *)malloc(InitSize * sizeof(ElemType))是malloc 向操作系统申请一块连续的、空闲的内存。
- InitSize * sizeof(ElemType)：我要租 10 个住户的位置，每个住户占 sizeof(ElemType) 字节。
- (ElemType *)：把 malloc 返回的 void* 强制转换成指向 ElemType 的指针。
- 最后把这块内存的首地址交给 L.data 保管。

>  为什么要 (ElemType *) 强制转换？
> - 严格来说，在标准 C 里 malloc 返回 void*，赋值给任何指针类型会自动转换，不写也行。但写上去更明确，而且有些老编译器/教学场景会要求显式转换。属于习惯写法，不用太纠结。


## 3.顺序表的插入、查找和删除

### 3.1 插入

ListInsert(&L, i, e)：在表 L 中的第 i 个位置（位序）上插入指定元素 e 
- 插入位置及之后的所有元素需要依次向后移动一位
- 必须从表尾方向开始移动（从后往前），否则会导致数据覆盖

```c
void ListInsert(SqList &L, int i, int e) {
    // 将第i个元素及之后的元素后移（j从表尾开始）
    for(int j = L.length; j >= i; j--)
        L.data[j] = L.data[j - 1];
    
    L.data[i - 1] = e;    // 在位置i处放入e（位序i = 数组下标i-1）
    L.length++;           // 长度加1
}
```

可以考虑增加健壮性：

```c
bool ListInsert(SqList &L, int i, int e) {
    // 判断位序i的范围是否有效：合法范围是 [1, length+1]
    if(i < 1 || i > L.length + 1)
        return false;
    
    // 判断存储空间是否已满
    if(L.length >= MaxSize)
        return false;
```

时间复杂度：

设问题规模 n=L.length （表长），关注最深层循环语句的执行次数：

| 情况       | 插入位置                           | 循环次数            | 时间复杂度      |
| -------- | ------------------------------ | --------------- | ---------- |
| **最好情况** | 表尾（$i = n+1$）                  | 0 次（无需移动）       | **$O(1)$** |
| **最坏情况** | 表头（$i = 1$）                    | $n$ 次（全部后移）     | **$O(n)$** |
| **平均情况** | 假设各位置概率均等（$p = \frac{1}{n+1}$） | $\frac{n}{2}$ 次 | **$O(n)$** |

### 3.2 查找

#### 3.2.1 按位查找

GetElem(L, i)：按位查找操作，获取表 L  中第 i  个位置的元素的值。

```c
//按位查找
ElemType GetElem(SqList L, int i) {
    return L.data[i - 1];    // 位序i对应数组下标i-1
}

```

顺序表支持随机存取：通过起始地址 + 偏移量直接定位元素。时间复杂度：O(1)  —— 这是顺序表相比链表的最大优势


#### 3.2.2 按值查找

LocateElem(L, e)：按值查找操作。在表 L 中查找第一个值等于 e 的元素，并返回其位序。

```c
//按值查找
int LocateElem(SqList L, ElemType e) {
    // 遍历顺序表，注意只遍历有效元素（i < L.length）
    for(int i = 0; i < L.length; i++) {
        if(L.data[i] == e)    // 找到值为e的元素
            return i + 1;     // 返回其位序（下标+1）
    }
    return 0;                 // 查找失败，返回0（0不表示合法位序）
}
```
- 循环条件必须是 i < L.length，不能写成 i < MaxSize（避免扫描未使用的脏数据）
- 返回值是位序（1∼n ），不是数组下标
- 查找失败返回 0 是一种常见约定（因为位序从 1 开始）

| 情况       | 元素位置        | 比较次数              | 时间复杂度      |
| -------- | ----------- | ----------------- | ---------- |
| **最好情况** | 表头（$i = 1$） | 1 次               | **$O(1)$** |
| **最坏情况** | 表尾或不存在      | $n$ 次             | **$O(n)$** |
| **平均情况** | 假设各位置概率均等   | $\frac{n+1}{2}$ 次 | **$O(n)$** |

> 若表中元素有序，按值查找可优化为折半查找（O(logn) ）


### 3.3 删除

ListDelete(&L, i, &e)：删除操作。删除表 L 中第 i 个位置（位序）的元素，并用 e 返回被删除元素的值。

与插入相反，删除位置之后的所有元素需要依次向前移动一位，覆盖掉被删除的元素。移动方向为从前往后（从被删位置的下一个元素开始，逐个前移）

```c
bool ListDelete(SqList &L, int i, ElemType &e) {
    // 判断位序i的范围是否有效：合法范围是 [1, length]
    if(i < 1 || i > L.length)
        return false;
    
    // 将被删元素值赋给e（带回删除结果）
    e = L.data[i - 1];
    
    // 将第i个元素之后的元素前移
    for(int j = i; j < L.length; j++)
        L.data[j - 1] = L.data[j];
    
    // 表长减1
    L.length--;
    
    return true;
}
```

- 循环条件 j < L.length：j 最大取到 length-1（最后一个元素的下标）
- L.data[j-1] = L.data[j]：用当前元素覆盖前一个位置
- 移动次数 = L.length - i，即被删元素后面的元素个数

时间复杂度:

设问题规模 n=L.length ：

| 情况       | 删除位置                         | 循环次数               | 时间复杂度      |
| -------- | ---------------------------- | ------------------ | ---------- |
| **最好情况** | 表尾（$i = n$）                  | 0 次（无需移动）          | **$O(1)$** |
| **最坏情况** | 表头（$i = 1$）                  | $n-1$ 次（除首元素外全部前移） | **$O(n)$** |
| **平均情况** | 假设各位置概率均等（$p = \frac{1}{n}$） | $\frac{n-1}{2}$ 次  | **$O(n)$** |


## 4.顺序表的优缺点

| 操作       | 最好     | 最坏     | 平均     | 核心特征       |
| -------- | ------ | ------ | ------ | ---------- |
| **按位查找** | $O(1)$ | $O(1)$ | $O(1)$ | **随机存取** |
| **按值查找** | $O(1)$ | $O(n)$ | $O(n)$ | 需遍历比对      |
| **插入**   | $O(1)$ | $O(n)$ | $O(n)$ | 需移动后继元素    |
| **删除**   | $O(1)$ | $O(n)$ | $O(n)$ | 需移动后继元素    |

| 维度        | 优点                 | 缺点                         |
| --------- | ------------------ | -------------------------- |
| **存取速度**  | 支持随机存取，按位访问 $O(1)$ | —                          |
| **存储密度**  | 高（只存数据本身，无额外指针开销）  | —                          |
| **缓存友好性** | 物理地址连续，CPU缓存命中率高   | —                          |
| **容量弹性**  | —                  | 静态分配容量固定；动态分配扩容需拷贝全部元素，开销大 |
| **增删效率**  | —                  | 插入/删除需移动大量元素，平均 $O(n)$     |
| **空间利用率** | —                  | 需预先分配连续空间，可能产生内部碎片         |

顺序表适用于"查询多、增删少"的场景，例如：
- 数据量稳定、频繁按索引访问的场合
- 元素总数可预估，且主要操作为遍历和读取
- 不适合频繁插入删除的场合，此时应考虑链式存储（链表）。
