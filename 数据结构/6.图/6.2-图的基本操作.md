
图的存储结构主要包括邻接矩阵（Adjacency Matrix）、邻接表（Adjacency List）、十字链表（Orthogonal List）和邻接多重表（Adjacency Multilist）。其中，邻接矩阵与邻接表是最为常用的两种物理存储方式，也是分析基本操作时间复杂度的主要依据。

## 1.图的基本操作定义

设图 G=(V,E) ，其中 V 为顶点集，E 为边集，∣V∣为顶点数，∣E∣为边数。图的基本操作共包含以下十项：
- Adjacent(G, x, y)：判断图 G  中是否存在有向边 <x,y>  或无向边 (x,y) 。
- Neighbors(G, x)：列出图 G  中与顶点 x  邻接的所有边。
- InsertVertex(G, x)：在图 G  中插入新顶点 x 。
- DeleteVertex(G, x)：从图 G  中删除顶点 x  及其关联的全部边。
- AddEdge(G, x, y)：若无向边 (x,y)  或有向边 <x,y>  不存在，则将其加入图 G 。
- RemoveEdge(G, x, y)：若无向边 (x,y)  或有向边 <x,y>  存在，则将其从图 G  中删除。
- FirstNeighbor(G, x)：返回图 G  中顶点 x  的第一个邻接点的顶点号；若 x  没有邻接点或图中不存在 x ，则返回 −1 。
- NextNeighbor(G, x, y)：假设顶点 y  是顶点 x  的一个邻接点，返回 x  除 y  之外的下一个邻接点的顶点号；若 y  是 x  的最后一个邻接点，则返回 −1 。
- Get_edge_value(G, x, y)：获取边 (x,y)  或 <x,y>  对应的权值。 
- Set_edge_value(G, x, y, v)：将边 (x,y)  或 <x,y>  的权值设置为 v

## 2.图的基本操作的时间复杂度分析

以下分别针对邻接矩阵和邻接表，对无向图与有向图进行对比分析。

### 2.1 Adjacent(G, x, y) — 判断边是否存在

**无向图与有向图均适用**。
- 邻接矩阵：基于数组的随机访问特性，直接定位 A[x][y] ，时间复杂度为 O(1)。
- 邻接表：需在顶点 x  的边表中顺序查找顶点 y 。时间复杂度为 O(1) ~ O(|V|)。最坏情况下，x  与图中所有其他顶点均相连，需遍历长度为 ∣V∣−1  的边表。

### 2.2 Neighbors(G, x) — 列出邻接边

无向图：
- 邻接矩阵：需扫描第 x 行的全部 ∣V∣ 个元素以确定所有邻接点，时间复杂度为 O(|V|)。
- 邻接表：遍历顶点 x 的边表即可，时间复杂度为 O(1) ~ O(|V|)，取决于顶点 x 的度。

有向图：
- 邻接矩阵：同样扫描第 x 行，时间复杂度为 O(|V|)。
- 邻接表：需区分出边与入边。
  - 出边：遍历 x 的边表，时间复杂度为 O(1) ~ O(|V|)。
  - 入边：由于标准邻接表仅存储出边，必须遍历所有顶点的边表以查找指向 x 的边，时间复杂度为 O(|E|)。


### 2.3 InsertVertex(G, x) — 插入顶点

**无向图与有向图均适用**。
- 邻接矩阵：在顶点表末尾增加顶点 x ，并在矩阵中新增一行一列（初始化为 0）。若采用动态数组或仅需逻辑追加，时间复杂度为 O(1)。
- 邻接表：在顶点数组（或链表）中增加一个表头结点，并将其边表指针置空，时间复杂度为 O(1)。

### 2.4 DeleteVertex(G, x) — 删除顶点

无向图：
- 邻接矩阵：需将第 x 行、第 x 列清零（或物理删除并移动后续行列以维持矩阵紧凑），涉及 O(∣V∣)  量级的元素操作，时间复杂度为 O(|V|)。
- 邻接表：需释放 x 的边表；同时，必须遍历其余所有顶点的边表，删除与 x 相关联的边结点，时间复杂度为 O(1) ~ O(|E|)。

有向图：
- 邻接矩阵：同无向图，时间复杂度为 O(|V|)。
- 邻接表：
    - 删出边：删除 x 的边表，时间复杂度为 O(1) ~ O(|V|)。
    - 删入边：遍历所有顶点的边表以删除指向 x 的边，时间复杂度为 O(|E|)。


### 2.5 AddEdge(G, x, y) — 添加边

**无向图与有向图均适用**。
- 邻接矩阵：直接修改 A[x][y]（无向图还需对称修改 A[y][x]），时间复杂度为 O(1)。
- 邻接表：在 x 的边表头部（或尾部）插入新边结点，时间复杂度为 O(1)。


### 2.6 RemoveEdge(G, x, y) — 删除边

**无向图与有向图均适用**。
- 邻接矩阵：需修改 A[x][y]（无向图还需对称修改 A[y][x]），时间复杂度为 O(1)。
- 邻接表：需在 x 的边表中定位并删除 y 对应的结点。若采用单向链表，需遍历查找前驱，时间复杂度为 O(1) ~ O(|V|)。

### 2.7 FirstNeighbor(G, x) — 返回第一个邻接点

无向图：
- 邻接矩阵：从第 x 行第一个元素开始顺序扫描，直至找到第一个非零元素，时间复杂度为 O(1) ~ O(|V|)。
- 邻接表：直接读取 x 边表的首结点，时间复杂度为 O(1)。

有向图：
- 邻接矩阵：同无向图，为 O(1) ~ O(|V|)。
- 邻接表：
    - 出边邻接点：直接取 x 边表的首结点，为 O(1)。
    - 入边邻接点：需遍历所有顶点的边表，时间复杂度为 O(1) ~ O(|E|)。

### 2.8 NextNeighbor(G, x, y) — 返回下一个邻接点

无向图：
- 邻接矩阵：从第 x 行中 y 所在位置的下一个元素继续顺序扫描，时间复杂度为 O(1) ~ O(|V|)。
- 邻接表：在 x 的边表中定位到 y 的结点后，直接取其后继结点，时间复杂度为 O(1)。

有向图：在出边语境下，邻接矩阵为 O(1) ~ O(|V|)，邻接表为 O(1)。

### 2.9 Get_edge_value / Set_edge_value — 边权值操作

**无向图与有向图均适用**。
- 这两项操作的核心在于定位边，与 Adjacent 操作逻辑雷同。
- 邻接矩阵：直接访问 A[x][y] ，时间复杂度为 O(1)。
- 邻接表：在 x 的边表中顺序查找 y ，时间复杂度为 O(1) ~ O(|V|)。


## 3.总结

邻接矩阵：空间复杂度为 O(∣V∣^2) ， 与边数无关。适用于稠密图，或在算法中需要频繁判断边是否存在、频繁获取/修改边权值的场景。其优势在于随机访问，缺陷是空间浪费（对稀疏图而言）。

邻接表：空间复杂度为 O(∣V∣+∣E∣) ，适用于稀疏图。其优势是节省空间且遍历一个顶点的所有邻接点效率高；缺陷是在标准实现中不便于处理有向图的入边（需遍历全图），且判断某条特定边是否存在需要顺序查找。

十字链表（Orthogonal List）：专为有向图设计。它将每条有向边结点同时链接入起点的出边表和终点的入边表，从而在有向图中实现出边与入边的高效遍历，解决了标准邻接表入边操作时间复杂度过高的问题。

邻接多重表（Adjacency Multilist）：专为无向图设计。每条无向边仅用一个结点存储，同时链接入两个端点的边表。这使得删除边时无需在两个端点的边表中分别查找和删除，简化了无向图的边维护操作。

在标准邻接表中，入边相关操作（如查找入边、删除入边、找入边邻接点）的时间复杂度为 O(∣E∣) ，其根本原因是邻接表只显式存储了出边。若应用需求频繁涉及入边，除采用十字链表外，也可额外维护一个逆邻接表，以空间换时间。

上述基本操作是图遍历算法的底层支撑。特别是 FirstNeighbor 与 NextNeighbor，为深度优先遍历（DFS, Depth-First Search）和广度优先遍历（BFS, Breadth-First Search）提供了按序访问邻接点的统一接口。图的遍历是后续学习最小生成树、最短路径、拓扑排序等高级算法的必要基础。
